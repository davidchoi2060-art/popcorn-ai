# 디자인 브리프 서식 — 화면을 클로드 디자인에 맡길 때

**PM 이 쓰고, 사장님이 클로드 디자인에 붙여 넣고, 돌아온 파일에 PM 이 데이터를 넣는다.**

    ①  PM      데이터를 재서 브리프를 쓴다        <- 이 문서의 §A + §B
    ②  사장님   클로드 디자인에 붙여 넣는다        claude.ai/design
    ③  사장님   나온 `.dc.html` 을 리포에 둔다     docs/design/incoming/
    ④  PM      배선한다 — 값·상태·동작            <- §C

**§A + §B 를 통째로 붙여 넣는다.** §C 는 우리가 볼 몫이라 넘기지 않는다.

---

## 왜 이 순서인가

사용자 지시(2026-08-12): *"내가 클로드 디자인을 통해서 디자인을 구현한 파일을 가져오면,
거기에 데이터와 코드를 넣는 게 어떨까요?"*

그리고 재구축 규약이 이미 같은 것을 말한다 — **① 콘텐츠 기획 → ② 형태 → ③ 표출.**
반대로 하면 **포맷이 내용을 지시하고, 그 칸을 채우려고 데이터를 만들게 된다.**
`26,480` 과 「호환성 5종」이 그렇게 생겼다.

그래서 **§A 는 형태를 적는 칸이 아니라 내용을 적는 칸이다.** 색·여백·카드 수를
브리프가 정하지 않는다. 그건 맡기는 쪽의 일이다.

---

# §A 화면 브리프 (화면마다 새로 쓴다)

> 아래를 채운 뒤 §B 를 이어 붙여 통째로 넘긴다. **빈칸을 남기지 않는다** —
> 「없음」도 적는다. 안 적으면 디자인이 그 칸을 상상해서 만든다.

## A-1 무엇

    화면 ID     ADM-___-___          (신규면 PM 이 부여 · `docs/decisions/admin-identity.md` 규칙)
    경로        /admin2/___
    도메인      상품 / 사양 / 소싱 / 판매가 / 인계 / AI / 시스템
    보는 사람    운영자 · owner · 고객 중 누구
    이 화면이 답하는 질문   한 문장. 두 개면 화면이 둘이다.
    여기서 내리는 결정      이 화면을 보고 사람이 **무엇을 하는가**.
                          「본다」로 끝나면 그건 화면이 아니라 보고서다.

## A-2 실제 데이터 (재서 적는다 — 지어내지 않는다)

**실측값을 준다.** 자릿수·글자 길이·건수가 레이아웃을 정한다.
「상품 목록」이라고만 적으면 22,838건짜리 표를 10행짜리로 그려 온다.

| 항목 | 원천(테이블·API) | 실측 | 최댓값·최장 문자열 |
|---|---|---|---|
| 예) 상품명 | `products.product_name` | 22,838건 | 최장 87자 (P-…) |
| 예) 판매가 | `products.sell_price` | — | 최대 2,560,000원 (8자리) |

    없는 데이터   여기에 명시한다. 디자인이 칸을 만들지 않게.
                예) 「쿨러 TDP 는 324건이 비어 있다 — 값 없음 표시가 필요하다」

## A-3 상태 — 전부 그려 달라고 명시한다

정상 화면만 받으면 **나머지는 우리가 급조하게 되고, 그때 화면이 조용히 죽는다.**
`cap=null` 하나에 LIVE 스크립트가 통째로 멈춰 다른 구성이 장바구니에 담긴 적이 있다.

    빈 상태      0건일 때 무엇을 말하나
    로딩         첫 진입 · 갱신 중
    실패         401 세션 만료 · 500 · 부분 실패(일부 항목만 실패)
    경계         가장 긴 문자열 · 가장 큰 수 · 값 없음(—)

## A-4 동작

    버튼·링크    무엇을 하는가 · 어디로 가는가
    되돌릴 수 없는 것   있으면 표시한다. 화면이 **먼저** 말해야 한다.
    일괄 동작    있으면: 자격 없는 대상을 어떻게 다루나(막지 않고 사유와 함께 건너뛴다)

## A-5 이 화면에서 하지 말 것

화면마다 다르면 적고, 없으면 「없음」.
예) 「가격을 정하는 화면이 아니다 — 예외를 잡는 화면이다」

# §B 고정 계약 (매번 그대로 붙인다)

## B-1 디자인 토큰 — **값은 여기 적지 않는다**

브리프를 만들 때 **`design-system/tokens.css` 의 `:root` 블록을 그대로 복사해** 이 자리에
붙인다. 이 문서에 HEX 를 옮겨 적으면 낡는다 — CLAUDE.md 가 `#005ab3`(폐기된 색)을
들고 있다가 실제 토큰과 어긋난 채 오래 남은 적이 있다.

    ```css
    /* ← 여기에 design-system/tokens.css 의 :root 를 붙인다 (2026-08-12 기준 44개) */
    ```

넘길 때 함께 적을 문장:

> **색·여백·라운드·서체는 위 `:root` 변수만 쓴다. 임의 HEX·px 를 새로 만들지 않는다.**
> 필요한 값이 없으면 **만들지 말고 「없다」고 알려 달라** — 토큰을 늘릴지는 우리가 정한다.

    통과·정상   관리자 화면은 `--primary`. 초록(`--success*`)은 고객 화면 전용이다(U-01).
    위험        `--error`
    **색만으로 판정을 말하지 않는다 — 항상 텍스트를 병기한다**(색약 배려).
    차트에 초록을 쓰지 않는다 — 주문 상태·분류 건수는 통과/실패가 아니라 공정 단계다.

## B-2 산출물 형태

    형식        HTML 파일 하나 (CSS 는 `<style>` 인라인)
    금지        React · Vue · Tailwind · 빌드 도구
                — 우리는 FastAPI + Jinja2 서버 렌더다
    금지        외부 CDN 일체 (웹폰트 · 아이콘 · 차트 라이브러리 · 스크립트)
                — 폰트·아이콘은 전부 자체 호스팅한다(A-30). 글리프 7종 때문에
                  아이콘 폰트를 통째로 받고 있던 적이 있다.
    서체        `var(--font)` · `var(--font-head)` · 숫자는 `var(--font-num)`
                `@import` · `<link>` 로 폰트를 불러오지 않는다
    아이콘      인라인 SVG 또는 자리만 표시. 우리 팩(Streamline Ultimate Color)으로 바꾼다
    차트        `<canvas data-chart="이름">` 자리만. 라이브러리를 쓰지 않는다

## B-3 마크업 계약 — **이게 배선의 전부다**

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 최상위 | `data-screen-id="ADM-…"` `data-domain="…"` | 화면을 식별한다 |
| **서버에서 오는 값 전부** | `data-bind="키"` | **하나라도 빠지면 그 자리는 영영 가짜다** |
| 반복 목록 | `data-repeat="키"` + **본보기 행 하나만** | 여러 줄이면 지우다 남긴다 |
| 버튼·링크 | `data-action="키"` | 동작을 잇는 자리 |
| 예외 상태 | 미리 그려 두고 `hidden` | 없으면 급조하게 되고 그때 죽는다 |

**A-2 에 적은 값 중 `data-bind` 가 없는 것이 하나라도 있으면 반려한다.**
근거: 랜딩·S0 이 "실시간 재고 검증"이라 써 붙이고 API 를 한 번도 안 불렀다 —
`data-bind` 만 있고 아무도 바인딩하지 않은 자리가 오래 남아 있었다(슬라이스 59).

## B-4 예시 값 — 진짜처럼 쓰지 않는다

    입력 폼      `value=` 를 **비운다**. 셀렉트 기본은 「선택하세요」.
                마크업에 남아 있던 다른 상품명·가격이 신규 등록의 기본값이 되어
                그대로 저장될 뻔했다.
    표·카드      본보기 한 줄. 숫자는 **자릿수만 맞추고 실제 값을 쓰지 않는다**.
    지어낸 수치   금지. 후보 수·가격·건수·규칙 수는 서버 응답만 쓴다 —
                「모든 견적에는 이유가 있습니다」가 이것으로 무너진다.

## B-5 그 밖

    한국어 UI    기술 약어(CPU·GPU·DDR5)만 영문
    문구         **관리도구 용어**로 쓴다 — 서술문·구어체 금지
                  「값이 모자랍니다」 -> 「사양 값 부족」
                  「보내지 못했습니다」 -> 「전송 실패」
                  「도는 팀원이 없습니다」 -> 「실행 중인 작업 없음」
    반응형       768px 이하 세로 스택. 가로 스크롤은 표·차트 **자기 상자 안에서만**
    접근성       시맨틱 태그 · 이미지 `alt` · 입력 `label` 연결 · `aria`
    다크모드     쓰지 않는다 (Popcorn Light 단일 · D-07)

# §C 받은 뒤 (우리 몫 — 넘기지 않는다)

## C-1 두는 자리

    docs/design/incoming/<화면ID>.dc.html      받은 원본. **고치지 않는다**
    templates/admin/<이름>.html.j2             배선한 것

원본을 남기는 이유: 다시 맡길 때 **무엇이 원안이고 무엇이 우리가 바꾼 것인지**
구분되어야 한다. 원본을 덮으면 다음 브리프를 쓸 때 근거가 없다.

## C-2 셸에 얹는다 — **독립 페이지로 두지 않는다**

    `templates/admin/_layout.html.j2` 를 상속한다 (좌측 메뉴 · 상단바 · tokens.css)

받아 온 파일의 `:root` 와 셸 마크업은 **버린다.** 안 그러면 화면마다 팔레트가 하나씩
늘어난다 — 실제로 그렇게 됐다(§C-4).

## C-3 배선 검사 — 통과해야 다음 화면으로 간다 (P-08)

    ① 실패 자원 0            네트워크 탭에 404·500 없음
    ② 콘솔 에러 0
    ③ `data-bind` 전수        **바인딩되지 않은 자리가 0개**
    ④ 화면 수치 ↔ API 대조    같은 사실을 두 경로로 구해 일치를 본다
    ⑤ 경계 입력              미로그인 · 빈 상태 · 서버 실패 · 최장 문자열
    ⑥ 문구 전수 검사          §B-5 기준으로 문자열 전부(사용자 지시 2026-08-12)
    ⑦ 비율에는 표본 병기

③ 을 사람 눈으로 하지 않는다. `[data-bind]` 를 전부 걷어 **값이 채워졌는지 세는** 것이
검사다 — 통과는 증거가 아니다.

## C-4 지금 어긋나 있는 것 (2026-08-12 실측 · **미결**)

손으로 짠 두 화면이 디자인 시스템 밖에 있다.

| 화면 | 셸 | tokens.css | 자체 `:root` 변수 | 파일 내 HEX |
|---|---|---|---|---|
| home · products · spec_standard | `_layout` 상속 | 읽음 | 0개 | — |
| **build_map(조감도)** | 독립 | **안 읽음** | **12개** | 32회 |
| **dash(현황판)** | 독립 | **안 읽음** | **15개** | 16회 (+oklch 2) |

토큰이 모자라서가 아니다 — `--card`·`--on`·`--outline`·`--sp-*` 까지 44개가 이미 있다.
그냥 손으로 짜면서 안 쓴 것이다.

**고칠지는 사장님이 정한다.** 조감도의 지금 모습을 보고 *"정말 맘에 듭니다"* 라고
하셨는데, 토큰으로 옮기면 **색이 바뀐다.** 맞바꿈이라 여기 비워 둔다.

    ㉮ 그대로 둔다        두 화면은 예외로 기록하고 신규만 규약을 지킨다
    ㉯ 토큰으로 옮긴다     보기가 달라진다. 지금 팔레트가 마음에 들면 손해다
    ㉰ 토큰을 늘린다       지금 두 화면의 색을 tokens.css 에 정식 편입한다
                        — 겉보기는 안 변하고 정본은 하나가 된다

## C-5 브리프를 쓸 때 PM 이 지키는 것

- **재고 나서 쓴다.** A-2 의 실측은 DB·API 에서 뽑은 값이어야 한다.
  2026-08-11 하루에 다섯 번 틀렸고 다섯 번 다 「재보지 않고 말한 것」이었다.
- **모르는 것은 「미정」이라 적는다.** 임의로 메우면 그 값이 화면이 되어 돌아온다.
- **한 브리프에 화면 하나.** 두 개를 묶으면 둘 다 어중간하게 온다.
