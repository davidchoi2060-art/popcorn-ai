# 정본 계약 — 에이전트가 일 시작 전에 반드시 읽는다

이 저장소가 가장 자주 걸리는 병은 **같은 것을 두 벌 두는 것**이다.
2026-08-05 하루에만 네 건을 찾았고 **넷 다 이미 갈라져 있었다** — 좌측 메뉴가 36화면에
복제돼 어떤 화면에서는 갈 길이 아예 없었고, 디자인 토큰은 아무도 읽지 않아 폴백으로
떨어져 있었다.

**에이전트를 쓰면 이 병이 심해진다.** 각자 자기 문맥만 보고 «없네» 하고 새로 만들기 때문이다.
그래서 무엇을 짓기 전에 **여기 있는지부터 본다.**

## 2. 절대 규칙 — 어기면 결과물을 버린다

1. **화면이 숫자를 지어내지 않는다.** 후보 수·가격·건수·규칙 수는 **서버 응답만** 쓴다.
2. **재고는 원장 밖에서 바뀌지 않는다.** `stock_qty` 를 고치면 `stock_movements` 를 함께 남긴다.
   불변식 `stock_qty = SUM(qty_delta)` 를 회귀가 전 상품에서 검사한다.
3. **모르는 것을 지어내지 않는다.** 과거 입고 시점을 모르면 `opening`(기초 재고)로 적는다.
4. **되돌림은 삭제가 아니라 역방향 전이다.** 역참조 키는 `ref_log_id`.
5. **비밀값을 리포·설정·메모리에 적지 않는다.** `.env` 만(gitignore).
6. **실서비스(`popcornpc.co.kr`)는 읽기 전용.** GET 만. 폼 제출·담기·저장 금지.
7. **UI·데이터 문구는 관리도구 용어로.** 서술어(`~한다`)·의문형(`~는가`)·구어체 금지.
   만들 때마다 사용자에게 보이는 문자열을 **전수 추출해** 훑는다.

## 3. 범위 (2026-08-11 확정)

**팝콘AI 는 신규 고객 유입 채널이다. 판매하지 않는다.**

    고객 → 용도·조건 → 호환성 판정 → 견적 → **팝콘PC 쇼핑몰로 인계**
    결제 · 배송 · 환불 · 회원관리 = 쇼핑몰 소관

- 몰 상품코드 `pd_no` == 우리 `products.product_code` (실측 확인 — 매핑 불필요)
- 가격 원천은 몰. **소싱한 경우만** 우리가 덮어쓰고 `locked_fields` 로 잠근다
- 인계 원장은 `handoffs` — **`orders` 가 아니다**(주문이 아니므로)

## 4. 일하는 방식

- **탐색 최소화.** 전체를 훑지 마라. 필요한 파일만.
- **계획 먼저.** 파일을 만들기 전 3~5줄로 접근을 요약한다.
- **측정하고 말한다.** 「~일 것이다」로 보고하지 않는다. 재고 말한다.
- **엔진·규칙·게이트·원장을 건드렸으면 회귀를 돌린다.** 실패는 전부 코드 문제다 —
  값을 맞추지 말고 고친다.
- **실패를 삼키지 않는다.** `if(!res.ok) return;` 같은 조용한 포기 금지.

## 5. 오늘까지 겪은 실패 — 같은 데 빠지지 마라

| 무엇 | 왜 |
|---|---|
| 서버가 둘인 줄 알고 세 번 죽임 | venv 실행기와 실제 인터프리터가 부모-자식으로 잡히는 것을 몰랐다 |
| 「쿨러 48% 탈락」 오진 | `std` 채움률을 `public` 엔진 것으로 착각 |
| 없는 함수 이름 호출 | `_db_all`·`note`·`_HAS_DB` — 있는 줄 알고 썼다. **부르기 전에 있는지 본다** |
| `\a`·`\v` 가 제어문자로 | 경로 문자열을 이스케이프 문맥에 그대로 썼다. 눈에 안 보인다 |
| 한 문단에 수정 둘일 때 하나만 적용 | `break` 로 끊었다. 스크립트가 «못 찾음»을 보고해 잡혔다 |
| 시연용 상품이 견적에 | 뷰가 `data_origin` 을 읽기만 하고 거르지 않았다 |

**공통점: 재보지 않고 말한 것.** 그리고 **잡은 것은 전부 측정이었다.**
