# 신 관리자 전환 기획 및 기존 기능 처리안

2026-10-02 · 사용자 승인 범위: 구 관리자는 개발 중이며 전체 폐기와 DB 변경에 따른 구 화면 단절을 허용한다. 운영 화면의 무중단 호환 유지가 이번 목표가 아니다.

## 목표와 경계

`관리자-NEW`를 기존 LNB 상단의 독립 진입 버튼으로 제공한다. 진입하면 신 관리자 LNB만 표시하며 구 메뉴를 그 안에 다시 중첩하지 않는다. 구 관리자 접근은 하단 보조 링크로 둔다. 구 화면은 재사용할 기능의 자료이며 보존해야 하는 제품 계약이 아니다. 이번 문서는 설계안이며 화면 삭제·DB 마이그레이션·배포를 실행한 결과가 아니다.

공유 셸·색상·아이콘·인증은 재사용한다. 메뉴 정의는 api/admin_nav.py 한 곳에서 구/신 프로필로 관리하고, 화면마다 LNB를 복제하지 않는다. 별도 신규 셸·디자인 토큰을 중복 생성하지 않는다. 신 화면 진입 이후 제품 상세·이미지·영상·추천 테스트를 이동해도 신 LNB가 유지되어야 한다. 구 화면 직접 URL 진입과 신 업무 경로를 명확히 구분하며 URL 방식은 개발 전 확정한다.

## 신 LNB

1. 처리할 일 — 정보 보완, 가격 확인, 호환 확인, 승인 대기, AI 보완 상태. 이유와 다음 행동 표시.
2. 조립PC 제품군 — 목록 → 제품 상세의 구성·설명·검토·고객 공개·추천 테스트·이미지·영상. 부품 변경 이력도 여기서 연결.
3. 신규 조립PC 생성 — 보유/판매 부품 선택 → 호환·가격 검토 → 저장 → 제품군 검토. 코드 존재는 실제 동작 검증 완료와 별개.
4. 부품 관리 — 상품 정보·사양·설명·가격·판매 상태·보유 재고를 통합. 공급처·소싱·몰 동기화·일괄 가져오기는 하위 화면.
5. 사용·성능 자료 — 게임·업무·로컬 AI·모니터 시나리오, 근거·조건·미준비 질문. 실행/권장/실측 성능 구분.
6. 변경 이력 — 제품·부품·가격·AI 제안·상담·인계 기록. 역할별 조회와 개인정보 범위 유지.

하단 보조 메뉴: 설정 · 자료 관리 / 구 관리자. 설정에는 사양 정의·호환 규칙·추천 정책·운영자·AI 비용/연동을 모은다. 필요한 설정을 없애는 것이 아니라 매일 하는 작업과 구분한다.

## 메뉴에 없는 기존 신규 기능

`/admin2/pc-builder`와 api/admin_pc_builder.py에 판매/보유 부품 선택(source=owned), 미리보기, BOM 중복 조회, 가격·호환 재검토와 저장 경로가 존재한다. 신 메뉴의 신규 조립PC 생성에서 재사용 검토한다. 이미지와 영상은 pc-media / pc-video와 각각 pc_media_jobs / pc_video_jobs를 사용하며, 제품 안의 자산 탭으로 묶는다. 새 통합 작업 기능을 이전 메뉴 항목 수와 혼동하지 않는다.

## DB 처리 원칙과 변경 순서

1. 구성의 원천 pc_configurations / pc_configuration_parts / pc_configuration_offers와 설명 products / product_explanations는 우선 재사용 대상으로 둔다. 화면 혼란만을 이유로 모든 데이터를 다시 생성하지 않는다.
2. pc_media_jobs는 구성 외래키, pc_video_jobs는 구성 및 대표 이미지 외래키를 갖는다. BOM/설명 변경 시 검토·이미지·영상 현재성 기준도 함께 검토한다. JSONB 스냅샷, job_id와 클라우드 파일 참조의 연결을 보존하거나 명시적으로 이전한다.
3. 사양·호환·가격·재고·사용 조건에는 기존 public/std 저장소 및 계산 정본이 있다. 실제 읽기/쓰기 경로와 중복 기준을 확인한 뒤 하나로 정리한다. 메뉴 폐기를 테이블 폐기로 바로 연결하지 않는다.
4. DB 변경 전 필요한 데이터·소스·미디어 참조를 복구 가능하게 보관한다. 마이그레이션 및 소비 API를 함께 변경하고 구 화면 단절은 허용한다. 다만 신 관리자 인증·권한·BOM·가격·재고 원장·추천 승인 조건이 끊기는 것은 허용한 범위가 아니다.
5. 격자 생성 경로·중복 API는 소비 경로 조사 후 제거한다. 모델을 구성해 가격·용도 칸을 채우는 방식은 신 관리자에 이전하지 않는다. 기존 데이터를 이용한 적합성 조회는 별도 판단한다.

## 개발 순서 및 완료 기준

시안 확인 → 관리자-NEW 진입/신 LNB → 처리할 일·제품군·제품 상세 → 신규 구성 → 부품 통합 → 성능 근거 → 설정·이력 → 중복 구 화면/API/DB 정리.

각 업무는 목록 선택 → 편집/AI 제안 → 검사 → 저장/검토 → 목록 복귀 흐름으로 확인한다. 상태·다음 행동·미저장 변경 경고, 검색/표시 수 유지, 팝업/스크롤/작은 화면, 권한과 실패 메시지를 검증한다. 이미지·영상 API 비용은 클릭 및 생성 조건 검사를 거친 실제 생성 작업에서만 발생해야 한다.

이번 확인: 기존 NAV 항목 전수 분석, 기존 업무 LNB와 화면별 혼용 확인, 신규 구성/이미지/영상의 소스 및 테이블 참조 확인. 미확인: 모든 기존 화면 실행, 운영 DB 현재 구조·데이터 직접 조회, 전체 의존 API 호출 관계, 백업·복원 실험. 따라서 지금 DB 테이블 폐기 목록을 확정하지 않는다.
