# 사양축 재정의 기획안 — 게임 · 3D

작성 2026-09-18 · 사장님 지시로 **기획안 먼저, 승인 후 구현**
근거 = `games` 86종 · `game_measured_fps` 150행 · 주사율 DB · `software` 42종 · `refresh_gpu_requirement` 42행

---

## 0. 결론 먼저

**게임 등급 체계(E/A/B/C/S/L)는 이미 잘 설계돼 있다. 건드리지 않는다.**
문제는 **`usage_floors` 가 그걸 하나도 안 쓴다**는 것이다.

```
game         GPU 550W · RAM 16GB · SSD 1TB
game_casual  GPU 550W · RAM 16GB · SSD 500GB    <- GPU·RAM 같음. SSD만 다름
gaming_high  GPU 650W · RAM 32GB · SSD 1TB
```

**GPU 를 「와트」로만 거른다.** 등급도 · 해상도도 · 주사율도 · VRAM 도 안 본다.
그런데 정작 `game_grade_resolution_tiers` 18행은 **등급 × 해상도 → GPU 티어**를
이미 정확히 말하고 있다.

## 1. 게임 — 지금 무엇이 잘못됐나

### 1-1. 등급 체계는 정확하다 (그대로 둔다)

| 등급 | 뜻 | 예 |
|---|---|---|
| **E** | 경쟁 이스포츠 | 발로란트 · CS2 · 롤 · 오버워치 · 에이펙스 |
| **L** | 경량 캐주얼 | 메이플 · 로블록스 · 로스트아크 · 던파 |
| **A** | 일반 AAA(래스터) | AC 섀도우스 · 스파이더맨 · 호라이즌 |
| **B** | RT 적용 AAA | 스타워즈 아웃로스 · 몬헌 와일즈 |
| **C** | 패스트레이싱·UE5 극한 | 사이버펑크 RT · 앨런웨이크2 · 검은신화 오공 |
| **S** | CPU 바운드 시뮬 | MSFS · 시티즈2 · 대규모 전략 |

그리고 해상도별 GPU 티어가 이미 있다:

```
E  1080p T1 (144fps+) / 1440p T1 (240 목표면 T2) / 4K T2
L  전 해상도 T1
A  1080p T1 (VRAM 8GB) / 1440p T2 (12GB) / 4K T3 (16GB)
B  1080p T2 / 1440p T3 / 4K T4 (업스케일 필수)
C  1080p T3 / 1440p T4 / 4K T5 (프레임생성 없이 60fps 불가)
S  전 해상도 GPU T2 + CPU T4 ← 비대칭
```

**이게 정답에 가깝다.** 새로 조사한 주사율 데이터와도 맞는다.

### 1-2. 진짜 문제 셋

**① `usage_floors` 가 등급표를 안 읽는다**
고객이 "롤 해요"라고 하면 `game_casual`(GPU 550W)로 가는데,
등급표는 "E등급 1080p → T1"이라고 말한다. **두 표가 서로 모른다.**

**② 86종 중 21종만 등급 배정** (미배정 65종)
PC방 **3위 리니지 클래식** · **10위 스타크래프트**가 미배정이다.
고객이 가장 많이 하는 게임인데 등급이 없다.

**③ 주사율 축이 없다**
새로 넣은 데이터가 이걸 말한다:

```
롤       목표 240fps  병목 CPU 단일코어 (GPU 무관)
발로란트  목표 360fps  병목 CPU
배그     목표 240fps  병목 램 (3200 vs 4000 = 30fps 차)
오버워치2 목표 240fps  5070Ti 가 4070Ti Super 보다 1% low 낮음 (역전)
철권8    목표  60fps  단 모니터는 240Hz 유리 (입력지연)
```

**「게임 = GPU 550W」로는 이 중 어느 것도 표현할 수 없다.**

## 2. 게임 재정의 — 제안

### 2-1. 용도를 「게임 3종」에서 「게임 1종 + 축 3개」로

```
지금    game_casual / game / gaming_high   (와트로만 구분)

제안    game (하나)
          + 등급축     E · L · A · B · C · S   (이미 있음)
          + 해상도축   1080p · 1440p · 4K      (이미 있음)
          + 주사율축   60 · 144 · 240 · 360    (새로 넣음)
```

고객이 "롤을 240Hz로 하고 싶다"고 하면
→ **E등급 × 1080p × 240fps** → GPU T1~T2 + **CPU 고클럭 우선**

### 2-2. 주사율이 GPU 등급을 올린다

`refresh_gpu_requirement` 42행이 이미 이걸 말한다:

| 모니터 | 경쟁게임 | AAA |
|---|---|---|
| FHD 144~165Hz | 50~60급 | 60Ti급 |
| FHD 240Hz | **60Ti급** | **90급** (RTX 5090) |
| QHD 165Hz | 70급 | 70Ti급 |
| QHD 240Hz | 70Ti급 | 80급+ |
| 4K 60Hz | 70급 | 70Ti급 |
| 4K 120~144Hz | 70Ti급 | 80~90급 + DLSS 필수 |

**같은 모니터인데 용도로 갈린다.** 하나로 뭉개면 둘 다 틀린다.

### 2-3. 병목이 부품 우선순위를 바꾼다

`games.bottleneck` 이 이미 채워져 있다(84/86):

```
bottleneck=cpu   -> CPU 예산 비중을 올린다 (롤·발로·오버워치·메이플·로아)
bottleneck=ram   -> RAM 속도·용량을 본다   (배그·타르코프)
bottleneck=gpu   -> GPU 등급이 지배        (AAA 대부분)
```

**지금은 전부 GPU 와트로만 거른다.**

### 2-4. 조건부 RAM 규칙 연결

이미 `part_cond_rules` 표를 만들어 뒀다(시드 1행):
```
GPU.vram_gb <= 8  →  RAM >= 32GB
```
근거: VRAM 8GB 초과분이 램으로 넘어가 페이지파일 스왑 → 프레임타임 붕괴.
**엔진 연결이 아직 안 됐다.**

## 3. 3D 재정의 — 사장님 확정: 「CAD·설계 / 3D그래픽·렌더링」

### 3-1. 왜 갈라야 하나 (DB 실측)

같은 「3D」인데 **병목이 정반대**다:

| 프로그램 | 병목 | RAM(공식/커뮤) | VRAM | 근거 |
|---|---|---|---|---|
| 오토캐드 | **CPU** | 32/32 | 8 | "코어 수가 아니라 **클럭**을 지목" |
| 솔리드웍스 | **CPU** | 32/32 | — | "형상 재생성이 **순차 연산**" |
| 인벤터 | **CPU** | 32/32 | 8 | "부품 500개↑ 32GB, 초대형 64GB" |
| 3ds 맥스 | **CPU** | 8/— | — | "V-Ray·Corona 렌더러를 붙여 씀" |
| 블렌더 | **GPU** | 32/**64** | 8/**12** | "Cycles 렌더링이 GPU 연산" |
| 마야 | 혼합 | 16/32 | — | "뷰포트는 GPU, 렌더링(Arnold)은 CPU" |
| 스케치업 | **VRAM** | 8/— | 8 | "PBR 재질은 VRAM 32GB↑" |

**현재는 이 일곱을 `video_3d` 하나(GPU 850W · RAM 64GB · SSD 2TB)로 묶었다.**

그 결과:
- **오토캐드 고객에게 850W GPU를 판다** (실제론 고클럭 CPU가 필요)
- **블렌더 고객에게 코어 수를 안 본다** (실제론 GPU + 코어 둘 다)

### 3-2. 제안하는 두 용도

```
cad          CAD·설계          RAM 32GB · VRAM 8GB · CPU 고클럭 우선
             오토캐드 · 솔리드웍스 · 인벤터 · 스케치업
             낱말: CAD · 캐드 · 오토캐드 · 솔리드웍스 · 인벤터 · 도면 · 설계 ·
                   스케치업 · 건축 설계 · 기계 설계

render_3d    3D그래픽·렌더링    RAM 64GB · VRAM 12GB · GPU 등급 + 멀티코어
             블렌더 · 마야 · 3ds 맥스
             낱말: 3D · 렌더링 · 렌더 · 블렌더 · 마야 · 3ds · 시각화 ·
                   애니메이션 · 모델링 · V-Ray · Arnold · Cycles
```

### 3-3. ⚠ 판단이 필요한 자리

- **마야가 어디로 가나** — 병목이 「혼합」이다. 뷰포트는 GPU, 렌더는 CPU.
  제안: `render_3d`(3D 그래픽 계열이므로). 다만 CPU 하한도 함께 건다.
- **3ds 맥스 공식값이 낮다** — 공식 RAM 8GB인데 조사자가 "실무 기준으로 현저히 낮아
  견적 근거로 그대로 쓰면 안 된다"고 적었다. **커뮤니티 값도 없다.**
  → 같은 계열(블렌더 64GB)을 따르되 **근거에 그 사실을 밝힌다.**
- **스케치업 VRAM 32GB** — "PBR 재질 쓰면"이라는 조건부다.
  `part_cond_rules` 로 표현할 수 있으나 조건("PBR 쓰나")을 고객에게 물을 수단이 없다.
  → 하한은 8GB로 두고 **근거에만 적는다.**

## 4. 함께 정리되는 것들

### 4-1. 「디자인」에 GPU 하한이 없다
`design`(포토샵·일러스트)이 사양축인데 GPU 조건이 비어 있다.
DB 근거: 포토샵 커뮤니티 **VRAM 8GB**(공식 2GB의 4배) · 라이트룸 **16GB**.
→ **VRAM 하한 8GB 신설 제안.**

### 4-2. 영상편집 SSD 2TB가 맞나
`video` SSD 2TB인데, 조사자가 "병목 5분류에 **저장장치 축이 없다**"고 지적했다.
프리미어 4K 렉의 실제 원인은 GPU가 아니라 **H.264 디코딩**이었다.
→ 이번 범위 밖. 별도 검토.

### 4-3. AI 용도가 VRAM 을 안 본다
`ai` = GPU 650W · RAM 32GB인데, 실제 병목은 **VRAM**이다:
```
스테이블 디퓨전   VRAM 12GB   부족하면 «느려지는 게 아니라 실행 실패(OOM)»
로컬 LLM        VRAM 24GB+   모델 크기로 계산됨 (70B Q4 = 42GB)
```
→ **VRAM 하한 신설 제안** (와트와 VRAM 은 같은 축이 아니다 — RTX 3060 12GB 가 반례).

**① 게임 용도를 하나로 합치는 것**

등급·해상도·주사율로 가르는 안이다. 고객 화면에서는 여전히
"롤 하실 건가요? 배그 하실 건가요?"로 물으므로 **보이는 건 더 정확해진다.**

**② 3D 두 용도의 이름**
`CAD·설계` / `3D그래픽·렌더링` — 고객이 이 말로 자기를 찾을 수 있나?

**③ 등급 미배정 65종을 어떻게 채울 것인가**
- 기계적으로: `bottleneck` + `fps_sensitivity` 조합으로 후보를 좁힌다
- 사람이: 사장님이 직접 확인
- 혼합: 기계가 제안하고 사장님이 승인 (추천)
