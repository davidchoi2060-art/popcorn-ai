## 값 넷 — 영향이 큰 순서로 쌓는다

### ① 카드수수료 (붉은 강조 — 맨 위)

    원천    pricing_settings.card_fee_rate
    배지    **「전 상품 공통 — 마진보다 영향이 큽니다」**
    입력    % 단위
    문구    **「카드사와의 계약값입니다 — 운영자가 임의로 정하는 숫자가 아닙니다.」**
            「미리보기가 «전 상품 N건»으로 세어 마진과 범위가 다르다는 것을 드러냅니다.」
    버튼    「미리보기」

### ② 전역 기본 마진율 (파랑)

    원천    POST /api/admin/pricing-settings · **owner만**
    부제    「예외가 없는 모든 분류에 걸립니다」
    입력    % · **저장된 값 → 고친 값**을 나란히 보여준다
    안내    「스키마 허용 **0% 이상 100% 미만**」
    공식    **제안가 = 매입가 × (1 + 카드수수료 + 마진) → 1,000원 단위 반올림**
            ⚠ **지금 입력된 값으로 계산해 보여준다**(원안이 `0.02585` · `0.14` 를 그대로 쓴다)

**「저장하면 이렇게 바뀝니다 — 서버가 센 값」 6칸** (판매중 · 재고>0 기준):

    대상 · 오름 · 내림 · 변화없음 · 잠김 · **해당 없음**

⚠ **「해당 없음」은 「공급처 0곳이라 안 움직임」**이다. **원안이 그 수를 `?` 로 비워 뒀다** —
**서버가 세게 하고, 못 세면 「못 셈」으로 정직하게 표시**해라. 0 으로 위장하지 마라.

**⚠⚠ 그 아래 반드시 붙는 고지 (그대로):**
> **⚠ 미리보기 전용 경로가 아직 없습니다.** 지금 있는 `GET /reprice/preview` 는
> **이미 저장된 값**으로만 계산합니다 — 그래서 위 숫자는 **저장된 N% 기준 실측**이고,
> 바꾼 값의 결과는 저장 후에야 셀 수 있습니다. **실제 순서는 저장 → 확인 → 되돌림입니다.**

⚠ **이 문장을 흐리지 마라.** 화면이 「미리보기」라 적어 놓고 실제로는 저장 후에야 아는데, 그걸 안 밝히면 거짓말이다.

### ③ 분류별 예외 (초록)

    배지    **「N건 — 정상입니다」**  ⚠ 0건이 지금의 정상 상태다
    버튼    「예외 추가」 → **우측 서랍**
    문구    「아직 예외를 두지 않았고 **N개 분류 전부가 전역값 N% 를 씁니다.**
            설정을 못 불러온 것이 아닙니다 — `category_margin_policies` 가 비어 있는 것이
            지금의 정상 상태입니다.」
    칩      **최상위 분류**를 상품 수와 함께 (부품 · 주변기기 · 쿨링·튜닝용품 · 기타 · 확장·연결 · 완제품)
            각 칩에 「전역」 표시

**하단 고지 두 줄:**
> 분류가 없는 상품 **N건**(`category_id IS NULL` / 전체 N건)에는 예외를 걸 수 없고 전역값이 걸립니다
> ⚠ **「상품 분류 관리」의 마진 칸은 «읽기 전용으로 바뀌고 이 화면을 가리킵니다»** —
> 두 곳에서 같은 값을 고치면 어느 쪽이 맞는지 모르게 됩니다

⚠ **그 변경은 다른 파일이다.** 이 화면 제작자는 **문구만** 적고 `product_category.html.j2` 를 열지 마라.

### ④ 부품별 예산 배분율 (회색 · 읽기 전용)

    배지    **「읽기 전용 · 향후 사용예정」**(점선 테두리)
    원천    `candidates.BUDGET_ALLOC` — **코드 상수**
    표시    부품별 % 칩

**문구 (그대로):**
> 이 값은 **DB 에 없습니다** — 코드 상수라 쓰기 경로가 없고, 편집을 열려면 코드에서 DB 로 옮기는
> 작업이 먼저입니다. 그전까지 여기서도 못 고칩니다.
> **「추천 기준 보기」의 잠긴 편집은 이 자리를 가리키게 바뀝니다.**

⚠ **경로로 판정해라** — 「가격 이력」이 admin2 에 없으면 비활성 + 사유. **라벨로 찾지 마라**(`api/admin_ui_swap_click_logs.py` 사고).

**② 「저장하면 무엇이 언제 바뀌나」**

> **다음 견적부터 적용됩니다 — 이미 만든 견적은 그대로입니다.**
> 이 문장은 **코드로 지켜집니다**(`quote_snapshots.items` 에 판매가를 박아 저장하고
> 그 표를 UPDATE 하는 코드가 저장소 전체에 **0건**).
>
> 전역 마진·카드수수료는 **이력형**입니다(INSERT만 · N행 누적) — 이전 행으로 되돌릴 수 있습니다.
> **⚠ 그런데 분류별 예외는 되돌리기 API 자체가 없습니다.**

**③ 「이 화면에서 안 하는 것」 + 「아직 정해지지 않은 것」**

    안 하는 것
      개별 상품 판매가 확정      → 가격 검토 대기
      대량 재계산 실행           → 판매가 재산정 — **화면 없음**
      예외 잡기 · 잠금           → 판매가 관리
      마진 이력 조회             → 가격 이력

    아직 정해지지 않은 것 — **화면이 「미정」이라 적는다**
      마진율 상한을 화면이 더 좁힐까        미정
      같은 분류에 예외가 둘이면              미정
      미리보기 전용 API 를 새로 만들까       미정
      분류별 마진 되돌리기를 만들까          **API 없음**
      권한 비대칭을 맞출까                   미정
      마진율 음수                            **거부**

⚠ **「미정」을 임의로 메우지 마라.** 화면이 그대로 「미정」이라 적는 것이 확정 사항이다.

## 예외 편집 서랍 (1b 에서 가져온다 · 492px)

**머리** — 「분류별 예외 마진 — {분류명}」
부제 — 「{경로} · 상품 N건 · 지금은 **전역 N%** 를 상속하고 있습니다」 · ✕

**입력** — % · 「스키마 허용 **0% 이상 100% 미만** · 음수는 거부(역마진) · 화면이 더 좁힐지는 **미정**」
**공식** — 제안가 = 매입가 × (1 + 카드수수료 + 이 분류 마진) → 1,000원 단위 반올림
+ **「하위 분류가 없어 이 값은 이 노드에만 걸립니다」**(있으면 하위에도 상속된다고 밝힌다)

**「저장하면 이렇게 바뀝니다」 4줄**

    이 분류에서 제안가가 바뀌는 상품
    그중 오름 / 내림
    **해당 없음 — 공급처 0곳이라 안 움직임**
    잠겨서 제외

**⚠ 그 아래 반드시 (그대로):**
> **⚠ 이 숫자는 서버가 「저장 전」에 센 값이 아닙니다.** 가상의 마진값을 받아 미리 계산해 주는
> 경로가 아직 없어(`dry_run` 파라미터 없음), 위 값은 **저장된 N% 기준 실측을 이 분류로 좁힌 것**입니다.
> 저장한 뒤 실제 결과를 다시 확인해야 합니다.

**⚠ 붉은 박스 — 되돌릴 수 없다**
> **저장하면 이 예외는 되돌릴 수 없습니다**
> 분류별 마진은 **되돌리기 API 자체가 없습니다.** 잘못 걸었으면 **예외를 삭제해 전역값으로
> 되돌리는 것**이 유일한 길이고, **그 사이에 돈 재산정 결과는 남습니다.**
> 공급처가 0곳인 상품은 정책을 바꿔도 **움직이지 않습니다** — 위 「해당 없음」이 그 몫입니다.

**「예외를 지우면」**
> 이 분류는 **전역 기본값 N% 로 돌아갑니다.** 지우는 것 자체가 값 변경이라 **삭제도 같은 확인 단계**를 지납니다.

**서랍 하단** — 「저장하면 **다음 견적부터** 적용됩니다 — 이미 만든 견적은 그대로입니다」 · 「취소」 · **「확인하고 저장」**
