## 문제의 정확한 모양
현 `BUDGET_ALLOC`(candidates.py) = 슬롯별 **상한**만: GPU 40% · CPU 25% · RAM 10% …, 전 용도 고정.
배치 20260912-02 실측:
- 팝콘 5 개발 = RTX 3050 29만(13%) + 울트라9 285K 102만(46%) — CPU 상한 25% 인데 통과?
  → recommend 티어는 `common`(배분 미적용) 풀도 쓰고, highend 는 ×1.5 라 CPU 37.5% 까지 허용.
  그리고 **GPU 하한이 없어** 남는 돈이 CPU 로 갔다.
- 팝콘 9 AI = RX 9070 116만(15%) + 서버램 64GB 441만(55%) — RAM 상한 10%×1.5 = 15% 인데 통과?
  → usage_tier_rules 가 RAM 64GB 를 강제 → 64GB 최저가가 441만(ECC/REG 서버램) → 배분 상한을
  넘어 조합 실패 → 배분 해제 폴백(슬라이스 58 규칙) → 아무 배분 없이 채워짐.
  ⚠ 진짜 원인: **재고에 일반 DDR5 64GB 가 135만부터인데 엔진이 441만짜리 서버램을 골랐다** —
  「가격 내림차순 첫 성립」이 RAM 에서 가장 비싼 것을 먼저 잡기 때문. 상한이 걸려 있었으면
  135만짜리로 갔을 것. 배분이 풀리는 순간 이 병이 도진다.

  그 조합을 버리고 다음을 본다. 상한(pct_max)은 지금처럼 후보 필터.

### 엔진 적용 (recommend.py)
1. `BUDGET_ALLOC` 상수 → `usage_alloc.for_usage(usage_key)` 가 {slot: (min,max)} 를 준다.
   usage_key 없거나 표에 없으면 기본(NULL) 행. **`BUDGET_ALLOC` 은 DB 못 읽을 때 폴백**으로만 남긴다
   (spec_fields·usage_floors 와 같은 패턴).
2. 상한 필터: `sale_price <= cap × pct_max` (지금 자리 그대로, 값만 용도별).
3. **하한 판정**: `_build_set` 이 조합을 완성할 때 슬롯가/총액 < pct_min 이면 reject 하고 계속 탐색.
   DFS 노드 예산 안에서 못 찾으면 → 하한만 풀고 재시도 + reasons 「시장 배분 하한으로는 조합이
   없어 상한만 적용」(기존 폴백 패턴).
4. **폴백 순서를 고친다**: 지금은 「배분 상한 풀로 실패 → 배분 전면 해제(common)」. 이게 441만
   서버램을 부른다. 바꿔서: 상한 ×1.0 실패 → 상한 ×1.5 → 상한 ×2.0 → 그래도 없으면 해제.
   단계마다 reasons 에 어느 단계에서 성립했는지 남긴다.
5. highend 의 `HIGHEND_CAP_X=1.5` 는 그대로(총액 상한). 슬롯 배분은 위 표.
6. 응답 `alloc: {usage_key, applied_stage: 1.0|1.5|2.0|none, items:[{slot,min,max,actual_pct}]}`.
   reasons 에 「예산 배분 — 그래픽카드 42%(시장 32~48%) · CPU 15%」처럼 **실제 비율을 적는다**.

### 회귀 불변식
- 활성 usage_alloc.usage_key ⊆ usage_floors.usage_key ∪ {NULL}
- 모든 행 0 ≤ pct_min < pct_max ≤ 1, 슬롯별 pct_min 합 < 1 (아니면 어떤 조합도 못 성립)
- 카드 실측: 배치 후 팝콘 5·7·9 각 게임·AI 카드의 GPU 비율이 그 용도 [min,max] 안 (스냅샷 아님·관계식)
