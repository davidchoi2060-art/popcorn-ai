# 관리자 화면 전수 감사 — 눈으로 본 기록

**일자:** 2026-08-06 · **방법:** 로컬 API(실데이터)에 붙은 화면을 브라우저에서 직접 열어 봄
**계기:** 사용자 지적 "지금 팝콘 AI 화면 UI 들이 정말 맘에 안듭니다"
**앞선 문서:** `phoenix-screen-match.md` — 그 문서의 §1 측정은 **무효**이고 이 감사가 대체한다.

---

## 왜 다시 했는가

첫 진단은 **정적 마크업 크기**로 화면을 줄 세웠다. 그런데 우리 관리자 화면 다수는
본문을 **JS로 그린다** — 마크업에는 빈 컨테이너 하나(`#liveRules`·`#host`·`#body`)만 두고
fetch 뒤 채운다. 그래서 "875자짜리 초라한 화면"으로 지목한 것들이 실제로는 충실했다.

두 번 틀린 뒤 내린 결론: **화면이 무엇을 보여주는지는 열어 봐야 안다.**
이 프로젝트는 이미 같은 것을 배웠다(CLAUDE.md "브라우저에서 실제로 열어 봐야 보이는 것").

**방법 표기(정직):** 22화면은 화면을 캡처해 눈으로 봤고, 13화면은 렌더된 본문·행수·카드수·
섹션 제목을 뽑아 확인했다. 아래 표의 `본` 열에 어느 쪽인지 적는다 — 텍스트로만 본 화면은
레이아웃 결함(열 접힘 같은 것)을 놓칠 수 있다.

## 총평

**관리자 UI는 내가 처음 말한 것보다 훨씬 나은 상태다.** 36화면 대부분이 KPI 타일 ·
필터 · 목록/상세 2단 · 단계 표시 · 정직한 빈 상태를 이미 갖췄다.
특히 아래 넷은 Phoenix 템플릿에서 베껴올 것이 없다 — 이미 그 형태다:

| 화면 | 이미 갖춘 형태 | 내가 "제안"하려던 것 |
|---|---|---|
| `review-queue` 상품 검수 | 좌 목록 / 우 상세 + 4단계 스테퍼 + 신뢰도 | `project-management/todo-list.html` |
| `product-edit` 상품 상세 | 좌 본문 / 우 사이드 2단 + 게이트 상태판 | `e-commerce/admin/add-product.html` |
| `sessions` 견적 상담 | 좌 목록 / 우 스냅샷 재현 | `crm/lead-details.html` |
| `refunds` 환불 | 목록·상세 2단 + 단계 파이프라인 | `e-commerce/admin/refund.html` |

**비어 보이는 화면은 대부분 데이터가 비어 있는 것이다** — 환불 2 · 후기 4 · 공급처 4 ·
회원 0 · 가격 검토 대기 0 · 일괄 등록 이력 0. 행이 없는 화면에 레이아웃을 얹으면 더 비어 보인다.

## 실제로 고칠 것 — 셋

### ① 대시보드 주문 상태 차트가 **echarts 기본 팔레트**를 쓴다 〔확인됨〕

`chOrders` 는 `itemStyle.color` 를 주지 않아 기본 팔레트로 떨어진다:

```
#5470c6  #91cc75  #fac858  #ee6666  #73c0de  #3ba272
           ↑초록                              ↑초록
```

두 가지를 동시에 어긴다:
- **`U-01` 초록 없음** — 통과=`--primary` · 위험=`--error`, 항상 텍스트 병기가 우리 규칙이다.
- **임의 HEX 금지** — 토큰이 단일 원천인데 남의 기본값 여섯 개가 화면에 들어와 있다.

같은 화면의 `chPool`·`chPending` 은 `C("primary")` 로 제대로 집는다 — 이 하나만 빠졌다.
**회귀가 못 잡는다**(마크업이 아니라 런타임 옵션이라서). 고치면서 검사도 함께 만들 것.

### ② 상품 관리 목록의 상품명 열이 **3~4줄로 접힌다** 〔확인됨〕

`(BonoBoss) BOS A2 /사운드/스피커` 같은 이름이 좁은 열에서 줄바꿈되어, 20행을 훑는 데
눈이 계속 걸린다. 목록의 본래 일(빠른 스캔)을 못 한다.
템플릿 `apps/e-commerce/admin/products.html` 은 **썸네일 + 넓은 이름 열**로 이 문제를 푼다.
열 너비 배분만 조정해도 대부분 해소된다.

### ③ 추천 기준 설정에 **같은 문구가 두 번** 나온다 〔확인됨〕

"추천 가중치 저장소(policy_weights)는 비어 있습니다 — …" 문장이 섹션 설명과 아래
`가중치` 카드에 그대로 반복된다. 서버가 준 `weights.note` 를 두 자리에 그렸다.

## UI 가 아닌 발견 — 운영 결함 하나

**상품 매핑의 `허용 종류 위반` 422건 = 완제품 PC 318 + 베어본 104.**

마이그레이션 `0031` 이 이 둘을 `part_type` 축에 새로 넣었는데(A-31), **판매 분류 트리에는
받아 줄 자리가 없다.** 그래서 전부 위반으로 잡힌다. 화면은 정확히 동작하는 중이고,
할 일은 카테고리 트리에 자리를 만들거나 기존 분류의 `allowed_part_types` 를 넓히는 것이다.
**이건 운영자 판단이라 임의로 하지 않는다.**
