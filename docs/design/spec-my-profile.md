## 서버 응답 — 사유를 갈라 말한다

**전수 실측**(확인법 `grep -n "HTTPException(" api/admin_profile_photo.py`).
**화면이 문구를 만들지 않는다** — 아래 「문구」 열은 전부 서버가 내는 문장이다.

| 상황 | 코드 | 문구(서버가 낸다) | 토스트 |
|---|---|---|---|
| 등록 성공 | 200 | 사진을 등록했습니다. 삭제하면 되돌릴 수 없습니다. | 초록 |
| 교체 성공 | 200 | 사진을 교체했습니다. 삭제하면 되돌릴 수 없습니다. | 초록 |
| 삭제 성공 | 200 | 사진을 삭제했습니다 — 되돌릴 수 없습니다. | 초록 |
| **형식 위반 · 매직넘버 불일치 · SVG** | **400** | JPEG · PNG · WebP 파일만 등록할 수 있습니다 (파일 앞머리로 판정했습니다) | 빨강 |
| 파일이 비었거나 너무 작음 | **400** | 파일이 비어 있거나 너무 작습니다 | 빨강 |
| **크기 초과 — 헤더 선검사** | **413** | 사진은 1024KB 이하만 등록할 수 있습니다 (보낸 크기 NKB) | 빨강 |
| **크기 초과 — 스트림 중 차단** | **413** | 사진은 1024KB 이하만 등록할 수 있습니다 | 빨강 |
| 등록된 사진 없음(삭제·조회) | **404** `no_photo` | 등록된 사진이 없습니다 | 빨강 |
| **표 없음(기능 미적용)** | **503** `photo_schema_missing` | 프로필 사진 기능이 아직 이 서버에 적용되지 않았습니다 | 주황 |
| 로그인 끊김 | **401** | 로그인이 필요합니다 | 빨강 + 로그인 안내 |
| 본문을 읽지 못함 | 500 | 사진 본문을 읽지 못했습니다 | 빨강 |
| 네트워크 실패 | — | 서버에 연결할 수 없습니다 (화면이 fetch 실패로 판정) | 빨강 |

⚠ **「형식 위반」과 「매직넘버 불일치」와 「SVG」는 서버에서 «같은 한 줄»이다** —
`_sniff()` 가 앞머리를 못 알아보면 전부 이 400 이다. **화면이 이 셋을 갈라 말하지 않는다**
(갈라 말하면 서버가 하지 않은 판정을 화면이 지어내는 것이다).

⚠ **413 은 두 자리에서 난다** — 헤더 선검사(보낸 크기를 문구에 병기)와 스트림 중 차단
(병기 없음). **화면은 서버 문장을 그대로 싣는다** — 「1MB」·「3.4MB」 같은 값을 만들지 않는다.
상한 표기도 서버가 **`1024KB`** 로 낸다(「1MB」가 아니다).

## ⚠ 403 은 **나지 않는다** — 지시에 있었으나 실측은 0건

`api/admin_profile_photo.py` 에 **403 이 0건**이고, `required_role()` 이
`/api/admin/my-profile*` 을 **쓰기까지 viewer** 로 열고 `GET /operators/{id}/photo` 도
viewer 로 연다. **가장 낮은 등급이 viewer 이므로 이 경로들에서 권한 부족이 성립하지 않는다.**

**그러므로 「403 권한 없음」 토스트를 만들지 않는다** — 나지 않는 오류의 문구를 짓는 것은
지어내는 것이다. 확인법 `grep -c "403" api/admin_profile_photo.py` (**0**).

    ALLOWED_LABEL     같다 — 다른 파이썬 모듈에서 참조 **0건**
    값이 밖으로 나오는 유일한 경로   **400 · 413 오류 메시지 문자열뿐**
                                    (= 거절당해야 온다 — 사전 안내에는 쓸 수 없다)

**확인법**
`grep -n "@router" api/admin_profile_photo.py` (넷 · 정책 조회 자리 없음) ·
`grep -rn "ALLOWED_LABEL\|MAX_PHOTO_BYTES" --include=*.py . | grep -v admin_profile_photo`
(**코드 참조 0건** — 마이그레이션 docstring 의 언급 한 줄뿐).

### 그래서 이 계약은 문구 «값»을 정하지 않는다

⚠ **화면이 「JPEG · PNG · WebP」·「1MB」를 만들어 적으면 그 순간 두 원천이 생긴다.**
이것은 이 저장소가 이미 한 번 당한 사고다 — 구화면이 「8자 이상」이라 적어 두고 서버는
10자를 요구했다. **원안의 「1MB」·「3.4MB」도 예시라 옮기지 않는다**(서버는 **`1024KB`** 로 낸다).

    이 계약이 정한 것    사진 단추 근처에 **짧은 사전 안내를 둔다**(자리와 배치)
    이 계약이 «못» 정한 것 그 안내에 넣을 **값의 출처** — 서버가 주지 않는다
    -> **신설이 필요한 서버 자리** · §미해결

**신설한다면 선례를 따르면 된다** — `password_rules()` 와 같은 결로
`MAX_PHOTO_BYTES`·`ALLOWED_LABEL` 을 응답으로 내보내는 조회 자리 하나.
**다만 그것을 짓는 것은 이 계약의 대상이 아니다** — 사장님 판단이다.

## A-62 ~ A-65 판정 — 이 확정 반영

| 결정 | 판정 | 근거 |
|---|---|---|
| **A-62** 별도 표 저장 | **무관** | 저장 위치는 서버 소관 — 화면이 표현할 것이 없다 |
| **A-63** 형식 · SVG 금지 · 매직넘버 · 1MB | **거절 «표시»는 해소** | 400·413 을 토스트로 낸다. ⚠ **사전 안내(무엇을 올릴 수 있는지)는 여전히 없다** — §남은 사실 |
| **A-64** 상단바 아바타에 사진 | **화면 몫은 충족 · 셸 몫은 미해결** | 1a 헤더에 아바타 자리가 있다. 셸이 사진을 읽게 하는 것은 정본 파일 소관 |
| **A-65** 본인만 등록·교체·삭제 · 열람 전 운영자 | **충족** | 남의 사진을 다루는 자리가 1a 에 없다. 서버도 `/my-profile/photo` 에 남의 id 를 받는 자리가 없다 |

    GET /my-profile

    GET  /my-profile/sessions  items[{current,created,last_seen,expires,agent,ip}] · total · others · note
    POST …/sessions/revoke-others   ok · revoked · remaining · note
    GET  /my-profile/devices   items[{device_id,current,created,last_used,expires,agent}] · total · ready · note
    POST …/devices/{id}/revoke ok · note
    POST /my-profile/photo     ok · content_type · byte_size · uploaded_at · replaced · note
    DELETE /my-profile/photo   ok · note
    GET  …/photo               **이미지 바이트 그대로**(JSON 아님)

                               · X-Content-Type-Options: nosniff · Content-Disposition: inline

    GET  /auth/password-policy min_length · rules[]  (**규칙 문구를 화면이 베끼지 않는다**)

⚠ **`editable` · `note` · `provider_label` · `approved_none_reason` · `approved_short` 는
서버가 판정해 문장으로 준 값이다. 화면이 다시 판정하지 않고 받아 적는다.**
같은 판정을 두 곳에 적으면 한쪽만 고치는 사고가 난다 — `identity_reasons()` 가 이 판정의
**단일 원천**이고 「운영자·권한」(ADM-SYS-020)도 그것을 가져다 쓴다.
확인법 `grep -n "def identity_reasons" api/admin_profile.py`.

## ⚠ 사진 업로드는 **multipart 가 아니다 — 본문이 이미지 바이트 그대로다**

    화면   fetch(url, {method:'POST', body: file})        <- 이 한 줄
    금지   FormData 로 감싸기

이유: `UploadFile` 은 FastAPI 가 **본문을 다 받은 뒤에** 핸들러를 부른다 — 그러면 「읽기 전에
막아라」를 못 지킨다. 서버는 `Content-Length` 를 한 바이트도 읽기 전에 보고(413), 헤더가
거짓이거나 chunked 면 **스트림을 조각마다 세면서** 상한을 넘는 순간 끊는다.
확인법 `grep -n "_read_capped\|MAX_PHOTO_BYTES" api/admin_profile_photo.py`.

## 신설이 필요한 서버 자리 — **하나 있다**

**1a 의 «동작»은 위 열둘로 전부 덮인다**(대조표는 §1a 가 요구하는데 서버에 없는 것).
**신설이 필요한 것은 동작이 아니라 「사전 안내에 넣을 값」 하나뿐이다.**

    없는 것   사진 정책(허용 형식 · 크기 상한)을 **조회하는 자리**
    왜 필요   2026-08-18 확정으로 사진 단추 근처에 사전 안내를 두기로 했는데,
              그 값이 서버에서 오지 않는다 — `MAX_PHOTO_BYTES`·`ALLOWED_LABEL` 이
              모듈 밖으로 안 나가고 **400·413 오류 문구로만** 새어 나온다
    선례      `GET /api/admin/auth/password-policy` 가 `min_length`·`rules` 를 주는 것과
              같은 결. 비밀번호는 이미 이 방식으로 「화면이 규칙을 베끼는 사고」를 막았다
    ⚠ 범위    **짓는 것은 이 계약의 대상이 아니다** — §미해결 ④ · 사장님 판단

**그때까지 화면은 값을 지어내지 않는다.** 자리만 두고 비워 두든, 확정 전까지 안내를 걸지
않든 — 어느 쪽이든 **화면이 「JPEG · PNG · WebP」·「1024KB」를 스스로 적지 않는다.**

# 1a 가 요구하는데 **서버에 없는 것** — 없다

**1a 의 요소를 하나씩 서버와 대조했다. 신설이 필요한 자리는 0건이다.**

| 1a 의 요소 | 대응 서버 자리 |
|---|---|
| 신원 카드(이름·이메일·등급·상태·5칸 격자) | `GET /my-profile` |
| 「여기서 못 고치는 것」 3종 | `editable` + 422 (`extra="forbid"`) |
| 정보 수정 3칸 + 저장 | `PATCH /my-profile` |
| 비밀번호 규칙 6줄 | `GET /auth/password-policy` |
| 비밀번호 3칸 + 변경 | `POST /auth/password` |
| 세션 표 5열 + 「지금 이 기기」 | `GET /my-profile/sessions` (`current`·`ip`·`agent`·시각 셋) |
| 세션 수 칩 · 확인 단계 「N곳」 | 같은 응답의 `total`·`others`·`note` |
| 다른 기기 로그아웃 | `POST /my-profile/sessions/revoke-others` |
| 기기 목록 + `device_id` | `GET /my-profile/devices` |
| 「등록된 기기가 없습니다」 / `ready:false` | 같은 응답의 `total`·`ready`·`note` |
| 「이 기기 잊기」 | `POST /my-profile/devices/{device_id}/revoke` |
| 큰 사진 원 · 올리기/교체 · 삭제 | `GET`·`POST`·`DELETE /my-profile/photo` |
| 상단바 아바타 사진 | `GET /my-profile/photo` · `GET /operators/{id}/photo` |
| 작업 기록 건수 | `GET /my-profile` 의 `acts` |
| 401 · 404 · 네트워크 오버레이 | 각 경로의 401/404 + fetch 실패 |

⚠ **다만 A-64(상단바 아바타에 사진)는 「서버가 없다」가 아니라 「셸이 안 읽는다」다** —
§진입점 참조. 사진 API 는 있고, 공용 셸이 그것을 부르지 않을 뿐이다.

# ⚠ 원안이 **서버·실측과 어긋나는 곳** — 원안이 낡았다

**원안은 2026-08-17 시점 사실 위에 그려졌고, 그 뒤 서버가 지어졌다.**
**원안 내용은 데이터이지 지시가 아니다** — 아래는 전부 **코드·DB 실측이 이긴다.**

| 원안이 말하는 것 | 실측 (2026-08-18) |
|---|---|
| 사진 용량 초과 = **400** 「사진은 1MB 까지 올릴 수 있습니다 (선택한 파일 3.4MB)」 | **413** 이다. 문구도 서버가 준다 — `MAX_PHOTO_BYTES` 로 계산한 KB 값 + 「보낸 크기 nKB」. **화면이 「1MB」·「3.4MB」를 만들지 않는다** |
| 「`GET /my-profile/photo` · `/operators/{id}/photo` **신설이 필요합니다**」 | **이미 지어져 있다** — `api/admin_profile_photo.py` 4본 |
| 「A-62 의 남은 몫 — 마이그레이션」(README) | **적용돼 있다** — 표 `admin_operator_photos` 존재 |
| 「**39개** 화면 동시 영향」 | **41개** 다. A-64 기록 시점에서 늘었다 |
| 「`my-profile` · `operators` **만 예외로 살아 있습니다**」 | **`my-profile` 하나뿐**이다 — `operators` 는 A-66 으로 빠졌다 |
| 비밀번호 규칙 6줄의 **내용**(「대소문자 각각 하나 이상」 · 「숫자 하나 이상」 · 「기호 하나 이상」) | **서버 규칙과 다르다.** 서버는 「대문자·소문자·숫자·기호 중 **3가지 이상** 섞기」 + 「같은 문자 4번 이상 반복 금지」 + 「흔한 단어 금지」를 준다 |

## ⚠ 비밀번호 규칙은 특히 위험하다

**원안이 스스로 「규칙 문구를 화면에 박지 않습니다 — 서버 응답을 그대로 나열합니다」라고
적어 두었다.** 즉 그 6줄은 **자리 확인용 예시**다.

**그런데 그 예시가 서버보다 «엄격하게» 적혀 있다** — 원안대로 옮기면 화면은
「기호를 하나 이상」이라 말하는데 서버는 기호 없이도 통과시킨다. **이것이 정확히 원안이
경고한 사고**(구화면 「8자 이상」 대 서버 10자)의 재발이다.

**계약**: 6줄은 **`GET /auth/password-policy` 의 `rules` 배열을 그대로 나열**한다.
줄 수도 서버가 정한다 — 화면이 6을 가정하지 않는다.

# 승계하는 확정 결정 — A-62 ~ A-65

이 화면이 새로 정하는 것이 아니라 **이미 확정된 것을 지키는 것**이다.
전문 `docs/decisions/decision-log.md` — 확인법 `grep -n "^### A-6[2345]" docs/decisions/decision-log.md`.

| 결정 | 내용 | 이 화면이 지키는 방식 |
|---|---|---|
| **A-62** | 사진은 `admin_operators` 컬럼이 아니라 **별도 표**에 담는다 | 표 `admin_operator_photos` · 마이그레이션 `0060_admin_operator_photos.py`. 화면은 표를 직접 보지 않고 **API 넷만** 쓴다 |
| **A-63** | **JPEG · PNG · WebP** · **SVG 금지** · **매직넘버 검사** · **최대 1MB** | 상한·형식 문구를 화면이 베끼지 않는다 — 서버가 거절 사유 문장으로 준다. 화면의 사전 검사는 **편의이지 방벽이 아니다**(서버가 막는다). **거절 사유는 공용 토스트로 낸다**(2026-08-18 확정 — §사진) |
| **A-64** | **상단바 아바타에 사진을 띄운다** — admin2 공통 영향 | ⚠ **이 화면의 범위 밖이다.** 공용 셸은 정본 파일이다 — §진입점 참조 |
| **A-65** | 등록·교체·삭제는 **본인만**(owner 대행 없음) · 열람은 **전 운영자** | 화면에 「남의 사진을 다루는 자리」를 만들지 않는다. 남의 사진은 **표시만** 한다 |

**A-63 의 상한은 서버 단일 원천 `MAX_PHOTO_BYTES` 다.** 화면에 `1048576` 을 박지 않는다 —
같은 수가 두 곳에 살면 언젠가 어긋난다.

**A-65 의 열람 예외는 `required_role()` 한 곳에서 판정한다.** `_is_operator_photo_path()` 가
`/api/admin/operators/{정수}/photo` **정확히 그것**만 연다(접두어 판정이 아니다).
화면이 이 판정을 다시 구현하지 않는다.

⚠ **재인코딩(EXIF 제거 · 크기 정규화)은 하지 않는다** — 저장소에 이미지 라이브러리가 없고,
넣을지는 **미정**이다(§미해결 ①). 그 대가로 **EXIF(촬영 위치·기기)가 원본에 그대로 남는다.**
서버가 응답 헤더 셋(`nosniff` · `inline` · CSP `sandbox`)으로 재해석을 막는다 —
**화면이 그 헤더를 우회하는 방식으로 사진을 그리지 않는다**(예: `fetch` 로 받아 blob 을
다른 타입으로 다시 만들기 금지). `<img src="…/photo">` 가 정석이다.

|---|---|
| `provider` 는 **요청 본문 값을 그대로 저장**한다 — 검증이 없다 | 「로그인 방식」을 **서버가 준 `provider_label` 로** 표시한다. 화면이 「Google 계정」 같은 말을 지어내지 않는다 |
| `provider_verified` 는 **현재 어떤 값에서도 `false`** 다 | `false` 이면 **「미검증」 배지**를 함께 표시한다. 색만으로 말하지 않고 **텍스트를 병기**한다 |
| 왜 검증되지 않았는지 | `provider_note` 문장을 **그대로** 노출한다. 잘라내거나 요약하지 않는다 |
| `'google'` 이라 적힌 계정도 구글이 확인한 것이 아니다 | 같은 배지를 붙인다 — 값에 따라 배지를 빼지 않는다 |

**회귀가 「검증하지 않은 제공자를 검증됐다고 말하지 않는다」를 고정한다.**

⚠ **`_verify_google()` 은 존재하지 않는 함수 이름이다** — `api/auth.py` docstring 한 줄에만
있고 **정의는 저장소 어디에도 없다**. 확인법 `grep -rn "def _verify_google" --include=*.py .`
(**0건이어야 한다**). 실 OAuth 는 「채우면 되는 빈 함수」가 아니라 **신설 대상**이다.
이 화면은 **「지금은 검증되지 않는다」는 사실을 보여줄 뿐**이다.

# 상태 · 예외 — **서버가 문장으로 주는 것은 그대로 표시한다**

## ㉮ 빈 값의 이유 — 셋을 `—` 하나로 덮지 않는다

`identity_reasons()` 가 **이 판정의 단일 원천**이다. 화면이 빈 값을 보고 이유를 추측하면
그것이 지어낸 근거가 된다. 실제로 이 DB 에 셋이 다 있다.

| 상태 | 화면이 말하는 것 |
|---|---|
| 승인 시각 없음 | `approved_none_reason` 문장을 **그대로**. 표 칸에는 `approved_short` |
| 승인 시각 있음 | `approved_note` 를 그대로. **`approved_note` 와 `approved_none_reason` 은 둘 중 하나만 채워진다**(회귀가 그 배타를 지킨다) |
| 열려 있는 세션이 현재 기기 하나뿐 | 「다른 기기는 없습니다」 — **철회 단추를 내지 않는다**(회귀가 `live_sessions > 1` 분기를 검사한다) |
| 기억된 기기 0건 | 「등록된 기기가 없습니다」(서버 `note`) |
| 기기 기억 스키마 미적용 | `ready:false` + 서버 문장. **0건을 지어내는 것과 «다른» 빈 상태다** |
| 사진 없음 | **404 `no_photo`** → 이름 첫 글자 원형. 이름도 없으면 `?` |
| 사진 기능 미적용 | **503 `photo_schema_missing`** → 「기능이 아직 적용되지 않았습니다」 |
| 접속 IP 없음(`ip` null) | **화면이 이유를 지어내지 않는다** — null 그대로 받는다 |
| 연락처 · 직무 없음 | 빈 문자열은 서버가 **NULL 로 저장**한다. 데이터 필드에 표시용 `—` 를 넣지 않는다 |

⚠ **사진의 세 갈래를 구분한다: 404(없다) · 503(기능이 아직 없다) · 401(로그인이 끊겼다).**
셋을 같은 빈 원으로 덮으면 화면이 거짓말을 한다.

## ㉯ 실패 — 서버가 준 사유를 **그대로** 보여준다

오류 본문은 `{"detail": {"error":…, "message":…}}` 모양이다(저장소 전체 관례 ·
`ui-progress.js` `errText()`). 화면도 같은 헬퍼(`window.popcornProgress.errText`)를 쓴다.

| 상황 | 응답 |
|---|---|
| 미로그인 | 401 「로그인이 필요합니다」 → `/admin2/login` 안내 |
| 계정 행 없음(삭제됨) | 404 「계정을 찾을 수 없습니다」 |
| 이름 미입력 | 400 「이름을 입력하세요」 |
| 길이 초과 | 400 (이름 100 · 연락처 30 · 직무 100) |
| **못 고치는 필드 동봉** | **422**(`ProfileBody` 가 `extra="forbid"`) — 「그 필드는 여기서 못 고친다」를 분명히. **조용히 무시하지 않는다** |
| 현재 비밀번호 불일치 | 401 「현재 비밀번호가 올바르지 않습니다」 ⇒ **2026-08-19 문체 규약(§문서·화면 어휘 표준) 적용으로 코드는 『현재 비밀번호가 올바르지 않다』** — 이 문서의 위 표기는 그 이전 것(확인법 `grep -n "현재 비밀번호가" api/auth.py`) |
| 강도 미달 | 400 (사유 문장 — 서버가 만든다) |
| 이전과 같은 비밀번호 | 400 「이전과 다른 비밀번호를 쓰세요」 ⇒ **2026-08-19 문체 규약 적용으로 코드는 『이전과 다른 비밀번호를 써야 한다』** — 이 문서의 위 표기는 그 이전 것(확인법 `grep -n "이전과 다른 비밀번호" api/auth.py`) |
| 세션 쿠키 없이 철회 요청 | 400 「현재 세션을 확인할 수 없습니다」 — **자기 세션까지 끊기는 것을 서버가 막는다** |
| 기기 없음 · 남의 기기 | 404 「기기를 찾을 수 없습니다」 |
| 사진 상한 초과 | **413** 「사진은 {n}KB 이하만 등록할 수 있습니다」(+ 보낸 크기) |
| 사진 형식 불가 · SVG | **400** 「JPEG · PNG · WebP 파일만 등록할 수 있습니다 (파일 앞머리로 판정했습니다)」 |
| 파일이 너무 작음 | 400 「파일이 비어 있거나 너무 작습니다」 |
| 사진 없음 | 404 `no_photo` |
| 사진 기능 미적용 | 503 `photo_schema_missing` |
| 서버 연결 실패 | 「서버에 연결할 수 없습니다」 — **401 세션 만료 · 네트워크 · 서버 오류를 «구분»한다** |

⚠ **원안(`docs/design/dc-my-profile.html` 632·634·636행)은 옛 문구를 그대로 보존한다** —
승인 원안은 **승인 시점의 기록**이라 코드의 문체 교정과 무관하게 갱신하지 않는다(위
「원안이 서버·실측과 어긋나는 곳」 절과 같은 원칙 — 원안은 데이터이지 지시가 아니지만,
동시에 «그때 무엇이 승인됐는지»의 증거라 고치지 않는다). **계약자는 이 차이를 어긋남으로
잡지 말 것** — 위 표의 두 행(현재 비밀번호 불일치·이전과 같은 비밀번호)은 2026-08-19
문체 규약 적용 이후의 코드 문구로 갱신했고, 원안 632·634·636행은 그 이전 문구 그대로다.
경위 전문은 `docs/decisions/decision-log.md` **T-15**.

⚠ **`if(!res.ok) return;` 금지**(CANON §2 · MAKER-CHECKLIST §3). 저장을 눌러도 아무 일도
일어나지 않는 화면이 된다.

⚠ **화면 스크립트가 죽는 경우까지 대비한다.** 구화면은 실제로 파싱 오류로 통째로 죽어
「불러오는 중」에서 영원히 멈췄고 **사용자에게는 아무 신호도 없었다**(슬라이스 92).
구화면은 **별도 `<script>` 감시자**를 두어 5초 뒤에도 본 스크립트가 살아나지 않으면
「화면 스크립트가 실행되지 않았습니다」를 표시한다. **같은 보호가 필요하다** —
형태는 원안이 정한다.

## ㉰ 권한 없음 — **이 화면에는 그 상태가 없다**

세 등급 전부가 자기 정보를 조회·수정한다. 막히는 것은 **등급이 아니라 필드**다.

⚠ **다만 세션의 신뢰 수준은 다르다.** 기기 기억으로 만든 세션은 `password_verified=false`
이고 `OWNER_WRITE_PREFIXES` 아래 쓰기에서 401 `reauth_required` 로 막힌다.
**`/my-profile` 은 그 접두어 목록에 없으므로 이 화면의 쓰기는 재확인 없이 통과한다.**
본인 비밀번호 변경은 **현재 비밀번호를 요구하는 것으로 자체 방어**된다.

## ㉱ 경계값

    이름          1~100자 (공백만 입력하면 400)
    연락처 · 직무  빈 문자열은 **NULL 로 저장**(`strip() or None`) · 30자 / 100자
    비밀번호       **서버가 규칙을 준다** — 화면이 「N자 이상」을 베끼지 않는다.
                  구화면이 「8자 이상」이라 적어 두고 서버는 10자를 요구한 전례가 있다
                  (**화면이 규칙을 틀리게 말했다** — 슬라이스 100)
    사진          형식 3종 · 상한은 서버 `MAX_PHOTO_BYTES`

## ㉲ 시각 — **서울 시각으로 표시한다**

서버는 `api/timeutil.iso()` 로 **절대시각(UTC · `+00:00`)만** 준다. 표시는 화면이 한다.

⚠ **타임존 없는 ISO 문자열을 그대로 내보내면 브라우저가 로컬 시각으로 해석해
UTC 04:57 이 서울 04:57 로 찍힌다 — 실제는 13:57 이다**(슬라이스 62 · 100 실사고).
이 화면이 보여주는 **모든 시각**(가입 · 승인 · 마지막 로그인 · 비밀번호 설정 ·
세션 생성/최근 사용/만료 · 기기 생성/최근 사용/만료 · 사진 등록)에 적용된다.
회귀 [27] 이 이 규약을 검사한다.

## ㉳ 되돌릴 수 없는 것 — **누르기 «전에» 밝힌다**

| 동작 | 되돌리기 | 누르기 전에 밝히는 것 |
|---|---|---|
| 정보 수정 | `[되돌리기]` = **서버 값 재적용**(저장 전 입력 취소)이지 원장 되돌림이 아니다 | 이름을 바꾸면 **지난 작업 기록의 표시 이름도 함께 바뀐다** — 서버가 `note` 로 그 사실을 준다. **화면이 그 문구를 잘라내지 않는다** |
| 다른 기기 로그아웃 | **없다** | **먼저 `GET /my-profile/sessions` 로 몇 개가 끊기는지 조회해 보여주고 확인을 받는다.** 누르고 나서 알면 늦다 |
| 기기 철회 | **없다** | **지금 열려 있는 세션은 끊기지 않는다** — 다음 로그인부터 비밀번호를 다시 묻는다. 세션 철회와 **다른 일**이다 |
| 비밀번호 변경 | **없다** | 성공하면 **다른 기기의 세션과 기기 기억이 전부 철회된다** |
| 사진 삭제 | **없다 — 실제로 지운다** | 「되돌릴 수 없습니다」 |

⚠ **사진에는 원장 규약을 적용하지 않는다**(정의서 판정 · 코드 주석과 일치). 원장이 지키는
것은 「사실의 이력」이고 **사진은 본인의 개인 자료**다. **자료는 지우고 사실은 남긴다** —
「누가 언제 등록·교체·삭제했다」는 `admin_operator_activity_logs` 에 남는다.
비밀번호와 같은 결이다.

⚠ **세션 식별자는 화면에 나오지 않는다** — 그 값이 곧 로그인 자격이다. 서버가 `session_id`
를 내보내지 않고 `current` 불리언만 준다. **`device_id` 는 노출해도 안전하다**(시크릿은
해시만 저장 — 그것만으로 로그인할 수 없다). **이 둘을 같게 다루지 않는다.**

## ㉴ 비밀번호 입력 — **화면에 보이지 않아야 한다**

구화면은 브라우저 `prompt()` 를 두 번 써서 **비밀번호가 화면에 그대로 보였다**(어깨너머
노출). 회귀 [17] 이 `prompt(` 미사용과 `type="password"` **3칸 이상**을 검사한다 —
현재 비밀번호 · 새 비밀번호 · **새 비밀번호 확인** 셋을 받는다(구화면은 확인칸이 없어
오타를 잡을 수 없었다).

| ⑤ | **토스트가 7초 뒤 사라진다** | **사실만 적는다 · 영역을 신설하지 않았다.** 다시 시도해야 하는 실패(413·400)와 되돌릴 수 없는 삭제가 여기 걸린다. ⚠ 토스트 정본이 **동작 단추**(`action`+`onAction`)를 지원하므로 새 영역 없이 풀릴 수도 있다 — **만들어 봐야 안다.** 삭제는 「누르기 전」 확인 단계가 본래 규약이라 사후 토스트가 그것을 대신하지 않는다 |
