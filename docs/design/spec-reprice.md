## ★ 맨 앞에 무엇을 둘까 — 확정

**「지난 회차」 표가 맨 앞에 온다. 경고 배너가 아니다.**

    ✗ 쓰지 않는다   「지난 재산정은 99.99%가 되돌려졌습니다 — 세 번째도 같아지지 않게」
                    「왜 물러졌는지는 어느 기록에도 사유가 없습니다」
                    붉은 경고 톤 · 큰 숫자로 몰아붙이는 배너

    ✓ 쓴다          「지난 회차」 — 언제 · 누가 · 어떤 정책으로 · 몇 건 · **되돌렸나** · **왜**
                    ⚠ **`note` 열을 «반드시» 둔다** — 사유가 실제로 거기 적혀 있다
                    되돌림까지의 **간격**도 적는다 — 그게 「검증이었다」를 말한다

⚠ **간격 표기는 «사람이 읽는» 형식으로 한다** — 「1분 1.5초」이지 「61.50초」가 아니다.
이 문서 아래쪽의 `61.50초`·`67.62초` 는 **하네스가 제작자에게 실측을 설명하려고 적은 값**이고
**화면 문구가 아니다.** 요점은 「1분 만에 물렸다」가 한눈에 보이는 것이다 — 초 단위 정밀도가 아니라.
(2026-08-15 정정 — 제작자가 이 어긋남을 스스로 짚어 보고했고, 그 판단이 옳았다.)

**표 아래 한 줄** (사실만, 해석 없이):

> 되돌림은 **삭제가 아니라 역방향 이력 행**입니다(`margin_policy_undo`) — 값이 원래대로
> 돌아가고 두 행이 함께 남습니다.

⚠ **회차가 0건이면** 「아직 재산정을 실행한 적이 없습니다」 — 빈 상태를 실패처럼 그리지 않는다.

## ⚠⚠ 왜 경고를 뺐나 — 서사가 뒤집혔다

**디자인과 정의서가 함께 세운 전제:**

> **지난 재산정은 99.99%가 되돌려졌습니다** — 세 번째도 같아지지 않게 먼저 읽어 보십시오
> **왜 물러졌는지는 어느 기록에도 사유가 없습니다**

**조사자 실측(2026-08-15):**

    회차 1   apply 2026-08-04 14:22:02.300119 -> undo 14:23:03.795455   **간격 61.50초**
             note: **"슬라이스 E 검증"**    scope=live · 7,239건 · margin 0.12 / fee 0.022
    회차 2   apply 2026-08-05 14:50:28.210853 -> undo 14:51:35.827765   **간격 67.62초**
             note: **"점검 반영"**          scope=live · 7,239건 · margin 0.12 / fee 0.02585

**사유가 없는 것이 아니다 — `note` 에 적혀 있다. 그리고 «1분 뒤»에 물렸다.**
이건 운영 사고가 아니라 **검증 작업**이다. 돌려보고 바로 되돌린 것이다.

**그리고 「99.99%」도 정확하지 않다.** 안 되돌려진 2건은 재산정이 놓친 것이 아니라
**「가격 검토 대기」 화면(`price_review_decide`)이 만든 별개 행**이다 —
`reason='margin_policy'` 문자열을 두 화면이 공유해 섞여 보였다.

    정확한 문장   재산정 회차는 **2번**이고 **둘 다 100% 되돌려졌다**.
                  **둘 다 검증 작업이었고 1분 뒤에 물렸다.**

⚠ **그래서 「세 번째도 같아지지 않게」라는 경고는 근거가 없다.** 첫 두 번은 «실수»가 아니었다.

## ⚠ 이것이 안 선택을 바꾼다

    1a   회차 표 -> 범위 -> 미리보기 -> 실행, 한 줄기. 위험 갈래는 우측
    1b   **회차 원장이 화면 절반.** 실행은 오른쪽 열

**1b 는 「지난 회차를 읽는 것」이 이 화면의 절반이라는 전제 위에 있다.**
그런데 **실측 회차는 2개**(margin_policy 기준)다. price_import 7회를 합쳐도 9개이고,
그 7회는 **2026-07-23 13:00:51~13:06:08 — 5분 17초 안에 몰린 다른 성격의 작업**이다.

**2행짜리 표에 화면 절반을 주는 셈이 된다.** → **하네스 소견은 1a 다.** 다만 **사장님 결정 사항**이다.

## 두 안 «공통» — 여기는 확정이다

안이 무엇이든 아래는 그대로 간다. **제작 착수 시 이 절을 그대로 따른다.**

### ① 실행은 미리보기를 거친다 — 예외 없다

    ① 범위를 고른다   ② 미리보기   ③ 확인하고 실행

⚠ **미리보기 없이 실행하는 경로를 만들지 않는다.**
⚠ **이 화면의 미리보기는 «진짜로 된다»** — `GET /reprice/preview` 가 저장된 정책으로
실제 영향을 세어 준다(마진 정책 화면과 다른 점이다. 거긴 가상값을 못 받는다).

### ② 실행 버튼이 「저장」처럼 보이면 안 된다

**몇 건이 움직이는지를 버튼에 적는다.** 실측 기준 판매중·재고>0 만 해도 **7,279건**이 움직인다.

> 되돌릴 수 있지만 **그 사이에 나간 견적은 그 값으로 나갑니다.**

### ③ 409 는 오류가 아니라 안전장치다

`expect_changed` 불일치 시 서버가 409 로 거부한다. **미리보기와 실행 사이에 누가 값을 바꿨다는 뜻.**

> **미리보기 이후 값이 바뀌었습니다 — 다시 미리보기 하십시오**
> 오류가 아니라 안전장치입니다.

### ④ 진행 표시는 화면이 «직접» 둔다

⚠ 미리보기 요청에는 **공용 진행 배너가 뜨지 않는다**(2026-08-15 확정 · A-41).
**버튼 비활성 + 인라인 「미리보기 중…」**을 화면이 둔다.

## 실측이 «채운» 것 — 디자인이 「조사 중」으로 비워 둔 자리

### 회차 원장 — **전용 표는 없다. 그러나 복원은 된다**

62개 base table 전수 확인 — 재산정 회차 전용 표 없음.
**대신 두 경로가 서로를 검증한다:**

    product_price_history.changed_at (마이크로초)  로 묶으면 4개 그룹
    그중 큰 둘이 admin_operator_activity_logs 의 action='판매가 재산정' 로그
    (log_id 3003 · 4247) 와 **마이크로초까지 정확히 일치**

⚠ **화면은 「추정 회차」가 아니라 «활동 로그»를 원천으로 삼는다.** 그게 `undo` 가 받는 키이기도 하다.

### 되돌리기 — **회차 단위 확정**

`POST /reprice/undo` 는 `log_id` **하나**를 받아 그 apply 의 `detail.before` 를 **전부** 되돌린다.

    한 트랜잭션    부분 실패 없음 — 전부 아니면 전무
    회차 단위      **마지막 apply 만이 아니다.** 되돌리지 않은 «과거» 회차도 받는다
    상품 단위      **불가** — before 목록 중 일부만 되돌리는 경로가 없다
    이중 되돌림    **409** 로 막는다 (`detail->>'ref_log_id'` 로 판정)
    남는 것        원 로그 그대로 + `margin_policy_undo` 이력 행 + 새 활동 로그

⚠ **삭제가 아니라 역방향 이력 행이다.** 두 행이 함께 남는다.

### MAX_APPLY 초과 — **거부가 아니다**

```
targets = c["up"] + c["down"]              # product_code 오름차순
if len(targets) != body.expect_changed: 409   # ← 자르기 «전» 전체 건수로 비교
if len(targets) > MAX_APPLY:
    dropped = len(targets) - MAX_APPLY
    targets = targets[:MAX_APPLY]          # 앞 20,000건만 실행
```

    HTTP        **200** (예외가 아니다)
    알림        verdict 에 「상한 20,000건을 넘어 N건은 남았습니다」 + `dropped` 필드
    남은 건     **자동 재처리 없음** — 새 preview 부터 다시
    before      잘린 뒤 기준 — **실제 반영분만 되돌릴 수 있다**

⚠⚠ **상한과 비교되는 값은 `target` 이 아니라 `changed`(오름+내림)다:**

    live 7,174 · selling 7,269 · **all 18,425**   (정의서의 18,631 은 target)
    -> **지금은 셋 다 상한을 넘지 않는다**(all 도 여유 1,575)

### 구 화면 — **회차를 보여주는 자리가 없었다**

`mockups/admin/reprice.html`(819줄, 동결)의 되돌리기 바는
**그 세션에서 방금 apply 를 눌렀을 때만** 뜬다. `LAST_LOG` 가 서버 값이 아니라 **JS 변수**라,
**새로고침하면 되돌릴 방법이 화면에서 사라진다.**

⚠ **이것이 이 화면을 새로 짓는 실질적 이유다** — 「99.99%」보다 이쪽이 근거가 단단하다.
