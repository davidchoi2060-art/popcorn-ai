expert·talk, `CLAUDE.md` §화면 "4모드")로 갈리는데, 이번에 처음 실측한 것은 **그중
셋(guided·chat·talk)만 S2 로 이어지고 expert 는 이어지지 않는다**는 사실이다 —
expert 는 `fetch` **0건**, `consult_sessions` 에 `mode='expert'` 행이 4주간 **0건**
(근거·확인법은 `docs/decisions/decision-log.md` **A-71**).
**이 정정은 S1→S2 구간에만 해당한다** — 이 문서의 나머지 다이어그램(①·③~⑥)은
이번 재검토의 측정 범위 밖이라 **손대지 않았다.** 문서 전체 재측정은 여전히 별도
물결로 남아 있다(`HANDOFF.md` §0 pathfinder 「첫 임무 후보」). **「그린 것이 아니라
잰 것」** 원칙에 따라 재지 않은 부분을 지금 고치지 않는다 — A-71 1단계(서버 실판정 +
S2 연결)가 실제로 지어지면 이 정정을 다시 실선 다이어그램으로 흡수한다.

**우리가 장바구니를 대신 담지 않는다**(CANON ⑥ 실서비스는 GET 만). 인계는
「원장에 남기고 · 담을 목록을 보여주고 · 몰로 보낸다」까지다. 자동 담기는 윈윈소프트 API 이후다.

`POST /api/handoff` 를 직접 불러 **409 를 실측**했다(쓰기 전 가드에서 막힌다).
인계 원장에는 제작 때 검증으로 만든 **2건**(`handoff_items` 18행)이 있다 —
개발 서버라 잔재를 두어도 되지만(I-01), 운영은 **원장을 비우고** 시작한다.

### 운영 스위치 5개 — 확정 범위와 맞는 것은 2개뿐

| 스위치 | 현재 | 확정 범위 | 판정 |
|---|---|---|---|
| `ship` 배송 | `mall` | 몰 | 맞음 |
| `refund` 환불 | `mall` | 몰 | 맞음 |
| `pay` 결제 | `mall` | 몰 | 맞음 (2026-08-12 전환 · 되돌림 `6110`) |
| `settle` 정산 | `mall` | — | `pay` 를 따라 서버가 자동 보정했다 |
| `member` 회원 | **`own`** | 몰 | **어긋남** — 몰 회원 ID 공유는 윈윈소프트 API 대기 |

**스위치를 임의로 바꾸지 않는다** — 되돌릴 수 없는 일에 걸린 설정이고, 바꾸는 순간
고객 화면의 동작이 달라진다.

조립PC 제품군 → 전체 구성·부품 보기 → 부품 구성 변경(구성표) → 변경 버튼 → 오른쪽 후보 검색·현재/선택 비교 → 이 부품 선택(로컬 변경안) → 변경 내용 확인(서버 차액 계산) → 기존 제품군 수정 / 새 제품군으로 저장 → 검토 대기 제품군. 다른 부품의 변경안은 유지한다. 저장 전 단계에서는 DB를 바꾸지 않는다. 상품 설명 편집과 부품 편집의 미저장 변경이 섞이지 않도록 탭·고객 미리보기를 보호한다.

이 흐름은 관리자 편집이다. 고객 견적 변경·최종 확정 경로(0119)와 공개 승인 UI는 아직 별도 후속이다.

### 2026-09-30 관리자 구성 검토와 추천 반영

전체 구성 보기 → 검토 기록 → 현재 DB 호환 규칙 대조 → 보완 항목 해결 → 장착·연결·수량/설명/가격 근거 기록 → 검토 내용 저장 또는 검토 완료·추천 반영. 작성 중 닫기는 입력 취소 여부를 확인한다. 규칙상 불일치, 설명 원문 불일치, 판매중이 아닌 부품 등이 있으면 승인할 수 없다. 사양 누락은 통과로 표시하지 않고 별도 수동 확인 근거를 요구한다.

승인은 관리자 조립PC 상담 검토 후보에 반영한다. 승인 후 구성·설명·가격·부품 사양·호환 규칙이 바뀌면 재검토 상태로 표시하고 후보에서 제외한다. 추천 제외는 사유를 남기며 이력을 보존한다. 기존 고객 mvp2 공개 경로와 실제 출고 승인은 별개다.

### 2026-09-30 추천 판정 / 고객별 조립 분리

위 검토 흐름에서 물리적 조립 확인을 추천 승인 필수 체크에서 분리했다. 제품군 목록 → 전체 구성 → 검토 기록 → 추천 규격 대조 / 조립 확인 예정 → 추천 설명·가격 근거 → 추천 검토 처리. 핵심 규격 미확인은 메모로 승인할 수 없고 근거 사양을 먼저 보완한다. 조건부 후보는 확인 예정 항목을 계속 표시하며 고객 필수 조건과 다시 대조한다.

같은 검토 화면의 고객별 기록 → 등록된 견적 선택 → 조립 이슈 → 준비된 변경안 비교 → 전화 동의/거절/미응답 기록 → 유효한 검증과 동의 확인 → 견적 새 버전 적용 → 이슈 해결 → 재검수. 현재 실제 견적0건은 빈 상태로 표시한다. 견적 신규 등록·변경안/검증 생성 상위 경로는 아직 미연결이다. 계약과 제한은 `recommendation-assembly-workflow-20260930.md`.
