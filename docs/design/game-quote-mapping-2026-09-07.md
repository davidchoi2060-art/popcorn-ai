## 0. 왜 이 기획이 필요한가

화면이 「이 견적으로 배틀그라운드 됩니다」라고 말하려면 **판정 규칙**이 있어야 한다.
지금은 재료(게임 DB·격자)만 있고 연결 규칙이 없다. 규칙 없이 화면이 말하면
그것이 곧 지어낸 판정이다(화면 정직성 규약 위반).

**연결 재료의 현실 (2026-09-07 실측):**

| 재료 | 상태 | 문제 |
|---|---|---|
| games.rec_gpu | 자유 문자열 「GTX 970 / Arc A750 / RX 470」 | 그대로는 비교 불가 |
| GPU 부품 성능 축 | required_power_watt (300/550/650/750) | 550W에 RTX 3050과 RX 9060 XT가 동급으로 묶임 — 게임 판정엔 너무 거침 |
| GPU VRAM (capacity_gb) | **전부 NULL** | AI 연결(VRAM 기준)이 현재 불가 |
| game_performance | 6행 (사이버펑크만) | 실측 경로는 아직 얇다 |

## 1. 연결의 핵심 부품 — GPU 성능 서열표 (신설 제안)

**`gpu_ladder` 테이블**: GPU 칩셋 정규형마다 성능 서열 하나.

```
gpu_ladder(
  chipset      varchar UNIQUE   -- gpu_chipset_key() 정규형 ("RTX 5070 Ti" 등)
  ladder_rank  int              -- 성능 서열 (높을수록 강함, 등수 아니라 점수 밴드)
  vram_gb      int              -- 이 칩셋의 표준 VRAM
  source_url   varchar          -- 서열 근거 (공개 벤치마크 집계 — 예: TechPowerUp 상대성능)
  checked_date date
)
```

- 정규형은 **`catalog_map.gpu_chipset_key()` 재사용** — 이미 상품명→칩셋 94.3% 추출
  (9/3 규약 GPU 칩셋 축과 같은 어휘 · 새 어휘 금지 원칙).
- ladder_rank 근거는 공개 상대성능 지표 하나를 정본으로 고정(미정-B).
- **VRAM을 여기 두면 부품별 백필 없이 AI 연결이 선다** — 칩셋이 정해지면 VRAM은
  표준값이 정해진다(같은 칩셋 변형은 무시 — 판정엔 표준값이면 충분).

## 2. 판정 규칙 — 세 경로, 우선순위 순

### 경로 ① 실측 프레임 (있으면 최우선)

```
game_performance에 (게임, 해상도) 행이 있으면:
  견적 GPU의 gpu_band ≥ 그 행의 gpu_band  →  fps_band를 그대로 표시
  표시: 「QHD 60+ 예상 — 출처: <source_url>, <checked_date> 확인」
```
- 출처·날짜를 화면에 함께 표시한다. 데이터 없는 (게임×해상도)는 **그 줄을 그리지 않는다.**

### 경로 ② 공식 요구사양 (기본 경로 — 21종 전부 가능)

```
games.rec_gpu 문자열 → 칩셋 후보 파싱 → gpu_ladder에서 최고 rank 하나 = 기준 rank
견적 GPU의 rank ≥ 기준 rank        → 「권장 사양 충족」
견적 GPU rank ≥ 최소사양 rank만    → 「최소 사양 충족 — 낮은 옵션 권장」
미달                               → 그 게임을 그 견적에 표시하지 않는다
+ RAM: 견적 RAM ≥ games.rec_ram_gb 함께 검사 (AND 조건)
```
- 표시 문구가 프레임을 약속하지 않는다: 「권장 사양 충족 (제조사 기준)」까지만.
  프레임 구간은 경로 ①이 있을 때만 말한다.

### 경로 ③ AI 작업 (VRAM 기준)

```
ai_workloads.min_vram_gb ≤ 견적 GPU의 gpu_ladder.vram_gb  → 「구동 가능(양자화 기준 명시)」
rec_vram_gb까지 충족                                       → 「권장 구성」
+ min_ram_gb ≤ 견적 RAM 함께 검사
```

### 격자 칸 권장 (게임/AI → 칸 별칭)

```
게임의 권장 칸 = 경로 ②를 만족하는 칸 중 «가장 싼» 칸 (낭비 없는 추천)
  단, 실측(경로 ①)이 있으면 목표 해상도·프레임을 만족하는 가장 싼 칸
AI 작업의 권장 칸 = 경로 ③ 충족 칸 중 가장 싼 칸
계산 시점: 실시간이 아니라 «배치에서» — grid_generate 뒤에 매핑 갱신 단계 추가.
결과는 테이블에 저장(game_cell_map · workload_cell_map) — 화면은 조회만.
```

## 3. 화면 문구 규약 (정직성)

| 상황 | 말한다 | 말하지 않는다 |
|---|---|---|
| 실측 있음 | 「QHD 60+ 예상 · 출처·날짜」 | 정확 프레임 값 단정 |
| 공식 사양만 | 「권장 사양 충족 (제조사 기준)」 | 프레임 언급 일체 |
| 데이터 없음 | (그 줄 자체를 안 그림) | 「아마 될 겁니다」류 |
| AI | 「Q4 양자화 기준 구동 가능」 | 양자화 조건 생략한 「돌아갑니다」 |

## 4. 미정 — 사장님 확정 대기

| # | 무엇 | 제안 |
|---|---|---|
| 미정-A | gpu_ladder 신설 (판정의 기둥) | 신설. 칩셋 수십 개 규모 — 수집·검증 1회 작업 |
| 미정-B | ladder_rank 근거 지표 | 공개 상대성능 집계 1곳을 정본으로 고정, 출처·날짜 기록 |
| 미정-C | 최소사양 충족을 팔지 (「낮은 옵션 권장」 표시) | 표시하되 권장 칸으로는 안 쓴다 — 팔고 나서 「느리다」 소리 듣는 자리 |

## 5. 확정 후 작업 순서

```
① gpu_ladder 수집·시드 (칩셋·rank·VRAM·출처)   ← 조사팀 + 마이그레이션
② 매핑 배치 (game_cell_map · workload_cell_map) ← grid_generate 뒤 단계
③ 회귀: 매핑 칸이 실존 칸인가 · 출처 없는 판정 0건
④ 진열대 화면이 이 테이블을 조회 (배선은 진열대 물결에서)
```
