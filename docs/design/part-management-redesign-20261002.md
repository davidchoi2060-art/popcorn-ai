# 부품관리 재디자인 시안

2026-10-02 · 사용자 요청에 따른 디자인 검토 단계. 운영 템플릿·API·DB 변경 없음.

## 현재 확인
신 관리자 LNB의 부품 관리는 /admin2/part-explanations. 운영 목록은 201개로 표시됨. 화면은 고객용 PopcornPartExplanations.markup의 아코디언을 20개 반복하며 검색·종류·이전/다음만 제공한다. 사양/고객 설명/근거를 길게 펼쳐 비교하는 구조이며, 별도 관리자 비교 표와 다음 행동 영역이 없다. 현재 조회 API는 q/slot/offset/limit 및 설명 상태/상품 연결/source_current 제공. 판매 상태·DB 재고·사용 제품군 개수는 별도 조회/확장이 필요. AI 보완·편집·승인 버튼은 이 페이지에 아직 구현되어 있지 않다.

## 제안
신 관리자 공통 LNB/아이보리·차콜·그린 유지. 목록과 선택 부품 상세를 같은 화면에서 비교한다. 상단 검색, 부품 종류, 필요한 보완 조건, 판매/보유 조건, 표시10/20/30을 두고 선택을 보존한다. 목록은 이미지/제품명·코드/주요규격/현재판매가/설명검토상태로 간결하게 구성. 상세는 사양·고객설명·근거자료·사용제품군 탭으로 분리하고 필요한 작업을 표시한다. 고객 설명은 관리용 사양과 분리한다. 상세 영역은 좁은 모달 대신 화면 높이를 사용하고 좁은 화면에는 전체 폭 상세 전환과 목록 복귀를 제공한다. 내부 스크롤·작은 화면·하단 동작 가려짐을 검증한다.

AI 보완 버튼은 아직 없는 제안 기능이며 근거 확인 → 변경 제안 비교 → 운영자 반영 순서. AI가 임의 사양/가격/재고를 생성하거나 확인/승인된 것처럼 처리하지 않는다. 사양 변경에 영향받는 제품군을 실제 연결에서 조회하며, 불일치/원문 변경/설명검토/판매 상태는 별개로 관리한다. 완성도 퍼센트 및 승인 통계는 지어내지 않는다. 시안 내 제품/상태는 배치 예시임을 표시한다. 실제 건수201은 현재 화면 관찰치이며 이후에는 서버 응답으로 표시한다.

## 승인 후
실제 API 필드·보완 상태 정의와 편집/AI 기능 지원을 확인해 단계적으로 구현. 먼저 목록·상세 조회와 필터·표시수 보존. 이후 근거 기반 보완 제안과 변경 반영·사용제품군 영향 관리. 시안은 완성 기능으로 보고하지 않으며 사용자 확인 후 구현·검증·배포.

## 2026-10-02 승인 시안 구현
사용자 시안 승인 후 부품관리 페이지를 관리자 전용 목록/상세로 교체. 검색(이름/코드/표시 사양), 종류/판매/검토/DB재고 필터와 10/20/30개 localStorage 유지. 사양·고객설명·근거·사용제품군 탭, 근거를 남기는 설명/표시사양 편집, 기존 task.ops_assist LLM의 선택형 AI 제안을 추가했다. 신규 테이블 없이 product_explanations를 사용. 편집은 draft로 전환, 기존 근거/보완항목 보존, 변경 전후 이력 저장, 관련 PC는 기존 설명 digest를 통해 재검토 대상이 된다. AI는 등록된 자료로 고객 설명만 제안하며 외부검색/임의 사양·가격·재고 수정·승인 없음. 승인 이력 없는 상태를 승인으로 표시하지 않음. 유료 호출은 운영자 생성 확인 후만 진행. 제안 및 저장 시 basis 비교로 오래된 근거 적용 차단.
검사: 설명·검토 회귀 포함37개 통과, JS 구문 통과. 실제 DB 설명 편집→draft/근거·사양 보존→전량롤백 확인. 실제201개 조회, CPU38개/10개 표시 및 재접속 유지, 사용제품군/근거/편집폼 확인, 600x650 가로넘침 없음 및 목록복귀. AI provider는 stub 검사이며 유료 실제 생성은 실행하지 않음. 운영 배포·운영 UI 확인은 후속 확인.
