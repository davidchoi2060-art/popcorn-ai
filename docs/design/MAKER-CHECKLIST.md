# 화면 제작 공통 지시 — 지시서마다 다시 적지 않는다

> 제작자·계약자가 **화면 작업을 받으면 이 파일을 먼저 읽는다.**
> 지시서에는 **그 화면에만 해당하는 것**만 적힌다. 아래는 전부 공통이고 항상 적용된다.
>
> 이 파일이 생긴 이유(2026-08-14): 하네스가 지시서마다 같은 규약 1,500자를 다시 적고,
> 승인 디자인 30KB 를 손으로 옮겨 적느라 제작팀이 대기했다. **한 세션에 293.8KB 를
> 전사했다** — 서버에 이미 있는 내용이다. 중계를 없앤다.

---

## 0. ★ Phoenix 를 참조하지 않는다 (2026-08-14 사장님 지시)

> *"앞으로는 피닉스 디자인은 참고하지 말고, 내가 주는 화면 UI 대로 해줘."*

**승인 디자인이 유일한 원천이다.** Phoenix 템플릿에서 마크업·컴포넌트·레이아웃을
가져오지 마라. 「옆 화면을 베낀다」·「템플릿을 혼합한다」는 옛 절차이고 **지금은 금지다.**
`docs/design/phoenix-template-map.md` 는 역사 기록이지 지침이 아니다.

**남는 것은 공용 셸**(`templates/admin/_admin2_shell.html.j2`)과 `admin2.css` 뿐이다 —
그건 우리 것이다. 승인 디자인에 없는 배치가 필요해 보이면 **짓지 말고 보고해라**
(화면 설계는 사장님 몫 — §화면 작업의 경계).

## 1. 승인 디자인 — 지시서가 주는 형태로 받는다

⚠ **`DesignSync` 는 서브에이전트에서 막혀 있다**(세션 정책, 2026-08-14 확인).
그래서 지시서가 둘 중 하나를 준다:

    ① 계약 요약   docs/design/spec-<화면>.md
                   확정 사항 · 반드시 들어갈 문구 · 구조 · 데이터 · 금지 사항
                   **원문은 Claude Design 서버에 있고 그것이 아카이브다**
    ② 로컬 원안   docs/design/dc-<화면>.html
                   예전에 하네스가 받아 둔 것

**둘 다 계약이다.** 여기 없는 것은 짓지 않는다. **치수 대조가 필요하면 하네스에게 요청해라** —
하네스만 원안을 열 수 있다.

⚠ **캔버스에는 안이 여럿 들어 있다.** 지시서가 **확정 안**(1a / 1b / v2 …)을 못 박는다.
**확정 안만 정본이다.** 확정 근거는 `docs/decisions/decision-log.md` 의 `UX-nn` 이다.

⚠ **디자인 안의 수치는 전부 스냅샷 예시다.** 5,156 · 22,840 · 93.2% 같은 값을
**코드에 박지 마라.** 화면은 서버 응답만 말한다. 디자인 예시값이 코드에 남으면
그 자체가 결함이다(등록 폼에 남의 상품명·가격이 기본값으로 남아 저장될 뻔한 전례).

⚠ **디자인이 확정 문구로 박아 둔 상태 표기는 그대로 옮긴다** — 「향후 사용예정」·
「원천 없음」·「스키마 없음 — 집계 불가」·「화면 없음」 같은 것. 이것들은 장식이 아니라
**빈 값의 종류를 가르는 장치**다. 같은 「0」으로 뭉개면 화면이 거짓말을 한다.

## 3. 지킬 것 — 어긴 이력이 전부 있다

- **`:root` 에 디자인 토큰 재정의 금지** (회귀 [30] 검사 항목)
  ⚠ **이 검사는 과탐할 수 있다(2026-08-15 확인).** `:root` 인지는 안 보고 파일 전체
  텍스트에서 정규식 `(--[a-z-]+)\s*:\s*[^;]+;` 로 "선언처럼 보이는 문자열"을 찾는다.
  `.pg-btn--primary:disabled{...}` 같은 **BEM 클래스명 + 가상선택자**도 우연히 이
  모양과 겹쳐 걸린다(`part_grade.html.j2` 실측 — `:root` 리터럴은 **0건**인데 회귀는
  `--primary` 매치를 결함처럼 보고했다). **잡히면 먼저 `grep -n ":root" 그파일` 로
  진짜 `:root{}` 블록이 있는지 본다 — 없으면 과탐이니 멀쩡한 코드를 고치지 마라.**
- **외부 CDN 링크 0건** (A-30 — 글리프 7종 때문에 폰트를 통째로 받던 전례)
- **`[hidden]` 오버라이드** — 저작 `display:flex` 는 UA 의 `[hidden]{display:none}` 을
  이긴다. `.그클래스[hidden]{display:none}` 를 함께 넣어라. **안 넣으면 숨겼는데 그대로 보인다**
- **비활성은 진짜 `disabled` + 이유를 `title` 로.** 색에만 의존하지 말고 **텍스트 병기**
- **표·격자 열 정렬** — `1fr` 열이 0px 로 붕괴하지 않게 **`minmax()` 로 최소 폭**을 주고,
  헤더·본문이 **둘 다 스크롤 컨테이너**여야 거터가 맞는다.
  (연달아 두 화면이 이 문제로 지적받았다. 상품명 열이 0px 로 붕괴해 이름이 안 보인 적 있다)
- **`if(!res.ok) return;` 금지** — 저장을 눌러도 아무 일도 안 일어나는 화면이 된다.
  실패는 **서버가 준 사유를 그대로** 보여준다(401 세션 만료 / 네트워크 / 서버 오류를 **구분**)
- **`data-screen-id` · `data-domain` · `data-bind` · `data-repeat` · `data-action`**
- **예외·상태 UI 는 `hidden` 으로 미리** 마크업
- **`data-keep="1"`** — 바깥 클릭으로 선택이 풀리면 안 되는 영역(사이드바·서랍·필터·행).
  루트 클릭 핸들러는 `closest('[data-keep]')` 이면 아무것도 하지 않는다
- **서버 페이지네이션** — 전 행 반환 금지. 화면은 「전체 N건 중 이 페이지」를 명시
- **선택지는 서버가 준다**(`/api/admin/product-meta` 등). 화면이 현재 페이지에서 뽑지 마라
- **반응형 768px 이하 세로 스택** — 헤더와 행이 **서로 다른 열을 숨기지 않게**
- **로그 문자열은 ASCII 기호만** (서버 stdout 이 cp949 라 em-dash·화살표가 500 을 만든다)
- **회귀 실행 주소는 `127.0.0.1` — `localhost` 아니다** (2026-08-15 실측):
  `REGRESSION_BASE=http://127.0.0.1:8002` 는 861/862 정상, `REGRESSION_BASE=http://localhost:8002`
  는 세션 쿠키가 안 붙어 **35건이 무더기로 401 실패**한다. 회귀가 갑자기 대량으로
  깨진 것처럼 보이면 **코드를 의심하기 전에 이 주소부터 확인해라.**
- **서버가 「포트는 열려 있는데 응답이 없는」 상태로 멎을 수 있다 — 원인은 `--reload`
  가 아니라 비동기 미들웨어다.** (2026-08-15 하룻밤에 세 번 났고 매번 팀 전원이
  막혔다 — 결정 로그 **T-05**. ⚠ **최초 판은 「SSE + `--reload`」를 원인으로 적었는데
  틀렸다** — 원시 로그 0건으로 확인된 오판이었다. T-05에 정정 경위가 있다.)
  **진짜 원인**: `api/auth.py`·`api/customer_auth.py`의 `async def` 미들웨어 둘이
  동기 DB 호출(`resolve_session()`)을 스레드풀 없이 직접 부른다 — 미들웨어는 라우트와
  달리 **항상 이벤트 루프 위**에서 돈다. 커넥션 풀이 마르면(기본값 `pool_size=5·
  max_overflow=10·pool_timeout=30초`) 그 호출이 **최대 30초 동안 이벤트 루프 전체를
  막는다** — `/admin2/*`뿐 아니라 `/shared/*.css`·폰트까지 전부 멎는다
  (`member_middleware`의 `OPEN_PREFIXES`가 `/api/auth/`만 열어 두기 때문).
  ⚠ **지금 제작자가 이 미들웨어를 고치는 중이다** — 고쳐지면 이 문단도 다시 갱신된다.
  **그때까지 지킬 것**: 서버가 멈추면 **직접 재기동하지 말고 하네스에게 보고**한다
  (재기동이 원인을 안 없앤다 — 같은 조건이면 다시 멎는다). SSE(작업 현황판)를 오래
  열어 두는 것 자체는 여전히 피한다 — 이 원인과 무관하게 장기 연결은 자원을 오래
  쥔다. `:8002`는 `--reload`를 뺐다(`E:\DEV\.claude\launch.json` — ⚠ popcorn-ai 안의
  동명 파일이 아니다, 그건 8002 설정이 없는 옛 사본이다) — **해가 없지만 근본
  원인은 아니다.** 코드를 고치면 자동 반영이 안 되니 **하네스에게 재시작을 요청**한다.

### 회귀는 «한 명이, 한 번만» 돌린다

**화면마다 돌리지 마라.** 862건이고 한 번에 8분이다 — 화면 12개에 붙이면 96분이 같은
검사를 반복하는 데 들어간다. **물결이 끝나는 시점에 한 명이 한 번**(CLAUDE.md §제작팀
「갈래 ②」 그대로 — 이건 새 규칙이 아니라 지켜야 했던 규칙이다).

⚠ **그보다 더 중요한 이유가 있다 — 동시에 돌리면 서로를 죽인다.** 2026-08-15 하루 동안
「회귀가 401 무더기로 죽는다」가 반복됐고, 원인이 셋으로 갈렸다 — 셋 다 실증됐다(전문은
`docs/decisions/decision-log.md` **T-04**):

    ① 쿠키가 호스트에 묶인다      127.0.0.1 과 localhost 는 «다른 사이트»다.
                                  한쪽에서 로그인한 쿠키로 다른 쪽에 가면 401.
                                  **바로 위 항목대로 `REGRESSION_BASE=http://127.0.0.1:8002` 를 써라**
    ② test_session_revoke        tests/regression.py:2918 이 revoke-others(:2966)를
                                  실제로 호출해 **같은 계정의 다른 세션을 전부 철회**한다.
                                  그 함수 주석(:2946~2948)이 이미 같은 사고를 적어 뒀다:
                                  "재기동 탓이 아니었다 … 끊고 있던 것은 이 검사였다"
    ③ 로그인 실패 잠금            api/auth.py:179-180(MAX_FAILS=5·LOCK_MINUTES=15),
                                  판정 api/auth.py:227-271. 잠기면 회귀가 **로그인 단계에서**
                                  죽는다 — ①·②를 다 고쳐도 소용없다

**셋 다 같은 뿌리다: 여러 팀원이 같은 시드 계정(`admin@popcornpc.local`)으로 동시에
실제 로그인 경로를 두드린다.**

**그래서:**
- **회귀를 돌리라는 지시를 받지 않았으면 돌리지 마라.**
- 돌려야 하면 **`REGRESSION_BASE=http://127.0.0.1:8002 REGRESSION_KEEP_SESSIONS=1`** 로.
  (`KEEP_SESSIONS` 는 `tests/regression.py:2953` 의 실재하는 스위치 — ②를 건너뛴다.
  **③은 못 막는다** — 다른 프로세스의 로그인 시도까지는 막지 못한다)
- **401·429 로 죽으면 네 코드 문제가 아니다.** 재시도하지 말고 그 사실만 보고해라.
  (429 는 **계정이 잠긴 것**이다 — 재시도할수록 더 잠긴다)
- **화면 확인은 `dev-login` 을 써라** — 별도 계정(`ui-check@popcornpc.local`)이라
  이 잠금과 무관하다.

⚠ **예외**: 엔진·규칙·게이트·원장을 건드린 변경은 그 자리에서 한 번 더 돌린다(CANON §4
그대로). 그때도 **한 명만**이다.

## 5. 숫자 — 화면이 지어내지 않는다

- 건수·가격·후보 수·규칙 수는 **서버 응답만** 쓴다
- **못 잰 값은 0 이 아니라 「못 쟀음」**
- **「없다」와 「범위 밖에 있다」를 구분**한다
- **비율에는 표본을 병기**한다
- **서버가 준 판정을 화면이 버리지 않는다**(`verdict`·`over_by` 등)

## 6. 파일 소유권

- 지시서에 적힌 **담당 파일 밖은 읽어도 되지만 고치지 않는다**
- **`git checkout` · `git restore` · `git stash` 금지** — 남의 미커밋 작업이 사라진다(전례 있음)
- 정본 파일(공용 셸 · tokens · `CANON.md` · `CLAUDE.md`)은 **하네스만** 만진다.
  ⚠ **`admin_nav.py`(라벨·href, 기계적 편집만)와 `decision-log.md`는 T-02(2026-08-14)로
  기록자에게 이관됐다** — 더 이상 하네스 전용이 아니다(이 줄이 낡아 있었다, 2026-08-15
  정정). 어느 쪽이든 원칙은 같다 — **정본 파일은 동시에 두 명이 못 만진다**
  (`CLAUDE.md` §제작팀 「정본 파일은 언제나 한 명」)

## 7. 확인

- `http://127.0.0.1:8002` · 세션은 `GET /api/admin/auth/dev-login`
- **`:8000` 은 건드리지 마라. 서버를 새로 띄우지 마라**
- **부작용을 남기지 마라** — 로그인·등록·주문처럼 무언가를 만드는 경로를 두드릴 때는
  ① 무엇이 만들어지는지 알고 ② 끝나면 치운다
  (없는 이메일로 로그인을 시험했다가 그게 신청으로 접수돼 owner 계정이 된 전례)
- **`.env` 값을 어떤 형태로도 출력하지 마라 — 마스킹도 포함.** (2026-08-15 실사고 —
  결정 로그 **T-07**) `DATABASE_URL`을 마스킹해 보여주려다 정규식이 스킴을 잘못
  가정해 **DB 비밀번호가 도구 출력에 평문으로 한 번 노출됐다.** 마스킹은 패턴이
  하나라도 어긋나면 원문이 그대로 샌다 — 안전한 마스킹이란 없다. 필요한 것이
  스킴·존재 여부처럼 **비밀값 자체가 아닌 사실**뿐이면, 그 판정만 파이썬으로 해서
  **불리언이나 문자열 하나로만** 보고한다(예: `"psycopg" if "psycopg2" not in url else
  "psycopg2"`의 결과만 말하고 `url` 자체는 어디에도 찍지 않는다).
- **조회 전용 화면인지 쓰기 화면인지 코드로 확인하라** — 지시서가 틀릴 수 있다
- 콘솔 에러 0 · 404 자원 0 · 외부 CDN 0 을 **직접 재서** 보고한다

## 8. ⚠ 하네스 말을 믿지 말고 코드를 읽어라

지시서의 경로·표 이름·필드명·API 이름 중 **틀린 것이 있을 수 있다.** 실제로 있었다:

    없는 API 경로를 지어내 지시서에 넣었다        (/api/admin/product-category/*)
    「셸만」을 넷이라 적었는데 실측은 둘이었다
    정본을 spec_field_defs 31행이라 했는데 실제는 std.spec_defs 49행
    「넷 다 조회 전용」이라 했는데 둘은 쓰기 화면이었다

**어긋나면 지시가 아니라 코드를 따르고, 지시가 틀렸다는 것도 보고에 적어라.**

## 9. 돌려줄 것

- 만든/고친 파일 **전체 경로**
- 실제로 소비하는 API·필드 전수
- **실측 결과** — 콘솔 · 404 · CDN · 치수(디자인 원안이 있으면 대조표)
- **못 한 것과 그 이유** (「없음」과 「못 함」을 구분)
