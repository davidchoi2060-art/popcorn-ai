## 왜 이 축이 필요한가 (화면에 그대로 적는다 — 4줄)

1. 엔진이 읽는 사양 22종은 전부 호환(소켓·전력·길이)과 취향(RGB·저소음)입니다 — **CPU·GPU에 성능을 나타내는 값이 하나도 없습니다.**
2. 그래서 거르고 남은 것 중 항상 가장 싼 것이 뽑힙니다 — **"최선의 부품"이라 말하면서 실제로는 최저가를 고르고 있습니다.**
3. 점수는 슬롯 밖에서 비교되면 안 됩니다 — GPU 80점과 CPU 80점은 같은 뜻이 아니고 환산 근거가 없습니다.
4. 근거 없는 등급은 지어낸 태그와 같은 문제를 만듭니다 — "왜 55점인가"가 없으면 나중에 아무도 검증할 수 없습니다.

## 공통 확정 — 반드시 지킨다

**① 절대 점수 0~100 · 같은 슬롯 안에서만 비교**
> 0~100 **절대 점수** · **같은 슬롯 안에서만** 비교합니다 — GPU 80점과 CPU 80점은 같은 뜻이
> 아닙니다(환산 근거가 없습니다).

**② 엔진은 아직 이 값을 읽지 않는다 — 입력 시점에 명시한다** (`engine_reads = false`)

헤더 배지: **「엔진 미연결」** + 「매겨도 지금 견적은 바뀌지 않습니다」

> ▲ 견적 엔진은 아직 이 값을 읽지 않습니다. 지금 매긴 등급은 견적 결과를 바꾸지 않습니다.
> 값이 어느 정도 찬 뒤에 연결하기로 한 **의도된 순서**입니다 — 지금 연결하면 등급 없는
> 절대다수가 0점 취급되거나 극소수만 추천됩니다. 연결되면 **동급 후보 정렬 + 하한 둘 다**에 쓰입니다.

⚠ **저장 응답에 「견적 엔진은 아직 이 값을 읽지 않습니다」가 항상 함께 온다 — 지우거나 숨기지 않는다.**

**③ 근거(basis)는 필수**
> 근거를 비우면 저장되지 않습니다 — **"근거를 적어 주세요 — 근거 없는 등급은 저장하지 않습니다"**

**④ 자동 수집 병행 — 출처와 사람 확인 여부를 구분한다**

원천에서 뽑아온 값은 **「사람 확인 대기」**로 따로 모으고, **확인 전에는 서열로 취급하지 않는다.**
행마다 출처 배지(예: `다나와 벤치마크`) · 버튼 둘 — **「확인」 · 「고쳐서 확인」**

**⑤ 등급 없는 것도 함께 보여주고 비싼 것부터**
> 비쌀수록 견적에 미치는 영향이 커서 먼저 매길 값이 있습니다

**⑥ 삭제 가능** — 다시 매기면 복원되지만 점수·근거를 다시 입력해야 한다(직접 동작, 화면이 밝힌다)

**⑦ 대상은 조립 부품 10종만**
> 주변기기·완제품은 비교 축이 달라 열지 않습니다 · **공랭·수랭은 한 슬롯으로 합쳐 봅니다**

## 구조 — 본문은 1a, 입력은 1b 우측 패널

**상단 — 슬롯 칩 줄** (1a·1b 공통) — 그래픽카드 · CPU · 메인보드 · 메모리 · SSD · HDD · 파워 ·
케이스 · 쿨러(공랭·수랭). 각 칩에 후보 수. **서버 값을 쓴다** — 원안 예시(334 · 211 · 482 · 409 ·
266 · 44 · 499 · 788 · 186)를 박지 마라.

**상단 카드 3장** (1a) — 「이 슬롯의 등급 채움」(재고>0 후보가 분모) · 「척도」(0~100 절대 점수,
같은 슬롯 안에서만) · 「보기」 필터(전체 / 등급 있음 / 등급 없음)

**본문 표** (1a) — 상품코드 · 상품명 · 판매가 · 등급 · 근거·출처 · 작업

    위    이미 매긴 것 — 점수 · 근거 · 출처·날짜 · 「고치기」 · 「삭제」
    구분선 「아직 매기지 않은 것 — 비싼 것부터」
          부제: 비쌀수록 견적에 미치는 영향이 커서 먼저 매길 값이 있습니다
    아래  등급 없는 것 — 등급 칸은 점선 `—`, 「근거를 적어야 저장됩니다」 힌트,
          행 끝에 **「등급 매기기」** 버튼 → 누르면 **우측 패널이 열린다**

⚠ **행 안에서 입력받지 마라.** 1a 의 행 내 입력 카드는 쓰지 않는다.

⚠ 실측 기준 **13,311개 대상 중 등급 1건**이다. 원안이 그 한 건에 이렇게 적었다:
> 이 한 건이 지금 이 기능이 실제로 동작한다는 유일한 증거입니다 — 서열은 여기서부터 쌓입니다.

**자동 수집분 — 사람 확인 대기** (1b) — 본문 아래 또는 별도 구역
> 원천에서 뽑아온 값입니다. 확인하면 서열에 들어갑니다 — **확인 전에는 서열로 취급하지 않습니다**

행마다 점수 · 상품명 · 근거 · **출처 배지**(예: `다나와 벤치마크`) · 버튼 둘 —
**「확인」 · 「고쳐서 확인」**

**우측 패널 — 지금 매길 상품 하나** (1b · **유일한 입력 자리**)
- 상품명 · 코드 · 판매가 · 슬롯
- 점수 입력(0~100) + 가로 막대
- **지금 서열 안에서 어디에 놓이는지 알려준다** — 예: 「지금 서열: 55점(4060 Ti) 위 · 이 슬롯 최고점이 됩니다」
- 근거(필수, textarea) · 출처(선택)
- 버튼 — **「건너뛰기」 · 「저장하고 다음」**
- 하단: **저장 응답에 「견적 엔진은 아직 이 값을 읽지 않습니다」가 항상 함께 온다**

**우측 하단 — 「왜 이 축이 필요한가」 4줄** (1b · 위 그대로)

**하단**
> 등급 0건도 정상 상태입니다 — **"몇 %를 채웠는가"가 아니라 "지금부터 채울 목록"으로 보여줍니다** ·
> 삭제는 값이 사라지는 직접 동작입니다(다시 매기면 복원되지만 점수·근거를 다시 입력해야 합니다)
