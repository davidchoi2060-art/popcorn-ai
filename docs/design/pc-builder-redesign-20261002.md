# 신규 조립PC 생성 화면 재디자인

2026-10-02 · 사용자 시안 및 보완 의견 승인 후 구현. 저장 API·호환 규칙은 유지한다.

## 문제와 목표

기존 화면은 긴 부품 목록과 선택 구성·합계가 한꺼번에 늘어나 아래로 내려가야 다음 행동을 찾는다. 스크롤 차단은 별도 수정·배포했고, 이번 요청은 화면 자체의 재디자인이다. 신 관리자의 승인된 아이보리·차콜·그린 톤과 공통 LNB를 그대로 사용한다.

## 부품 선택 화면

- 상단: 신규 생성 제목, 제품군 목록 복귀, 부품 선택 / 구성·가격 확인 / 검토 대기 등록 단계.
- 왼쪽: 판매 부품 / 보유 부품 선택, 상품명·코드 검색, 부품 종류, 간결한 제품·주요 사양·판매 상태·가격·추가 버튼. 부품 목록은 별도 스크롤과 페이지 이동을 제공한다.
- 오른쪽: 상품명, 선택 부품·수량·금액·제거, CPU 내장그래픽/기본 쿨러 옵션, 조립비 30,000원, 합계, 구성·가격 확인 버튼. 긴 구성도 끝까지 스크롤할 수 있어야 한다. 가능한 넓은 화면에서는 합계·다음 동작을 하단에 유지한다.
- 좁은 화면: 좌우 분할을 상하로 변경한다. 스크롤과 접근성을 보장하며 고정 하단이 내용·버튼을 가리지 않게 한다. 선택 구성으로 바로 이동하는 동작을 검토한다.

## 다음 단계

구성·가격 확인에서는 실제 API 응답의 BOM·가격·호환 검사·조립 확인·중복 구성을 구분해 표시한다. 불일치/미확인/DB 규격 일치를 섞지 않는다. 검토 대기 저장은 고객 공개나 출고·추천 승인이 아니다. 저장 완료 화면은 등록된 제품 검토 및 다른 구성 만들기로 연결한다.

## 실제 기능과 표현 제한

판매/보유 선택, 검색, 부품 종류, 페이지 이동, 선택·제거·수량, 검사·저장은 기존 API를 재사용한다. 가격순은 현재 API의 가격 오름차순을 표시하며, 다른 정렬을 선택 가능하게 보이게 하려면 실제 지원을 추가한다. 초기화는 현재 구성 초안만 비우고 상품을 삭제하지 않는다. 보유 수량은 DB 기준이며 실사/예약/출고 가능으로 표기하지 않는다. RAM 수량은 판매 패키지 단위임을 표시한다.

호환 검사는 검사 버튼 실행 뒤 실제 응답이 있을 때만 결과를 표시한다. 부품 선택 단계의 합계는 현재 조회 가격에 따른 예상 금액이다. 이미지·영상은 구성 완료와 호환 검토 후 별도로 생성하며 자동 생성하지 않는다. 시안 모델과 금액은 디자인 예시이고 판매 상품 확정값이 아니다.

## 구현 및 검증 순서

시안 확인 → 공통 셸을 유지한 템플릿/CSS/JS 개편 → 검색·선택·제거·패키지 수량·합계·초기화 확인 → 검사 결과 및 중복·자료 갱신 시 차단 유지 → 긴 목록·작은 화면·하단 버튼·키보드 접근 검증 → 서버 반영. 사용자 승인 후 본 화면을 구현·검증하여 서버에 반영한다.

## 승인 후 반영

부품 누락 안내와 해당 종류 바로 선택, RAM·SSD 판매 패키지 수량과 등록 사양 기반 총 용량, 조립비 별도 합계, 초안만 초기화하는 확인 동작을 구현했다. 검색 후 입력 초점과 구성 변경 중 내부 스크롤 위치를 유지한다. 가격 낮은 순은 서버의 실제 정렬로 표시한다. 새 판매/보유 목록을 조회하는 동안 이전 목록 추가를 차단한다. 넓고 높은 화면은 목록별 스크롤과 하단 합계를 유지하며, 낮거나 좁은 화면은 페이지 스크롤로 하단 접근을 보장한다.
