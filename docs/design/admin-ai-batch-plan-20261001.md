# AI 일괄 보완 화면과 신규 조립PC 생성 후속 범위

## 이번 진행 범위

2026-10-01 사용자는 일괄 보완 대상 목록 → AI 제안 비교 → 선택 적용 화면 설계에 동의했다. 실제 DB 읽기 스냅샷을 사용하는 클릭 가능한 3단계 시안을 로컬 `http://127.0.0.1:8784/`에 구성했다. 기존 관리자 셸·메뉴·팔레트를 그대로 재사용한다. 시안의 제안은 명시적으로 표시한 설명 예시이고 LLM 호출·상품 저장·승인을 수행하지 않는다. 운영 서버 화면/API 구현은 다음 단계다.

## 화면 1 · 대상 선택

- 동일 부품 코드 또는 보완 사유로 묶음 선택. 같은 이름이더라도 코드·원문이 다르면 합치지 않는다.
- 실제 제품별 CPU/GPU/RAM/저장 용량·가격·검토 상태 확인, 검색 및 개별/전체 선택.
- 공통 부품의 역할 설명과 해당 PC에서 부품을 선택한 이유를 구분한다. CPU가 같아도 GPU/RAM/SSD 차이와 사용 조건을 제품별로 반영한다.
- 시안의 대표 묶음: CPU113800, GPU128400, SSD128702, RAM127920. 실제 스냅샷에서 각각7/2/7/9개 연결되며 전수 그룹 화면은 후속 구현이다. 대상 간 중복은 허용하며 전체 제품 수로 더하지 않는다.
- 설명 보완 작업과 호환 사양·근거 보완 작업을 분리한다. 알려진 불일치 제품을 설명 변경만으로 정상화하지 않는다.

## 화면 2 · 제안 비교

왼쪽 선택 제품, 오른쪽 현재 설명/제안 비교. 제품별·필드별 적용/제외, 생성 근거와 확인 사항 표시. 시안은 소개1개 항목이며 실제 구현에서는 기존6개 허용 필드(title/intro/benefits/scene/checks/faq)를 재사용한다. 가격·재고·BOM·추천 승인·공개는 AI 변경 허용 필드가 아니다.

공통 부품 설명 자체를 수정하면 해당 부품이 연결된 다른 제품군의 영향 범위를 별도 표시하고 원문/근거 유효성 및 설명 해시 동기화 계약을 따른다. PC 설명 보완과 부품 설명 정본 변경을 하나의 저장으로 숨기지 않는다. 이번 시안은 PC 상품 설명 작업만 다룬다.

## 화면 3 · 저장 내용 확인

선택 제품 수, 적용/제외 제품, 변경 필드, 예상 검토 필요 상태를 확인한다. 실제 기능은 생성 당시 revision과 사양·근거 지문을 저장 직전에 다시 비교하고 바뀐 제품은 덮어쓰지 않는다. 성공/충돌/실패를 제품별로 표시하며 실패 제품만 재검토한다. 같은 제안 재전송으로 중복 이력을 만들지 않도록 실행 식별자와 상태 관리가 필요하다. 일괄 설명 저장은 승인·고객 공개와 분리하며 변경 이력과 검토 작업으로 연결한다.

기존 `save_copy`, `parse_proposal`, `source_context`를 재사용하는 구현을 권장한다. 대량 LLM 호출은 제한된 묶음으로 나누고 상품별 문맥과 응답을 분리한다. 취소·오류·제공자 폴백·비용 한도도 기존 LLM 연결을 재사용한다. 이 단락은 구현 계획이며 신규 작업 테이블/API를 적용한 결과가 아니다.

## 후속 필수 · 보유 부품 기반 신규 조립PC 생성

사용자는 보유 부품으로 운영자가 직접 새 조립PC 상품을 생성하는 기능을 누락하지 않도록 기록과 리마인드를 요청했다. 기존 제품의 부품 변경 → 새 제품군 저장과 별개의 빈 구성 생성 흐름이다.

1. 사내 보유 부품과 조달 가능 부품 구분. 현재 판매중 DB 표시만으로 사내 실재고를 확정하지 않는다.
2. 빈 구성에서 CPU/메인보드/RAM/GPU 또는 내장그래픽/저장/쿨러/파워/케이스 선택과 수량 지정.
3. CPU 기본 쿨러 포함 여부, 소켓·메모리 규격·장착 공간·저장 슬롯·전원·필수 구성 누락 확인. 근거 미확인은 유지한다.
4. 실제 가격 정본과 조립비 포함 조건 대조. 이미 포함된 조립비는 중복 가산하지 않는다. 판매가/단품가/견적 예상가를 구분한다.
5. 설명과 용도 평가 → 동일 BOM 중복 확인 → 신규 검토 대기 제품군 저장 → 운영자 검토 및 추천 반영.
6. 고객 공개/쇼핑몰 등록/실조립·출고는 별도 상태·권한·후속 절차로 둔다. 현재 기능 포함 요청이 팝콘PC 쇼핑몰에 쓰기를 수행하라는 뜻은 아니다.

관리자 개편 마무리 전에 이 기능이 구현됐는지 확인한다. 이 대화에 heartbeat 리마인드 `ai-pc`를 설정했다. 6시간마다 진행 상태를 확인하되 AI 일괄 보완 완료 뒤 다음 단계 또는 관리자 마무리 시점에 누락되면 한 번 알리고, 변화가 없을 때는 알리지 않는다. 구현을 자동 수행하는 예약은 아니다.
