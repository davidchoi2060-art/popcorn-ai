# 내 정보 (ADM-SYS-022) — admin2 신규 구축 · 핸드오프

> 요구사항 정의서(2026-08-17 실측) 입력. **정의서의 문구·숫자를 화면에 박지 않았다** — 결과 문구는 전부 서버 응답 자리이고, 모형에 보이는 이름·이메일·기기·IP·시각은 자리 확인용이다.
> 구화면 `mockups/admin/my-profile.html`은 동결(P-09) — 링크·안내 없음.

- 파일: `내 정보.dc.html` — 1440×960 · `#1a` 한 열(순서대로) / `#1b` 두 열(신원·보안)
- 공용 셸 상속(사이드바 + 상단바). **LNB 항목 없음** — 실측대로 메뉴에 이 화면을 넣지 않았고, 사이드바 하단에 「진입점은 상단바 프로필」이라고 적었다. 상단바 아바타 자리에 **점선 표시**를 달아 사진이 서는 자리(A-64)를 드러냈다.
- 트윅 여섯: **서버 응답 18가지**(수정·비밀번호·세션·기기·사진·전면 실패로 갈라 그 자리에 표시) · **계정 상태 5가지** · **세션 수** · **기기 상태 3가지**(`ready:false` 포함) · **사진 유무** · **결정 3**(이미지 라이브러리 신설 여부 — 미정)

## 두 안이 가른 축

이 화면은 성격이 다른 두 덩이다 — **내가 누구인가(읽기 + 필드 셋 수정)**와 **내 로그인을 정리한다(비밀번호·세션·기기, 전부 되돌릴 수 없는 쓰기)**. 두 안은 그 둘을 **시간순으로 쌓을지, 공간으로 가를지**에서 갈린다.

| | 1a 한 열 · 순서대로 | 1b 두 열 · 신원 / 보안 |
|---|---|---|
| 구조 | 신원 → 정보 수정 → 비밀번호 → 세션 → 기기 | 왼쪽 신원·사진·수정 / 오른쪽 비밀번호·세션·기기 |
| 강한 쪽 | **폭이 980px이라 서버 `note`를 자르지 않는다**(정의서가 「잘라내면 안 된다」고 못 박은 자리) · 임시 비밀번호로 들어온 사람이 위에서 아래로 읽으면 비밀번호 변경에 도달한다 | **세션·기기가 첫 화면에 보인다** — 미사용 API 넷 중 셋이 이 둘이라 「화면이 없어서 못 쓰던 것」이 실제로 열린다 · 읽기(왼쪽)와 위험한 쓰기(오른쪽)가 물리적으로 갈린다 |
| 약한 쪽 | **세션·기기가 접힌 아래**에 있다 — 기기 기억 UI가 처음 서는 화면인데 눈에 안 보인다 | 열이 좁아 **긴 서버 문장이 여러 줄로 접힌다** · 세션 철회 확인 단계가 좁은 카드 안에 선다 |

**추천: 1b.** 이 화면이 막고 있는 세 곳(㉠ 임시 비밀번호의 목적지 · ㉡ 구 화면 문 닫기 · ㉢ 미사용 API 넷) 가운데 둘이 **세션·기기**다. 그것이 스크롤 아래에 있으면 화면은 섰는데 그 기능은 여전히 발견되지 않는다. 1a의 장점(넓은 폭)은 1b에서도 **결과 상자를 카드 폭 전체로 두는 것**으로 상당 부분 회수된다 — 실제로 그렇게 그렸다.

## 화면이 반드시 계속 말해야 하는 것

1. **결과 문구는 서버가 준 것을 그대로** — 특히 「이름을 바꾸면 지난 작업 기록의 표시 이름도 바뀐다」는 문장을 **잘라내지 않는다**. 잘라내면 나중에 「예전 기록이 왜 바뀌었나」를 묻게 된다.
2. **바뀐 값이 없으면 성공 문구를 내지 않는다** — 원장에도 남기지 않는다.
3. **못 고치는 필드는 조용히 무시되지 않고 422로 거절된다** — 화면이 그 사실을 분명히 말한다. 고칠 수 있는 목록은 서버 `editable`이 정한다.
4. **비밀번호 규칙은 서버 조회** — 화면이 베끼지 않는다(「8자」로 적어 두고 서버가 10자를 요구한 전례). 거절당하기 전에 보여 준다.
5. **세션 철회 ≠ 기기 철회** — 기기를 잊어도 열려 있는 세션은 끊기지 않는다. 두 카드에 각각 그 문장을 붙였고, 같은 결과 상자를 공유하지 않는다.
6. **철회는 누르기 전에 몇 개가 끊기는지 말하고, 되돌릴 수 없다고 밝힌다.** 다른 기기가 없으면 **단추를 아예 내지 않는다.**
7. **세션 식별자는 화면에 나오지 않는다**(그 값이 곧 로그인 자격) · `device_id`는 노출한다.
8. **빈 값을 갈라 말한다** — 「기기 0건」과 「스키마 미적용(`ready:false`)」, 「승인 안 됨」과 「부트스트랩 자동 승인」과 「기록 없음」을 `—` 하나로 덮지 않는다. 접속 IP가 비면 **이유를 지어내지 않는다.**
9. **로그인 방식은 검증되지 않았다** — `provider_verified`가 어떤 값에서도 `false`인 현실을 붉은 힌트로 그대로 노출한다.
10. **모든 시각은 서울 표시** · **스크립트가 죽으면 5초 감시자가 그 사실을 표시한다**(둘 다 하단 띠에 상설 문구로 적었다).

## 사진 — 확정분을 화면이 어떻게 반영했나

- **A-62**(별도 표 · DB 보관 · API 서빙) · **A-63**(JPEG·PNG·WebP · SVG 금지 · 매직 넘버 · 1MB) · **A-64**(상단바 아바타에 표시) · **A-65**(본인만 등록·교체·삭제 · 열람은 전 운영자) — 넷 다 화면 문구와 정책 목록에 그대로 들어가 있다.
- **사진이 없으면 이름 첫 글자**(점선 원). 「사진 없음」과 「불러오지 못했다」를 같은 빈 원으로 두지 않는다. 상단바 아바타도 같은 규칙을 따른다.
- **삭제하면 실제로 지운다**(원장 규약 미적용) — 다만 「누가 언제 등록·교체·삭제했다」는 활동 로그에 남는다. 되돌리기 없음을 누르기 전에 밝힌다.
- 사진 자리는 **스트라이프 자리표시**다(실제 이미지 아님). 실물 사진은 업로드 경로가 서기 전엔 넣을 수 없다.

## 결정 대기 — 화면이 서기 전에 필요한 것

- **결정 3 (이미지 라이브러리 신설)** — 유일하게 화면 문구를 바꾸는 미정 사항이라 **트윅 `reencodeServer`로 두 모습을 갈라 뒀다.** 끄면 「원본 바이트를 그대로 보관합니다 — EXIF가 남습니다」, 켜면 「서버가 다시 인코딩합니다 — EXIF 제거·크기 정규화」. **사용자에게 하는 약속이 달라지므로 화면 확정 전에 닫혀야 한다.**
- **결정 7 (경로)** — `/admin2/my-profile`을 전제로 그렸고 상단바에 「제안」이라고 표시했다.
- **결정 6 (문서 정정)** — `api/auth.py:380` 주석의 `ADM-SYS-030` 오기와 `_verify_google()` 표현은 남아 있다. 화면은 「지금은 검증되지 않는다」는 사실만 보여준다.
- **A-62의 남은 몫** — 표 이름·컬럼(제안 `admin_operator_photos`)과 마이그레이션·ERD 개정, `GET /my-profile/photo`·`/operators/{id}/photo` 신설.
- **A-64의 남은 몫** — `/auth/me` 응답 확장 또는 셸 호출 추가. **39개 화면 동시 영향**이고 정본 셸 수정이라 이 화면 범위 밖이다.
- **회귀 이전** — `tests/regression.py` [17]·[21]·[27]이 아직 구화면 파일을 직접 읽는다. 옮기지 않으면 구화면이 사라지는 날 조용히 SKIP된다.
- **`_ADMIN_AUTH_DOOR_SCREENS`** — 이 화면이 서면 `my-profile`을 뺄 수 있다. **`operators`와 한 번에 둘을 닫지 않는다.**
