# 표준 검증 — **실물로 증명한다** (2026-08-10)

> 사용자 질문: *"데이터를 많이 만드는 게 중요한 건 아니고, 진짜 제대로 된 표준을 세우는
> 게 중요합니다. 지금 방향이 맞는건지요?"*
>
> 맞는 방향이었지만 **증거가 없었다.** 42,022건을 넣었으면서 표준이 옳다는 증명은 하나도
> 하지 않았다. 이 문서가 그 증명이다.

---

## 1. 검증 방법 — 실제로 조립되어 팔린 PC 로 친다

**실제로 조립되어 나간 PC 가 우리 규칙에서 탈락하면 규칙이 틀린 것이다.**
이것이 가장 강한 검증이다.

표본: `products.part_type='PC_COMPLETE'` **318종**(판매중 208).
구성이 `spec_source_text` 에 `슬롯명@@부품명 ,@@` 형식으로 들어 있다.

    프로세서(CPU)@@ AMD 라이젠5 라파엘 7500F ,@@CPU쿨러@@쿨러마스터 HYPER 212 ,@@
    메모리(RAM)@@ 마이크론 Crucial DDR5-5600 16GB ,@@메인보드@@ASRock B650M Pro X3D ,@@…

> **이걸 저쪽에서 읽어오려 했는데 우리 DB 에 이미 318종 전부 있었다.**
> 브라우저로 옮길 필요가 없었다 — 먼저 확인했어야 했다.

### 이 검증이 정직하게 세는 것

| | |
|---|---|
| **이름 매칭률** | 구성의 부품명을 우리 카탈로그에서 찾았는가(유사도 0.55 이상) |
| **판정 가능률** | 표준 값이 **양쪽에 다 있어야** 비교할 수 있다 |
| **판정 결과** | 통과 / **탈락** |

**'모름'을 '통과'로 세지 않는다.** 그러면 값이 없을수록 통과율이 올라가는 거짓 지표가 된다.
도구 = `tools/std_validate.py` (읽기 전용).

---

## 2. 결과 — 표본 40종 · 탈락 3건

| | |
|---|---|
| 판정할 수 있었던 것 중 **통과율** | **98.5%** (196/199) |
| 판정 가능 비율 | 55.3% (나머지는 값이 없거나 부품을 못 찾았다) |
| **탈락** | **3건** |

## 3. 탈락 3건을 제조사 자료로 확인했다 — **셋 다 우리 규칙이 옳았다**

사용자 지시: *"제조사의 홈페이지를 검색해서 맞춰봅시다."* 그대로 했다.

### ① `cooler_socket` — 실제 판매 구성이 **조립 불가능**하다

    상품 122753  워크스테이션 AI/빅데이터/딥러닝 7970X
    COOLER  NZXT KRAKEN 360   지원: AM4·AM5·LGA115X·1200·1700·1851·sTRX4·TR4
    CPU     스레드리퍼 7970X   소켓: sTR5                        → 탈락

**NZXT 공식 지원 문서 확인 결과 Kraken 은 sTR5(스레드리퍼 7000) 를 지원하지 않는다.**
우리 `socket_list` 가 맞고, **실제 운영 쇼핑몰에 조립 불가능한 구성이 판매 중이다.**

> 이것이 "조립 불가능한 PC 는 우리에게선 안 나온다"(A-01)가 막으려는 바로 그것이다.
> 표준의 가치를 실물로 증명한 사례다.

### ②③ `power` — 실제 판매 구성이 **위험**하다

    상품 122423 · 122424   9800X3D/32G/2TB/RTX5090
    POWER  마이크로닉스 Classic II 850W
    GPU    RTX 5090        권장 전원: 1000W                     → 탈락

NVIDIA 공식 권장은 **1000W** 이고, TechPowerUp 측정에서 **순간 스파이크 901W(1ms 미만)** 가
나와 850W 유닛이 트립할 수 있다. **RTX 5090 은 1000W 권장이 여유가 아니라 실제 필요인
예외 사례**다(출처 아래).

> `required_power_watt` 를 "권장값이라 막지 말자"고 완화하려던 참이었는데,
> **제조사 자료가 완화하지 말라고 답했다.** 실물 검증 없이 감으로 고쳤으면
> 위험한 구성을 통과시킬 뻔했다.

---

## 4. 그래서 답: **방향이 맞다. 그리고 방금 증명됐다.**

- 규칙이 낸 탈락 3건이 **전부 실제 판매 구성의 결함**이었고, 우리 규칙은 **하나도 틀리지 않았다.**
- 실물 검증이 아니었으면 ②③을 "규칙이 과하다"고 완화했을 것이다.

## 5. 그러나 **판정 가능 비율 55%** 가 진짜 문제다

통과율 98.5% 는 **판정할 수 있었던 것 중**의 값이다. 절반은 아예 판정하지 못했다.

| 못 하는 이유 | 건수(표본 40종) |
|---|---|
| **부품을 못 찾음** | 106 |
| **표준 값이 없음** | 55 |

### 5.0 ⚠ **판정 가능률이 낮으면 통과율도 못 믿는다** — 실례가 나왔다

전량(318종) 1차 실행에서 `mem`(메모리 규격 일치) 규칙이 **26건 탈락**했다. 사례:

    122325   RAM  마이크론 Crucial DDR5 5600 CL46 16GB  = 'DDR4'
             MB   ASRock Z890 Pro RS                    = 'DDR5'

이름은 DDR5 인데 값이 DDR4 라 **우리 적재가 틀린 것처럼 보였다.** 확인해 보니:

    이름 DDR5 · 값 DDR4 : 0건
    이름 DDR4 · 값 DDR5 : 0건        (램 전체 1,766건)

**우리 DB 에는 그런 모순이 하나도 없다.** 즉 그 탈락은 규칙 문제도 데이터 문제도 아니라
**잘못된 매칭**이었다 — 구성의 DDR5 램이 카탈로그의 **다른 DDR4 램**에 붙었다.

> **매칭이 부정확하면 탈락도 통과도 의미가 없다.** 그래서 모델 번호 매칭이
> "정확도를 조금 올리는 개선"이 아니라 **검증이 성립하기 위한 전제**다.

### 5.1 부품을 못 찾는 이유 — 이름 형식이 다르다

    완제품 구성 : 인텔 15세대 코어 울트라7 265 Turbo 5.3GHz, 20코어(8+12), 인텔 Xe Graphics
    우리 카탈로그: 인텔 코어 울트라7 시리즈2 265 (애로우레이크) (정품)
    유사도 0.40 → 못 찾음

CPU 가 대부분이다. **완제품 구성은 「사양 요약형」, 카탈로그는 「상품명형」**이라 어휘가 다르다.
모델 번호(`265`·`9950X`)로 맞추는 매칭이 필요하다.

### 5.2 값이 없어 판정 못 하는 규칙

`radiator` 36/40 · `cooler_tdp` 6/40 이 '값 모름'이다.
`cooler_tdp` 는 채움률 22.4% 로 이미 알려진 구멍이고, 다나와에도 없다.

---

## 6. 다음에 할 것 (순서)

1. **모델 번호 매칭**을 넣어 부품 매칭률을 올린다 → 판정 가능 비율이 올라간다.
2. 그 상태로 **318종 전량 재검증** → 탈락이 더 나오는지 본다.
3. 탈락마다 **제조사 자료로 확인** → 규칙이 틀렸으면 고치고, 데이터가 틀렸으면 검수로 돌린다.
4. 그 뒤에 값 채우기(③ 다나와 · ④ 사람 입력)로 간다.

**데이터를 더 넣기 전에 2·3을 끝낸다.** 틀린 표준으로 채운 값은 두 번 일하게 만든다.
