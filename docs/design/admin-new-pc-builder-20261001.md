# 신규 조립PC 생성 · 대표 이미지 화면 설계 (2026-10-01)

## 범위
사용자가 신규 구성 화면 방향과 대표 이미지 기능을 승인했고, 이후 비용 절감을 위해 전체 부품 구성 및 호환성 검사가 끝난 뒤 생성하도록 정정했다. 이번 산출물은 관리자 공통 셸을 사용하는 4단계 클릭 시안이다. 실제 제품 등록/호환성 검사/LLM/이미지 API/업로드는 구현하지 않았다. localhost8785와 4개 PNG, 실제 N07 부품 읽기 스냅샷을 제공한다.

## 화면 흐름
1. 부품 구성: 빈 BOM에서 시작, 등록 판매 부품과 사내 보유 부품 구분. 실제 보유 수량 미연동을 재고 있음으로 표시하지 않는다. 내장그래픽과 CPU 기본쿨러는 확인된 사양으로 별도 선택한다.
2. 구성·가격 확인: 필수 부품/수량, CPU·메모리 규격, GPU/쿨러 장착 공간, SSD 슬롯, 전원 및 냉각 방식 점검. 새 구성의 조립비 30,000원 표시. 기존 완제품 포함 조립비는 중복 가산하지 않는다. 마진/가격정책은 기존 정본 재사용.
3. 설명: 확정한 BOM에 맞는 설명 초안과 선택 적용. 게임 FPS·작업 성능을 근거 없이 생성하지 않는다.
4. 대표 이미지·등록: 케이스 이미지 기반 생성, 실제 조립 사진 업로드, 결과 선택/재생성, 중복 BOM 확인, 검토 대기 등록. 추천 승인과 고객 공개는 별도.

## 이미지 호출 제한 — 사용자 정정 반영
- 부품 구성이 완성되어 있고 최신 BOM에 대한 호환성 검사 완료 상태가 유효할 때만 생성 버튼 활성화.
- 페이지 진입, 부품 선택, 설명 생성, 검사 완료만으로 자동 이미지 호출하지 않는다. 운영자가 비용 안내를 확인하고 생성 버튼을 직접 누른다.
- 서버도 필수 구성/수량/검사 완료/basis를 확인한다. 브라우저 체크값을 신뢰하지 않는다. 검사 미완료·불일치·구성 변경 후 오래된 검사로는 생성 요청 거절.
- 부품 또는 수량 변경 시 검사 무효화. 이미지 생성 대기/진행 중 BOM이 바뀌면 결과는 해당 이전 구성의 이력으로 남기고 새 구성 대표 이미지로 자동 적용하지 않는다.
- 케이스·냉각 방식·LED 설정은 최종 구성 근거로 고정/제한한다. 공랭 구성에 수랭을 임의로 그리지 않는다.
- 구성/표현 조건 fingerprint로 기존 이미지 우선 조회. 동일 요청 실행키와 진행중 작업을 중복 처리하지 않아 더블클릭/재시도 중복 과금 방지.
- 기존 적합 이미지 재사용, 비용 안내 후 명시적 재생성. 변경시 재확인 표시만 하고 자동 재호출하지 않는다.
- 생성 실패 시 작업상태/비용 로그와 재시도 제공. 사용자 요청 없이 무한 재시도하지 않는다. 이미지 없이 검토 대기 상품 등록 가능.

## 데이터 연결 설계 (미구현)
현재 pc_configurations/parts/offers/history/review와 부품 설명/이미지 정본을 재사용한다. 이미지 작업은 별도 실행 이력(작업ID, 임시구성ID 또는 제품군ID, BOM/시각조건 해시, 호환 검토 basis, 공급자/모델, 상태, 비용/사용량, 원본참조, 객체경로, 생성시각, 실패사유)을 두고, 확정한 이미지 자산ID만 제품군에 연결한다. 이미지 파일은 기존 비공개 상품미디어 저장소 정책을 재사용하고 원본/웹미리보기/썸네일을 구분. 실제 사진/AI조립예시 구분, 프롬프트 및 참조모델, 선택이력 보존. 고아 임시자산 정리 및 재사용 이력도 포함. 별도 테이블명과 마이그레이션은 구현시 기존 스키마와 중복검사 후 확정한다.

## 확인
시안에서 빈구성 및 구성완료/검사전 이미지 버튼 잠금, 검사완료 시 활성화 확인. 기존 N07 예시이미지 사용, 새 유료 생성 없음. 실제 가격은 표본 조회 시점의 개별 부품 판매가이며 운영 신규상품 가격 확정이 아니다.
