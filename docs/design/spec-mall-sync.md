## 이 화면의 정체 — 값을 고치지 않는다

> **실서비스는 읽기만 합니다** — 담기·저장 요청을 보내지 않습니다

**이 화면은 동기화가 얼마나 건강한지만 본다.** 우리 판매가를 몰 값으로 맞추거나 잠그는 일은 **「판매가 관리」 소관**이다.

> **같은 건들을 두 화면이 각자 고치면 정본이 갈라집니다** — 이 화면은 값을 고치지 않습니다.

⚠ **정정 버튼을 만들지 마라.** 대신 **「판매가 관리에서 열기 →」** 링크만 둔다.

## ⚠⚠ 「받아온 시각」을 정직하게 적는다 — 이 화면의 핵심 정직성

**주기적으로 도는 동기화가 아직 없다.** 상단에 경고 배너로 밝힌다:

> **주기적으로 도는 동기화가 아직 없습니다**
> 몰 가격은 **고객이 인계를 누르는 그 순간, 그때 담기는 상품에 대해서만** 확인됩니다.
> 그래서 여기 「받아온 시각」은 **마지막 인계 시점에 확인한 상품만**의 시각입니다 —
> 나머지 N개 상품은 **마지막으로 받아온 시각 자체가 없습니다.**
> 카탈로그 전체 동기화는 원인소프트 API(10~30분 주기 배치로 요청) 도착 후에나 가능합니다.

배너 우측에 **마지막 확인 시각 + 인계 번호**.

⚠ **「받아온 시각」을 전체 카탈로그의 시각처럼 보이게 하면 그 자체가 거짓말이다.**

서랍 하단:
> 품절 여부는 판정하지 않습니다 — **재고 원장은 쇼핑몰이 갖습니다.**

### ⚠⚠ 「지금 확인」은 실서비스를 친다 — **API 로 만들 예정 업무다**

**사장님 확정(2026-08-15):**
> 실제 팝콘PC 쇼핑몰(실서비스)을 치는 기능은 **API 를 통해서 만들 예정 업무**로 기록해 놔.

**판매가 관리(ADM-PRC-060)의 「지금 물어보기」와 «같은» 기능이다** — 둘 다 이 예정 API 를 쓴다.

    ✅ 확정   실서비스 조회는 **API 로 만든다** — **화면이 직접 긁지 않는다**
    ⏳ 시점   **예정 업무**(작업 목록 #38). 지금은 아직 없다

**그러니 이 화면에서는:**
- **스크래퍼를 짓지 마라.** 화면 안에 실서비스 조회 코드를 넣지 않는다
- 서버에 그 API 가 **이미 있으면** 붙인다
- **없으면 「향후 사용예정 — 실서비스 조회 API 준비 중」으로 잠근다**
- **어느 쪽인지 코드로 확인하고 보고해라**

**④ 「값을 고치려면」**
> 이 화면은 동기화가 얼마나 건강한지만 봅니다. 우리 판매가를 몰 값으로 맞추거나 잠그는 일은
> **판매가 관리** 소관입니다 — 같은 건들을 두 화면이 각자 고치면 정본이 갈라집니다.
