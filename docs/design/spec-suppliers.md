# ★ 이 화면의 성격 — 먼저 이해해라

**조회 화면이 아니라 «등록·수정·중지» 화면이다.**

    제목      공급처
    화면 ID   **ADM-SRC-030**
    경로      **/admin2/suppliers**
    LNB       「매입 · 소싱」 그룹
    헤더 배지  「등록 · 수정 · 중지 — 삭제는 없습니다」

## ⚠⚠ 삭제는 «없다» — 이게 이 화면의 첫 제약

**참조하는 표가 6개다.** 지우면 과거 기록이 깨진다. **활성 ↔ 중지만 있다.**

    · **삭제 버튼을 만들지 마라.** 화면 어디에도 없다
    · 하단에 **「삭제 → 없습니다(참조 테이블 6개, 원장 보존)」**를 적는다
    · 중지 확인 창에도 **「삭제가 아닙니다 — 언제든 되돌립니다」**를 «제목 옆»에 둔다

## ⚠ 기본키는 `id` 다 — `supplier_id` 가 «아니다»

⚠⚠ **이 저장소가 정확히 여기서 사고를 냈다**(CLAUDE.md §실패를 삼키지 않는다):
> 목록 API 는 `id` 로 주는데 화면이 `s.supplier_id` 를 읽어 `value="undefined"` ->
> `+value` 가 **NaN** -> JSON 에서 null -> **저장할 때마다 422**

**같은 병을 두 번 만들지 마라.** 목록 행에 `id {{ s.id }}` 를 «보이게» 두는 것도 그 때문이다.

# 문구 — 그대로 쓴다

## 등록줄

> **새 공급처 등록**
> 이름만 필수 — 플랫폼·브랜드는 나중에 수정할 수 있습니다 · 상태는 활성으로 만들어집니다

**성공**:
> 「이엠텍 등록했습니다 — **상품 상세의 [공급처별 매입가]에서 선택할 수 있습니다**」

⚠ **끝내지 말고 «다음에 할 수 있는 일»까지 말한다.**

**409 중복**:
> 기존 공급처(이름·상태·id)를 함께 보여주고,
> **중지 상태면 「새로 만들지 말고 되살리기」**를 같은 자리에 놓습니다

## ⚠ 409 처리 — 자세히

    · 대소문자 · 앞뒤 공백을 «무시하고» 비교한다
    · ⚠ **서버가 «기존 공급처를 그대로 돌려준다»** — 무엇과 겹쳤는지 **화면이 추측하지 않는다**
    · 기존 공급처를 **이름 · 상태 배지 · id** 로 보여준다
    · 중지 상태면:
      > **「중지 상태입니다 — 새로 만들지 말고 되살리세요.」**
      > 되살리면 이미 연결된 매입가·단가표가 그대로 이어집니다.
      -> 버튼 둘: **[이 공급처를 활성으로 되돌리기]** · [이름 고치기]
    · ⚠ **동시 등록으로 유니크 인덱스가 먼저 잡히는 경우도 «같은 문구»로 뭉뚱그린다**
      -> **DB 원문 오류를 그대로 보이지 않는다**

## 그 밖의 오류 문구 — 그대로

    이름 누락      400  「공급처 이름을 입력하세요」
    100자 초과     400  「이름은 100자 이하로 입력하세요」
    없는 공급처 수정 404  「공급처를 찾을 수 없습니다」
    변경분 없음     **오류가 아니다** — 「바뀐 값이 없습니다」

# ⚠⚠ ⑤ 중지 확인 창 — 이 화면의 «핵심»

> **「누르고 나서 알면 늦습니다.」** 중지로 바꾸기 «전에» 영향을 먼저 본다 —
> **확인 없이 바로 전환하지 않는다.**

**제목**: 「{이름}을 중지하기 전에」 · 옆에 **「삭제가 아닙니다 — 언제든 되돌립니다」** · 우측에 `id {n}`

## 영향 카드 셋 — 큰 숫자로

    연결된 매입가            {n}건
    업로드된 단가표 파일       {n}건
    ⚠ **이 공급처가 «유일한» 매입처인 상품**  {n}개   <- **붉게 · 배경도 다르게**

⚠ **세 번째가 이 창의 존재 이유다.**

> **「상품 {n}개는 이 공급처가 «유일한» 매입처입니다」**
> 중지하면 이 상품들은 **새 매입가를 넣을 곳이 없어집니다** —
> 판매가 산정의 근거도 함께 끊깁니다.

## 결과 안내 — 중지하면 무엇이 되나

> **중지하면:** 새 매입가 입력의 선택지에서 빠집니다.
> **이미 연결된 매입가 {n}건과 단가표 파일 {n}건은 그대로 남습니다** — 과거 기록은 지워지지 않습니다.

**버튼**: [중지로 바꿉니다] · [그만두기] · 우측에 작게
> 되돌리기는 목록의 「활성으로」 버튼 한 번입니다

# ④ 하단 2단 — 둘 다 사장님 결정이다

## 좌 — 파서 프리셋 경고

> **파서 프리셋이 없는 공급처 {n}곳 — 「단가표 일일 반영」을 쓸 수 없습니다**
> 프리셋(파일명 인식 규칙 · 열 매핑)을 만드는 화면·API가 **코드 전체에 없습니다.**
> 여기서 등록해도 누군가 DB 에 직접 넣어야 그 공급처의 단가표를 반영할 수 있습니다 —
> **이 화면은 그 경로를 제공하지 않습니다**(사장님 결정 1).

## 우 — 이 목록이 «판단하지 않는» 것

> 연결 0건 · 파일 0건인 공급처는 **아직 실사용 흔적이 없다**는 사실만 보여줍니다.
> 점검용인지 실거래처인지 **화면이 단정하지 않습니다** — 정리 여부는 사람이 정합니다(사장님 결정 2).
