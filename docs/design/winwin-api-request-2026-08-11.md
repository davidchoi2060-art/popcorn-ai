# 윈윈소프트 API 개발 요청서 — 팝콘AI 연동

작성 2026-08-11 · 팝콘PC

## 배경

팝콘PC 는 **AI 견적 서비스(팝콘AI)** 를 신규 고객 유입 채널로 준비하고 있습니다.
고객이 용도·예산을 말하면 부품 호환성을 판정해 최적 구성과 견적을 제시하고,
**구매 단계에서 팝콘PC 쇼핑몰로 인계**합니다.
결제·배송·환불·회원관리는 전부 쇼핑몰에서 처리합니다 — 팝콘AI 는 판매하지 않습니다.

    고객 → 팝콘AI(용도 입력 → 호환성 판정 → 견적) → 쇼핑몰 장바구니 → 결제·배송(쇼핑몰)

연동에 필요한 API 를 우선순위대로 정리했습니다. **1·2번이 없으면 인계 자체가 불가능합니다.**

---

## 1순위 — 상품 조회 (벌크) · **필수**

**용도** — 고객에게 견적을 확정해 보여주기 직전에 **가격과 재고를 실시간으로 재확인**합니다.

**왜 필요한가** — 현재 팝콘AI 는 엑셀로 상품 정보를 받고 있어 시차가 생깁니다.
2026-08-11 표본 10건 대조에서 **2건의 가격이 어긋났습니다**(GPU 127,300 vs 실제 125,200,
HDD 189,000 vs 실제 **194,100**). 싸게 안내하고 넘기면 고객이 장바구니에서 다른 금액을 보게 되어
신뢰가 깨집니다. **한 견적에 부품이 6~8개이므로 반드시 여러 건을 한 번에 조회해야 합니다.**

    요청   상품코드 목록 (pd_no 배열, 1회 최대 50건)
    응답   pd_no · 상품명 · 판매가(price) · 공급가(dealer_price)
           재고수량 · 판매상태(판매중/품절/중지) · 최종수정시각

호출 빈도: 견적 확정 시 1회. 일 수백 건 예상.

---

## 2순위 — 장바구니 담기 · **필수**

**용도** — 확정된 견적의 부품 전체를 고객의 쇼핑몰 장바구니에 담습니다.

    요청   회원 식별자 (아래 3번 참조)
           품목 배열 [{ pd_no, 수량 }]   — 1회 최대 20건
    응답   성공 여부 · 장바구니 이동 URL (가능하면 토큰 포함)
           품목별 결과(품절·가격변동 등으로 담기지 못한 건은 사유와 함께)

**중요** — **품목 전체를 한 번의 요청으로** 담을 수 있어야 합니다.
현재 쇼핑몰 화면은 `/shop/order_basket_action.php` 로 상품 하나씩 POST 하는 구조인데,
부품 8개면 8번을 왕복하게 되어 이탈이 발생합니다.

**부분 실패 처리** — 일부 품목이 품절이어도 **나머지는 담고**, 실패한 건만 알려주십시오.
전부 실패로 되돌리면 고객이 처음부터 다시 해야 합니다.

---

## 3순위 — 회원 식별 · **필수 (방식은 협의)**

**용도** — 인계한 장바구니를 **그 고객의 것**으로 만들기 위함입니다.

아래 셋 중 **하나만** 제공되면 됩니다. 귀사에서 구현이 쉬운 방식으로 알려주십시오.

| 안 | 내용 | 팝콘AI 측 처리 |
|---|---|---|
| **(가) SSO 토큰** | 쇼핑몰 로그인 후 발급되는 토큰을 팝콘AI 가 검증 | 가장 선호. 고객이 한 번만 로그인 |
| **(나) 회원 조회 API** | 이메일 또는 로그인 ID → 회원 식별자(mall_member_id) 반환 | 팝콘AI 가 이메일을 받아 조회 |
| **(다) 익명 장바구니 + 인계 URL** | 회원 없이 장바구니를 만들고, 그 URL 로 이동하면 로그인 후 승계 | 회원 연동 없이도 오픈 가능 |

**(다)만 되어도 오픈은 가능합니다.** (가)·(나)는 이후 개선 과제로 두어도 됩니다.

> 참고: 팝콘AI 는 **회원 원장을 따로 두지 않습니다.** 쇼핑몰 회원이 유일한 회원입니다.
> 팝콘AI DB 에는 쇼핑몰 회원 식별자를 참조로 보관할 준비가 되어 있습니다.

---

## 4순위 — 상품 목록 동기화 (증분)

**용도** — 현재 **엑셀 수동 업로드**로 하고 있는 카탈로그 반영을 자동화합니다.
1순위(벌크 조회)가 견적 시점의 오차를 막아 준다면, 이것은 **오차의 원천 자체**를 없앱니다.

    요청   기준시각 (이후 변경된 건만) · 페이지
    응답   pd_no · 상품명 · 분류 · 판매가 · 공급가 · 재고 · 판매상태 · 최종수정시각
           (삭제·판매중지 건도 포함)

호출 빈도: 10~30분 주기 배치.

---

## 5순위 — 주문 결과 회신 (웹훅 또는 조회)

**용도** — 팝콘AI 가 인계한 견적이 **실제 구매로 이어졌는지** 확인합니다.
유입 채널의 성과 측정에 쓰이며, 없으면 «몇 건을 보내 몇 건이 팔렸는가»를 알 수 없습니다.

    방식 A (선호)  웹훅 — 주문 완료 시 팝콘AI 로 통지
    방식 B         조회 — 우리가 넘긴 장바구니/주문 식별자로 상태 조회

    필요 항목   주문번호 · 주문상태 · 결제금액 · 주문시각
                (팝콘AI 가 인계 시 전달한 참조값이 함께 회신되면 가장 좋습니다)

---

## 공통 사항

- **인증** — API 키 또는 OAuth. 서버 대 서버 호출이며, 키는 팝콘AI 서버 환경변수에만 보관합니다.
- **호출 IP** — 고정 IP 에서 호출합니다. 허용 목록이 필요하면 알려주십시오.
- **형식** — JSON 을 선호하나 귀사 표준을 따르겠습니다.
- **오류** — HTTP 상태코드와 함께 **사유 코드**를 주십시오(품절·존재하지 않는 상품·권한 등).
  고객에게 무엇이 잘못됐는지 정확히 안내하기 위함입니다.
- **테스트** — 개발/테스트 환경 계정이 필요합니다. 실 데이터로 시험할 수 없습니다.

## 확인 요청

1. 위 5종 중 **현재 제공 가능한 것**과 **개발이 필요한 것**을 구분해 주십시오.
2. 개발이 필요한 건의 **예상 일정**을 알려주십시오.
3. 3순위(회원 식별) 중 **어느 방식이 가능한지** 회신 부탁드립니다.
