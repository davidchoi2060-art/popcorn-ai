# 요구사항 정의서 — 공급처 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **대상은 admin2 신규 구축이다 — 구 `mockups/admin/suppliers.html`을 옮기는
> 것이 아니라 새로 만드는 것이다.** 구화면은 백업용 동결(수정·링크 금지, P-09).
>
> 작성일 2026-08-13. ④의 수치는 **그 시각의 실측 스냅샷**이다(`api.db.engine`으로
> `suppliers`·`product_supplier_prices`·`supplier_presets`·`supplier_price_files`·
> `supplier_product_map`·`product_price_history`·`product_sourcing_quotes`를 직접
> SELECT, 읽기 전용·DB 미변경). 화면은 이 문서의 숫자를 그대로 박지 않는다 — 서버
> 응답만 쓴다.

---

## ① 화면 성격

**관리 화면(마스터 데이터)이며 동시에 매입·소싱 전체 파이프라인의 관문이다.**
조회 전용이 아니다 — 공급처를 만들고 상태를 바꾸는(등록·수정·중지) 화면이고,
이 화면이 비어 있으면(활성 공급처 0건) 그 뒤에 있는 매입 견적·단가표 반영·상품
상세의 매입가 입력이 전부 대상을 잃는다.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

**빈 DB(신규 개업)에서 이 화면이 없으면 실제로 아무것도 시작할 수 없었다** —
슬라이스 93 실사고. 원인은 `INSERT INTO suppliers`가 개발용 시드(`db/seed/seed.sql`)
에만 있었고, API는 목록 조회와 상품별 매입가 연결뿐이라 **새 공급처를 만드는
수단이 코드 어디에도 없었다**는 것이다. 그 결과가 다음 연쇄다(`api/admin_suppliers.py`
docstring, `docs/07_운영-시작-순서.md` 3단계 원문 그대로):

    공급처 0 → 매입가 넣을 대상 없음 → 판매가 산정 불가
              → 4중 게이트 통과 불가 → 추천 후보 0 → 견적 0건

`docs/07_운영-시작-순서.md`가 상품보다 공급처를 먼저 두는 이유도 같다 — "매입가는
공급처별로 기록된다. 공급처가 없으면 매입가를 넣을 대상이 없고, 매입가가 없으면
판매가가 산정되지 않는다."

**삭제가 아니라 상태 전이인 이유도 정의의 일부다.** `suppliers`를 참조하는 테이블이
**6개**다(아래 ④). 매입 이력이 걸린 공급처를 지우면 과거 단가·매입 기록이 깨지므로
원장 규약대로 '활성' ↔ '중지'로만 접는다.

## ④ 데이터

### 실측 방법

`api.db.engine`으로 관련 테이블을 직접 SELECT(읽기 전용). 아래는 2026-08-13 스냅샷.

### 쓰는 테이블

| 테이블 | 역할 | 컬럼(실측) |
|---|---|---|
| `suppliers` | 공급처 원장 | `supplier_id` PK · `name` NOT NULL · `platform` NULL · `brands` NULL · `created_at` · `status` NOT NULL DEFAULT `'활성'`(0025에서 추가, DB 레벨 CHECK 없음 — 코드가 `('활성','중지')`로 검증) · 유니크 인덱스 `ux_suppliers_name`(이름 대소문자·앞뒤공백 무시) |
| `product_supplier_prices` | 공급처별 매입가(1상품:N공급처) | 이 화면은 **건수만** 읽는다(중지 영향 판단용) — 입력 자체는 다른 화면 소관 |
| `supplier_presets` | 단가표 파서 규칙 | 이 화면은 **건수만** 읽는다 — 생성 API가 코드 전체에 없다(아래 비범위) |
| `supplier_price_files` | 단가표 업로드 이력 | 이 화면은 **건수만** 읽는다 |
| `supplier_product_map` | 모델명↔상품코드 매핑 | suppliers를 참조하는 6개 테이블 중 하나(직접 노출은 안 함) |
| `product_price_history` | 가격 변경 이력 | `supplier_id` FK(매입가 이력의 출처 표시용) |
| `product_sourcing_quotes` | 매입 견적 | `supplier_id` FK |

### 실측 스냅샷(2026-08-13)

- **공급처 4건, 전부 '활성'**(중지 0건). 목록: MSI(웨이코스)/플랫폼 윈윈/브랜드 MSI,
  클릭나라/플랫폼 없음/브랜드 GIGABYTE(PCD), 점검-공급처-A/플랫폼 직거래/브랜드
  테스트브랜드, 용산 중앙/플랫폼 용산 거래처/브랜드 메모리·노트북.
  **뒤 2건은 이름·비고로 보아 실거래처가 아니라 점검·개발 과정에서 생긴 데이터로
  보인다**(단정은 아니다 — 이 화면의 권한은 상태 전이까지이고 판단·정리는 별도).
- 참조 테이블 실측 건수: `supplier_presets` 2건(공급처 2곳만) · `supplier_price_files`
  6건 · `supplier_price_rows` 308건 · `supplier_product_map` 6건(전부
  `match_method='manual'`) · `product_supplier_prices` 6건(5개 상품 · 2개 공급처만
  — 공급처 95·104는 연결 0건) · `product_price_history`(공급처 표기 있는 매입 이력)
  11건 · `product_sourcing_quotes` 12건.
- 공급처 1(MSI)에 매입가 연결 2건, 공급처 2(클릭나라)에 4건 — 나머지 두 공급처는
  아직 실사용 흔적이 전혀 없다.

### API(기존 계약)

| 엔드포인트 | 역할 |
|---|---|
| `GET /api/admin/suppliers` | 목록 + `active`/`empty`/`note`(빈 상태 문구를 서버가 판정) |
| `POST /api/admin/suppliers` | 등록. 이름 필수, 중복(대소문자·공백 무시) 시 409 |
| `PATCH /api/admin/suppliers/{id}` | 수정(이름·플랫폼·브랜드·상태). 변경분만 반영 |
| `GET /api/admin/suppliers/{id}/impact` | 중지 전 영향 미리보기 — 연결된 매입가 건수·단가표 파일 건수·**이 공급처가 유일한 매입처인 상품 수** |

**참고(비범위지만 데이터를 공유)**: 상품 상세의 `POST/DELETE /products/{code}/suppliers`
(ADM-PRD-030 소관)도 `product_supplier_prices`에 쓴다 — 전화로 받은 매입가를 단건
보정하는 경로다. 이 경로는 **`_reprice()`(매입가/판매가 재판정)를 부르지 않는다** —
단가표 반영·매입 견적 확정과 달리, 여기서 입력한 매입가는 저장만 되고 자동으로
판매가에 반영되지 않는다(실측 코드 확인 — 이 화면의 요구사항은 아니지만 같은
테이블에 쓰는 세 번째 경로로서 알아둘 사실).

## ⑤ 기능 — 동사

- 공급처 목록을 본다(이름·플랫폼·취급 브랜드·상태·**연결된 상품 수**·**단가표 파일
  수**와 함께 — 둘 다 화면이 세지 않고 서버가 센다).
- 새 공급처를 등록한다(이름 필수, 플랫폼·취급 브랜드는 선택, 상태 기본값 '활성').
- 기존 공급처 정보를 수정한다(이름·플랫폼·브랜드·상태).
- 공급처를 중지한다 — **삭제가 아니다.** 중지 전에 영향(연결된 매입가 건수·단가표
  파일 건수·이 공급처가 유일한 매입처인 상품 수)을 먼저 확인한다.
- 중지한 공급처를 다시 활성으로 되돌린다.

## ⑥ 인터랙션 — 입력 · 선택 · 저장 · 이동의 흐름과 결과

- 등록: 이름을 입력하면 대소문자·앞뒤공백을 무시하고 중복을 먼저 확인한다 — 중복이면
  409와 함께 기존 공급처명·상태·id를 그대로 돌려주고, **"중지 상태면 재활성화하라"는
  대안을 안내한다**(원인 없는 거부로 끝내지 않는다). 성공하면 "○○ 등록했습니다 —
  상품 상세의 [공급처별 매입가]에서 선택할 수 있습니다"처럼 **다음에 무엇을 할 수
  있는지**까지 알려야 한다.
- 상태를 '중지'로 바꾸는 조작 전: **영향(impact)을 먼저 보여준다** — 연결된 매입가
  건수·단가표 파일 건수·이 공급처가 유일한 매입처인 상품 수. "누르고 나서 알면
  늦다"(슬라이스 67·75와 같은 원칙) — 확인 없이 바로 전환하지 않는다.
- 중지 확정 시 결과: "새 매입가 입력에서 빠집니다. 이미 연결된 매입가 N건은 그대로
  남습니다"처럼 **삭제되는 것이 아니라는 사실**을 함께 알린다.
- 변경 사항이 없는 저장 시도: "바뀐 값이 없습니다"로 안내(빈 변경을 침묵하지 않되
  오류로도 취급하지 않는다).

## ⑦ 상태 · 예외

- **빈 상태(활성 공급처 0건)**: 서버가 이미 이 상태를 판정해 note로 문구를 준다 —
  "공급처가 없으면 매입가를 넣을 대상이 없고, 매입가가 없으면 판매가가 산정되지
  않아 추천 후보가 되지 않습니다." 화면은 이 문장을 그대로 보여주고 **등록
  행동으로 바로 이어져야 한다** — 과거 이 화면 자체가 없어서 이 빈 상태를 벗어날
  방법이 아예 없었다(슬라이스 93 실제 장애, 이제는 등록 폼이 있으므로 막히면 안 된다).
- 이름 누락: 400 "공급처 이름을 입력하세요".
- 이름 100자 초과: 400 "이름은 100자 이하로 입력하세요".
- 상태값이 활성·중지가 아님: 400.
- **이름 중복(등록·수정 공통)**: 409, 기존 공급처명·상태·id를 함께 반환.
- 존재하지 않는 공급처 수정·영향조회: 404 "공급처를 찾을 수 없습니다".
- 동시 등록으로 유니크 인덱스가 먼저 잡는 경쟁 상태: 409(원문 오류 그대로 노출 대신
  "이미 있는 공급처입니다"로 뭉뚱그림).

**과거 사고 재발 방지 요구사항(반드시 지킨다)**

1. **응답 필드명을 추측하지 않는다.** `GET /api/admin/suppliers`의 각 항목은 기본키를
   `id`로 준다(`supplier_id`가 아니다). 과거 상품 상세 화면이 이 값을 `s.supplier_id`로
   읽어 `undefined`→`NaN`→저장할 때마다 422가 나는 사고가 있었다(2026-08-05 사용자
   신고). 새 화면은 이 계약(`id`)을 그대로 따라야 한다.
2. **지킬 수 없는 약속을 화면에 적지 않는다.** 매입가(`product_supplier_prices.cost_price`)는
   DB에서 NOT NULL이다 — "비워 두면 미확인으로 처리됩니다" 같은 문구를 적으면
   실제로는 500이 난다(2026-08-05 실사고, 현재 API는 400 "매입가를 입력하세요 —
   가격 없이 공급처만 등록할 수는 없습니다"로 방어됨). 이 화면이 매입가 입력을
   직접 다루지는 않지만, 공급처 등록 폼도 **같은 원칙**(빈 값을 허용하는 척하지
   않는다)을 지켜야 한다.

## 비범위 — 이 화면이 하지 않는 일

- **매입가 입력 자체** — 상품 상세(ADM-PRD-030, 단건 보정) 또는 매입 견적·단가표
  반영(대량) 화면 소관.
- **공급처 삭제** — 설계상 존재하지 않는다(참조 테이블 6개, 원장 보존 규약). 중지만
  가능하다.
- **단가표 파서 프리셋(`supplier_presets`) 생성** — 실측: 이 테이블에 행을 넣는
  API/화면이 **코드 전체에 없다**(가장 최근 데이터도 2건뿐이며 둘 다 초기 구축
  과정에서 만들어졌다). 즉 **이 화면에서 새 공급처를 등록해도, 그 공급처가 단가표
  반영(ADM-PRC-040)을 실제로 쓰려면 누군가 DB에 직접 프리셋 행을 넣어야 한다** —
  이 화면이 그 경로를 제공하지 않는다.

## 사장님 결정이 필요한 지점

1. **단가표 파서 프리셋을 만드는 화면·경로가 없다.** 이 화면(공급처)이 등록 시
   프리셋 설정(파일명 인식 규칙·열 매핑)까지 함께 받아야 하는지, 아니면 별도
   화면/작업(개발)으로 미룰지 — 미루면 새 공급처는 사실상 "단가표 반영"을 영원히
   못 쓴다.
2. **실측 4건 중 2건("점검-공급처-A", "용산 중앙")이 점검용으로 보인다.** 운영
   오픈 전 정리(중지 처리) 대상인지 확인이 필요하다(이 화면의 요구사항 범위는
   아니고 데이터 정리 건이지만, 이 화면이 보여줄 목록에 그대로 노출된다).
