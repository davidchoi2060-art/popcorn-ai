# 요구사항 정의서 — 단가표 반영 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **대상은 admin2 신규 구축이다 — 구 `mockups/admin/price-import.html`을 옮기는
> 것이 아니라 새로 만드는 것이다.** 구화면은 백업용 동결(수정·링크 금지, P-09).
>
> 작성일 2026-08-13. ④의 수치는 **그 시각의 실측 스냅샷**이다(`api.db.engine`으로
> `supplier_price_files`·`supplier_price_rows`·`supplier_presets`·`supplier_product_map`·
> `pricing_settings`를 직접 SELECT, 읽기 전용). 화면은 이 문서의 숫자를 그대로
> 박지 않는다.

---

## ① 화면 성격

**반복 작업 화면(매일 처리하는 루틴).** 공급처가 보내는 단가표 엑셀을 업로드해
어제와 비교(diff)하고, 변경분만 선택해 일괄 반영하는 화면이다 — "무변동 행은
자동 통과, 매일 아침 3분 루틴"으로 설계된 화면이다(`docs/decisions/admin-identity.md`).

| 항목 | 값 | 근거 |
|---|---|---|

| 구화면 | `mockups/admin/price-import.html` | 백업용 동결. 참고만 |
| LNB 위치 | "매입 · 소싱" 그룹(공급처 → 매입 견적(용산) → **단가표 반영**) | |

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

거래처가 보내는 단가표를 정본(`product_supplier_prices`, `products.purchase_price`/
`sale_price`)에 반영하는 **유일한 대량 경로**다. 이 화면이 없으면 공급처 가격
변동을 상품 단위로 일일이 손으로 넣어야 한다 — 상품 상세의 단건 보정은 대량
갱신용이 아니며 자동 재판정도 하지 않는다(req-suppliers.md ④ 참조). ERD §6.4의
"판매가 재계산은 제안+승인" 원칙을 실행하는 화면이기도 하다 — diff가 재계산될
판매가를 먼저 보여주고, 운영자의 "선택 반영" 클릭이 곧 승인이다(자동 집행이 아니다).

## ④ 데이터

### 실측 방법

`api.db.engine`으로 직접 SELECT(읽기 전용). 아래는 2026-08-13 스냅샷.

### 쓰는 테이블

| 테이블 | 역할 | 실측(2026-08-13) |
|---|---|---|
| `supplier_price_files` | 일일 업로드 스냅샷(파일 단위) | 총 6건 — 반영 완료 2 · 대기 4 |
| `supplier_price_rows` | 파일 안의 행(모델명·가격열·상태) | 총 308건 |
| `supplier_presets` | 공급처별 파서 규칙(JSONB — 파일명 인식·열 매핑·상태 정규화) | 총 2건, **공급처 2곳만**(4곳 중) |
| `supplier_product_map` | 모델명↔상품코드 매핑 기억 | 총 6건, 전부 `match_method='manual'` |
| `pricing_settings` | 판매가 공식 파라미터(카드수수료·마진, 버전형) | 6개 버전 이력, **현재 유효값** `card_fee_rate=2.585%`·`margin_rate=12%`(최신 `effective_from` 기준) |

### 핵심 동작 실측

- **`GET /api/admin/price-import`는 공급처별 "가장 최근 파일 1건만" 보여준다**
  (`DISTINCT ON (supplier_id) ... ORDER BY received_at DESC`). 실측상 같은 파일명이
  재수신되면(예: `MSI_단가표0716MTF.xlsx`가 07-16과 07-24 두 번 업로드됨) **새
  file 행이 생기고, 예전 파일은 화면 조회 대상에서 밀려난다**(삭제되진 않지만 diff
  조회 API가 더 이상 반환하지 않는다). 지금 MSI·클릭나라 두 공급처 모두 **가장 최근
  파일이 '대기'(미반영) 상태로 남아 있다**.
- **매칭 우선순위**: ① 기억된 `supplier_product_map` → ② `danawa_code` 일치(자동)
  → ③ 이름 유사도(trgm, 후보 제시만) → ④ 매칭 없음(신규 등록 필요, 이 화면에서
  반영 불가). 실측: 확정된 매핑 6건이 전부 'manual'이고, danawa_code 자동 매칭·
  유사도 후보로 확정된 이력은 지금 없다(파이프라인은 있으나 실사용 실적 0).
- 반영은 `admin_sourcing.confirm_quote`와 **같은 `_reprice()`를 공유**한다 —
  매입가는 공급처 간 최저가로, 판매가는 `locked_fields`에 `'sale_price'`가 없을
  때만 정책대로 갱신(잠긴 판매가 스킵은 응답에서 `sale_locked_skipped`로 집계된다).

### API(기존 계약)

| 엔드포인트 | 역할 |
|---|---|
| `POST /api/admin/price-import/upload` | .xlsx 업로드 → 파일명으로 공급처 인식 → 파싱·적재(`dry_run=1`이면 미적재 요약만) |
| `GET /api/admin/price-import` | 공급처별 최신 파일의 diff(가격변동/신규/발주상태전환/무변동) |
| `POST /api/admin/price-import/{file_id}/apply` | 선택한 행(매칭+대기 상태인 것만) 일괄 반영 |
| `POST /api/admin/price-import/undo/{log_id}` | 되돌리기 — 반영 이후 다른 변경이 겹쳤으면 거부 |

## ⑤ 기능 — 동사

- .xlsx 파일을 업로드한다(파일명으로 공급처를 자동 인식 — 인식 실패·중복 매칭 시 거부).
- 업로드된 파일의 파싱 요약(시트 수·제외된 시트·건너뛴 행·표본 3행)을 먼저 확인한다
  (`dry_run`).
- 공급처별 "가장 최근 파일"의 diff를 본다 — 가격 변동(매칭된 것/매칭 안 된 신규
  모델 구분), 발주 상태 전환(품절↔가능↔문의), 무변동 건수.
- 매칭되고 변경된 행 중 반영할 것을 선택해 일괄 반영한다.
- 반영을 되돌린다.
- (참고, 실행 불가) 매칭 안 된 신규 모델은 이 화면에서 반영할 수 없다는 사실을
  확인한다 — 신규 등록·후보 매칭 확정은 다른 경로(검수) 소관이다.

## ⑥ 인터랙션

- 업로드: .xlsx가 아니면 400. 파일명이 어느 프리셋의 `file_pattern`과도 안 맞거나
  둘 이상과 겹치면 400("공급처를 인식하지 못했습니다"). 파싱된 행이 0건이면 400.
- 같은 파일명 재업로드도 허용된다 — 새 file 행이 생기고(수신 시각으로 구분) 그
  공급처의 "최근 파일"이 그것으로 갱신된다(예전 파일은 조회에서 밀려난다 — 위 ④
  참조).
- 반영: 선택한 행 중 "매칭 안 됨" 또는 "이미 반영돼 대기 상태가 아님"이 하나라도
  섞여 있으면 **전체를 400으로 거부**한다(부분 성공 없음) — 문제 행 id 목록을
  함께 알려준다.
- 반영 결과는 세 가지를 구분해 알려야 한다: 반영 시도 건수 / 실제로 가격이 바뀐
  건수(`price_changed`) / 판매가가 잠겨서 건너뛴 건수(`sale_locked_skipped`) —
  "반영했다"와 "실제로 바뀌었다"는 다른 말이다(매칭은 됐지만 이미 같은 값이면
  자연히 대상에서 빠진다).
- 파일 전체의 매칭된 변경분을 모두 반영하면 파일 상태가 '반영 완료'로, 매칭 안 된
  chg가 남아 있으면 '부분 반영'으로 바뀐다.
- 되돌리기: 반영 이후 같은 행에 다른 변경(예: 다른 경로에서 손으로 고침)이 있었으면
  되돌리지 않고 409로 막는다("최종 승자 원칙") — 침묵하지 않는다.

## ⑦ 상태 · 예외

- **새로 만든 공급처는 프리셋이 없어 파일을 올릴 수조차 없다**(400 "공급처를
  인식하지 못했습니다"). 실측: `supplier_presets`를 만드는 API·화면이 코드
  어디에도 없다. 공급처 화면(req-suppliers.md)에서 공급처를 등록해도 이 화면으로
  바로 이어지지 않는다는 뜻이므로, **화면은 이 한계를 감추면 안 된다**(지킬 수
  없는 약속을 적지 않는다).
- 지원하지 않는 형식(.xlsx 아님): 400.
- 추출된 행 0건: 400 "추출된 상품 행이 없습니다 — 프리셋·파일을 확인하세요".
- 반영 대상에 매칭 안 된/미대기 행 포함: 400(문제 행 id 목록 포함).
- 이미 '반영 완료'인 파일에 재반영 시도: 409 "이미 반영 완료된 파일입니다".
- 되돌릴 기록 없음/이미 되돌림: 404/409.
- 되돌리기 중 다른 변경 감지: 409(침묵 금지).
- **가격지도(단가 단속) 시트는 적용하지 않는다는 사실을 명시해야 한다** — 구화면
  근거를 승계: 단품 외부 노출 없음(2026-07-21 사용자 확인 사항).

## 비범위 — 이 화면이 하지 않는 일

- **공급처 등록 자체** — 공급처 화면(req-suppliers.md) 소관.
- **파서 프리셋(`supplier_presets`) 생성·수정** — 실측: 코드 어디에도 이 경로가
  없다(위 ⑦ 참조).
- **모델명↔상품코드 매칭 확정** — 유사도 후보까지만 제시하고, 확정은 검수 소관이다.
- **정본 카탈로그 적재**(ADM-CSV-010) — 이 화면은 가격·매입 상태만 다루고, 상품
  마스터 전체(이름·분류·사양)는 다루지 않는다. 목적이 달라 별도 화면이다.

## 사장님 결정이 필요한 지점

1. **새 공급처의 파서 프리셋을 누가·어떻게 만드는지.** 수동 DB 개입 없이는 지금
   불가능하다 — 이 화면의 요구사항으로 "프리셋 등록 UI"를 포함할지, 별도
   화면/개발 작업으로 둘지(req-suppliers.md 결정 필요 1과 같은 사안).
2. **"공급처별 최신 파일 1건만 보여준다"는 지금 동작을 그대로 요구사항으로
   받아들일지.** 실사용에서 실제로 하루 여러 번 재업로드가 있었고(실측), 그때마다
   이전 미반영 파일은 조회에서 조용히 사라진다. "최신본만 유효"로 명문화할지,
   "미반영 이력 전체를 보여야 한다"로 바꿀지 결정이 필요하다.
