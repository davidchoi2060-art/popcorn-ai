## ① 화면 성격

작업 화면이 아니라 **조회·선택 화면**이다. 고객이 대화(`talk.py`)로 용도·예산·
플랫폼을 밝히면, 서버가 사전 계산한 격자(상품 매트릭스)에서 해당하는 칸을 찾아
카드로 보여준다. 고객은 카드를 눌러 상세를 보고 장바구니로 넘어간다.

## ② 제목·화면 ID

- CUS-QUO-010 (기존 슬라이스 그대로, 확장)
- 경로: `/mvp2/`(랜딩 → 견적 시작 버튼과 연결됨, A-128 ③)
- API: `POST /api/grid/recommend`(카드 조회), `GET /api/grid/workstations`(AI 워크스테이션 별도 진열)

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

이 화면이 없으면 고객은 "내 용도·예산에 맞는 실제 구성이 얼마인지" 라이브 견적
엔진을 매번 새로 돌려야 한다(수 초 소요, `consult_sessions` 원장에 매 조회가
쌓임). 격자는 **사전 계산된 후보 카드**를 즉시 보여주는 자리다 — "모든 견적에는
이유가 있습니다"라는 정체성을 대화 한 번으로 확인시키는 첫 접점.

이번 재설계가 없으면: ① 가격 구간을 먼저 정해두고 그 안에 부품을 욱여넣는
방식이 계속돼 "사무용 65만원에 쓸모없는 GPU가 낀다"는 왜곡이 재발한다
(2026-09-15 사장님 지적, iGPU 슬롯 생략으로 근본 해소했으나 격자 자체도 같은
사고방식을 벗어나야 함). ② 게임 용도를 하나로 뭉뚱그려 "롤"과 "사이버펑크
2077"이 같은 격자 칸에 들어가는 문제가 계속된다.

## ④ 데이터 — 실측 근거

**신규 스키마(0091, 이번 물결에서 마이그레이션·검증 완료)**:

- `spec_tiers`(T0~T5): 스펙 하한 6단계, 팝콘3~X 브랜드명과 1:1 매핑.
  `gpu_vram_min_gb`·`gpu_watt_min`·`cpu_cores_min`·`ram_min_gb`·`ssd_min_gb`.
  T0는 GPU 하한 없음(iGPU 슬롯 생략, `b4180fd`로 엔진 구현 완료).
- `game_load_grades`(E/A/B/C/S/**L**): 게임 부하 등급 6종.
  L은 2026-09-15 신설(경량 캐주얼 — MMORPG·2D 액션·샌드박스 등 5등급 정의
  밖 장르를 묶음).
- `game_grade_resolution_tiers`: 등급×해상도(1080p/1440p/4K) → `spec_tiers.tier_key`.
  S등급만 GPU/CPU 비대칭(`cpu_tier_key_override`).
- `game_grade_assignments`: `games` 23종 중 **22종 확정**(game_id=17 GTA만
  미배정 — 재고값 없음 + 버전 특정 불가, `grade IS NULL`로 정직하게 남김).
  근거는 2회 독립 웹조사(`game-grades-2026-09-15.md` 1차 10종·
  `game-grades-round2-2026-09-15.md` 2차 6종 추가 확정, 총 16종 E/A/B/C/S +
  6종 L).

**기존 스키마(0090, 이번 물결에서 반영 완료)**:

- `usage_floors`: 9개 usage_key(office·trading·game·game_casual·gaming_high·
  design·video·video_3d·ai) — orphan 4종(dev·stream·media·web) 폐기, xlsx
  8군 실측 반영.
- `usage_tier_rules`·`usage_alloc`: 기존 유지, dev 관련 2행만 비활성화.

**격자 저장소(재설계 대상, 이번 물결 미착수)**:

- `grid_cells`(현재 112행, 7티어×8용도×2플랫폼): **스펙 하한 축으로 재정의
  필요** — 지금은 `budget_min`/`budget_max`가 "입력 상한"이지만, 재설계 후는
  "배치가 찾은 결과 가격의 관측값"으로 역할이 바뀐다(사장님 확정, 2026-09-15
  "억지로 금액에 맞추다 보니까 이상해진다").
- `grid_quotes`(is_current 원장): 카드 하나당 현재 **1개 구성**만 저장. 재설계
  후는 **3종(가성비·추천·고성능) 전부 저장**(사장님 확정 — "다 저장해두고
  고객이 탭으로 골라본다").

## ⑤ 기능 — 할 수 있는 일 (동사로)

1. **용도를 고른다** — 대화 또는 버튼으로 9개 용도 중 하나(게임은 세부적으로
   E/A/B/C/S/L 6등급 중 하나로 더 좁혀질 수 있음. 예: "롤 하려고요" → game_casual).
2. **예산을 밝히거나 생략한다** — 밝히면 그 근처 스펙 티어(T0~T5)로, 생략하면
   서버가 기본 티어(현재 T1=팝콘5 상당)를 중심으로 잡는다.
3. **카드를 본다** — 격자가 찾은 후보 최대 3장(인접 티어 포함). 각 카드는
   가성비/추천/고성능 **3종 탭**을 가진다(재설계 후).
4. **카드 안에서 구성을 바꿔본다** — 탭 전환으로 같은 칸의 가성비↔추천↔고성능
   구성을 즉시 비교(추가 API 호출 없음, 서버가 3종 다 이미 보냄).
5. **부품 상세를 펼친다** — 근거 문구(`reasons`) 전부 + 부품 8종 전부(생략된
   슬롯 포함, 예: "iGPU 확정이라 그래픽카드 생략" 사유 노출).
6. **예산 초과를 인지한다** — 카드가 예산을 넘으면 빼지 않고 "예산 초과"
   배지로 표시(기존 방침 유지).
7. **AI 워크스테이션을 별도로 본다** — 용도가 AI일 때만 격자와 별개로 진열.

## ⑥ 인터랙션 — 입력·선택·저장·이동의 흐름과 결과

- **입력**: 채팅창에 자유 문장(용도·예산 등) 또는 용도 버튼 클릭.
- **파싱**: `talk.py`가 문장을 `constraints`(용도·예산·플랫폼)로 변환 — 게임
  세부 등급(E/A/B/C/S/L)은 `usage_floors.match_terms`가 이미 이 갈래를 인식.
- **조회**: `constraints` → `/api/grid/recommend` → 중심 티어(스펙 기준) ± 2단계
  = 최대 3장.
- **선택**: 카드 클릭 → 상세(부품 8종·근거) → "장바구니" 또는 "이 구성으로
  진행" → 다음 단계(결제·상담).
- **탭 전환**(신규): 같은 카드 안에서 가성비/추천/고성능 버튼 클릭 → 화면
  안에서 즉시 다른 구성으로 바뀜(재조회 없음, 서버가 3종 다 준 payload 안에서
  전환).
- **되돌아가기**: 용도를 다시 물으면(예: "역시 사무용으로 바꿔줘") 이전
  예산·플랫폼은 유지한 채 용도만 갱신 — 부적합하면(스펙 하한이 안 맞으면)
  그 사실을 이유로 밝힌다(억지로 끼워 맞추지 않는다, §화면 정직성).

## ⑦ 상태·예외

- **빈 상태**: 격자에 해당 칸이 없으면(`intended_empty` 또는 아직 배치 안 됨)
  카드 0장 + 사유 문구("이 용도·가격대는 준비 중입니다" 등, `empty_cells[]`).
- **미로그인**: 이 화면은 게이트 밖이다(읽기 전용, 인증 불필요) — 게스트도
  카드를 본다.
- **서버 실패**: `POST /api/grid/recommend`가 500이면 폴백 UI 없이 읽을 수
  있는 한 줄 오류 + 재시도(기존 A-128 원칙 유지, 지어낸 카드를 보여주지 않는다).
- **경계값**: 예산이 티어 경계에 딱 걸치면(예: 150만원) 그 값이 포함되는
  티어로 판정(`tier_index_for`의 반열림 구간, 기존 로직 유지).
- **GTA 미배정**: 고객이 "GTA 하려고요"라고 말하면 게임 등급 매칭이 안 되므로
  일반 게임(game) 갈래로 흡수되거나 "등급 확인이 필요합니다" 안내가 필요함
  (엔진 연결 설계 시 결정 필요 — 이 정의서는 사실만 기록, 결정은 다음 단계).
- **L등급 게임**: 고사양을 요구하지 않는다는 사실을 근거 문구에 명시해야
  한다("이 게임은 고사양 그래픽카드가 필요하지 않습니다" 류) — 고객이 "왜
  이렇게 저렴한 구성이 나왔지"라고 의아해하지 않도록.
