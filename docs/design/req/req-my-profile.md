# 요구사항 정의서 — 내 정보 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **대상은 admin2 신규 구축이다.** 구 `mockups/admin/my-profile.html`을 옮기는 것이
> 아니라 새로 짓는다. 구화면은 백업용 동결이다(P-09 — 수정·사용자 안내·화면 간 링크 금지).
>
> 작성일 **2026-08-17**. ④의 사실은 그 시각의 **코드·DB·기동 중인 로컬 API 실측**이다
> (`api/admin_profile.py` · `api/auth.py` · `api/main.py` · `api/timeutil.py` ·
> `templates/admin/_admin2_shell.html.j2` · `mockups/admin/my-profile.html` ·
> `deploy/popcorn-api.service` · `tests/regression.py` 직접 대조 · DB 집계 조회 ·
> `GET http://127.0.0.1:8000` 읽기 전용 호출 2본). **DB에 쓰지 않았다.**
>
> **수에는 잰 시각을 병기한다** — 이 저장소는 문서에 고정한 수가 여러 번 어긋났다
> (`CLAUDE.md` §데이터). 화면은 이 문서의 수를 옮겨 적지 않고 **서버 응답만** 쓴다.

## ① 화면 성격

**본인 계정 작업 화면.** 운영자가 자기 계정을 조회하고, 본인이 고칠 수 있는 범위만
수정하며, 자기 세션·기기·비밀번호를 스스로 정리하는 자리다.

**남의 계정을 다루지 않는다.** 남의 계정 관리는 「운영자·권한」(ADM-SYS-020,
`/admin2/operators`) 소관이다. 경계는 §⑦ ㉳에 적는다.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

**세 곳이 이 화면 하나 때문에 막혀 있다.** 셋 다 실측된 현재 상태다.

**㉠ 임시 비밀번호로 들어온 운영자를 보낼 곳이 없다.**
`POST /api/admin/auth/operators/{id}/password`(owner의 임시 비밀번호 발급)는
`must_change_password=true`를 함께 심는다(`api/auth.py` `issue_password()`). 그 사람이
로그인하면 응답에 `must_change_password:true`가 실려 온다. 그런데 오늘 지어진 로그인
화면(ADM-SYS-021)은 **그 사실을 문구로만 알리고 대시보드로 보낸다** — 코드 주석 원문:
「세션은 이미 발급됐고 「내 정보」(ADM-SYS-022)는 admin2 에 아직 없어서 여기 머물게 하면
막다른 길이 된다(구화면으로 보내는 것은 P-09 금지)」(`templates/admin/login.html.j2:360-366`).
**비밀번호를 바꿀 화면이 admin2에 없어서 안내에 링크를 달지 못한 것이다.**

**㉡ 구 관리자 화면을 닫지 못한다.**
`api/main.py:227` `_ADMIN_AUTH_DOOR_SCREENS = {"my-profile", "operators"}` — 구
`/admin/*.html`은 전부 410으로 차단됐는데 이 둘만 예외로 살아 있다. 예외 기준은
「이 화면이 없으면 사람이 이 시스템에 (재)진입할 방법이 원천적으로 없어지는가」이고,
`login`은 `/admin2/login`이 서면서 2026-08-17에 예외에서 빠졌다. **`my-profile`은
admin2 대체 화면이 없어 남아 있다.** `operators`는 `/admin2/operators`가 이미 있다.

**㉢ API는 다 있는데 화면이 없다.**
`api/admin_profile.py`가 엔드포인트 6본, `api/auth.py`가 본인 비밀번호 관련 2본을 이미
제공한다(§④). **이 여덟 중 넷은 admin2 어디에서도 호출되지 않는다** — 뒷단만 서 있고
앞단이 없다. 기기 기억(2026-08-15 신설)은 **구화면에도 UI가 없다**(실측:
`mockups/admin/my-profile.html`에 "devices" 0건).

**등급 근거**(`api/auth.py` `required_role()` L378-390): `/api/admin/my-profile`로 시작하는
경로는 **쓰기까지 viewer**로 연다. 코드 주석 원문 — 「조회 등급 직원도 자기 이름·연락처는
고칠 수 있어야 한다. 권한 상승은 등급이 아니라 `admin_profile.EDITABLE` 화이트리스트가
막는다」. 이 검사는 `/api/admin/operators`(owner 전용) **앞에** 있어 접두어로 걸리지 않는다.
**즉 이 화면은 owner 전용이 아니다 — 세 등급 전부가 쓴다.**

### 본인이 고칠 수 있는 필드 — 셋뿐

`api/admin_profile.py` `EDITABLE = ("name", "phone", "duty")`. 서버가 응답의 `editable`
배열로 그 목록을 함께 내려준다(화면이 스스로 정하지 않는다).

| 필드 | 상한 | 못 고치는 것 | 이유(코드 주석 원문 취지) |
|---|---|---|---|
| `name` | 100자 · 필수 | `role` · `status` | 자기 권한 상승·정지 해제를 막는다. 승인 게이트의 의미가 사라진다 |
| `phone` | 30자 · 선택 | `email` | **로그인 신원 그 자체다.** 본인이 바꾸면 계정이 통째로 다른 사람에게 옮겨간다. 정정은 owner 경로(`/operators/{id}/email`)로만 한다 |
| `duty` | 100자 · 선택 | | |

**모르는 필드는 무시하지 않고 거절한다** — `ProfileBody`가 `extra="forbid"`라
`{"name":"x","role":"owner"}`는 422다. 회귀 [21]이 이것을 검사한다(권한·이메일 각각).

| 규칙 | 값 | 상수명 |
|---|---|---|
| 절대 만료 | 8시간 | `ABSOLUTE_HOURS` |
| 유휴 만료 | 480분 | `IDLE_MINUTES` |
| 로그인 실패 제한 | 5회(계정 단위) | `MAX_FAILS` |

있다 — **화면이 규칙을 틀리게 말했다**(슬라이스 100).

### 시각 — 9시간 어긋남의 자리

| 사실 | 값 |
|---|---|
| 세 테이블의 시각 컬럼 | 전부 `timestamp without time zone`(naive) |
| DB `TimeZone` | UTC. 저장값은 **UTC 벽시계값**이다(2026-08-17 실측: `now()` 13:05 UTC ↔ 1.5분 전 생성 행 `created_at` 13:03) |
| 서버 응답 | `api/timeutil.py` `iso()`가 naive를 **UTC로 간주해 `+00:00`을 붙인다** |
| 표시 | **화면이 한다.** 서버는 절대시각만 준다 |

**사고 원문**(슬라이스 62 · 100): 타임존이 없는 ISO 문자열을 브라우저가 로컬 시각으로
해석해 **UTC 04:57이 서울 04:57로 찍혔다 — 실제는 13:57이다.** 구화면은 그 뒤
`mockups/shared/fmt-time.js`의 `PT.full()`로 포맷한다.

**요구사항**: 이 화면이 보여주는 모든 시각(가입 · 승인 · 마지막 로그인 · 비밀번호 설정 ·
세션 생성/최근 사용/만료 · 기기 생성/최근 사용/만료)은 **서울 시각으로 표시한다.
ISO 원문을 그대로 내보내지 않는다.** 회귀 [27]이 이 규약을 검사한다.

### 빈 값의 이유 — 서버가 문장으로 준다

`api/admin_profile.py` `identity_reasons()`가 **이 판정의 단일 원천**이다. 화면이 빈 값을
보고 이유를 추측하면 그것이 지어낸 근거가 된다.

| 응답 필드 | 내용 |
|---|---|
| `provider_label` | 「개발용 임시 인증」 · 「Google(신고된 값)」 · 「기록 없음」 · 「{값}(신고된 값)」 |
| `provider_verified` | **현재 어떤 값에서도 `false`다** — 검증하는 경로가 없다 |
| `provider_note` | 왜 검증되지 않았는지 한 문장 |
| `approved_note` / `approved_none_reason` | 둘 중 **하나만** 채워진다(회귀가 그 배타를 지킨다) |
| `approved_short` | 표 칸에 넣을 짧은 라벨(「부트스트랩(자동)」 · 「계정 삭제됨」 · 「승인 안 됨」) |

**셋이 서로 다른 사실인데 `—` 하나로 덮으면 같아 보인다**(코드 주석 원문): 시드가 만든
계정 · 부트스트랩 자동 승인 · 승인 대기. 실제로 이 DB에 셋이 다 있다.

### 관리자 신원은 아직 dev 어댑터다 — 화면이 숨기지 않는다

| 사실 | 근거 |
|---|---|
| `provider`는 요청 본문 값을 **그대로 저장**한다. 검증이 없다 | `api/auth.py` `login()`의 신청 INSERT — `"p": body.provider` |
| 그래서 `'google'`이라 적힌 계정도 **구글이 확인한 것이 아니다** | `PROVIDER_KO["google"]` = 「Google(신고된 값)」 · `verified=False` |
| 현재 분포에 `google` 1건이 실제로 있다 | 2026-08-17 실측 |
| 회귀가 「검증하지 않은 제공자를 검증됐다고 말하지 않는다」를 고정한다 | `tests/regression.py` |

⚠ **`_verify_google()`은 존재하지 않는다.** 2026-08-17 전수 검색 결과 이 이름은
`api/auth.py:10`의 **docstring 한 줄에만** 있고 **정의(`def _verify_google`)는 저장소
어디에도 없다.** `CLAUDE.md`와 `deploy/README.md`가 「붙일 자리는
`api/admin_profile.PROVIDER_KO` + `_verify_google()`」이라 적지만, 실제로 존재하는 것은
`PROVIDER_KO`뿐이다. **실 OAuth는 「채우면 되는 빈 함수」가 아니라 신설 대상이다.**

**요구사항**: 이 화면은 「로그인 방식」을 **서버가 준 `provider_label`로** 표시하고,
`provider_verified=false`이면 **검증되지 않았다는 사실을 함께 표시한다.** 구화면은 이것을
붉은 힌트로 밝혔다(`provider_note`를 그대로 노출). 표시 형태는 설계 소관이다.

### 비밀번호 미설정 계정이 비밀번호를 받는 경로

**현재 6건이다**(2026-08-17). 이 사람들은 `POST /login`에서 **403 `password_not_set`**으로
막힌다 — 「비밀번호가 아직 설정되지 않았습니다 — 관리자에게 발급을 요청하세요」.

| 단계 | 경로 | 화면 |
|---|---|---|
| 발급 | `POST /api/admin/auth/operators/{id}/password` — owner 전용 + **비밀번호 재확인(reauth) 필수**(`_require_owner_reauth`) | 「운영자·권한」(ADM-SYS-020) |
| 수령 | owner가 전달(경로는 시스템 밖이다 — **응답에 비밀번호를 돌려주지 않는다**) | 없음 |
| 최초 로그인 | `must_change_password=true`로 로그인 | 로그인(ADM-SYS-021) |
| 변경 | `POST /api/admin/auth/password` | **이 화면** |

⚠ **자기 스스로 푸는 「비밀번호 찾기」는 없다**(`api/auth.py` 전수 — 재설정 메일·토큰
경로 0건). **잊으면 owner 재발급이 유일한 복구 경로다.** 이 화면은 발급 수단을 갖지
않는다 — 그 사실을 안내할 수 있을 뿐이다.

### 되돌림 · 원장 — 이 화면의 쓰기가 무엇을 남기는가

| 동작 | 남는 것 | 지워지는 것 | 되돌리기 |
|---|---|---|---|
| 정보 수정(`PATCH`) | `admin_operator_activity_logs`에 `operator_self_update` + **바뀐 필드의 before/after 원문** | 없음 | 화면의 `[되돌리기]`는 **서버 값 재적용**일 뿐 원장 되돌림이 아니다. 바뀐 게 없으면 **원장에 남기지 않는다**(「고쳤다」는 기록이 거짓이 되므로) |
| 다른 기기 로그아웃 | `admin_sessions.revoked_at` 기록 + 활동 로그 `session_revoke_others`(`{"revoked": n}`) | 세션 행은 **삭제하지 않는다** | **없다.** 끊은 세션을 되살리는 것은 위험하다 — 대신 누르기 전에 몇 개가 끊기는지 말한다 |
| 기기 철회 | `admin_operator_devices.revoked_at` + 활동 로그 `device_forget` | 행은 삭제하지 않는다 | **없다.** 그 기기는 다음 로그인부터 비밀번호를 다시 묻는다 |
| 비밀번호 변경 | `password_set_at` 갱신 · `must_change_password=false` · 실패 횟수·잠금 해제 | **다른 세션 전부 철회 + 기기 기억 전부 철회** | **없다.** 원문은 어디에도 저장하지 않는다 |

**규약**: 되돌림은 삭제가 아니라 역방향 전이이고(CANON §2-4), 이 화면의 세 철회는 전부
`revoked_at` 기록이다 — 「언제 어디서 열려 있었나」를 잃지 않는다.

**세션 철회와 기기 철회는 서로 다른 일이다.** 기기를 잊어도 **지금 열려 있는 세션은
끊기지 않는다**(코드 주석 원문). 화면이 이 둘을 같은 것으로 보이게 하면 안 된다.

### 저장 위치 판정 — **㉯ DB에 담는다**

**세 후보를 실측 근거로 비교했다.**

| 후보 | 실측 사실 | 판정 |
|---|---|---|
| **㉮ 서버 파일시스템(리포 밖)** | 전례가 있다 — `api/admin_catalog_import.py:40` `STAGE_DIR = os.environ.get("POPCORN_UPLOAD_DIR") or tempfile.gettempdir()/popcorn-uploads`. 다만 그것은 **1시간 TTL로 지우는 임시 스테이징**이다(`STAGE_TTL`·`_sweep()`). ⚠ 배포 서버는 `deploy/popcorn-api.service`가 **`ProtectSystem=strict` + `ReadWritePaths=/srv/popcorn-ai/.cache` 한 곳** + `PrivateTmp=true`다 — **새 경로를 쓰려면 systemd 유닛을 고쳐야 하고, `/tmp`는 서비스 재시작마다 비워진다.** ⚠ 백업은 **DB만이다**(`deploy/RESTORE.md` 전문에 파일·디스크·업로드 언급 0건 · `deploy/README.md` §백업 3항 전부 DB) — 사진만 백업 대상 밖에 남는다 | **채택하지 않음** |
| **㉯ DB에 담는다** | 백업이 **자동으로 따라온다**(자동 백업 7건 + PITR 7일). systemd·nginx·정적 마운트를 **하나도 고치지 않는다**. 배포의 `git pull --ff-only`(강제 리셋 없음)와 무관하다 | **채택** |
| **㉰ 외부 저장소** | ⚠ **A-30을 근거로 반대하는 것은 과장이다** — A-30 원문은 「폰트·아이콘은 자체 호스팅 — 외부 CDN 0건」으로 **범위가 폰트·아이콘에 한정**된다. 「외부 네트워크 의존 0건」이라는 더 넓은 결정은 `decision-log`에 **없다**(전수 검색). 반대 근거는 다른 것이다: **전례가 0건**이고, 자격증명이 하나 늘며(`.env`만 허용 · CANON §2-5), 백업·복구 절차(`RESTORE.md`)에 대상이 하나 더 생긴다 | **채택하지 않음** |

**채택 근거 — 크기가 결정적이다.**
표시 크기 실측: 공용 셸 아바타 **26px**(`admin2.css:137`) · 「운영자·권한」 목록 28px ·
상세 34px · 구 「내 정보」 64px. 운영자는 **18명**(2026-08-17). 사진 한 장을 1MB로 잡아도
**전체 18MB 규모**이고, 이는 상품 22,000행대를 담고 있는 DB에서 무시할 수 있다.
「이미지가 DB 용량을 늘린다」는 일반론은 맞지만 **이 규모에서는 성립하지 않는다.**

**설계 제약 두 가지를 함께 정한다.**

1. **`admin_operators`에 바이너리 컬럼을 두지 않는다. 1:1 별도 표를 신설한다.**
   근거: `api/auth.py` `resolve_session()`은 **모든 `/api/admin/*`·`/admin2/*` 요청**이
   지나는 자리이고 매번 `admin_operators`를 조인한다. 같은 표에 이미지 바이트를 두면
   언젠가 `SELECT *` 한 줄이 인증 경로에서 그 바이트까지 함께 읽는다.
   → 제안: `admin_operator_photos`(`operator_id` PK/FK · `content_type` · `bytes` ·
   `byte_size` · `uploaded_at` · `uploaded_by`). **표 이름·컬럼은 확정이 아니다**
   (마이그레이션 + ERD 개정은 이 문서 권한 밖 — §사장님 결정 1).
2. **사진은 API로 내보낸다. 정적 마운트에 두지 않는다.**
   근거: 정적 마운트는 둘뿐이다 — `/design-system`(`api/main.py:131`)과 캐치올
   `/` → `mockups/`(`:264`). **`mockups/`는 커밋된 저장소 폴더다** — 거기에 업로드
   파일을 쓰면 커밋되지 않은 파일이 배포 서버에 생기고, 그 폴더는 `ProtectSystem=strict`
   아래에서 쓰기가 막힌 곳이다. nginx도 정적 서빙을 하지 않는다(전부 `proxy_pass`).
   → 신설 필요: `GET /api/admin/my-profile/photo`(본인) ·
   `GET /api/admin/operators/{id}/photo`(타인 표시용, §「누가 볼 수 있는가」 참조).

### 형식 · 크기 — 근거와 함께

| 항목 | 제안 | 근거 |
|---|---|---|
| 허용 형식 | **JPEG · PNG · WebP** | 표시 크기가 26~64px이라 이 셋으로 충분하다 |
| **SVG 금지** | 명시적으로 거절한다 | SVG는 스크립트를 품을 수 있다. 같은 출처에서 서빙되면 그 스크립트가 관리자 세션 문맥에서 돈다 |
| 최대 크기 | **1MB 제안** | ⚠ **기존 상수에서 도출한 값이 아니다.** 저장소의 업로드 상한은 `MAX_BYTES = 64MB`(`api/admin_catalog_import.py:38`) 하나뿐이고 그것은 **28MB짜리 카탈로그 CSV**를 위한 값이라 근거가 되지 않는다. 표시 크기(최대 64px, 고해상도 2배 기준 128px)에서 역산한 값이다 — **확정은 §사장님 결정 2** |
| 검사 방식 | 확장자·클라이언트가 보낸 MIME을 믿지 않고 **바이트 앞머리(매직 넘버)로 판정** | 클라이언트가 보낸 `provider`를 그대로 믿어 지금 신원 검증이 없는 것과 같은 부류의 실수를 반복하지 않는다 |
| 서버 재인코딩 | **지금은 못 한다** | 실측: 저장소에 이미지 라이브러리가 **없다**(`requirements.txt` 전수 · `.venv`에 `PIL` 미설치). 재인코딩(EXIF 제거·크기 정규화)을 하려면 **의존성 신설**이 필요하다 — §사장님 결정 3. `python-multipart`는 이미 있어 업로드 수신 자체는 새 의존성이 필요 없다 |

### 사진이 없을 때 — 이니셜 원형이 이미 관례다

| 화면 | 현재 표시 | 근거 |
|---|---|---|
| 구 「내 정보」 | 이름 첫 글자 원형 64px | `mockups/admin/my-profile.html:271-274, 321-323` |
| 「운영자·권한」 목록 · 상세 | 이름 첫 글자 원형 28 / 34px | `templates/admin/operators_roles.html.j2:181, 541, 694` |
| **admin2 공용 셸 상단바** | **빈 회색 원 26px** — 이니셜조차 없다 | `_admin2_shell.html.j2:90` `<span class="a2-avatar"></span>` · `admin2.css:137`. `admin2-shell.js`는 `roleBox`만 채우고 이 원은 건드리지 않는다 |

**요구사항**: 사진이 없으면 **이름 첫 글자**를 표시한다(이름도 없으면 `?`). 이것은
「사진이 없다」와 「불러오지 못했다」를 구분하는 장치다 — 둘을 같은 빈 원으로 표시하지 않는다.

### 어디에 보이는가 — 상단바가 그 자리다

**공용 셸을 상속하는 admin2 화면은 39개다**(2026-08-17 실측). 그 39개 전부의 상단바
우측에 `a2-avatar`가 있다. **사진이 생기면 이 39개가 전부 그 값을 읽어야 한다.**

⚠ **셸은 이미 화면당 한 번 `GET /api/admin/auth/me`를 부른다**(`admin2-shell.js:92` —
「권한 표시를 화면마다 다시 부르지 않는다」). 그런데 **그 응답에는 사진이 없다**
(실측 응답: `authenticated` · `operator`(= `operator_id` · `name` · `email` · `role` ·
`status` · `password_verified`) · `note`).
→ **상단바에 사진을 띄우려면 `/auth/me` 응답에 사진 참조를 싣거나, 셸이 호출을 하나
더 하거나 둘 중 하나다.** 어느 쪽이든 **정본 파일(공용 셸)을 고치는 일이라 이 화면의
범위 밖이다** — §사장님 결정 4.

### 교체 · 삭제 — 사진은 원장이 아니다

**판정: 사진에는 원장 규약을 적용하지 않는다. 삭제하면 실제로 지운다.**

**근거.** 원장·되돌림 규약(CANON §2-2·2-4)이 지키는 것은 **「사실의 이력」**이다 — 재고가
어떻게 움직였는지, 세션이 언제 어디서 열려 있었는지, 누가 승인했는지. 그것을 지우면
과거를 되짚을 수 없다. **프로필 사진은 그런 사실이 아니라 본인의 개인 자료다.** 지운
사진을 시스템이 계속 보관하는 것은 개인정보를 필요 이상으로 보관하는 것이고, 그것이
바로 `docs/06_db-erd.md` §3.9가 「우리가 갖지 않은 정보는 유출될 수 없다」로 적어 둔
설계 원칙에 어긋난다.

**다만 행위는 남긴다.** 「누가 언제 사진을 등록·교체·삭제했다」는 `admin_operator_activity_logs`에
기록한다. **비밀번호와 같은 결이다** — 원문은 저장하지 않되 `password_set_at`과 활동
로그는 남는다. 즉 **자료는 지우고 사실은 남긴다.**

**교체**는 같은 `operator_id` 한 행을 덮어쓴다(과거 사진을 쌓지 않는다). 같은 이유다.

### 누가 바꿀 수 있는가 · 누가 볼 수 있는가

| 항목 | 제안 | 근거 |
|---|---|---|
| **본인 사진 등록·교체·삭제** | **✅ 확정(2026-08-17, decision-log A-65) — 이 화면. 등급은 `viewer` 이상**(= `/my-profile` 경로 규칙 그대로), **본인 계정 한정** | `EDITABLE` 화이트리스트가 커지는 것과 같은 성격이다. 사진은 `role`·`status`·`email`과 달리 **권한·신원에 영향을 주지 않는다** |
| **owner가 남의 사진을 바꾸는가**(등록·교체·삭제) | **✅ 확정(2026-08-17, decision-log A-65) — 안 만든다.** 사장님 원문 「안중요함. 이상한 사진 올리는 거 없음」 — owner의 삭제 대행·등록 대행 경로는 **이번 물결에 넣지 않는다** | 「운영자·권한」(ADM-SYS-020)과의 경계 문제였다. 참고: owner는 이미 남의 **이메일 정정**과 **임시 비밀번호 발급**을 할 수 있지만, 사진은 개인 자료라 **같은 경로를 열지 않기로 확정됐다** |
| **운영자끼리 서로 보이는가** | **✅ 확정(2026-08-17, decision-log A-65) — 전 운영자가 서로 본다.** 원안의 「owner 전용이라 사실상 owner만 본다」 가정은 사장님이 그대로 승인하지 않고 넘어섰다 | 사장님 원문 「전 운영자 열람」. 「운영자·권한」(ADM-SYS-020)이 owner 전용인 것과 **무관하게**, 이 화면(또는 그 파생 API)은 등급 무관 열람을 허용해야 한다 |
| **고객 화면 노출** | **없다.** 이 값이 `/api/my/*`·`/mvp1/*` 어디에도 나가지 않는다 | 관리자 신원은 고객에게 내보내지 않는다. 인계 원장(`handoffs`)도 운영자 사진을 담지 않는다 |
| **개인정보** | 사진은 개인정보다. **네 항목 전부 확정됐다**(2026-08-17) | |

## ⑤ 기능 — 동사

- 본인 계정 정보를 조회한다.
- 이름 · 연락처 · 직무를 수정한다.
- 수정 전 값으로 되돌린다(저장 전).
- 본인 비밀번호를 변경한다.
- 비밀번호 강도 규칙을 **거절당하기 전에** 조회한다.
- 열려 있는 세션 목록을 조회한다.
- 현재 기기를 남기고 다른 기기의 세션을 일괄 철회한다.
- 비밀번호 없이 로그인할 수 있도록 기억된 기기 목록을 조회한다.
- 기억된 기기를 **하나씩** 철회한다.
- 프로필 사진을 등록 · 교체 · 삭제한다(**전부 신설** — §④-2).
- 본인이 고칠 수 없는 항목과 그 이유를 조회한다.
- 로그인 방식이 검증되지 않았다는 사실을 조회한다.
- 본인이 남긴 작업 기록 건수를 조회한다.

## ⑥ 인터랙션 — 입력 · 선택 · 저장 · 이동의 흐름과 결과

**정보 수정**
- 이름 · 연락처 · 직무를 입력하고 저장한다 → `PATCH` → 성공하면 **서버가 준 `note`를
  그대로** 표시하고 화면을 응답 값으로 다시 그린다. 화면이 문구를 지어내지 않는다.
- 바뀐 값이 없으면 서버가 「바뀐 값이 없습니다」를 주고 **원장에 남기지 않는다.**
- **이름을 바꾸면 지난 작업 기록의 표시 이름도 함께 바뀐다**(로그는 `operator_id`를
  참조하고 이름은 조인으로 나온다). 서버가 `note`에 그 사실을 함께 준다 —
  **화면은 그 문구를 잘라내지 않는다.** 잘라내면 「예전 기록이 왜 바뀌었나」를 묻게 된다.
- `[되돌리기]`는 **서버 값 재적용**이다(저장 전 입력 취소). 원장 되돌림이 아니다.

**비밀번호 변경**
- 규칙을 **먼저** 조회해 표시한다(`GET /auth/password-policy`). 화면이 규칙을 베끼지 않는다.
- 현재 비밀번호 · 새 비밀번호 · 새 비밀번호 확인, **셋을 받는다.** 구화면이 두 번째를
  한 번만 받아 오타를 잡을 수 없었다.
- **입력이 화면에 보이지 않아야 한다.** 구화면은 브라우저 `prompt()`를 두 번 써서
  **비밀번호가 화면에 그대로 보였다**(어깨너머 노출). 회귀 [17]이 `prompt(` 미사용과
  `type="password"` 3칸 이상을 검사한다.
- 성공하면 **다른 기기의 세션과 기기 기억이 전부 철회된다** — 서버가 `note`로 그
  사실을 알린다. **누르기 전에도 그 사실을 밝힌다.**

**세션 정리**
- `[다른 기기에서 로그아웃]`을 누르면 **먼저 `GET /my-profile/sessions`로 몇 개가
  끊기는지 조회해 보여주고 확인을 받는다.** 누르고 나서 알면 늦다.
- 끊을 다른 세션이 없으면 그 사실을 알리고 아무 일도 하지 않는다.
- **되돌릴 수 없다는 사실을 확인 단계에서 밝힌다.**
- 현재 기기는 유지된다. 목록은 어느 것이 현재 기기인지 표시한다(`current` 필드).
- **세션 식별자는 화면에 나오지 않는다** — 그 값이 곧 로그인 자격이다. 서버가
  `session_id`를 내보내지 않고 `current` 불리언만 준다.

**기기 정리**
- 기억된 기기를 목록으로 표시하고 **하나씩** 철회한다(사장님 지시 원문 「그 기기
  잊어버려」 — 단수).
- 철회해도 **지금 열려 있는 세션은 끊기지 않는다.** 다음 로그인부터 비밀번호를 다시
  묻는다는 뜻이다 — 화면이 이 차이를 밝힌다.
- `device_id`는 노출해도 안전하다(그것만으로 로그인할 수 없다 — 시크릿은 해시만 저장).

**사진**(신설 — 흐름만 정의한다)
- 파일을 선택하면 **저장 전에** 형식·크기를 검사하고 결과를 밝힌다.
- 등록·교체는 즉시 반영한다. 반영 뒤 **상단바 표시도 함께 갱신되는지**는 §④-2의
  셸 문제에 달려 있다(§사장님 결정 4).
- 삭제하면 이니셜 표시로 돌아간다. **되돌리기는 없다** — 누르기 전에 그 사실을 밝힌다.

| 기억된 기기 0건 | 「등록된 기기가 없습니다」. **현재 DB가 실제로 이 상태다**(살아 있는 기기 0건, 2026-08-17) |

### ㉯ 실패

| 상황 | 응답 | 화면 |
|---|---|---|
| 미로그인 | 401 「로그인이 필요합니다」 | 로그인 화면으로 안내(`/admin2/login`) |
| 세션은 살아 있으나 계정 행이 없음(삭제된 경우) | 404 「계정을 찾을 수 없습니다」 | 사유 그대로 |
| 이름 미입력 | 400 「이름을 입력하세요」 | 사유 그대로 |
| 길이 초과 | 400(이름 100 · 연락처 30 · 직무 100) | 사유 그대로 |
| 못 고치는 필드 동봉 | **422**(`extra="forbid"`) | 「그 필드는 여기서 못 고친다」를 분명히 — **조용히 무시하지 않는다** |
| 현재 비밀번호 불일치 | 401 「현재 비밀번호가 올바르지 않습니다」 | 사유 그대로 |
| 강도 미달 | 400(사유 문장) | 사유 그대로 |
| 이전과 같은 비밀번호 | 400 「이전과 다른 비밀번호를 쓰세요」 | 사유 그대로 |
| 세션 쿠키 없이 철회 요청 | 400 「현재 세션을 확인할 수 없습니다」 | **자기 세션까지 끊기는 것을 서버가 막는다** |
| 기기 없음 · 남의 기기 | 404 「기기를 찾을 수 없습니다」 | 사유 그대로 |
| 서버 연결 실패 | — | 「서버에 연결할 수 없습니다」. **401 세션 만료 · 네트워크 · 서버 오류를 구분한다** |

⚠ **`if(!res.ok) return;` 금지**(CANON §2). 저장을 눌러도 아무 일도 일어나지 않는 화면이
된다. 오류 본문은 `{"detail": {"error":..., "message":...}}` 모양이다 — 이 저장소 전체
관례다(`ui-progress.js` `errText()`).

⚠ **화면 스크립트가 죽는 경우까지 대비한다.** 구화면은 실제로 파싱 오류로 통째로 죽어
「불러오는 중」에서 영원히 멈췄고 **사용자에게는 아무 신호도 없었다**(슬라이스 92).
구화면은 **별도 `<script>` 감시자**를 두어 5초 뒤에도 본 스크립트가 살아나지 않으면
「화면 스크립트가 실행되지 않았습니다」를 표시한다. **같은 보호가 필요하다** — 형태는
설계 소관이다.

### ㉰ 권한 없음

**이 화면에는 「권한 없음」 상태가 없다.** 세 등급 전부가 자기 정보를 조회·수정할 수
있다(§④ 등급 근거). 막히는 것은 등급이 아니라 **필드**다.

⚠ **다만 세션의 신뢰 수준은 다르다.** 기기 기억으로 만든 세션은 `password_verified=false`이고,
`OWNER_WRITE_PREFIXES` 아래 쓰기에서 401 `reauth_required`로 막힌다. **`/my-profile`은 그
접두어 목록에 없으므로 이 화면의 쓰기는 재확인 없이 통과한다.** 본인 비밀번호 변경은
**현재 비밀번호를 요구하는 것으로 자체 방어**된다(코드 주석: 「reauth와 동등하거나 더 강함」).

### ㉳ 경계 — 「운영자·권한」(ADM-SYS-020)과 어디서 갈리는가

**기준: 내 계정을 내가 고치는 것과 남의 계정을 관리하는 것은 다른 화면이다.**

| 이 화면(ADM-SYS-022) | 「운영자·권한」(ADM-SYS-020) |
|---|---|
| 본인 이름 · 연락처 · 직무 수정 | 타인 계정 목록 · 상세 조회 |
| 본인 비밀번호 **변경**(현재 비밀번호 확인) | 타인 임시 비밀번호 **발급**(owner + reauth) |
| 본인 세션 철회(**현재 기기 유지**) | 타인 **정지**(그 계정 세션 전부 즉시 철회) |
| 본인 기기 기억 목록 · 개별 철회 | 계정 승인 · 반려 · 등급 부여 |
| 본인 이메일 **표시만**(수정 불가) | 타인 이메일 **정정**(`/operators/{id}/email`) |
| 등급: viewer 이상 | 등급: **owner 전용**(조회조차) |

**공유하는 판정은 복제하지 않는다.** 「로그인 방식」·「승인」의 빈 값 판정은
`api/admin_profile.identity_reasons()` **하나가 원천**이고 「운영자·권한」도 그것을
가져다 쓴다(슬라이스 102). 새 화면이 같은 판정을 다시 구현하면 한쪽만 고치는 사고가 난다.

**사진의 경계는 아직 안 정해졌다** — §사장님 결정 5.

## 비범위 — 이 화면이 하지 않는 일

- **타인 계정 관리 일체**(승인 · 반려 · 등급 · 정지 · 이메일 정정 · 임시 비밀번호 발급)
  — 「운영자·권한」 소관.
- **비밀번호 찾기 · 재설정 메일** — **저장소에 그런 경로가 없다.** 잊으면 owner
  재발급이 유일한 복구 경로다(§④).
- **실 OAuth 검증 구현** — `_verify_google()`은 **존재하지 않는 함수 이름**이다(§④).
  이 화면은 「지금은 검증되지 않는다」는 사실을 보여줄 뿐이다.
- **기기 기억 등록** — 로그인 화면(ADM-SYS-021)의 체크박스 소관. 이 화면은 목록
  조회와 철회만 한다.
- **작업 기록 열람** — 「작업 기록」(ADM-SYS-030, `/admin2/activity-logs`) 소관.
  이 화면은 **건수**만 표시한다(`acts`).
- **공용 셸 수정** — 상단바 아바타는 정본 파일(`_admin2_shell.html.j2`) 소관이다(§④-2).
