> 가능하도록 패턴으로 만들 수 있으면 좋겠어"* · 선행 결정 **A-93**(예산 범위를 이력으로

> 이 문서는 **요구사항까지만** 적는다(§화면 작업의 경계). 화면 배치·컴포넌트·색은 없다.

## 0. 사장님 확정 둘 — 하네스 판단을 **뒤집은** 결정

경위를 지우지 않고 남긴다. 하네스가 ㉮ 원문 비저장 ㉯ 사람 승인만을 권고했고,
사장님이 **둘 다 뒤집었다**(2026-08-22).

    사장님 확정 ①   고객 문장 «원문»도 저장한다 — 원문 비적재 규약을 뒤집는다
    사장님 확정 ②   자주 나온 질문은 «자동»으로 답변 패턴이 된다

하네스가 냈던 반대 근거는 §0-3 에 그대로 보존한다 — **뒤집혔다고 지우지 않는다**
(나중에 「왜 이렇게 됐나」를 되짚는 재료다). 아래 §0-1·§0-2 는 그 확정을
**안전하게 이행하기 위한 장치**이고, 지시를 좁히는 것이 아니다.

### 0-1 원문 저장 — 함께 두어야 하는 장치 넷

원문을 남기는 것은 **되돌릴 수 없다**(한 번 새면 회수가 없다). 그래서 저장 자체는
확정대로 하되, 넷을 함께 세운다.

    ㉮ 저장 «전» 마스킹    전화번호·이메일·계좌·주민번호 패턴을 치환해 넣는다.
                           지어내는 것이 아니라 «지우는» 것이라 A-02 와 무관하다.
                           마스킹 결과도 원문 컬럼에 그대로 들어간다(별도 사본 없음).
    ㉯ 보관 기간           `raw_text` 는 N일 뒤 NULL 로 지운다(행은 남는다 — 원장 원칙).
                           N 은 사장님 확정 사항(§9 ㉤). 기본 제안 **90일**.
    ㉰ 권한                `raw_text` 를 «읽는» 화면·API 는 owner 전용. 운영자 등급은
                           의도·어휘까지만 본다.
    ㉱ 고객 고지           팝콘톡 화면에 「대화 내용이 서비스 개선에 쓰입니다」를 상시 표시.
                           **말 없이 쌓지 않는다.**

⚠ **선행 조건 하나**: 지금 고객 인증은 dev 어댑터라 **아무나 남의 이메일로 그 사람
세션을 받는다**(`CLAUDE.md` §베타 배포 상태 — "열면서 감수한 구멍"). 원문이 쌓인 뒤
그 구멍이 열려 있으면 **남의 대화를 볼 수 있다.** ㉰(owner 전용)가 그것을 막는 유일한
장치이므로, `raw_text` 는 **고객 경로(`/api/my/*`)에서 절대 반환하지 않는다.**

### 0-2 자동 승격 — 함께 두어야 하는 장치 넷

    ㉮ 회귀 트래픽 제외    `consult_sessions.data_origin='test'` 는 «세지 않는다».
                           안 빼면 회귀가 만든 질문이 답변 패턴이 된다 — 실측상 세션의
                           97.7%가 회귀였다(`regression-pollutes-the-ledger`).
    ㉯ 임계                같은 어휘 묶음이 **서로 다른 방문자** N명에게서 나와야 한다
                           (한 사람이 N번 물은 것은 1로 센다 — 안 그러면 한 명이 패턴을 만든다).
                           N 은 사장님 확정 사항(§9 ㉥). 기본 제안 **5명**.
    ㉰ 승격분은 표시가 다르다  `status='자동'` 으로 들어간다. 사람이 승인한 `사용` 과
                           구분해 관리자 화면이 **어느 것이 자동인지 항상 보여준다.**
    ㉱ 답변은 «수를 말하지 않는다»  자동 승격된 의도의 기본 `answer_kind` 는
                           `constraint_parse` 또는 `band_cards` 다. **`text`(자유 문구)로는
                           자동 승격하지 않는다** — 검증 없는 문장이 고객에게 나가는 유일한
                           경로가 그것이기 때문이다. 문구 답변은 여전히 사람이 쓴다.

⚠ **지금은 아무것도 자동 승격되지 않는다.** 실측(2026-08-22, 최근 3,000세션):
`guided 2,319 · chat 631 · expert 46 · **talk 4**`. 팝콘톡 실사용이 4건이라
임계 5명에 닿는 어휘 묶음이 없다. **장치를 먼저 세우고 트래픽을 기다린다.**

### 0-3 하네스가 냈던 반대 근거 (보존 — 뒤집힌 쪽)

**㉮ 원문 비저장 근거**: ① 재사용에 필요한 것은 의도와 답변 종류이지 문장 자체가 아니다
② 고객 인증이 dev 어댑터라 원문이 곧 유출 경로가 된다 ③ P-08 은 규약을 뒤집으려면
「왜 그 근거가 더는 유효하지 않은지」를 먼저 적으라 하는데, 원문 비적재의 근거는
무효화된 것이 없다.

**㉯ 사람 승인 근거**: ① 자동 승격의 전제인 빈도가 지금 없다(talk 4건) ② 틀린 답은
굳으면 되돌리기 어렵고, A-01·A-02 의 선을 사실상 넘는다 ③ 승인 큐는 `product_reviews`
검수 큐로 이미 있는 모양이다.

**사장님이 뒤집은 것은 「근거가 틀렸다」가 아니라 「그럼에도 그렇게 한다」이다.**
그래서 근거를 지우지 않고, 대신 위 §0-1·§0-2 장치로 그 위험을 줄인다.

## 1. 화면 성격

**작업 화면**(관리자). 쌓인 질문 의도를 보고, 답변 패턴으로 **승인·반려**한다.
고객 화면이 아니다 — 고객 쪽은 이미 있는 팝콘톡이 그대로 쓴다.

## 2. 제목 · 화면 ID

    제목      팝콘톡 응답 패턴
    화면 ID   ADM-TLK-010 (가칭 — 확정은 `admin-identity.md` 카탈로그 소관)
    경로      /admin2/talk-patterns

## 3. 정의 — 이 화면이 없으면 무엇이 안 되나

지금 팝콘톡의 답변 패턴은 **화면 코드에 박힌 20종**이 전부다
(`mockups/mvp1/s1-session.html` 의 `TALKS`). 그래서 셋이 안 된다:

    ① 늘리려면 코드를 고쳐야 한다      운영자가 못 늘린다
    ② 고객이 무엇을 묻는지 모른다       걸린 것도 안 걸린 것도 기록이 없다
    ③ 어느 답이 실제로 쓰였는지 모른다   19종 중 죽은 것이 있어도 알 수 없다

이 화면은 ②를 원장으로 만들고, ①을 데이터로 옮기고, ③을 세어 보여준다.

## 4. 데이터 — 표 둘 신설

**U-51(예산 이력)과 같은 표가 아니다.** 축이 다르다 —
U-51 은 「용도별 예산 «범위»」(A-92 카드가 보여줄 값)이고, 여기는 「질문 «의도»」다.
한 표에 담으면 둘 다 어색해진다. **U-51 은 별도로 남긴다.**

### 4-1 `talk_intents` — 의도와 그 답변 (정본)

지금 `TALKS` 20종을 옮겨 담는 자리다.

| 컬럼 | 형 | 뜻 |
|---|---|---|
| `intent_key` | varchar PK | `monitor_recommend` · `assembly_fee` · `as_warranty` … |
| `label` | varchar | 관리자 화면 표시명 |
| `match_terms` | jsonb | 이 의도로 접는 말 (정본 어휘) |
| `min_hits` | int | 몇 개가 걸려야 이 의도인가 (지금 `TALKS.min` 과 같은 뜻) |
| `answer_kind` | varchar | `text` · `band_cards` · `constraint_parse` · `handoff` |
| `answer_body` | text | `text` 일 때의 문구 |
| `answer_ref` | varchar | `band_cards` 일 때 부를 API (예: `/api/talk/monitor-bands`) |
| `status` | varchar | `대기` · `사용` · `자동` · `미사용` — **`자동`은 승격된 것**(§0-2 ㉰) |
| `approved_by` · `approved_at` | | 누가 언제 승인했나 |

⚠ **`answer_body` 에 부품명·가격·후보 수를 적지 않는다**(A-01·A-02 · §화면 정직성).
수가 필요한 답은 `answer_kind='band_cards'` 로 두고 **서버가 세게 한다** —
모니터 구간(`/api/talk/monitor-bands`)이 그 첫 사례다.

### 4-2 `talk_intent_hits` — 무엇이 걸렸나 (이력 · 원장)

| 컬럼 | 형 | 뜻 |
|---|---|---|
| `hit_id` | PK | |
| `session_id` | FK | `consult_sessions` |
| `intent_key` | FK nullable | **null = 어느 의도에도 안 걸렸다** ← 가장 중요한 행 |
| `matched_terms` | jsonb | 걸린 말 (정본 어휘에 있는 것만) |
| `unmatched_n` | int | 어휘에 없던 말의 수 — 우리 어휘가 부족하다는 신호 |
| **`raw_text`** | **text nullable** | **고객 문장 원문**(사장님 확정 ① · §0-1) |
| `raw_masked_yn` | bool | 마스킹을 거쳤나 — 거치지 않은 값은 저장하지 않는다 |
| `raw_purge_at` | timestamp | 이 시각 이후 `raw_text` 를 NULL 로 지운다(행은 남는다) |
| `visitor_key` | varchar | 자동 승격의 «서로 다른 사람» 판정용(§0-2 ㉯). 방문자 키다 |
| `answer_kind` | varchar | 실제로 무엇으로 답했나 |
| `llm_called` | bool | AI 를 태웠나 (비용 추적) |
| `created_at` | | |

**`intent_key IS NULL` 인 행이 이 표의 존재 이유다** — 「우리가 아직 답을 못 만든 질문」이
거기 쌓인다. 그것이 4-1 에 새 의도를 만들 후보 큐가 된다.

### ⚠ `raw_text` 를 다루는 규칙 (§0-1 의 구현 형태)

    저장 전   마스킹을 «반드시» 거친다. 마스킹 실패면 `raw_text` 를 비우고 나머지만 남긴다
              — 원문을 마스킹 없이 넣는 경로를 두지 않는다.
    읽기      owner 전용. **고객 경로(`/api/my/*`)는 이 컬럼을 어떤 형태로도 반환하지 않는다.**
    지우기    `raw_purge_at` 이 지난 행은 배치가 `raw_text = NULL` 로 만든다.
              **행을 지우지 않는다** — 의도·어휘·집계는 그대로 살아야 한다.
    로그      서버 stdout 에는 여전히 문장을 찍지 않는다(길이만). 규약이 뒤집힌 것은
              «표에 남기는 것»이지 «로그에 찍는 것»이 아니다.

## 5. 기능

    조회      의도 목록 · 걸린 횟수 · 마지막 사용 시각 · 상태
    조회      «안 걸린 질문» 큐 — intent_key IS NULL 행을 어휘 묶음으로 집계
    등록      새 의도 등록 (어휘 · 답변 종류 · 문구)
    수정      어휘·문구 수정
    승인      대기 -> 사용 (이때부터 고객 화면이 그 답을 쓴다)
    반려      대기 -> 미사용 (지우지 않는다 — 원장 원칙)
    조회      죽은 의도 — 등록돼 있으나 걸린 적 없는 것
    조회      자동 승격분 — status='자동' 만 따로. 사람 승인분과 섞어 보여주지 않는다
    되돌림    자동 -> 미사용 (자동으로 올라온 것도 사람이 내릴 수 있다)
    조회      원문 보관 현황 — 남은 건수 · 가장 오래된 것 · 다음 삭제 예정 (owner 전용)

## 6. 인터랙션

    ① 안 걸린 질문 큐에서 어휘 묶음을 고른다
    ② 「의도로 만들기」 -> 등록 폼에 그 어휘가 채워진 채 열린다
    ③ 답변 종류를 고른다 — 문구를 직접 쓰거나(text), 서버가 세는 API 를 고른다(band_cards)
    ④ 저장하면 상태 «대기» — **아직 고객에게 안 나간다**
    ⑤ 승인하면 «사용» — 다음 요청부터 팝콘톡이 그 답을 쓴다
    ⑥ 되돌리기는 상태 전이다(사용 -> 미사용). 행을 지우지 않는다

## 7. 상태 · 예외

    빈 상태        「아직 쌓인 질문이 없습니다」 — **지금이 이 상태다**(talk 세션 4건)
    권한           등록·승인은 owner. 조회는 운영자 이상
    어휘 충돌      두 의도가 같은 말을 물면 등록 시 경고하고 **막지는 않는다**
                   (min_hits 로 갈리는 설계가 실재한다 — 지금 `TALKS` 가 그렇다)
    회귀 트래픽    `consult_sessions.data_origin='test'` 인 세션은 **집계에서 뺀다**
                   (안 빼면 회귀가 만든 질문이 후보 큐를 채운다)
    답변 없는 의도 `status='사용'` 인데 `answer_body`·`answer_ref` 가 둘 다 비면 저장 거부
    마스킹 실패    `raw_text` 를 비우고 나머지만 남긴다 — 마스킹 없는 원문을 넣지 않는다
    자동 승격 대상 `answer_kind='text'` 는 자동 승격하지 않는다(§0-2 ㉱)
    한 사람 반복    같은 `visitor_key` 의 반복은 1 로 센다 — 한 명이 패턴을 만들 수 없다

## 8. 지금 만들면 무엇이 보이나 — 정직하게

**당장은 빈 화면이다.** 팝콘톡 실사용이 4건이라 쌓인 것이 없다.
그래도 지금 세우는 이유는 **쌓기 시작해야 나중에 쓸 수 있기 때문**이고,
`TALKS` 20종을 옮기는 것만으로도 ①(코드를 고쳐야 늘어난다)은 즉시 해소된다.

**「자동으로 자란다」고 말하지 않는다** — 자라려면 트래픽이 먼저 와야 한다.
