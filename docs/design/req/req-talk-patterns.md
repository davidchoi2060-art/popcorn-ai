## 0. 사장님 확정 둘 — 하네스 판단을 **뒤집은** 결정

경위를 지우지 않고 남긴다. 하네스가 ㉮ 원문 비저장 ㉯ 사람 승인만을 권고했고,
사장님이 **둘 다 뒤집었다**(2026-08-22).

    사장님 확정 ①   고객 문장 «원문»도 저장한다 — 원문 비적재 규약을 뒤집는다
    사장님 확정 ②   자주 나온 질문은 «자동»으로 답변 패턴이 된다

하네스가 냈던 반대 근거는 §0-3 에 그대로 보존한다 — **뒤집혔다고 지우지 않는다**
(나중에 「왜 이렇게 됐나」를 되짚는 재료다). 아래 §0-1·§0-2 는 그 확정을
**안전하게 이행하기 위한 장치**이고, 지시를 좁히는 것이 아니다.

### 0-1 원문 저장 — 함께 두어야 하는 장치 넷

원문을 남기는 것은 **되돌릴 수 없다**(한 번 새면 회수가 없다). 그래서 저장 자체는
확정대로 하되, 넷을 함께 세운다.

    ㉮ 저장 «전» 마스킹    전화번호·이메일·계좌·주민번호 패턴을 치환해 넣는다.
                           지어내는 것이 아니라 «지우는» 것이라 A-02 와 무관하다.
                           마스킹 결과도 원문 컬럼에 그대로 들어간다(별도 사본 없음).
    ㉯ 보관 기간           `raw_text` 는 N일 뒤 NULL 로 지운다(행은 남는다 — 원장 원칙).
                           N 은 사장님 확정 사항(§9 ㉤). 기본 제안 **90일**.
    ㉰ 권한                `raw_text` 를 «읽는» 화면·API 는 owner 전용. 운영자 등급은
                           의도·어휘까지만 본다.
    ㉱ 고객 고지           팝콘톡 화면에 「대화 내용이 서비스 개선에 쓰입니다」를 상시 표시.
                           **말 없이 쌓지 않는다.**

⚠ **선행 조건 하나**: 지금 고객 인증은 dev 어댑터라 **아무나 남의 이메일로 그 사람
세션을 받는다**(`CLAUDE.md` §베타 배포 상태 — "열면서 감수한 구멍"). 원문이 쌓인 뒤
그 구멍이 열려 있으면 **남의 대화를 볼 수 있다.** ㉰(owner 전용)가 그것을 막는 유일한
장치이므로, `raw_text` 는 **고객 경로(`/api/my/*`)에서 절대 반환하지 않는다.**

### 0-2 자동 승격 — 함께 두어야 하는 장치 넷

    ㉮ 회귀 트래픽 제외    `consult_sessions.data_origin='test'` 는 «세지 않는다».
                           안 빼면 회귀가 만든 질문이 답변 패턴이 된다 — 실측상 세션의
                           97.7%가 회귀였다(`regression-pollutes-the-ledger`).
    ㉯ 임계                같은 어휘 묶음이 **서로 다른 방문자** N명에게서 나와야 한다
                           (한 사람이 N번 물은 것은 1로 센다 — 안 그러면 한 명이 패턴을 만든다).
                           N 은 사장님 확정 사항(§9 ㉥). 기본 제안 **5명**.
    ㉰ 승격분은 표시가 다르다  `status='자동'` 으로 들어간다. 사람이 승인한 `사용` 과
                           구분해 관리자 화면이 **어느 것이 자동인지 항상 보여준다.**
    ㉱ 답변은 «수를 말하지 않는다»  자동 승격된 의도의 기본 `answer_kind` 는
                           `constraint_parse` 또는 `band_cards` 다. **`text`(자유 문구)로는
                           자동 승격하지 않는다** — 검증 없는 문장이 고객에게 나가는 유일한
                           경로가 그것이기 때문이다. 문구 답변은 여전히 사람이 쓴다.

⚠ **지금은 아무것도 자동 승격되지 않는다.** 실측(2026-08-22, 최근 3,000세션):
`guided 2,319 · chat 631 · expert 46 · **talk 4**`. 팝콘톡 실사용이 4건이라
임계 5명에 닿는 어휘 묶음이 없다. **장치를 먼저 세우고 트래픽을 기다린다.**

### 0-3 하네스가 냈던 반대 근거 (보존 — 뒤집힌 쪽)

**㉮ 원문 비저장 근거**: ① 재사용에 필요한 것은 의도와 답변 종류이지 문장 자체가 아니다
② 고객 인증이 dev 어댑터라 원문이 곧 유출 경로가 된다 ③ P-08 은 규약을 뒤집으려면
「왜 그 근거가 더는 유효하지 않은지」를 먼저 적으라 하는데, 원문 비적재의 근거는
무효화된 것이 없다.

**㉯ 사람 승인 근거**: ① 자동 승격의 전제인 빈도가 지금 없다(talk 4건) ② 틀린 답은
굳으면 되돌리기 어렵고, A-01·A-02 의 선을 사실상 넘는다 ③ 승인 큐는 `product_reviews`
검수 큐로 이미 있는 모양이다.

**사장님이 뒤집은 것은 「근거가 틀렸다」가 아니라 「그럼에도 그렇게 한다」이다.**
그래서 근거를 지우지 않고, 대신 위 §0-1·§0-2 장치로 그 위험을 줄인다.

## 5. 기능 — 네 덩어리

### 5-1 답변 패턴 목록 (기본 화면)

    보여줄 것   의도명 · 어휘(match_terms) · 답변 종류 · 상태 · **걸린 횟수** · 마지막 사용
    거를 것     상태(대기/사용/자동/미사용) · 답변 종류 · **자동 승격분만**
    찾을 것     의도명 · 어휘로 검색

⚠ **`자동`은 `사용`과 섞어 보여주지 않는다**(A-96 §0-2 ㉰). 사람이 승인한 것과 시스템이
올린 것은 신뢰도가 다르고, 운영자가 그 차이를 볼 수 있어야 내릴지 판단한다.

### 5-2 「안 걸린 질문」 큐 — **이 화면의 핵심**

`intent_key IS NULL` 인 행을 **어휘 묶음으로 집계**해 보여준다. 「우리가 아직 답을 못
만든 질문」이고, 새 의도를 만들 후보다.

    보여줄 것   비슷한 질문 묶음 · 건수 · **서로 다른 방문자 수** · 최근 발생
    셀 때       `data_origin='test'` 는 **뺀다**(회귀가 후보 큐를 채우면 안 된다)
    할 일       「의도로 만들기」 → 등록 폼에 그 어휘가 채워진 채 열린다

**「서로 다른 방문자 수」를 함께 보여주는 이유**: 자동 승격 임계가 그 수(5명)이기 때문이다.
운영자가 「이건 곧 자동으로 올라가겠구나」를 미리 안다.

### 5-3 등록 · 수정 · 승인

    등록      의도명 · 어휘 · 최소 매치 수 · 답변 종류 · 문구 또는 API 경로
    수정      위 전부
    승인      대기 → 사용
    반려      대기 → 미사용
    내리기    사용/자동 → 미사용 (지우지 않는다 — 원장 원칙)

⚠ **답변 종류가 `text` 가 아니면 문구 칸 대신 API 경로 칸**을 쓴다. 수가 필요한 답은
서버가 세야 한다(A-01·A-02) — 지금 쓰는 것은 `/api/talk/monitor-bands` 하나다.

### 5-4 원문 보관 현황 (**owner 전용**)

    보여줄 것   원문이 남은 건수 · 가장 오래된 것 · 다음 삭제 예정일
    안 보여줄 것 **원문 내용 자체는 이 화면의 기본 목록에 노출하지 않는다**

⚠ 원문을 «읽는» 것은 owner 만이고, 목록에서 바로 펼치지 않는다 — 한 화면에서 대량으로
읽히면 마스킹이 있어도 사실상 대화 열람이 된다. 단건으로 열되 그 사실이 기록돼야 한다.

## 6. 인터랙션 — 주 흐름 하나

    ① 「안 걸린 질문」 큐에서 묶음을 고른다
    ② 「의도로 만들기」 — 어휘가 채워진 등록 폼이 열린다
    ③ 답변 종류를 고르고 문구를 쓴다
    ④ 저장 → 상태 «대기». **아직 고객에게 안 나간다**
    ⑤ 승인 → «사용». 다음 요청부터 팝콘톡이 그 답을 쓴다
    ⑥ 내리기는 상태 전이다. 행을 지우지 않는다
