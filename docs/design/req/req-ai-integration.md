# 요구사항 정의서 — AI 연동 설정 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> 이 화면도 old admin에 대응 화면이 없다 — 완전 신설(`api/admin_nav.py` "AI 관리" 그룹,
> note: "신설 — 키는 서버 env").
>
> 작성일 2026-08-13. ④의 수치는 그 시각의 실측 스냅샷이다. 재측정은
> `SELECT count(*) FROM cost_thresholds`(및 `rate_limit_policies`)와 `.env.example` 읽기,
> `grep -rn "API_KEY" api/ tools/`를 다시 돌리면 된다.

---

## ① 화면 성격

**시스템 연결 상태 조회 화면 + 한도 정책 설정 화면.** 두 성격이 섞여 있다 — "지금 이
프로바이더가 살아 있는가"는 조회이고, "일 한도·분당 제한·초과 시 동작"은 설정이다.
**키 값을 입력받는 화면이 아니다** — 이건 이 화면의 정의 자체를 가르는 제약이라 ①에서
못박는다(근거는 ③).

- 연결 상태 열람: 로그인만 되면 등급 무관(viewer 이상)으로 제안.
- 한도·정책 변경: **owner 전용**으로 제안(AI 작업 설정과 같은 급 — ⑦ 참조).

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

- **지금 이 화면이 "볼" 연동 상태 자체가 인프라 차원에서 존재하지 않는다.** 실측: 프로젝트
  루트 `.env.example`에는 `DATABASE_URL`·`ADMIN_BOOTSTRAP_EMAILS`·`COOKIE_SECURE` 셋뿐이고
  (2026-08-13 확인), AI 프로바이더 키 항목은 템플릿에도 없다. `api/`·`tools/` 전체를
  뒤져도 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY`·`GEMINI_API_KEY`류를 참조하는 코드가
  **0건**이다(그레프 실측). 즉 이 화면은 인프라가 생긴 뒤에 "그것을 사람이 보는 창구"이지,
  인프라 자체를 만드는 화면이 아니다 — 오늘 이 화면을 그대로 켜면 3개 프로바이더 모두
  "미설정"이어야 정직하다.
- **연동이 실제로 붙은 뒤, 이 화면이 없으면 키 생존·한도 초과 여부를 서버 로그를 직접
  열어야만 알 수 있다** — 운영자가 아니라 개발자만 알 수 있는 상태가 된다.
- **비밀값 규약을 화면 차원에서 지키는 자리.** CANON.md §2-5: "비밀값을 리포·설정·
  메모리에 적지 않는다. `.env`만." 이 화면이 "키 입력 폼"이 되는 순간 이 규약이 깨진다.
  같은 프로젝트 안에 이미 선례가 있다 — 텔레그램 연동(`docs/telegram-rules.md`)의
  자격증명도 "프로젝트 `.env`"에만 있고 화면·리포에 노출되지 않는다(이 문서의 관리
  대상은 아니지만 같은 원칙의 실증 사례로 인용한다).

## ④ 데이터

### 실측 방법

`.env.example` 직접 읽기 + `grep -rn "API_KEY" api/ tools/`(0건 확인) + `api.db.engine`으로
`cost_thresholds`·`rate_limit_policies` 컬럼·행수 직접 SELECT(읽기 전용). 랜딩 카피
(`mockups/mvp1/main-landing.html`)의 프로바이더 암시 색상 대조. 2026-08-13 스냅샷.

### 지금 있는 것

| 원천 | 실측 내용 |
|---|---|
| `.env.example` | `DATABASE_URL`·`ADMIN_BOOTSTRAP_EMAILS`·`COOKIE_SECURE` 3개뿐. AI 키 항목 없음 |
| `api/`·`tools/` 코드 | AI 프로바이더 키를 참조하는 코드 0건(그레프 실측) |
| `cost_thresholds` | 컬럼: `key`(PK, 자유문자열)·`daily_usd`(NUMERIC)·`action`(자유문자열, CHECK 제약 없음)·`updated_at`. **0행** |
| `rate_limit_policies` | 컬럼: `key`(PK, 자유문자열)·`per_minute`·`per_day`·`updated_at`. **0행** |
| `docs/telegram-rules.md` | "자격증명은 프로젝트 `.env`"(선례, 관리 대상은 다름) |

`cost_thresholds`·`rate_limit_policies` 둘 다 `key`가 자유 문자열 기본키라, 한도를
**프로바이더 기준**으로 매길지 **작업 종류 기준**으로 매길지가 스키마만으로는 정해져
있지 않다(AI 작업 설정과 맞물리는 지점 — 결정 필요).

### 연동 후에야 생기는 것

- `.env`의 실제 프로바이더 키 항목 — 신설 필요(현재 템플릿에도 없음).
- "연결 상태" 판정 로직(키 존재 확인만 할지, 실제 핑까지 할지) — 결정 필요, 지금은 없음.
- 프로바이더별 오늘/이번 달 사용량 대비 한도 잔여치 — `api_cost_logs` 0행이라 계산 불가
  (AI 사용량·비용 화면과 공유하는 제약).

## ⑤ 기능 (동사)

- 프로바이더별 연결 상태(정의는 결정 필요)를 본다.
- 프로바이더별로 지금 쓰는 모델명(문자열)을 본다.
- 일 한도(`cost_thresholds.daily_usd`)·분당/일 호출 제한(`rate_limit_policies`)을 정한다.
- 한도 초과 시 동작(`cost_thresholds.action`)을 정한다.
- **키 값 자체는 입력·수정·삭제하지 않는다**(비범위 — 강한 요구).

## ⑥ 인터랙션

- 한도·정책 저장은 즉시 반영 + 이력 기록을 요구한다(AI 작업 설정과 같은 급의 정책 화면 —
  owner 전용, 원장 규약).
- 저장 실패 시 사유를 그대로 보인다 — "저장 실패"만 뜨는 화면 금지(원장 규약).
- 연결 상태는 화면을 열 때(또는 명시적 새로고침 시) 확인하며, 그 확인 자체가 프로바이더
  과금을 유발하는지는 "연결 상태" 정의(결정 필요)에 달려 있다 — 정의에 따라 인터랙션이
  "자동 폴링"이 될 수도 "수동 확인 버튼"이 될 수도 있다.

## ⑦ 상태 · 예외

- **키가 없는 프로바이더는 "미설정"으로 정직하게 표기한다** — 화면이 "연결됨"이라
  지어내면 화면 정직성 규약의 핵심을 정면으로 위반한다. 오늘 이 화면을 그대로 열면
  (실측) **3종 전부 미설정이어야 맞다.**
- **"확인 실패"(네트워크 등)와 "애초에 키가 없어 확인 대상이 아님"을 구분한다** — 상품
  사양 검수 요구사항(`req-admin2-reviews-2026-08-13.md`)의 "신뢰도 취급"과 같은 종류의
  "없음 vs 못 함" 구분 원칙을 그대로 적용한다.
- 권한 없음: 미로그인 401, owner 미만 쓰기 시도 403.

## 비범위 — 이 화면이 하지 않는 일

- **키 값 입력·수정·삭제 폼.** 과제 지시 명시 사항(CANON §2-5) — 다르게 하려면 이
  문서가 아니라 사장님 결정으로 명시적으로 뒤집어야 한다.
- **개별 호출 로그**(무엇을 물었고 뭐라 답했나) — AI 응답 기록 소관.
- **비용 추이·용도별 분석** — AI 사용량·비용 소관.
- **작업↔모델 배정, 폴백 순서** — AI 작업 설정 소관(이 화면은 "연결이 살아 있는가"만
  본다).
- **텔레그램 봇 연동 자체의 관리** — 별도 채널, 이 화면의 대상이 아니다(선례로만 인용).

## 사장님 결정이 필요한 지점

1. **"연결 상태"의 정의** — env 키 존재만 볼지, 실제 ping(과금 발생 가능) 성공까지
   요구할지.
2. **프로바이더 3종의 내부 표기** — Codex/OpenAI·Claude/Anthropic·Gemini/Google 실명을
   관리자 화면에 쓸지, 랜딩처럼 익명("AI 1/2/3")을 유지할지.
3. **한도 단위**(`cost_thresholds.key`)를 프로바이더 기준으로 할지 작업 종류 기준으로
   할지 — AI 작업 설정과 맞물린다.
4. **한도 초과 시 동작의 옵션 목록** — 2026-07-13 구상 문서(`admin-identity.md`)에 "고객
   대면 기능은 유지, 배치만 연기"라는 예시 문구가 있으나 이는 실측 확정 사양이 아니다
   (옛 초안 텍스트). 실제 옵션은 재정의가 필요하다.
5. **프로바이더 몇 개를 이 화면이 관리하는지** — `req-ai-task-settings.md`의 문서 간
   불일치(1개 vs 3개) 결정에 이 화면의 목록 구조가 종속된다.
