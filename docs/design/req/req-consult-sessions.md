# 요구사항 정의서 — 견적 상담 기록 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 결정권자(또는 지정 경로)가 별도로 한다.
>
> 대상은 admin2 신규 구축이다. 기존 `mockups/admin/sessions.html`(ADM-ORD-010)은
> 백업용 동결 — 참고만 하고 옮기지 않는다(P-09).
>
> 작성일 2026-08-13. ④의 수치는 그 시각의 실측 스냅샷이다. 재측정은
> `SELECT count(*) FROM consult_sessions`와 `GET /api/admin/sessions`를 다시
> 돌리면 된다.

---

## ① 화면 성격

**조회 화면이다(읽기 전용 관측창).** 고객이 어떤 조건으로 상담해 어떤 견적을 받았는지
**당시 그대로**(스냅샷) 재현해 분쟁·문의에 소명하는 자리다. 재현성 원칙(A-02: 같은
입력+같은 재고 → 같은 결과)의 증거를 보여주는 화면이며, 지금 재고로 다시 계산해서
"그때와 비교"하는 기능이 아니다 — **저장된 원문을 그대로** 보여주는 것이 재현의 정의다.

- 열람은 로그인만 되면 등급 무관(viewer 이상).
- 쓰기 기능 없음.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

- **"이 고객이 왜 이 견적을 받았는지"를 나중에 증명할 방법이 없다.** 상담은 제약
  객체(단일 원천, S1 상태 관리 원칙)를 그대로 저장하고, 티어별 견적은 부품·가격·근거를
  스냅샷으로 남긴다 — 이 화면이 없으면 "그때 그 가격이 맞았나"를 소명할 창구가 없다.
- **얼마나 많은 상담이 견적 없이 끝나는지(이탈)를 볼 자리가 없다.** 상담이 시작됐지만
  스냅샷(견적)이 하나도 안 남았으면 그 세션은 이탈로 본다 — 이 비율이 추천 로직·UX
  문제의 신호다.
- **상담 방식(맡김/함께/직접/팝콘톡)별로 실제 사용 비중이 어떤지 볼 자리가 없다** —
  기획 의도와 실사용이 어긋나면(아래 실측 참조) 이 화면이 유일한 증거가 된다.

## ④ 데이터

### 실측 방법

`SELECT` 직접 실행(`consult_sessions` 4,419행·`quote_snapshots` 12,401행 등, 읽기
전용) + `GET /api/admin/sessions` 코드 대조. 2026-08-13 스냅샷.

### 쓰는 테이블

| 테이블 | 역할 |
|---|---|
| `consult_sessions` | 상담 세션 본체. `session_id`·`member_id`(전부 NULL)·`mode`·`constraints`(JSONB, 제약객체 스냅샷)·`created_at`·`data_origin`·`user_id` — 7컬럼. **`user_id`·`data_origin` 컬럼이 있지만 현재 `GET /api/admin/sessions`의 SELECT 목록에 없다**(2026-08-13 코드 실측 — 아래 "실측된 간극" 참조) |
| `quote_snapshots` | 티어별 견적 스냅샷. `session_id` FK·`quote_type`(value/recommend/highend)·`items`(JSONB)·`companion`(JSONB)·`total_amount`·`created_at` |
| `orders` | `session_id` FK로 상담→주문 연결(아래 "실측된 간극" 참조) |
| `handoffs` | **더 최근에 생긴 인계 원장**(아래 "실측된 간극" 참조) |

### 쓰는 API

| 엔드포인트 | 역할 | 권한 |
|---|---|---|
| `GET /api/admin/sessions` | 최근 세션 목록 + 대표 스냅샷(부품·가격·컴패니언) + 오늘 건수 | viewer 이상(쓰기 없음) |

### 실측 값 (2026-08-13)

- **전체 4,419건**(2026-07-23~2026-08-12). 최근 10일 일별 추이(예): 8/12 154 · 8/11 153
  · 8/10 224 · 8/9 3(급감일, 원인 미상) · 8/8 282 · 8/7 386 · 8/6 272 · 8/5 553 ·
  8/4 518.
- **모드 분포(실측): `guided`(맡김) 3,488 · `chat`(함께) 928 · `talk`(팝콘톡) 3 ·
  `expert`(직접) 0건.** "직접" 모드는 코드에 라벨(`MODE_KO`)까지 준비돼 있지만 실사용
  기록이 전혀 없다 — 화면이 이 모드를 다른 3개와 동등하게 다루면 "쓰는 사람이 있다"는
  인상을 주므로, 0건이라는 사실을 감추지 않아야 한다.
- **스냅샷 보유(=완주) 4,116건(93.1%) / 미보유(=이탈) 303건(6.9%).**
- **회원 귀속은 사실상 없다.** `member_id`가 채워진 행은 **1건뿐**(4,419건 중). 반면
  방문자 키(`user_id`)가 채워진 행은 534건 — 즉 "누가 왔는지"는 방문자 단위로는 꽤
  잡히는데(12%), 회원으로 연결된 것은 예외적 1건뿐이다. 실 인증(소셜 로그인)이 붙기
  전까지는 이 상태가 정상이다.
- **`quote_snapshots` 12,401건 중 12,400건이 신형식(`items`가 JSON 객체), 1건만
  구형식(`items`가 배열, `session_id=1` — 가장 첫 세션)** — 화면은 두 형식을 모두
  방어적으로 읽어야 한다(`_parts()`가 이미 그렇게 구현돼 있다).
- **주문 연결: `orders` 20건 중 16건에 `session_id`가 있고, 그중 15개 세션이 실제
  매칭.** 4건은 `session_id`가 아예 없는 초기 테스트 주문(2026-06-25~07-23, 세션
  연결 이전 시기).

### ⚠ 실측된 간극 — "완주 → 주문" 판정의 원천이 최근 바뀐 흔적이 있다

지금 `GET /api/admin/sessions`는 `orders.session_id`를 조인해 "완주 → 주문" 상태를
매긴다. 이건 **A-10 커머스 승격(2026-07-16) 시절의 설계**다. 그런데 **CANON.md
(2026-08-11 확정)는 이후 범위를 되돌렸다**: "팝콘AI는 신규 고객 유입 채널이다.
판매하지 않는다 … 인계 원장은 `handoffs` — `orders`가 아니다." 실제로 `handoffs`
테이블이 이미 존재하고(컬럼 14개: `handoff_no`·`session_id`·`snapshot_id`·`quote_type`
·`total_quoted`·`total_mall`·`price_checked`·`changed_cnt`·`soldout_cnt`·`status`
등) **3건이 들어 있다**(전부 `status='인계'`, 2026-08-11~08-12 — `orders`의 마지막
행(08-10)보다도 나중이다). 즉:

- `orders`는 20건(6/25~8/10), 상담 세션과 연결된 것 16건 — **A-10 시절 데이터로
  보이며 그 이후로 새 행이 없다.**
- `handoffs`는 3건(8/11~8/12) — **CANON.md가 확정한 이후 실제로 쌓이기 시작한
  새 원장.**

**이 화면이 "완주 → 주문"을 계속 `orders` 기준으로 보여줄지, `handoffs` 기준으로
바꿀지는 이 문서가 임의로 정하지 않는다**(아래 결정 필요 지점 1번). 다만 측정 사실은
분명히 남긴다 — 지금 화면 요구사항을 옛 API 그대로 베끼면, 8/11 이후에 실제로 일어난
인계(`handoffs` 3건)는 이 화면에 전혀 보이지 않는다.

### ⚠ 실측된 간극 — 목록에 페이지네이션이 없다

CLAUDE.md 목록 화면 규약("목록은 전부 서버 페이지네이션이다 — 전 행 반환 금지")과
달리, 지금 `GET /api/admin/sessions`는 **`LIMIT 200` 고정이고 offset·page 파라미터가
없다.** 전체 4,419건 중 최신 200건(4.5%)만 조회 가능하고, **그 이전 4,219건은 이 화면
어디에서도 볼 방법이 없다.** admin2 재구축 요구사항에는 실제 페이지네이션(전체 건수
표시 + 페이지 이동)을 반드시 포함해야 한다 — 지금 API를 그대로 옮기면 규약 위반이
그대로 재구축된다.

## ⑤ 기능 (동사)

- 세션 목록을 최신순으로 본다 — 시각·모드·제약 요약·결과 요약(대표 견적 총액+부품
  수 또는 "견적 미생성")·상태(완주/이탈/완주→주문)를 함께 본다.
- 세션 하나를 열어 제약 객체 전체(칩으로 표현된 조건들)를 원문 그대로 본다.
- 그 세션에서 생성된 모든 티어 스냅샷(가성비/추천/고성능, 각각 총액·부품 수)을 본다.
- 대표 스냅샷(추천형 우선, 없으면 마지막)의 부품 구성·가격·컴패니언 제안을 상세히
  본다.
- 오늘 생성된 세션 수를 확인한다.
- 완주율/이탈률을 확인한다(스냅샷 유무 기준).
- 모드별 분포를 확인한다.

## ⑥ 인터랙션

- 목록에서 세션을 고르면 그 세션의 제약·스냅샷·부품 상세가 펼쳐진다(별도 페이지
  이동 없이 같은 화면 안에서 상세를 보는 방식을 권장하되, 이는 UI 설계 영역이라 이
  문서는 "무엇을 보여줘야 하는지"까지만 정한다).
- 페이지를 넘기면 다음 페이지를 서버에 요청한다(위 간극 항목 — 지금 API에는 없는
  기능이므로 백엔드 확장이 함께 필요하다).
- 필터(모드별·완주/이탈별·기간별)를 걸면 목록과 집계(오늘 건수·완주율)가 함께 다시
  요청된다 — 단, 지금 API는 필터 파라미터를 전혀 받지 않는다(전량 최신 200건 고정).
  admin2 요구사항에 필터를 포함하려면 이 부분도 백엔드 확장이 필요하다.
- "이 스냅샷으로 재현" — 저장된 스냅샷 원문(부품·가격·근거)을 그 시점 그대로 다시
  보여주는 것이며, **지금 재고로 엔진을 다시 돌려 대조하는 기능은 아니다**(재고가
  바뀌면 결과가 달라지는 게 정상이므로, 그런 "재실행 대조"는 이관 대상으로 명시돼
  있다).

## ⑦ 상태 · 예외

- **빈 상태**: 세션이 아예 없는 것과 필터 결과가 0건인 것은 다르다(필터 기능이
  생긴다면). 지금은 필터가 없으므로 "세션 자체가 0건"만 해당 — 이론상 발생하지
  않는다(4,419건 존재).
- **회원 귀속 없음**: `member_id`가 없는 세션(99.98%)을 "회원 없음/비식별"이 아니라
  마치 오류처럼 보여주면 안 된다 — 지금은 로그인 전 세션이 절대다수인 것이 **정상
  상태**다(실 인증 슬라이스 이전이므로).
- **스냅샷 형식 방어**: `items`가 배열이든 객체든(1건은 구형식) 화면이 죽지 않아야
  한다.
- **서버 실패**: 침묵하지 않는다.
- **권한**: 미로그인 401. 열람은 등급 무관.
- **200건 초과 조회 시도(지금 상태)**: 화면이 "이 밖의 과거 기록은 지금 볼 수 없습니다"는
  사실을 숨기지 않아야 한다 — 은근슬쩍 "최근 기록"이라고만 적으면 4,219건이 조용히
  안 보이는 것을 사람이 눈치채지 못한다.

## 비범위 — 이 화면이 하지 않는 일

- **지금 재고로 견적을 재실행해 당시와 비교하는 일** — 이관 대상으로 코드에 명시돼
  있다.
- **회원 식별·매핑** — 회원 인증이 실제로 붙기 전까지는 구조적으로 불가능하다.
- **인계(`handoffs`) 상세 관리** — LNB "인계·성과" 그룹의 "인계 기록" 화면(현재
  `href=None`, 신설 예정) 소관. 이 화면은 위에서 밝힌 대로 "완주 → 인계됨" 여부를
  **표시**하는 것까지만 검토 대상이지, 인계 자체의 상세 관리(전달 상태·재시도 등)를
  다루지 않는다.
- **주문·결제·배송·환불** — 그룹 밖. CANON.md §3: "결제·배송·환불·회원관리는 쇼핑몰
  소관."

## 사장님 결정이 필요한 지점

1. **"완주 → 주문" 판정을 `orders` 기준으로 유지할지 `handoffs` 기준으로 바꿀지(또는
   둘 다 보여줄지).** 실측: `orders`는 A-10 시절 데이터로 8/10 이후 갱신이 없고,
   `handoffs`는 8/11부터 실제로 쌓이기 시작했다(3건). 지금 API를 그대로 admin2로
   옮기면 최근 실제 인계(8/11~8/12, 3건)가 이 화면에 안 보인다.
2. **목록 페이지네이션·필터를 이 화면의 요구사항에 포함할지.** 포함하면 백엔드
   (`GET /api/admin/sessions`)에 `page`/`size`/모드·완주 여부 필터 파라미터 추가가
   선행돼야 한다 — 지금은 최신 200건 고정이라 95%가 조회 불가능한 상태다.
3. **`expert`(직접) 모드 실사용 0건을 이 화면이 어떻게 다룰지.** 다른 세 모드와 같은
   비중으로 보여줄지, "미사용"으로 별도 표시할지는 판단이 필요하다.
