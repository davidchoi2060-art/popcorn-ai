# 요구사항 정의서 — 고객 간편로그인·회원가입 화면 (mvp4)

- 작성일: 2026-11-17
- 근거: `docs/design/customer-social-login-v1.md`(2026-10-13 확정, D-1~D-8) · 사장님 지시 2026-11-17 「23일에 포함」, 「화면은 코덱스 맡겨」
- 범위: 2026-11-23 오픈에 필요한 최소 화면. 화면 배치·모양은 이 문서가 정하지 않는다(코덱스가 mvp4 기존 양식에 맞춰 설계한다).
- 서버 계약의 정본은 코드다: `api/customer_auth_oauth.py`, `api/customer_auth_issuer.py`, `api/customer_auth.py`.

## 공통 전제

| 항목 | 내용 |
|---|---|
| 스위치 | 서버의 `CUSTOMER_AUTH_ENABLED` 가 꺼져 있으면 화면에 로그인 관련 요소가 **하나도 보이지 않는다**. 판정은 `GET /api/auth/providers` 응답의 `enabled` 만 쓴다. |
| 공급자 | 표시할 공급자는 같은 응답의 `providers` 배열(`google` · `kakao` · `naver` 중 켜진 것)만 쓴다. 화면이 목록을 고정하지 않는다(D-1: 검수가 늦는 공급자는 버튼만 늦게 켠다). |
| 호출 실패 | `/api/auth/providers` 또는 `/api/auth/me` 가 실패(네트워크 오류·5xx)하면 로그인 요소를 숨기고 나머지 화면은 그대로 동작한다. 콘솔 오류로 다른 스크립트가 멈추지 않아야 한다. |
| 보안 | 화면은 토큰·공급자 고유 ID 를 다루지 않는다. 세션은 HttpOnly 쿠키다. `localStorage` 에 회원 정보를 저장하지 않는다. |
| 쓰기 요청 | `POST` 는 같은 출처에서만 받는다(`same_origin`). `fetch` 는 `credentials: 'same-origin'` 으로 보낸다. |
| 비회원 보관 키 | `POST /api/auth/join` 과 `POST /api/auth/attach-guest` 에는 `X-Access-Key` 헤더(`assets/js/saved-quotes-client.js` 의 보관 키)를 함께 보낸다. 키가 없으면 헤더 없이 보낸다. |
| 어휘 | `CLAUDE.md` §문서·화면 어휘 표준을 따른다. 항목명은 명사형, 안내는 시스템 안내체. |

## 화면 1. 로그인 진입점 (상단바)

① 화면 성격: 전 화면 공통 관문. `assets/js/core.js` 의 `PAI.shell` 상단바(`header-actions`)와 전체 메뉴 창에 놓인다.

② 제목 · 화면 ID: 로그인 진입점 · CUS-AUTH-010 · mvp4 전 화면

③ 정의: 이 요소가 없으면 고객이 로그인·로그아웃을 시작할 수 없다.

④ 데이터
- `GET /api/auth/providers` → `{enabled: bool, providers: [..]}`
- `GET /api/auth/me` → 켜져 있을 때 로그인 여부. 응답 형태는 `api/customer_auth.py` 의 `create_auth_router` 를 읽어 그대로 쓴다(키를 추측하지 않는다). 꺼져 있으면 503.
- `POST /api/auth/signout` → `{ok: true, revoked: bool}`

⑤ 기능
- 로그인 창 열기(비로그인 상태)
- 로그인 상태 표시(로그인 상태). 닉네임이 있으면 닉네임, 없으면 「회원」.
- 로그아웃
- 회원 탈퇴 창 열기(화면 4)

⑥ 인터랙션
- 진입 시 `providers` → `enabled` 가 참일 때만 `me` 를 조회한다.
- 로그아웃 성공 시 현재 화면을 다시 불러온다. 실패 시 안내 문구를 표시하고 상태를 바꾸지 않는다.
- 주소에 `login_error=<코드>` 가 있으면 안내 문구를 한 번 표시하고 주소에서 그 매개변수를 지운다(`history.replaceState`).

| 코드 | 안내 문구 |
|---|---|
| `cancelled` | 로그인을 취소했습니다. |
| `state_mismatch` · `attempt_expired` | 로그인 시간이 지났습니다. 다시 시도해 주세요. |
| `identity_revoked` | 탈퇴한 로그인 정보입니다. 고객지원으로 문의해 주세요. |
| `member_inactive` | 이용이 제한된 회원입니다. 고객지원으로 문의해 주세요. |
| `provider_failed` · 그 밖 | 로그인하지 못했습니다. 잠시 후 다시 시도해 주세요. |

- 로그인 직후 한 번 `POST /api/auth/attach-guest` 를 호출한다(재로그인은 서버가 보관 키를 받지 못해 견적이 붙지 않는다). 실패해도 화면에 오류를 띄우지 않는다. 같은 세션에서 반복 호출하지 않는다(`sessionStorage` 표시 허용).

⑦ 상태 · 예외
- 스위치 꺼짐 · 공급자 0개: 진입점 숨김.
- 조회 중: 진입점 숨김(깜빡임 없이 확정 뒤 표시).
- 모바일 폭(390px)과 넓은 폭(1440px) 모두에서 상단바의 기존 요소(검색 · 내 견적 · 전체 메뉴)가 줄바꿈되지 않는다.
- 관리자 미리보기 호스트(`admin.`)에서는 로그인 시도가 성립하지 않는다(콜백이 `www.` 로 돌아온다). 진입점을 숨기지는 않되, 실패 안내가 위 표대로 나오면 된다.

## 화면 2. 로그인 방법 선택 창

① 화면 성격: 선택 창(기존 `site-dialog` 양식).

② 제목 · 화면 ID: 간편로그인 · CUS-AUTH-020

③ 정의: 이 창이 없으면 고객이 공급자를 고를 수 없다.

④ 데이터: 화면 1 의 `providers`.

⑤ 기능
- 공급자 선택(켜진 공급자만, 순서: 카카오 · 네이버 · 구글)
- 닫기
- 이용약관 · 개인정보처리방침 열기(`terms.html` · `privacy.html`)

⑥ 인터랙션
- 공급자 선택 시 `/api/auth/{provider}/start?return=<현재 경로+쿼리>` 로 **페이지 이동**한다(fetch 아님). `return` 은 `/mvp4/` 로 시작하는 현재 주소이고 `login_error` 매개변수는 뺀다. 서버는 `/mvp4/` 로 시작하지 않거나 300자를 넘는 값을 기본 화면으로 바꾼다.
- 안내 문구: 「처음이시면 로그인 뒤 가입 동의 화면으로 이동합니다.」

⑦ 상태 · 예외
- 공급자 버튼은 각 공급자의 버튼 표시 지침(색 · 로고 · 문구)을 따른다. 로고는 저장소에 자체 보관한다(외부 주소 참조 금지).
- 키보드로 열기 · 닫기 · 선택이 가능하고, 닫으면 초점이 진입점으로 돌아온다.

## 화면 3. 가입 동의 화면

① 화면 성격: 작업 화면. 신규 고객이 공급자 인증 뒤 한 번 거친다.

② 제목 · 화면 ID: 회원가입 동의 · CUS-AUTH-030 · `/mvp4/join.html`

③ 정의: 이 화면이 없으면 신규 고객의 회원이 만들어지지 않는다(서버가 인증 뒤 이 주소로 보낸다).

④ 데이터
- `GET /api/auth/join/pending` → `{provider, nickname, consent_version, required: ["terms","privacy","age14"], optional: ["marketing"]}`
- `POST /api/auth/join` 본문 `{consents: {terms: true, privacy: true, age14: true}, nickname: <선택>}` → `{ok, return_path, attached}`

⑤ 기능
- 인증한 공급자와 닉네임 표시
- 필수 동의 3항목 선택: 이용약관 · 개인정보 수집·이용 · 만 14세 이상
- 전체 동의
- 약관 · 처리방침 본문 열기(새 창)
- 가입
- 취소(가입하지 않고 나가기)

⑥ 인터랙션
- 필수 3항목이 모두 선택돼야 가입 단추가 활성화된다.
- 마케팅 수신 동의는 표시하지 않는다(D-8). `optional` 에 값이 와도 화면에 내지 않는다.
- 가입 성공 시 응답의 `return_path` 로 이동한다.
- 취소 시 `/mvp4/` 로 이동한다. 회원은 만들어지지 않는다.
- 안내 문구: 「다른 로그인 방법으로 이미 가입하셨다면 그 방법으로 로그인해 주세요. 로그인 방법이 다르면 별도 회원으로 가입됩니다.」(D-2: 자동으로 합치지 않는다)

⑦ 상태 · 예외

| 경우 | 처리 |
|---|---|
| `pending` 이 401 · 404 · 410 등 실패(대기 정보 없음 · 10분 경과) | 「가입 대기 시간이 지났습니다. 다시 로그인해 주세요.」와 로그인 다시 시작 단추 |
| `pending` 이 503(스위치 꺼짐) | 「지금은 회원가입을 받지 않습니다.」와 홈으로 이동 단추 |
| `join` 이 400(필수 동의 누락) | 누락 항목 안내, 화면 유지 |
| `join` 이 409 `already_joined` | 이미 가입된 것으로 보고 `/mvp4/` 로 이동 |
| `join` 이 그 밖의 실패 | 「가입하지 못했습니다. 잠시 후 다시 시도해 주세요.」, 화면 유지, 단추 재활성화 |
| 가입 단추 두 번 누름 | 요청 중에는 단추 비활성화 |

- 실패 응답의 사유는 `detail.code` 로 온다. 화면은 상태 코드와 `detail.code` 를 본다.
- 이 화면은 검색 노출 대상이 아니다(`noindex`).

## 화면 4. 회원 탈퇴 확인 창

① 화면 성격: 확인 창.

② 제목 · 화면 ID: 회원 탈퇴 · CUS-AUTH-040

③ 정의: 이 창이 없으면 고객이 스스로 탈퇴할 수 없다(개인정보 처리 요구 대응).

④ 데이터: `POST /api/auth/withdraw` → `{ok: true}` (서버는 별도 PR 로 만든다. 그 전에는 404 가 온다)

⑤ 기능
- 탈퇴 안내 확인
- 탈퇴
- 취소

⑥ 인터랙션
- 안내 문구: 「탈퇴하면 로그인 정보가 삭제되고 되돌릴 수 없습니다. 같은 방법으로 다시 가입하면 새 회원이 되며 이전 기록은 이어지지 않습니다.」(D-5)
- 확인 선택 1개(「안내를 확인했습니다」)를 선택해야 탈퇴 단추가 활성화된다.
- 성공 시 「탈퇴했습니다.」 안내 뒤 `/mvp4/` 로 이동한다.

⑦ 상태 · 예외
- 404 · 5xx: 「탈퇴를 처리하지 못했습니다. 고객지원으로 문의해 주세요.」, 로그인 상태 유지.
- 401: 이미 로그아웃된 상태로 보고 화면을 다시 불러온다.

## 이번 범위가 아닌 것

로그인 방법 연결(D-2 의 「계정 연결」) · 마이페이지(프로필 · 내 견적 · 내 문의) · 다른 기기에서 내 견적 보기 · 관리자 회원 화면 · 마케팅 수신 동의.

## 검증 기준

- 스위치 꺼짐(지금의 개발·운영 상태)에서 mvp4 전 화면의 겉모습과 동작이 이 변경 전과 같다.
- 콘솔 오류 0 · 404 자원 0 · 외부 주소 참조 0.
- 390px · 1440px 에서 상단바 줄바꿈 없음.
- 화면 동작 테스트는 저장소의 기존 mvp4 화면 테스트 방식(Node 테스트)을 따른다.
