## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

**셋이 막혀 있다.**

**(가) 「가격 검토 대기」의 유형이 하나뿐이다**

승인 디자인 원문:
> ±15% 매입가 임계 초과·**마진 정책 위반 유형은 원천이 없어 아직 합류하지 못했습니다** —
> 특히 **분류별 마진 정책이 0건**이라 "정책 위반"이라는 유형 자체가 성립하지 않습니다.
> **정책을 채우는 화면(마진 정책)이 살아나야 이 유형이 생깁니다.**

**(나) 전 상품에 같은 마진이 걸린다**

지금 마진은 **전역 하나뿐**이다 — 그래픽카드와 케이스가 같은 마진율일 이유가 없다.

**(다) 부품별 예산 배분율을 못 고친다**

「추천 기준 보기」가 그 편집을 **「향후 사용예정」으로 잠가** 두고 있다(값이 코드 상수라서).

### 조사자 실측 완료 (2026-08-15) — **셋이 정의서를 뒤집는다**

**⚠⚠ 뒤집힌 것 ① — `category_margin_policies` 는 «부품 종류»를 못 담는다**

    키       category_id INTEGER  PK/FK → **categories.category_id**  (0030_category_margin_by_node.py:36-42)
    ⚠        **`part_type` 이 아니다** — `api/pricing.py:38-41` 주석이 그렇게 못박아 뒀다
    값       margin_rate NUMERIC(7,6) NOT NULL CHECK(0 ≤ x < 1)
    현재     **0건**

**`categories` 트리 실측**: 34행 = 최상위 6 + 하위 28, **깊이 정확히 2단**(3단 이상 0건).
최상위별 상품 수 — 부품 13,308 · 주변기기 4,605 · 쿨링·튜닝용품 1,668 · 기타 1,628 · 확장·연결 1,207 · 완제품 422.

**`products.part_type` 은 19종**(ETC 4,725 · MONITOR 2,563 · GPU 2,458 · CASE 2,327 · MB 2,087 · RAM 1,766 · POWER 1,247 · SSD 1,049 …).

⚠ **사장님이 「부품 종류별」을 고르셨는데 지금 표가 그 축이 아니다.** → §확정 참조

**⚠⚠ 뒤집힌 것 ② — 「상품 분류 관리」가 «이미» 이 기능을 하고 있다**

**「마진 정책」의 기능 ②(분류별 예외 등록·수정·삭제)와 범위가 겹친다.**

**⚠⚠ 뒤집힌 것 ③ — 「미리보기 → 확인 → 저장」이 «지금은 불가능하다»**

    있는 것   GET /reprice/preview  — **이미 저장된** 설정값으로만 계산한다
    없는 것   **가상의 새 마진값을 인자로 받아 하양값을 미리 계산해 주는 경로**
              `PricingBody`·`MarginBody` 둘 다 `dry_run`/`preview` 파라미터가 없다

**지금 가능한 것은 「저장 → 확인 → (필요시 되돌림)」뿐이다.**
⚠ 내 §⑥ 이 요구한 2단계 강제를 지키려면 **새 API 가 필요하다.**

## ⑤ 기능 — 할 수 있는 일

1. **전역 기본 마진율을 본다 · 고친다**
2. **분류별 예외 마진율을 등록 · 수정 · 삭제한다**
3. **바꾸기 전 영향을 미리 본다** — 「이 정책을 저장하면 상품 N건의 제안가가 바뀝니다」
4. **지금 정책이 0건이라는 사실을 본다** (0건이 정상 상태임을 화면이 밝힌다)
5. **카드수수료를 본다 · 고친다** ✅ 확정 — ⚠ **전 상품에 걸린다**(마진보다 영향이 크다)
6. **부품별 예산 배분율을 본다 · 고친다** ✅ 확정 — 같은 화면에서 다룬다

## ⑥ 인터랙션 — 흐름과 결과

### 값 변경 — **2단계 강제**

    ① 값을 고친다
    ② **미리보기** → 「상품 N건의 제안가가 바뀝니다」 (서버가 센 값)
    ③ 확인 → 저장

⚠⚠ **미리보기 없이 바로 저장하는 경로를 만들지 않는다.**
「용도별 최소 사양」(ADM-ENG-040)이 이미 이 패턴으로 검증을 통과했다 — **그 이음새를 그대로 쓴다.**

⚠ **미리보기 요청에는 공용 진행 배너가 뜨지 않는다**(2026-08-15 확정). 대신 **버튼 비활성 + 인라인 「미리보기 중…」**을 화면이 직접 둔다.

### 저장 후

> 저장하면 **다음 견적부터 적용됩니다 — 이미 만든 견적은 그대로입니다.**

⚠ **이 문장이 코드로 지켜지는지 조사자가 확인 중**이다. 안 지켜지면 문장을 바꾸는 것이 아니라 **코드를 고쳐야 한다**.

### 삭제 (분류별 예외)

예외를 지우면 **전역 기본값으로 돌아간다.** 그 사실을 삭제 확인에 적는다.

### 이 화면에서 «안» 하는 것

    개별 상품 판매가 확정        「가격 검토 대기」 소관
    대량 재계산 «실행»            「판매가 재산정」 소관 (아직 화면이 없다)
    예외 잡기 · 잠금              「판매가 관리」 소관
    마진 «이력» 조회              「가격 이력」 소관

⚠ **경계를 화면이 직접 밝힌다** — 다른 판매가 화면들이 전부 그렇게 하고 있다.

## ⑦ 상태 · 예외

### 빈 상태 — **0건이 정상이다**

`category_margin_policies` **0건**이 지금의 정상 상태다.
⚠ **「설정을 못 불러왔다」처럼 보이게 하면 안 된다.** 「아직 예외를 두지 않았고 전역값만 쓴다」는 사실을 그대로 말한다.

### 실패

    권한 없음        owner 미만 → 입력칸·버튼 비활성 + **사유를 title 로 병기**
    미로그인         401 → 「세션이 만료됐습니다」 (다른 화면과 같은 문구)
    조회 실패        사유를 갈라 말한다 — `if(!res.ok) return;` 금지
    저장 실패        서버 사유를 그대로 노출

### 경계값

    마진율 0%        허용인가 — **미정**
    마진율 음수      거부 (역마진)
    상한             있는가 — **미정** (예: 100% 초과)
    중복 분류        같은 분류에 예외가 둘이면? — **미정**

### ⚠ 위험 — 화면이 반드시 밝힐 것

**(가) 되돌림이 거의 1:1이다**

`margin_policy` 이력 **14,480건 중 14,478건이 되돌려졌다.**
**대량 재산정이 실제로 돌았고 거의 전부 물러졌다는 뜻이다.** 왜 그랬는지 지금 아무 화면도 말하지 않는다.

⚠ **정책을 바꾸는 이 화면이 그 사실을 모르는 채로 있으면 안 된다.** 최소한 「지난 변경이 어떻게 됐는지」로 이어지는 길을 둔다.

**(나) 공급처 0곳 상품은 정책을 바꿔도 안 움직인다**

`_reprice()` 가 공급처 배열이 비면 즉시 반환한다. **영향 미리보기에서 그 상품들을 「해당 없음」으로 갈라 세야 한다** — 안 그러면 「N건이 바뀝니다」가 거짓이 된다.

**(다) `save_pricing` 은 즉시 유효해진다**

제작자 보고: **살아 있는 이력 표에 새 행을 만들고 즉시 유효 마진율이 된다.**
⚠ **미리보기 단계에서 이 API 를 부르면 안 된다.** 미리보기 전용 경로가 필요하다(있는지 조사 중).

## ✅ 사장님 확정 (2026-08-15) — **최종**

    ① 분류 축      **`categories` 트리 그대로** — 지금 표(`category_margin_policies.category_id`)가
                   이미 그 축이다. 새 표·마이그레이션이 필요 없다
                   ⚠ 「부품 종류별」은 **철회**됐다 — 스키마가 그 축이 아니라는 실측 때문이다
    ② 범위        **마진 정책으로 «모은다»** — 전역 마진 · 분류별 예외 ·
                   카드수수료 · 배분율을 **한 자리에**
    ③ 배분율       **같은 화면에서 다룬다**
    ④ 카드수수료   **여기서 고칠 수 있게 한다**

### ① 분류 트리 — 무엇이 따라오나

**행이 정해졌다.** `categories` 트리 — **깊이 2단 · 최상위 6 · 하위 28 · 총 34행.**

    부품 13,308 · 주변기기 4,605 · 쿨링·튜닝용품 1,668
    기타 1,628 · 확장·연결 1,207 · 완제품 422

⚠ **미매핑 2건**(`category_id IS NULL`) — 화면이 그 사실을 밝힌다(전역값이 걸린다).
⚠ **상속이 이미 돈다** — 자기 노드 → 부모로 거슬러 → 전역(`api/pricing.py:49-71`, 회귀 `[40]` 통과).
   **화면이 「이 값이 어디서 왔나」(자기/부모/전역)를 보여줘야 한다** — API 가 `source` 를 이미 준다.

### ② 「마진 정책으로 모은다」 — 무엇이 따라오나

**⚠ 「상품 분류 관리」의 마진 칸을 «가리키게» 바꿔야 한다.**

    지금        /admin2/categories 가 `PUT /categories/{cid}/margin` 으로 **직접 고친다**
                (`templates/admin/product_category.html.j2:870-885`)
    바뀔 것     그 칸은 **읽기 전용 + 「마진 정책에서 보기」 링크**로
                — 두 곳에서 같은 값을 고치면 어느 쪽이 맞는지 모르게 된다

⚠ **API 자체(`PUT /categories/{cid}/margin`)는 그대로 쓴다.** 새로 만들지 않는다.
⚠ **「추천 기준 보기」의 잠긴 배분율 편집도 여기를 가리키게** 바꾼다(같은 이유).

**결과적으로 이 화면이 손대는 값 넷:**

    전역 마진 · 카드수수료   pricing_settings   POST /api/admin/pricing-settings   owner만
    분류별 예외              category_margin_policies   PUT /categories/{cid}/margin   owner+operator
    배분율                   candidates.BUDGET_ALLOC   **코드 상수 — 쓰기 경로가 «없다»**

⚠⚠ **배분율은 지금 DB 에 없다.** 편집을 열려면 **코드에서 DB 로 옮기는 작업이 선행**된다.
   그전까지는 **읽기 전용 + 「향후 사용예정」**으로 두고, 화면이 그 사실을 밝힌다.

## ⚠⚠ 반드시 함께 처리해야 하는 것 둘 — 안 하면 화면이 거짓말한다

**(가) 「가격 검토 대기」와 「단가표 반영」이 분류별 마진을 «안 읽는다»**

    admin_price_review.py:62    _settings()  ← **전역만**
    admin_price_import.py:180   _settings()  ← **전역만**
    resolve_margins / category_margin_policies 를 **부르지 않는다**(전수 grep)

**즉 분류별 마진을 걸어도 그 두 경로는 전역값으로 계산한다.**
⚠ **의도인지 누락인지 코드·회귀·결정 로그 어디에도 근거가 없다**(조사자 확인).

    고치거나        두 경로도 `resolve_margins` 를 쓰게 한다
    화면이 밝히거나  「분류별 마진은 «대량 재산정»에만 적용되고
                    가격 검토 승인·단가표 반영에는 전역값이 쓰입니다」

**둘 중 하나는 «반드시» 해야 한다.** 안 하면 운영자가 분류별 마진을 걸어 두고 왜 안 먹는지 모른다.

**(나) 미리보기 API 가 없다**

`GET /reprice/preview` 는 **이미 저장된** 값으로만 계산한다. **가상의 새 마진을 인자로 못 받는다.**
`PricingBody`·`MarginBody` 둘 다 `dry_run`/`preview` 파라미터가 없다.

**§⑥ 이 요구한 2단계 강제(미리보기 → 확인 → 저장)를 지키려면 새 경로가 필요하다.**
⚠ **없는 채로 지으면 「저장 → 확인 → 되돌림」이 되는데, 분류 마진은 «되돌리기 API 자체가 없다»**
(`api/admin_ui_product_category.py:13-14` 가 「실측 0건」이라 명시).

### ② 배분율 같은 화면 — 무엇이 따라오나

⚠ **「추천 기준 보기」(ADM-ENG-020)의 잠긴 편집이 «여기로» 옮겨온다.**
그 화면은 지금 「배분율 · 티어 정렬 기준 편집 — 향후 사용예정」으로 잠가 두고 있다.

    이 화면이 열리면   그 잠금을 풀지 말고 **여기를 가리키게** 바꾼다
                       (두 곳에서 같은 값을 고치면 어느 쪽이 맞는지 모르게 된다)

**배분율 실측값**(`candidates.BUDGET_ALLOC` — 코드 상수):

    그래픽카드 40% · CPU 25% · 메인보드 15% · SSD 12% · 메모리 10%
    파워 10% · HDD 8% · 케이스 8% · 공랭 쿨러 8% · 수랭 쿨러 8%

⚠ **화면이 이미 밝히고 있는 사실 둘** — 여기서도 지킨다:
> "이상"이나 숫자 없는 예산 표현("AI 추천 예산" 등)에는 이 배분율이 **적용되지 않습니다.**
> **가성비형은 배분율을 받지 않습니다** — 최저가를 고르는 티어에 「비싼 부품 차단」 상한은 무의미하다.

### ③ 카드수수료 편집 — ⚠ 영향 범위가 마진보다 «크다»

**마진은 분류별로 갈리지만 카드수수료는 전 상품 공통**이다.
**2.585% 를 한 번 바꾸면 제안가가 전부 움직인다.**

**그래서:**
- **마진 변경과 «같은» 2단계 강제**(미리보기 → 확인 → 저장)를 쓴다
- ⚠ **미리보기가 「전 상품 N건」을 말해야 한다** — 분류별 마진과 영향 범위가 다르다는 것을 화면이 드러낸다
- ⚠ **카드사와의 계약값이다** — 화면이 그 사실을 밝힌다(임의로 바꿀 값이 아님을 운영자가 알게)

## 아직 미정 — 디자인 전에 정해도 되고, 제작 중에 정해도 된다

| 무엇 | 지금 아는 것 |
|---|---|
| 마진율 상한 | 스키마는 `CHECK(0 ≤ x < 1)` 즉 **0% 허용 · 100% 미만**. 화면이 더 좁힐지는 미정 |
| 권한 비대칭을 맞출까 | 전역은 **owner만**, 분류는 **owner+operator**. 한 화면에 모으면 어색해진다 |
| 미리보기 API 를 새로 만들까 | **만들어야 2단계 강제가 성립한다**(위 §(나)). 안 만들면 화면이 그 사실을 밝혀야 한다 |
| 분류별 마진 되돌리기 | **API 자체가 없다.** 만들지 안 만들지 |
