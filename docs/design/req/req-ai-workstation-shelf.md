## ① 화면 성격

**고객 대화형 견적 화면(A-128 · `/mvp2/`)의 격자 카드 아래에 붙는 진열 한 줄.**
독립 화면이 아니라 **조건부 부속 영역**이다.

| 축 | 격자 카드(기존) | AI 워크스테이션 진열(이 문서) |
|---|---|---|
| 원천 | 엔진이 조립한 8부품 견적(`grid_quotes`) | 사장님이 구성해 파는 **몰 완제품 1개**(`products`, `part_type='PC_COMPLETE'`) |
| 성격 | 부품 교체 대상(③ 스왑 대화층) | **교체 대상 아님** — 상품 그대로 |
| 다음 행동 | 「이 구성으로 조정하기」 → 대화로 부품 교체 | 몰 상품 페이지 이동 **또는** 상담 인계 |
| 노출 | 항상(용도가 격자 용도로 대응될 때) | **조건부** — 용도 = AI 작업 AND (예산 없음 또는 예산 ≥ 550만) |

**격자에 섞지 않는다.** 격자 카드는 최대 3장이고 그 규칙(중심 티어 + 위 2개)은
바뀌지 않는다. 진열은 그 아래 별도 줄이다.

## ③ 정의 — 이 영역이 없으면 무엇이 안 되는가

1. **550만 이상 AI 용도 고객에게 «팔 수 있는 완제품»이 화면에 없다.** 격자는
   `팝콘 X`(800만~1,500만)가 상한이고 그 안에서도 부품 조립 견적만 낸다. 몰에는
   AI 라벨 완제품 26종(598만~2억 2,546만)이 이미 판매중인데 고객 화면 어디에서도
   닿지 못한다.
2. **1,500만 초과 구간(H100 등)의 응답이 없다.** 격자 티어 밖이라 격자 카드가 0장
   또는 예산 초과 카드만 나온다. 진열은 티어 경계와 무관하게 상품 가격으로만 고르므로
   이 구간이 **자연스럽게 노출**된다.
3. **「조립 견적」과 「완제품」의 구분이 화면에 없으면 고객이 완제품을 부품 교체
   대상으로 오해한다.** 진열을 격자와 다른 줄에 두는 이유다.

**이 영역이 하지 않는 것**: 부품 교체 · 견적 저장 · 결제 · 재고 차감. 완제품은
몰 페이지 또는 상담 인계로 넘어간다(A-11 「팝콘AI는 유입 채널, 판매하지 않는다」 유지).

판정하지 않는다.

### 4-2. 신설 API 계약 — `GET /api/grid/workstations`

**읽기 전용(SELECT 만) · 인증 없음 · 세션·원장 기록 없음** (`grid_public.py` 와 같은 등급).

#### 입력(쿼리 파라미터)

| 이름 | 형 | 필수 | 뜻 | 검증 |
|---|---|---|---|---|
| `usage` | string | 예 | 파서(`talk.py`)가 낸 용도 라벨. 이 API 는 **`AI 작업`** 만 받는다 | 다른 값 → `ok:true, items:[], shown:false, reason:"usage_not_ai"` (400 을 내지 않는다 — 격자 API 관례 「부족한 것은 말로 한다」) |
| `budget_won` | integer | 아니오 | 예산(원). 없으면 「예산 미언급」 | 0 이하·정수 아님 → 없는 것으로 본다 + `note` 에 사유 |
| `budget_bound` | string | 아니오 | `이상`·`이하`·없음 — 격자 API `parse_budget()` 이 낸 값 그대로 | 이 API 의 판정에는 쓰지 않는다(예산 값 하나로 고른다). 받아서 응답에 되돌려 준다 |

호출자(화면)는 격자 API 응답의 `budget_won`·`budget_bound`·`usage_grid` 를 그대로 넘긴다
— 예산 문자열 파싱을 두 곳에서 하지 않는다.

#### 노출 조건(서버 판정 · 사장님 확정 2026-09-13)

    shown = (usage == "AI 작업") AND (budget_won is None OR budget_won >= 5_500_000)

`5,500,000` 은 **`팝콘 9` 의 `budget_min`** 이다(`0082` `TIERS_2026H2`). 리터럴을 API 에
박지 않고 `grid_cells` 에서 `팝콘 9` 의 `budget_min` 을 읽는다(격자 API `_load_tiers()` 와
같은 이유 — 티어 경계가 바뀌면 이 API 는 고칠 것이 없다). 응답 `threshold_won` 에 그
값을 싣는다.

#### 선정 규칙(서버 · `shown = true` 일 때)

| 경우 | 선정 | 정렬 | 건수 상한 |
|---|---|---|---|
| **예산 있음** | ㉮ `sale_price <= budget_won` 인 상품 **전부** + ㉯ `sale_price > budget_won` 인 상품 중 가격이 낮은 **2개**(`over_budget: true`) | `sale_price` 오름차순(㉮ 뒤에 ㉯) | ㉮ 상한 없음(현 데이터 최대 26) · ㉯ 정확히 2 이하 |
| **예산 없음** | 가격 오름차순 **5개** | `sale_price` 오름차순 | 5 |

- 동가(同價)일 때 2차 정렬 = `product_code` 오름차순(재현성 — A-02).
- 재고 0 상품도 **빼지 않고** `in_stock:false` 로 표시한다(격자 API 의 부품 `in_stock`
  관례와 같다 — 저장 시점 재고를 믿지 않고 요청 시점 `stock_qty` 를 읽는다).
- 예산 초과 ㉯ 는 「바로 위 2개」다 — 예산 안 상품이 0건이어도 ㉯ 는 2개까지 나온다
  (⑦ 빈 상태 참조).

#### 출력

```json
{
  "ok": true,
  "shown": true,
  "reason": null,
  "usage": "AI 작업",
  "budget_won": 8000000,
  "budget_bound": null,
  "threshold_won": 5500000,
  "items": [
    {
      "product_code": 123456,
      "name": "팝콘PC AI 워크스테이션 …",
      "price": 5980000,
      "spec": { "cpu": "14900K", "ram_gb": 64, "ssd": "1TB", "gpu": "RTX5090", "gpu_count": 1 },
      "in_stock": true,
      "stock_qty": 1,
      "over_budget": false,
      "mall_url": "https://popcornpc.co.kr/shop/product_detail.html?pd_no=123456"
    }
  ],
  "counts": { "within_budget": 3, "over_budget": 2 },
  "note": ""
}
```

| 필드 | 형 | 뜻 |
|---|---|---|
| `ok` | bool | 항상 `true`(서버 오류만 5xx). 판정 실패는 `shown:false` + `reason` |
| `shown` | bool | 노출 조건 충족 여부. `false` 면 화면은 **영역 자체를 그리지 않는다** |
| `reason` | string\|null | `shown:false` 사유 코드 — `usage_not_ai` · `budget_below_threshold` · `usage_missing` |
| `usage` · `budget_won` · `budget_bound` | 입력 되돌림 | 화면 디버그·재현용 |
| `threshold_won` | int | 노출 하한(원) — `grid_cells` 팝콘 9 `budget_min` |
| `items[]` | array | 선정 규칙 순서 그대로. 화면이 재정렬하지 않는다 |
| `items[].product_code` | int | = 몰 `pd_no` |
| `items[].name` | string | `product_name` 에서 HTML 태그 제거 후(`display_name()`). 사양 문자열 `[…]` 은 **떼지 않는다**(현 상품명이 그렇게 팔리고 있다 — 뗄지는 ⑦-B) |
| `items[].price` | int | `sale_price`(원) |
| `items[].spec` | object | `builtpc_spec` 그대로 — `{cpu, ram_gb, ssd, gpu, gpu_count}`. 비어 있으면 `null`(지어내지 않는다) |
| `items[].in_stock` | bool | `stock_qty > 0`(요청 시점) |
| `items[].stock_qty` | int | 원값 |
| `items[].over_budget` | bool | 예산 있음일 때 ㉯ 여부. 예산 없음이면 항상 `false` |
| `items[].mall_url` | string | `https://popcornpc.co.kr/shop/product_detail.html?pd_no=<product_code>` — `api/mall.py:26 DETAIL` 형식. ⚠ 완제품 상품에 대해 이 경로가 실제로 열리는지는 **미실측**(⑦-B) |
| `counts` | object | `within_budget`(㉮ 건수) · `over_budget`(㉯ 건수). 예산 없음이면 `within_budget:null` |
| `note` | string | 사람이 읽는 부연(격자 API 와 같은 관례). 예: 「0088 미적용 — builtpc_kind 없음」 |

**넣지 않는 것**: 이미지·영상(A-128 ④ 단계 소관 · `product_media` 바인딩 뒤에 붙인다) ·
격자 티어명(완제품은 티어가 없다) · 부품 목록(교체 대상이 아니다).

### 4-3. 인계 API(기존 · 상담 인계 경로)

`POST /api/handoff`(`api/handoff.py:78`) 는 **`session_id` + `tier` + 주변기기**를 받아
격자 견적을 몰 장바구니로 넘기는 계약이다 — **완제품 1개를 넘기는 자리가 없다**
(`HandoffBody` 에 `product_code` 없음). 진열의 「상담 인계」가 이 API 를 그대로 쓸 수
없으므로 **⑦-B 미정**으로 올린다. 이 정의서는 새 인계 계약을 정하지 않는다.

## ⑤ 기능 (동사)

1. 격자 응답을 받은 뒤 **같은 조건**(`usage_grid`·`budget_won`·`budget_bound`)으로
   `GET /api/grid/workstations` 를 **조회한다**.
2. `shown:true` 일 때 격자 카드 아래에 진열을 **표시한다**. `shown:false` 면 영역을
   **표시하지 않는다**(빈 틀도 두지 않는다).
3. 각 상품의 이름 · 가격 · 사양(`spec`) · 재고 · 예산 초과 표시를 **보인다**.
4. 상품에서 몰 상품 페이지(`mall_url`)를 **새 창으로 연다**.
5. 상품에서 상담 인계를 **요청한다** — 인계 수단은 ⑦-B 결정 전까지 **비활성**
   (눌러도 반응 없는 버튼을 두지 않는다 — `CANON` 「화면이 무엇이 없는지 밝힌다」).
6. 조건(예산·용도)이 대화로 바뀌면 격자와 함께 **다시 조회한다**.

**하지 않는 일**: 부품 교체 대화로 진입 · 견적 저장 목록에 담기 · 가격·재고 재계산.

## ⑥ 인터랙션 — 입력 · 선택 · 이동의 흐름과 결과

| 입력·동작 | 결과 |
|---|---|
| 한 줄 입력 → 파서 → 격자 조회 완료 | 격자 카드 렌더 뒤 진열 API 호출. **격자 카드는 진열 응답을 기다리지 않는다**(진열 실패가 격자를 막지 않는다) |
| 진열 응답 `shown:true` | 격자 아래 한 줄로 표시. 첫 문구 예: 「팝콘PC AI 워크스테이션 · 조립 견적과 별도의 완제품」 — 격자와 성격이 다름을 **문구로 밝힌다** |
| 진열 응답 `shown:false` | 영역 없음. 안내 문구도 없다(고객이 요구하지 않은 것을 설명하지 않는다) |
| 상품 선택 | 몰 상품 페이지를 새 창으로 연다. 현재 화면·대화 상태는 유지 |
| 「상담 인계」 선택 | ⑦-B 결정 전 비활성 + 사유 문구 |
| 대화로 예산 변경(예: 「예산 1,000만으로」) | 격자 재조회와 함께 진열 재조회. 예산이 550만 미만이 되면 진열이 **사라진다** |
| 대화로 용도 변경(AI 작업 → 게임) | 진열이 사라진다 |
| `over_budget:true` 상품 | 「예산 초과」 표시를 붙인다. 빼지 않는다(격자 카드 `over_budget` 관례와 같다) |
| `in_stock:false` 상품 | 「재고 없음」 표시를 붙인다. 몰 이동은 막지 않는다(품절 여부 최종 판정은 몰 페이지) |

### ⑦-B 미정 — 사장님 확인 항목

| # | 항목 | 선택지 · 상태 |
|---|---|---|
| W-1 | **몰 상품 페이지 경로** | `api/mall.py:26` `DETAIL = /shop/product_detail.html?pd_no=%s` 형식이 부품 상품에서 실측됐다. **완제품(PC_COMPLETE)도 같은 경로로 열리는지 미실측** — 사장님 확인 또는 제작자가 1건 실호출로 확인 |
| W-2 | **상담 인계 수단** | 기존 `POST /api/handoff` 는 격자 견적 전용(`session_id`+`tier`) — 완제품 1개를 담을 자리가 없다. ㉮ 인계 API 에 `product_code` 단건 경로 신설 / ㉯ 몰 페이지 이동만 두고 인계 없음 / ㉰ 전화·문의 안내 문구만. 결정 전 화면의 「상담 인계」는 비활성 |
| W-3 | **상품명의 `[CPU/RAM/SSD/GPU]` 사양 문자열** | `builtpc_spec` 이 사양을 따로 주므로 이름에서 ㉮ 남긴다(몰과 같은 이름) / ㉯ 뗀다(중복 표시 제거). 이 문서의 계약은 ㉮(떼지 않음) |
| W-4 | **영역 ID** | 고객단에 화면 내 영역 ID 관례 없음. 부여 여부 |
| W-5 | **예산 없음 5개의 기준 재확인** | 「가격 오름차순 5개」 = 최저가 5종. AI 워크스테이션 최저가대(598만~)가 예산 미언급 고객에게 맞는 첫 진열인지 — 사장님 확정대로 적었고 대안은 두지 않는다. 실사용 후 재검토 시점만 남긴다 |
| W-6 | **0088 적용 시점** | DBA 작업 중. 적용 전 API 는 0건 + note. 이 정의서는 **컬럼 이름·jsonb 키를 DBA 가 만드는 그대로 따른다** — 이름이 달라지면 이 문서 4-1·4-2 를 고친다 |

## 비범위 — 이 영역이 하지 않는 일

- **부품 교체 대화(A-128 ③)에 완제품을 넣지 않는다.** 완제품은 스왑 엔진의 입력이 아니다.
- **결제·재고 차감·회원**을 하지 않는다(A-11 유지). 몰 또는 상담으로 넘긴다.
- **AI 외 용도의 완제품 진열**을 다루지 않는다. 사장님 확정은 「용도 = AI 작업」 하나다.
  게임용 완제품 등이 생기면 별도 정의서.
- **이미지·영상**을 다루지 않는다(A-128 ④ 단계 소관).
- **관리자 화면**(builtpc 표시·해제)을 다루지 않는다 — 상품 조회/수정(ADM-PRD-010) 소관.
