# 요구사항 정의서 — 상품 매트릭스 관리(ADM-GRD-010, 스펙 축 갱신)

작성일 2026-09-15 · 대상: 관리자 화면 `/admin2/grid`(기존 `api/admin_grid.py` +
`api/admin_ui_grid.py` + `templates/admin/grid.html.j2`, 2026-09-07 신설·
2026-09-14 개명) · 근거: A-135(decision-log) · `req-grid-matrix-2026-09-15.md`
(고객단 정의서, 같은 물결) · 마이그레이션 0091(적용 완료)·0092(설계 중).

**이 문서가 담지 않는 것**: 화면 배치·색·컴포넌트. 기존 화면(그리드형 표 +
칸 클릭 서랍)의 **구조 골격**은 유지하되, 축이 바뀌는 지점만 새로 정의한다.
배치 세부는 사장님 담당(CLAUDE.md §화면 작업의 경계).

**폐기 안내**: `req-game-matrix.md`(ADM-GRD-020, 게임·AI 매핑 감사 화면)는
이번 전환으로 **폐기**한다. 사유는 §0.

## ⓪ 왜 ADM-GRD-020이 사라지는가

ADM-GRD-020은 `game_cell_map`·`workload_cell_map`(게임이 격자 칸 70개 각각에서
성립하는지 **사전 계산해 캐시로 저장**한 결과)을 감사하는 화면이었다 — "이
게임이 어느 칸에서 되는지"를 되짚어 계산해야 했기 때문에 생긴 화면이다.

A-135 전환 이후로는 게임 칸 자체가 `(game_grade, game_resolution)`으로
**직접 정의**된다(0091 `game_grade_assignments`가 게임→등급을 이미 고정
매핑). "이 게임이 성립하는 칸"을 찾는 문제가 "이 게임의 등급이 몇 칸(해상도
3종)에 이미 위치해 있는가"로 바뀌어, 별도 감사용 캐시(`game_cell_map`)와
전용 화면이 필요 없어진다. 게임별 등급 조회는 §④-4로 흡수됐다.

## ① 화면 성격

**조회 화면.** 격자(`grid_cells`+`grid_quotes`)의 현재 상태를 관리자가 훑어
본다. 쓰기 기능 없음(기존과 동일 — 재생성은 배치 도구 `tools/grid_generate.py`
전용). 이번 개정은 **축 구조**(무엇으로 칸을 나누는가)만 바꾼다.

## ② 제목·화면 ID

- `ADM-GRD-010`(기존 유지, 경로 `/admin2/grid`)
- API: `GET /api/admin/grid`(전체 조회) · `GET /api/admin/grid/cells/{cell_id}`
  (칸 상세) — 둘 다 기존 엔드포인트 그대로, 응답 형태만 갱신.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

기존과 동일: 운영자가 "이 용도·이 스펙 등급에서 실제로 뭐가 나오는지"를
SQL 없이 확인할 방법이 없어진다. 추가로, 이번 전환 이후엔 "이 게임 등급이
왜 이 스펙 티어에 배정됐는지"까지 이 화면에서 근거를 볼 수 있어야
한다(A-135의 "모든 견적에는 이유가 있습니다" 원칙 — 게임 등급 판정도 예외가
아니다).

## ④ 데이터 — 실측 근거

**신규 축(0091 적용 완료, 0092 설계 대상)**

- `spec_tiers`(6행, T0~T5) — `popcorn_name`(팝콘1~5·팝콘X, 2026-09-15
  사장님 확정), `gpu_vram_min_gb`·`gpu_watt_min`·`cpu_cores_min`·
  `ram_min_gb`·`ssd_min_gb`.
- `game_load_grades`(6행, E/A/B/C/S/L) — L은 이번 물결 신설(경량 캐주얼).
- `game_grade_resolution_tiers`(18행, 6등급×3해상도) — 등급·해상도 조합마다
  `gpu_tier_key`(필수) + `cpu_tier_key_override`(S등급만, GPU/CPU 비대칭
  표현 — 단일 `tier_key`로 못 담는다).
- `game_grade_assignments`(22/23행 배정 — GTA만 미배정, `grade IS NULL`로
  정직하게 남김).

**격자 저장소(0092 설계, 이번 작업 대상)**

- `grid_cells` 재설계 — 비게임 칸(72 = 6티어×6용도×2플랫폼)은 `tier_key`
  (FK→`spec_tiers`)를 쓰고, 게임 칸(36 = 6등급×3해상도×2플랫폼)은
  `game_grade`+`game_resolution`을 쓴다(`tier_key IS NULL`). CHECK로
  `usage='게임' ⟺ game_grade·resolution NOT NULL AND tier_key IS NULL` 강제.
  `budget_min/max`는 입력이 아니라 배치 결과 관측값(nullable로 전환).
- `grid_quotes` 재설계 — `tier_variant`(가성비/추천/고성능) 컬럼 추가,
  칸당 최대 3개 현재본(부분 유니크 `(cell_id, tier_variant) WHERE
  is_current`).

## ⑤ 기능 — 할 수 있는 일 (동사로)

기존 6개 유지 + 신규 2개:

1. **조회** — 격자 전체를 표로 본다(기존).
2. **필터** — 티어·용도·플랫폼으로 좁힌다(기존, 게임 칸은 용도='게임' 선택
   시 등급×해상도 하위 축으로 다시 좁힌다 — 신규 인터랙션).
3. **정렬/강조** — 행·열 머리 클릭으로 해당 줄 강조(기존, 클라이언트
   필터 아님).
4. **칸 상세를 본다** — 클릭 시 서랍에 구성·근거·판정 표시(기존).
5. **신규 — 3종 탭 전환** — 칸 상세 서랍 안에서 가성비/추천/고성능 탭을
   전환해 같은 칸의 세 구성을 비교한다(재조회 없음, 서버가 3행을 이미
   보냄).
6. **신규 — 게임 등급 근거를 본다** — 게임 칸(용도='게임') 상세에서
   `game_grade_assignments`가 어느 게임들을 이 등급에 배정했는지,
   그 근거 문서(`game-grades-2026-09-15.md`/`round2`)의 판정 사유 요약을
   함께 보여준다(ADM-GRD-020이 하려던 것 중 "근거 확인"만 이 화면
   상세 서랍으로 흡수).
7. **재생성 버튼**(전체·칸·실패 칸) — 기존과 동일하게 disabled +
   "향후 사용예정"(쓰기 API 여전히 범위 밖).

## ⑥ 인터랙션 — 입력·선택·저장·이동의 흐름과 결과

1. 화면 진입 → 격자 표(행=스펙 티어 6단 + 게임 등급 6단이 별도 구획,
   열=용도 6종 + 게임은 등급별 열 대신 해상도 3열).
2. **레이아웃 분기 필요**(신규 — 이 정의서가 남기는 결정 사항): 비게임
   영역(6×6)과 게임 영역(6×3)은 축의 성격이 달라 **하나의 표로 억지로
   합치지 않는다** — 두 구획으로 나누는 안을 권장하되 최종 배치는 UI
   설계 몫.
3. 칸 클릭 → 서랍 열림 → 3종 탭(가성비/추천/고성능) 중 기본은 "추천"
   먼저 보여주고 탭으로 전환.
4. 게임 칸 서랍은 추가로 "이 등급에 속한 게임" 목록(예: E등급 클릭 →
   리그오브레전드·서든어택·발로란트·오버워치2·FC온라인·배틀그라운드)을
   보여준다.
5. 필터·강조는 기존과 동일하게 클라이언트 사이드.

## ⑦ 상태·예외

- **빈 칸(intended_empty)**: 기존과 동일 — "의도적으로 비운 칸" 문구.
- **미생성**: 기존과 동일 — 현재본 없음.
- **게임 등급 미배정 게임**(GTA): 이 화면 소관이 아니지만, 등급 목록에
  "미배정 1건(GTA) — 재고값 없음·버전 특정 불가"를 참고 정보로 노출할지는
  UI 설계 판단(강제 아님).
- **S등급 GPU/CPU 비대칭**: 서랍 상세에서 "그래픽카드 기준 T2 / CPU 기준
  T4"처럼 두 축을 분리해서 보여준다 — 단일 스펙 티어로 뭉뚱그리면 거짓
  정보가 된다(§화면 정직성 원칙 그대로 적용).
- **권한**: 기존과 동일(`/api/admin/*` 공통 인증 미들웨어, 조회 전용이라
  등급 제한 없음).
