# 요구사항 정의서 — 대시보드 (admin2 재구축 대상)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **이 화면은 이미 도는 화면이다.** 목차(`INDEX.md`)의 「셸만」 넷 중 하나 — 새
> 사이드바(admin2 셸)를 입었지만 본문은 옛 Phoenix 그대로다. 아래 ③~⑤는
> **「지금 있는 것」과 「재구축하면 무엇이어야 하나」를 구분**해 적는다.
>
> 작성일 2026-08-14. 실측은 `http://127.0.0.1:8002/admin2/`를
> `GET /api/admin/auth/dev-login`으로 로그인한 세션으로 직접 열어(HTML 원문·자산
> 참조 확인) 확인했다. 이 화면은 **서버 API 를 한 건도 부르지 않으므로** 화면에
> 뜨는 숫자는 전부 예시값이고 재측정 대상이 아니다(④ 참조).

---

## ① 화면 성격

**조회 전용 관문(landing) 화면 — 지금은 배치 견본이다.** 로그인 후 `/admin2/`가
곧 첫 방문지가 되는 자리이지만, 실측 결과 **이 화면은 업무 데이터를 하나도 담고
있지 않다.** 상단에 화면 스스로 다음과 같이 밝히는 배너가 있다(실측 확인,
`templates/admin/home.html.j2` 58~60행 · 렌더 결과 동일):

> 「레이아웃 견본입니다. 아래 수치·그래프·표는 전부 Phoenix 템플릿의 예시값이고
> 팝콘PC 데이터가 아닙니다. 제목만 우리 것으로 바꿔 배치를 확인하기 위한
> 화면입니다 — 실데이터 연결은 다음 단계입니다.」

템플릿 주석도 같은 사실을 명시한다: *"이 화면은 지금 레이아웃 견본이다 …
실데이터 연결은 나중이다(사용자 결정: 기존 데이터를 연계하는 것은 큰 의미가
없음)."* 즉 지금 상태는 의도된 임시 단계이고, 이 정의서가 다루는 것은 그
"나중"의 내용이다.

넘기지만, **`templates/admin/home.html.j2`는 이 두 값을 전혀 참조하지 않는다**
(실측: 템플릿 전문에서 `built`·`next_steps` 매치 0건). 즉 라우트 파일의 문서화
개념("재구축 현황판")과 실제로 렌더되는 화면(Phoenix 이커머스 대시보드 견본)이
이미 갈라져 있다 — 코드는 옛 개념대로 남고 템플릿만 교체된 상태다. ID·문서 정리는
재구축 시 함께 확인이 필요하다(⑦ 결함 목록에도 기록).

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

**지금(견본) 상태 기준으로는 "없어도 달라지는 것이 없다"가 사실에 가깝다** — 화면
전체가 정적 마크업이고 클릭 가능해 보이는 요소 다수가 실제로는 동작하지 않는다
(⑦). 이 사실 자체가 재구축의 근거다: 로그인 직후 운영자가 보는 첫 화면이 아무
정보도 주지 못하고 있다.

**재구축하면 있어야 하는 것.** 이 프로젝트에는 이미 대시보드급 실집계를 반환하는
API 네 벌이 살아 있는데(`api/admin_dashboard.py`), **admin2의 어떤 화면도 이들을
부르지 않는다**(실측: `mockups/admin/index.html`·`mockups/shared/admin-panel.js`
— 옛 `/admin/*` 화면만 사용 중). 즉 "콘텐츠가 없어서 재구축을 못 하는" 상태가
아니라 **콘텐츠는 이미 있는데 admin2에 연결만 안 된 상태**다. 무엇을 보여줄지
자체(콘텐츠 기획)는 사장님 결정이 필요하지만(⑤ 하단), 후보가 되는 실측 데이터는
④에 그대로 옮긴다 — 화면이 숫자를 지어내지 않으려면 **이미 있는 원천에서
고르는 것**이 출발점이다.

16,247"·"신규 회원 356"·최근 후기 10행·"슬롯별 추천 가능 부품" 표의

예시값**이다(우리 상품명 일부만 후기 표에 손으로 끼워 넣었을 뿐 — 예:
"인텔 코어i5-14400F"). 이 수치들은 실제 값과 **어느 쪽으로도 대응 관계가 없다**
(예: 실제 오늘 주문 처리 대기가 57건이라는 근거는 어디에도 없다).

### 재구축 후보 — 이미 존재하는 API(실측 응답, 2026-08-14 스냅샷)

아래 넷은 이미 구현·배포돼 있으나 **admin2 화면 중 어느 것도 쓰지 않는
고아 상태**다. 화면이 이 값을 그대로 표시한다면 반드시 매 방문 시 재조회해야
한다 — 아래는 "이런 데이터가 있다"는 증거이지 화면에 박을 확정값이 아니다.

| 엔드포인트 | 반환 구조 | 실측 스냅샷(2026-08-14) |
|---|---|---|
| `GET /api/admin/dashboard` | `pending`(검수·가격검토·입고·환불·미매핑·미분류 대기 건수) · `flow`(오늘 적재·추천후보풀·오늘 상담/완료·주문 상태별) · `system`(AI 사용량·최근 활동로그 3건) | `pending.review=5156`·`price=0`·`inbound=15338`·`refund=0`·`unmapped=2`·`unclassified=4725` / `flow.pool_ok=3219`·`pool_core=12985`(24.8%)·`sessions_today=206`·`sessions_done=195` |
| `GET /api/admin/quote-quality` | 견적 성립률(누적) · 모드별(가이드/대화/음성) · 티어별 분포 · 재고 정합(`stock_qty=SUM(qty_delta)`) | `sessions=4701`·`quoted=4383`·`rate=93.2%`·`stock_drift=0`(정합 이상 없음) |
| `GET /api/admin/funnel` | 접속→AI문의→견적성공→S2도달→장바구니→구매 6단계 | `visit=1102`·`consult=815`·`quote=772`·`cart=null`(원천 테이블 없음)·`order=10` |
| `GET /api/admin/worklist` | 화면별 "지금 할 일" 8항목 + 이동 링크(`href`) + 합계 | `total=25247`건, 최다는 `inbound`(재고 입고, 15,338) · `category`(카테고리 매핑, 4,727) |

**주의 — 이 넷은 2026-07-16 A-10(자체 커머스) 체제 문서 기준으로 짜여 있다.**
`orders`·`payments`·`refunds`를 직접 쿼리한다(예: `dashboard.flow.orders_by_status`).
그런데 2026-08-11 확정 범위(`CANON.md` §3)는 "팝콘AI는 판매하지 않는다 — 몰로
인계"이고 인계 원장은 `orders`가 아니라 `handoffs`다. 즉 **이 API들은 이미 한 번
낡은 프레임을 담고 있다** — 재구축 시 그대로 가져다 쓰면 안 팔지도 않는 "주문
처리 대기"를 대시보드가 다시 말하게 된다. `worklist`의 각 `href`도
`review-queue.html`처럼 **구화면 파일명**이라 admin2 경로(`/admin2/reviews` 등)로
다시 매핑해야 하고, 그 대상 화면 자체가 admin2에 아직 없는 경우(가격 검토·재고
입고·매입 견적 등)도 많다 — 이동할 곳 없는 링크가 되풀이될 위험이 있다(⑦).

## ⑤ 기능 (동사)

### 지금 — 전무

정적 마크업이라 실제로 값을 바꾸거나 다른 화면으로 정상 이동하는 기능이 없다
(⑦에서 구체적으로 확인).

### 재구축 후 요구(내용 후보 — 콘텐츠는 사장님 결정 필요)

- 처리 대기 열람 — 검수·가격검토·입고·환불·카테고리 매핑 등 **지금 즉시 할 일이
  몇 건인지** 한눈에 본다(`worklist` 데이터 존재).
- 각 대기 항목에서 **해당 admin2 화면으로 이동**한다(admin2 경로가 있는 것만 —
  없는 대상은 이동을 걸지 않는다, 아래 ⑥).
- 오늘의 흐름 열람 — 오늘 상담·견적 성립·주문/인계 건수(`dashboard.flow` 계열
  데이터 존재, 단 인계 프레임으로 재정비 필요).
  \n- 시스템 활동(최근 운영자 조작 로그) 열람(`dashboard.system.recent_logs`
  데이터 존재).
- 견적 품질 열람 — 성립률·모드별 비중(`quote-quality` 데이터 존재).
- 유입 성과(깔때기) 열람(`funnel` 데이터 존재, 단 장바구니 단계는 원천이 없어
  `null` — 화면은 0이 아니라 "원천 없음"으로 구분해야 한다, 이미 API가 그렇게
  준다).

무엇을 **이 화면에 담을지**(콘텐츠 선정)는 이 문서가 확정하지 않는다 — 후보
데이터가 이미 있다는 사실까지만 밝힌다(사장님 결정 필요 지점 참조).

### 재구축 후 요구

- 각 항목·카드는 **이동 대상이 실제로 존재할 때만** 클릭 가능해야 한다.
  `worklist`가 주는 `href`를 그대로 쓰면 admin2에 없는 화면(가격 검토·재고
  입고·매입 견적·주문 처리 등)으로 잇게 되므로, **admin2 경로로 재매핑하고
  없는 대상은 비활성 처리**해야 한다(상품 관리 화면이 이미 이 방식을 쓴다 —
  `disabled` + `title="이 화면은 아직 admin2에 없습니다"`, `req-products.md`
  참조).
- 못 채우는 항목은 지우지 않고 「향후 사용예정」으로 두되 숫자·차트는 남기지
  않는다(`CLAUDE.md` §관리자 화면 규약 원칙 — 이 화면에 그대로 적용).
- 수치는 방문마다(또는 일정 주기로) 서버에서 다시 받는다 — 목업 시절 값을
  굳혀 두지 않는다.

## ⑦ 상태 · 예외

**실측으로 확인된, 지금 화면의 구체적 문제.** 재구축 시 반복하지 않아야 할
목록이며, 동시에 「지어낸 값이 사람에게 사실로 읽힌 전례」(`CLAUDE.md` §화면
정직성)가 이 화면에도 있는지 확인해 달라는 지시에 대한 답이다.

- **외부 CDN 지도 타일을 부른다(A-30 자체 호스팅 원칙과 어긋남).**
  `mockups/admin/assets/js/dashboards/ecommerce-dashboard.js` 2617~2618행:
  ```
  const tileLayerTheme = 'https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png';
  ```
  leaflet 라이브러리 자체(`leaflet.js`·`leaflet.markercluster.js` 등)는
  `/admin/vendors/`로 자체 호스팅돼 있지만, **지도 타일 이미지는 매 렌더마다
  CartoDB(`basemaps.cartocdn.com`)에서 받는다.** 이 지도는 대시보드 하단
  `id="map"` 자리에 실제로 렌더된다(가짜 좌표 15곳). `CLAUDE.md`의 "외부
  CDN — 아이콘 폰트를 통째로 받고 있었다 … 폰트·아이콘은 전부 자체
  호스팅한다(A-30)"과 같은 종류의 문제다.
- **존재하지 않는 Phoenix 템플릿 경로로 가는 링크가 45곳 있다(실측).**
  최근 후기 표의 상품·고객 열이 전부
  `href="apps/e-commerce/landing/product-details.html"`,
  `href="apps/e-commerce/landing/profile.html"`로 연결돼 있다(상대경로,
  `templates/admin/home.html.j2`에서 `grep -c` 실측 **45건**). 이 화면 주소
  (`/admin2/`) 기준으로 풀리므로 실제로는
  `/admin2/apps/e-commerce/landing/product-details.html`이 되고, **직접
  확인 결과 404**다(`curl` 실측: `product-details.html` 404, `profile.html`
  404). 다른 admin2 화면들은 "관련 화면이 아직 없으면 링크를 진짜
  `disabled`로 막고 이유를 `title`에 적는다"는 규약을 지키는데(상품 관리
  화면이 대표적), 이 화면은 그 규약 이전(Phoenix 원본을 그대로 들여온
  시점)의 상태로 남아 있다.
- **드롭다운·검색창·연도 선택 등도 정적이다.** "2026년 6월/7월/8월" 셀렉트,
  "전체 부품" 버튼, 후기 검색창 모두 값을 바꾸거나 걸러내는 동작이 없다
  (뒤에 붙는 스크립트는 차트를 그릴 뿐 이 위젯들과 배선돼 있지 않다).
- **로그인 여부와 무관하게 완전히 동일하게 보인다.** 페이지 라우트 자체엔
  인증이 없고, 이 화면은 API를 하나도 안 부르므로 미로그인 방문자도 로그인한
  운영자와 같은 화면을 본다(지금은 전부 예시값이라 위험이 없지만, 재구축 후
  실데이터를 붙이면 **로그인 상태 분기(401 처리)가 새로 필요**해진다 — 지금
