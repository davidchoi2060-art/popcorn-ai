# 요구사항 정의서 — 상품 관리 (admin2 재구축 대상)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **이 화면은 이미 도는 화면이다.** 목차(`INDEX.md`)의 「셸만」 넷 중 하나 — 새
> 사이드바(admin2 셸)를 입었지만 본문은 옛 Phoenix 그대로다. 다만 실측 결과
> **목록·조회·일괄 상태 변경은 실제 데이터로 동작한다** — "셸만"이 뜻하는 것은
> 시각적 틀(Phoenix idiom)이지 데이터가 전부 가짜라는 뜻은 아니다. 아래 ③~⑤는
> 「지금 되는 것」과 「재구축하면 무엇이 더 있어야 하나」를 구분해 적는다.
>
> 작성일 2026-08-14. `http://127.0.0.1:8002/admin2/products`를
> `GET /api/admin/auth/dev-login`으로 로그인한 세션으로 직접 열어 확인했다.
> ④의 수치는 그 시각의 실측 스냅샷이며, 화면은 이 문서의 숫자가 아니라 서버
> 응답만 써야 한다.

---

## ① 화면 성격

**상품 목록 조회 + 상태 일괄 변경 작업 화면.** `CLAUDE.md`(§관리자 화면 규약)는
이 화면(ADM-PRD-010)을 **"상품 작업의 유일한 진입점"**으로 규정한다 — 좌측
메뉴에 편집 화면을 따로 두지 않고, 상품명 클릭은 읽기 전용 상세, 목록의 [수정]은
편집으로 그 자리에서 전환하는 구조다.

**지금은 그 규정의 절반만 실현돼 있다.** 목록·검색·필터·상태별 탭·일괄 상태
변경은 실제 API로 동작하지만, **등록·상세보기·수정은 전부 화면에서 잠겨
있다**(2026-08-14 오늘 그렇게 고쳤다 — admin2에 대체 화면이 없어서다). 즉 지금은
"상품을 들여다보고 무더기로 상태만 바꾸는" 화면이고, "상품 작업의 유일한
진입점"이라는 정의는 아직 미충족이다.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

- **지금 있는 것이 없으면**: 상품 22,840건(④ 실측)을 상태·분류·제조사로 걸러
  보고, 추천 가능/검수대기/재고없음/가격검토 중 어디에 몇 건이 있는지 한 번에
  볼 방법이 없다. 상태를 무더기로 바꿀 방법도 없다.
- **재구축 후에도 있어야(추가돼야) 하는 것**: 상품 하나를 새로 등록하거나,
  상세를 열어 값을 고치거나, 사양을 채워 검수를 해소하는 일 — `CLAUDE.md`가
  이미 명문화한 상품 작업의 핵심 흐름 — 이 지금 admin2 어디에도 없다. 구
  `/admin/product-edit.html`이 그 일을 했으나 **P-09 방침(구 admin 전면
  동결)에 따라 지금은 410으로 막혀 있다**(실측: `curl` 응답 410). 이 화면이
  "유일한 진입점"이 되려면 그 기능이 admin2 안에 다시 서야 한다 — 되돌리는
  것이 아니라 admin2에 새로 짓는 것이다(`CLAUDE.md`: "필요한 기능이
  구화면에만 있으면 그 기능을 admin2에 새로 짓는 것이지, 구화면을 고치거나
  그리로 보내는 것이 아니다").

## ⑤ 기능 (동사)

### 지금 되는 것

- 상품을 검색한다(상품번호·SKU·상품명, 300ms 입력 지연 후 서버 질의).
- 분류·제조사로 거른다(둘 다 서버 질의 — 슬라이스 66 교정 이후 방식).
- 상태 탭(전체/추천 가능/검수 대기/재고 없음/가격 검토)으로 본다.
- 현재 페이지 안에서 열을 클릭해 정렬한다(상품명·분류·필수사양·재고·판매가·
  상태).
- 페이지를 넘긴다(서버 페이지네이션, 100건/페이지).
- 행을 선택해 상태를 일괄 변경한다(판매중/품절/단종/삭제대기 중 하나로,
  최대 2,000건).
- 검수 대기 상품은 행 메뉴에서 **검수 큐(`/admin2/reviews`)로 이동**한다(구현된
  admin2 화면으로 실제로 연결되는 유일한 이동).

### 잠긴 것(자리는 있으나 실제 admin2 화면이 없어 비활성)

- **상품 단건 등록** — 상단 버튼이 `disabled` + `title="이 화면은 아직
  admin2에 없습니다"`.
- **상세 보기** — 행 메뉴에서 `disabled`로 막힘.
- **수정** — 행 메뉴에서 `disabled`로 막힘.
- 재고 없음 상품의 "매입 견적으로" 이동, 가격 검토 상품의 "가격 검토로" 이동
  — 둘 다 대상 화면(`/admin2/sourcing`, `/admin2/price-review`)이 아직 없어
  `disabled`.

### 재구축 후 요구

`CLAUDE.md` §관리자 화면 규약이 이미 이 화면 하나에 요구하는 것들이 admin2에
다시 서야 한다 — 되돌리는 것이 아니라 새로 짓는 것이다(P-09):

- **상품 상세(읽기 전용, `?code=`)** — 상품명을 누르면 여는 자리.
- **상품 수정(`?code=&edit=1`)** — 목록의 [수정]으로 그 자리에서 편집 전환,
  저장하면 읽기로 복귀. 고친 필드는 `locked_fields`로 잠가 다음 적재가
  덮어쓰지 않게 한다.
- **상품 신규 등록(`?new=1`)** — 예시 값이 기본값으로 남지 않아야 한다(빈
  분류 선택 강제 등, 과거 실사고 재발 방지).
- **등록 전 유사 상품 검사** — 이미 있는 `GET /product-similar`(임계 0.97)를
  붙인다.
- **공급처별 매입가 입력** — 이미 있는 `POST/DELETE /{code}/suppliers`를
  붙인다.
- **사양 값 입력** — `PATCH /{code}/specs`로 검수 대기를 그 자리에서 해소한다.
- **분류(부품 종류) 변경** — `preview`로 영향(필요/제외 사양, 추천 진입·이탈)을
  먼저 보여주고 확인받는다(슬라이스 67 규약, API는 이미 있음).

이 항목들은 전부 **API는 이미 구현돼 있고 admin2 화면만 없는 상태**다(④ 표
참조) — 신규 백엔드 설계가 아니라 admin2 프런트 신축이 필요하다는 뜻이다.

## ⑥ 인터랙션 — 입력 · 선택 · 저장 · 이동의 흐름과 결과

- 검색어 입력 → 300ms 지연 후 1페이지로 서버 재조회.
- 분류·제조사 변경 → 즉시 1페이지로 서버 재조회.
- 상태 탭 클릭 → 서버 재조회 없이, 이미 받은 현재 페이지 안에서만 다시
  그린다(주의: KPI 배지는 **전체 집계**인데 탭 클릭으로 보이는 행은 **현재
  페이지뿐**이라 배지 수와 화면에 보이는 행 수가 다를 수 있다 — 목록 화면
  규약상 의도된 동작이나 재구축 시 이 차이를 안내 문구로 밝힐지 확인이
  필요하다).
- 행 선택 → 상단에 선택 건수·상태 선택 상자·[상태 바꾸기]가 나타난다(선택
  0건일 때는 "행을 선택하면 상태를 한 번에 바꿀 수 있습니다" 안내만 보인다).
- [상태 바꾸기] → 브라우저 확인 대화상자("N건을 '상태'로 바꿉니다.
  계속할까요?") → 승인 시 실행 → 성공하면 선택을 해제하고 목록을 다시
  받는다 → 실패하면 **서버가 준 사유를 그대로** 보인다(공용 헬퍼
  `popcornProgress.errText`, `if(!res.ok) return;` 같은 침묵 없음).
- 성공 응답은 **건수가 아니라 영향**을 말한다 — 예: "1,204건을
  '품절'(으)로 바꿨습니다 · 추천 후보 87건이 줄었습니다 · 잠긴 12건은
  그대로 뒀습니다."
- 검수 대기 행의 […] 메뉴 → "검수 큐로" 선택 시 `/admin2/reviews`로 이동한다
  (필터를 지정해 넘기지는 않는다 — 단순 이동).

## ⑦ 상태 · 예외

- **요청 전**: KPI 전부 "—", 데이터 원본 배지 "불러오는 중…", 탭 배지도 "—"
  (0을 사실처럼 보이지 않는다 — `STATE!=="ok"`이면 숫자를 아예 안 보임).
- **실패**: 배지가 "연결 안 됨"으로 바뀌고, 표는 "서버에 연결되지 않아 불러오지
  못했습니다."(`colspan=9` — 열 수 9개와 일치, 목록 화면 규약 확인됨).
  ⚠ **실측: 이 화면은 실패 사유를 구분하지 않는다.** `fetch`의 `.catch()`가
  네트워크 오류·401(세션 만료)·그 밖의 서버 오류를 전부 같은 "연결 안 됨"
  문구로 뭉뚱그린다(코드에 상태 코드 분기 없음). 같은 admin2 화면인 조립 호환
  조감도·작업 현황판은 401을 "세션 만료"로 별도 안내하는데, 이 화면만 그
  구분이 없다(⑦ 결함 목록에도 별도 기록).
- **빈 결과**: "조건에 맞는 상품이 없습니다."(필터 조합이 걸리지 않을 때).
- **일괄변경 자격 없음**: 이미 그 상태이거나 `status` 필드가 잠긴 상품은
  자동으로 빠지고, 응답 문구에 "잠긴 N건은 그대로 뒀습니다"가 붙는다(CANON
  목록 화면 규약 — "자격 없는 대상을 막지 않고 사유와 함께 건너뛴다" 충족
  확인).
- **상한 초과**: 2,000건 넘게 선택하면 안내 문구("한 번에 2,000건까지
  바꿉니다 — 나머지는 다시 선택하세요")가 뜨고, 실제로 넘겨 보내도 서버가
  잘라 처리하며 응답에 "상한 2,000건을 넘어 N건은 건너뛰었습니다"가 붙는다.
- **없는 상품 코드가 섞였을 때**: 응답에 "없는 상품 N건은 건너뛰었습니다"가
  붙는다.
- **바꿀 것이 전부 없을 때**: 400 "바꿀 것이 없습니다 — 이미 모두 그
  상태이거나 잠겨 있습니다".
- **잠긴 기능**(등록·상세·수정·매입견적·가격검토 이동): 진짜 `disabled` +
  `title="이 화면은 아직 admin2에 없습니다"` — 눌러도 반응 없는 버튼을
  그럴듯하게 보이게 두지 않는다(CANON 확인: 화면이 무엇이 없는지 스스로
  밝힌다).
- **권한 부족**(POST를 viewer 등급이 시도): 403 "권한이 부족합니다(필요:
  operator, 현재: viewer)"(공통 미들웨어 표준 문구).
- **일괄변경 되돌리기 부재(실측 결함)**: `bulkApply()`가 성공 시
  `BULK_UNDO=res.j.log_id`로 로그 ID를 받아 두지만, **이 변수를 읽어 되돌리기를
  거는 버튼이 화면 어디에도 없다**(전문 검색 확인 — `BULK_UNDO`는 대입만 되고
  참조되지 않는다). 서버 API(`/api/admin/products/bulk-status/undo`)는 이미
  있으므로, 화면만 잇지 않은 상태다.

## 비범위 — 이 화면이 하지 않는 일

- **상품 단건 등록·상세·수정을 지금 하지 않는다.** 위 잠긴 기능들은 이
  화면의 책임 범위이지만, 이 문서 시점에는 admin2 대체 화면이 없어 동작하지
  않는다(⑤ "재구축 후 요구"가 그 격차를 명시한다).
  \n- **사양 정의 자체를 다루지 않는다.** 어떤 필드가 있고 무엇이 필수인지는
  "조립 사양 표준"·"상품 사양 정의" 화면 소관이다. 이 화면은 필수 사양
  충족 여부만 배지로 보여준다(`spec_done`/`spec_total`, 실측 응답 필드).
- **검수 자체를 처리하지 않는다.** 검수 승인·반려는 "상품 사양 검수"
  (`/admin2/reviews`) 소관이며, 이 화면은 그리로 이동만 시킨다.

## 사장님 결정이 필요한 지점

1. **잠긴 다섯 기능(등록·상세·수정·매입견적 이동·가격검토 이동)의 재구축
   우선순위** — `CLAUDE.md`는 이미 "상품 관리가 유일한 진입점"이라 규정했으므로
   방향은 정해져 있으나, 어느 것부터 지을지는 확인이 필요하다.
2. **상태 탭 배지(전체 집계)와 화면에 보이는 행(현재 페이지)의 수가 다를 수
   있는 것을 안내할지** — 지금은 안내 문구가 없다.
3. **일괄변경 되돌리기 버튼을 이번에 추가할지** — 서버 API는 이미 있다.
