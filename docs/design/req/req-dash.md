# 요구사항 정의서 — 작업 현황판 (admin2, 이미 구축 완료)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> **이 화면은 목차(`INDEX.md`)에서 유일하게 「지음」(완전히 구축됨)으로 표기된
> 화면이다** — 「셸만」 넷과 성격이 다르다. 그래서 이 문서는 「지금 있는 것과
> 재구축하면 무엇이어야 하나」를 가르지 않는다 — 지금 있는 것을 그대로
> 기록한다. 이 정의서가 뒤늦게 채워지는 이유는 화면이 미완성이라서가 아니라,
> **정의서를 쓰기 시작하기 전에 지어진 다섯 화면 중 하나**이기 때문이다.
>
> 작성일 2026-08-14. `http://127.0.0.1:8002/admin2/dash`를 dev-login 세션으로
> 직접 열고, `GET /api/admin/dash/state` 응답을 실측했다.

---

## ① 화면 성격

**에이전트 팀 운용 화면 — 다른 화면들과 도메인 자체가 다르다.** 상품·가격·
사양·주문 같은 팝콘PC 업무 데이터를 전혀 다루지 않는다. 이 화면이 보여주는
것은 **이 리포지토리를 만드는 "제작팀"(Claude Code 세션과 그 서브에이전트들)
자신의 진행 상황**이다 — 사장님이 팀에게 말을 거는 자리다.

새 데이터 배선이 없다. Claude Code가 세션 대화 내용을 이미 디스크에 쌓고
있고(`~/.claude/projects/…/*.jsonl`), 이 화면은 그것을 **읽기만 한다.** 화면이
쓰는 것은 메시지 큐 파일(사람이 보낸 말을 세션이 나중에 읽도록 남겨 두는 것)과
메모 테이블(DB) 하나뿐이다.

**"도중에는 못 읽는다"는 한계를 화면이 스스로 먼저 말한다** — 단일 스레드
구조라 세션이 다른 일을 하는 중에는 새 메시지를 받을 수 없고, 턴이 끝나야
읽는다. 텔레그램과 같은 구조·같은 한계다.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

이 화면이 없으면 "지금 팀이 무엇을 하고 있는지"를 보려면 텔레그램이나
터미널뿐이다. 텔레그램은 **진행 중인 것을 실시간으로 못 보고**(끝나야
알림이 온다) **긴 내용을 못 읽는다.** PC 앞에 있을 때는 화면이 낫다 — 이
화면이 그 둘을 푼다.

|---|---|

## ⑤ 기능 (동사)

- 팀원 카드를 본다 — 이름·역할(정의 파일의 `role:` 그대로, 산문 설명이
  아니라 명사구 한 줄)·신호(대기/실행/지연/실패/완료)·오늘 처리 건수를
  같이 본다.
- 팀원 카드를 눌러 **그 팀원의 사건만** 걸러 본다(당일 전체 — 화면에 보이는
  최근 구간(창)에 없어도 서버가 당일 전사본 전체에서 찾아 준다).
- 오늘 처리한 것을 본다 — 커밋·팀원 완료/실행 중/지연/실패·도구 호출·
  사장님 발화·현황판으로 보낸 메시지 수(못 잰 항목은 숫자 대신 "못 쟀음"으로
  구분해서 본다).
- 진행 흐름(사건 스트림)을 본다 — 누가(사장님/클로드/도구 결과) 무엇을
  했는지 시각순으로.
- 흐름 표시를 조절한다 — 간략히(발화만 남기고 도구·결과 줄은 숨김) /
  화면 비우기(그 시점 이전 사건을 화면에서만 숨김, **기록 자체는 지우지
  않는다**) / 모두 보기(되돌림).
- 백그라운드 작업을 본다(최근 30분 창, 창 밖 건수는 숨기지 않고 "몇 건은
  표시하지 않음"으로 알림).
- 사건에서 메모를 저장한다.
- 메모를 다시 보낸다(큐 재투입 — 재실행 이력이 남는다: 재실행 횟수·마지막
  사용 시각).
- 메모를 지운다.
- 메시지를 보낸다(큐에 적재).
- 감시자가 살아 있는지 확인한다.

## ⑥ 인터랙션

- 화면을 열면 즉시 조회하고, 이후 **SSE로 전사본 변화를 감지**해 자동
  재조회한다(SSE가 끊기면 3초 폴링으로 대체 — 폴백은 한 번만 세팅돼
  타이머가 겹쳐 쌓이지 않는다).
- 메시지 전송: 입력 → [보내기] → **버튼이 즉시 잠긴다**(중복 전송 방지) →
  성공 시 "전달 완료 · 작업 완료 후 읽음"(주의: "실행 완료"라고 말하지
  않는다 — 큐에 들어갔을 뿐 아직 세션이 처리했다는 뜻이 아니다) → 전달
  대기 큐가 있으면 그 사실을 계속 보여주다가, 세션이 읽어 큐가 비면 "읽음
  처리됨"으로 바뀐다. 응답이 8초 안에 없으면 "응답 없음 · 재시도 필요"로
  풀린다(무한 대기 없음). 버튼 잠금은 성공·실패·시간초과 **세 경로 모두에서
  풀린다**(한 경로에만 걸었다가 잠긴 채 남은 전례가 있어 이중으로 막음).
- 팀원 카드 클릭 → 로컬에서 즉시 다시 그리고, 이후의 모든 갱신(SSE·폴링)이
  `?agent=` 파라미터를 붙여 **서버가 당일 전사본 전체에서** 그 팀원 것만
  다시 모아 준다(화면에 보이는 최근 구간(창)만 걸러서는 이른 시간대 활동을
  놓치는 결함이 있었고, 지금은 그 결함이 고쳐진 상태 — 코드 주석에 결함
  이력이 남아 있다).
- 사건 행에 마우스를 올리면 [메모] 버튼이 나타나고, 누르면 그 사건의 내용을
  저장한다.
- 메모 목록의 [보내기]는 그 메모 내용을 다시 큐에 넣는다(재실행) — [삭제]는
  메모를 지운다(원장이 아니므로 삭제를 열어 둠).

## ⑦ 상태 · 예외

- **전사본 없음**: `{"ok": false, "reason": "세션 전사본 없음", "dir": "…"}`
  — 화면은 어느 디렉터리를 찾았는지 그대로 보여준다.
- **세션 만료(401)**: "세션 만료 — 로그인 필요"(상태 코드로 구분해서
  안내하는 화면 — 조립 호환 조감도와 함께 이 구분을 갖춘 둘뿐이다).
- **감시자 끊김**: 메시지 전송 자체는 막지 않되, 상단에 상시 경고가 뜬다
  ("감시자 ● 끊김 — 대시보드에서 보낸 메시지가 전달되지 않습니다") — 실측:
  이 문서 작성 시점에 실제로 이 상태였다(`watcher.alive=false`). 결과 없이
  조용히 사라지는 요청을 만들지 않는다는 뜻.
- **팀원 정의가 없음**(`.claude/agents/` 비어 있음): "팀원 정의가 없습니다
  — .claude/agents/".
- **정의에 없는 이름이 전사본에 등장**: 카드를 숨기지 않고 "정의 없음"으로
  뒤에 붙여 보여준다(단, Claude Code 기본 제공 서브에이전트 셋
  (`general-purpose`/`Explore`/`Plan`)은 예외적으로 별도 카드를 만들지 않고
  "하네스" 카드에 합산한다 — 과거에 이걸 몰라 "하네스" 카드가 둘 서는
  결함이 있었고 고쳐졌다, 코드 주석에 결함 이력 명시).
- **응답 지연/무응답**: 메시지 전송 8초 무응답 시 재시도 안내로 풀린다.
- **백그라운드 작업 창(30분) 밖의 파일**: 목록에서 빠지되 몇 건이 빠졌는지
  숫자로 알린다 — "없다"와 "창 밖에 있다"를 구분한다(오래된 파일이 "지금
  도는 작업"처럼 맨 위에 앉는 전례를 막기 위함).
- **"지연" 판정**: 팀원 호출이 시작된 지 10분(600초)이 넘도록 결과가 없으면
  "지연"으로 표시한다 — 기준 근거는 "오늘 실측에서 가장 긴 단일 작업이
  회귀 8분이었고, 10분이면 물린 것"이라는 실측 판단(코드 주석).
- **못 잰 값은 0이 아니라 "못 쟀음"**: 예를 들어 커밋 수를 `git log`로 못
  구하면(오류) `null`이고, 화면은 "0건"이 아니라 "못 쟀음"으로 구분해
  보여준다 — 0과 "모른다"를 섞으면 "오늘 아무 일도 없었다"는 거짓이 된다.
- **권한 부족**: 미로그인 401. 메시지 전송(POST)을 viewer 등급이 시도하면
  403.

## 비범위 — 이 화면이 하지 않는 일

- **코드 수정·배포를 직접 하지 않는다.** 이 화면은 관측(읽기)과 메시지
  큐잉만 한다 — 실제 작업은 로컬 PC에서 켜져 있는 Claude Code 세션이
  사람 판단으로 수행한다.
- **서브에이전트 내부 도구 호출을 보여주지 않는다.** 전사본에는 서브에이전트
  자신이 무엇을 했는지가 기록되지 않는다 — "백그라운드 작업" 패널이 보여주는
  것은 출력 파일뿐이고, 그마저 서브에이전트와 일반 백그라운드 셸 명령을
  구분하지 못한다(위 ④ 표에서 명시).
- **전사본을 고치지 않는다.** 읽기만 한다 — "화면 비우기"도 표시만 조절할
  뿐 기록은 그대로 남는다.

## 사장님 결정이 필요한 지점

없음 — 이 화면은 이미 지어졌고, 이 문서의 목적은 빠져 있던 요구사항 정의서를
사후에 채우는 것이라 이 화면 자체에 대한 미결 설계 결정은 실측 범위에서
확인되지 않았다. 다만 재차 밝힌다: 이 화면은 재구축 대상이 아니므로, 이
정의서는 향후 변경 시 참조용 스냅샷의 성격이 강하다.
