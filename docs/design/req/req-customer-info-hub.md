## ① 화면 성격

**견적 트랜잭션 흐름과 소비 패턴이 다른 독립 섹션.** 기존 고객 흐름
(게이트웨이 → S0~S5 → 인계 → MY, `mvp1`/`mvp2`)은 "목표를 갖고 들어와 빠르게
끝내는" 흐름이다. 이 섹션은 **목적 없이 둘러보다가 판단이 서면 견적으로
진입하는** 흐름이다 — 블로그·커뮤니티 성격의 **콘텐츠 허브**.

| 축 | 기존 견적 흐름(S0~S5) | 이 섹션(정보 허브) |
|---|---|---|
| 진입 동기 | "견적 내야 한다"는 목적이 이미 있음 | 목적 없이 둘러봄 — 게임 정보·용도 가이드·이미지/영상·팝콘AI 소개를 소비 |
| 원천 | 엔진이 조립한 견적(`grid_quotes`) | 콘텐츠(게임 카드 · 용도별 설명 · 미디어 · 소개) |
| 다음 행동 | 부품 확정 → 인계 | 콘텐츠 소비 → (판단이 서면) 견적 흐름으로 **진입** 또는 문의 등록 |
| 판매 관계 | A-97 그대로: 팔지 않는다, 구매 순간 쇼핑몰 인계 | 같음 — 이 섹션도 **유입 채널**이지 판매 채널이 아니다 |

**격자/대화 화면(mvp2)에 섞지 않는다.** 이 섹션은 별도 진입점을 갖는 형제
위치다(③-3 참조) — `mvp2`의 견적 대화 안에 얹는 것이 아니다.

## ③ 정의 — 이 섹션이 없으면 무엇이 안 되는가

1. **"바로 견적 낼 만큼 확신이 없는" 고객에게 줄 것이 없다.** 지금 고객 진입
   경로는 게이트웨이에서 곧장 견적 대화(S1/mvp2)로 들어간다. "롤 하려면
   뭐가 필요하지?", "요즘 영상편집은 뭘 하지?" 같은 **판단 이전 단계**의
   질문에 응답하는 화면이 없다 — 그 고객은 이탈하거나, 준비 안 된 채
   대화창에 억지로 입력한다.
2. **게임별·용도별로 "이 정도면 됩니다"를 설명할 자리가 없다.** 관리자용
   게임 매트릭스(`ADM-GRD-020`)에 이미 게임별 권장사양·설명·"이 게임이
   되는 가장 싼 견적" 연산까지 있는데, 고객은 이 데이터에 전혀 닿지
   못한다.
3. **팝콘AI 자체를 설명·홍보할 자리가 없다.** "이유가 있는 견적"이라는
   정체성(A-01)을 처음 접하는 고객에게 풀어 설명하는 콘텐츠 면이 없다.
4. **구매 의도 없는 단순 문의를 받을 원장이 없다.** 지금 있는
   `consult_sessions`/`handoffs`는 견적이 이미 나온 뒤의 흐름이다.
   "이거 물어보고 싶어요" 수준의 가벼운 문의를 받는 자리가 없다.

**이 섹션이 하지 않는 것**: 견적 계산 · 부품 조립 · 결제 · 재고 차감(A-97
그대로 — 팔지 않는다). 콘텐츠 소비 중 견적이 필요해지면 기존 견적 흐름
(S1/mvp2)으로 **진입시킬 뿐**이다.

### 이미지·영상 저장 방식 — Cloudflare R2 확정(W-7, ✅ 2026-09-14 사장님 결정)

**결정**: 이미지·영상 파일은 **Cloudflare R2**(오브젝트 스토리지)에 저장하고,
`game_media.url`에는 R2가 서빙하는 공개 URL을 저장한다. DB에는 바이트를
넣지 않는다 — `admin_operator_photos` 방식은 채택하지 않는다.

**근거(비용 조사, 2026-09-14 실측)**:

| | Cloudflare R2 | Google Cloud Storage(Standard, Asia) | DB 바이트 저장(`admin_operator_photos` 방식) |
|---|---|---|---|
| 저장 비용 | $0.015/GB/월(10GB까지 무료) | $0.020~0.023/GB/월 | Cloud SQL 저장 공간에 합산(별도 단가 없음) |
| 송출(egress) | **$0.00/GB — 무료**, 트래픽 무관 | $0.12/GB(3대 클라우드 중 최고가) | 없음(같은 DB 조회) |
| 이 화면 예상 규모(게임 23종 × 이미지 소수 + 영상) | 무료 티어 안에 들어감 | 저장비 미미하나 열람 트래픽마다 과금 | 다건·대용량 누적 시 Cloud SQL 백업 크기 증가(정의서 이전 버전이 지적한 우려) |
| 배포 서버 제약(`ProtectSystem=strict`)과의 관계 | 무관 — 파일을 로컬에 두지 않는다 | 무관 | 이 제약을 피하려고 고른 방식(운영자 사진 1인 1장 한정 조건에서 성립) |

`admin_operator_photos`가 DB 바이트를 택한 이유(로컬 파일시스템 쓰기 제약
회피)는 **운영자 사진 1인당 1장·1MB 상한**이라는 좁은 조건에서 성립했다.
게임 카드는 **다건·대용량(게임당 여러 장 + 영상)**이라 같은 이유가 그대로
적용되지 않는다 — 오브젝트 스토리지가 이 규모에 구조적으로 맞는 해법이다.

**NAS(자체 서버) 대안은 채택하지 않는다.** 검토 근거: ① 지금 배포 서버는
`127.0.0.1` 바인드 + 방화벽 80·22만 개방(§베타 배포 상태 최소 노출 원칙)인데
NAS를 공개 이미지 서버로 쓰려면 별도 장비를 인터넷에 노출해야 해 이 원칙과
반대 방향이다 ② CDN 캐싱이 없어 접속자와 물리적 거리가 멀수록 느리다
③ 정전·회선 장애 시 이미지 전체가 응답 불가 상태가 된다 ④ 이 규모(수GB)에는
초기 장비 비용(수십만 원대)이 매달 몇 달러(혹은 R2는 사실상 $0) 수준인
클라우드 비용 대비 맞지 않는다.

**⚠ A-30(폰트·아이콘 자체 호스팅, 외부 CDN 0건 규약)과의 관계 — 다른 대상이다.**
A-30은 **페이지 렌더링에 필수인 자산**(폰트·아이콘)이 남의 서버에 있으면
그쪽이 죽을 때 화면 자체가 깨지는 문제를 막는 규약이다. 이미지·영상은
**콘텐츠**이지 렌더링 골격이 아니다 — R2가 응답하지 않아도 텍스트 카드는
그대로 성립한다(④-B "콘텐츠 없는 게임의 카드는 텍스트만으로도 성립"과 같은
원칙). 다만 이것은 하네스의 해석이므로 **A-30의 적용 범위를 명시적으로
좁히는 판단이 필요하면 사장님 확인을 받는다** — 결정 로그에 별도 항목으로
등재해 근거를 남긴다(⑨ W-7 상태 참조).

**아직 정하지 않은 것**(제작 착수 시 확정): 버킷 이름·리전 · 업로드
엔드포인트(관리자 화면에서 올리는지, 별도 도구로 올리는지) · 접근 키
관리(`CLAUDE.md` 규약상 비밀값은 리포·설정·메모리에 저장 금지 — `.env`
전용, 서버 환경변수로만 전달) · 파일 크기·형식 상한(운영자 사진처럼 서버가
magic bytes로 판정할지).

### 카드에 들어가는 콘텐츠 요소(정리)

| 요소 | 원천 | 상태 |
|---|---|---|
| 게임명·장르·설명 | `games.name/genre/description` | 있음 |
| 권장/최소 사양 | `games.rec_*/min_*` | 있음(일부 게임은 `mapping_skip_reason`으로 판정 불가 표시, `ADM-GRD-020` 관례) |
| 예상 프레임(전력등급×해상도) | `game_performance` | 게임별로 있을 수도 없을 수도 있음(위 표 — 6행뿐) |
| 이 게임이 되는 가장 싼 견적 | `game_cell_map`→`grid_quotes` | 있음(`ADM-GRD-020`의 `_selection_cells()` 패턴 재사용) |
| 대표 이미지 | 신설 `game_media`(role=main), R2 저장 | 없음 — 콘텐츠 확보 필요(누가 찍거나 구하는지는 ⑨ W-1) |
| 추가 이미지 | 신설 `game_media`(role=sub), R2 저장 | 없음 |
| 영상 | 신설 `game_media`(media_type=video), R2 저장 | 없음 — 저장 인프라는 확정(R2), 촬영·확보 주체는 미정(⑨ W-1) |
| 커뮤니티 링크 | 신설(테이블 미정) | 없음(⑨ W-1) |

**콘텐츠가 없는 게임의 카드는 이미지 없이 텍스트만으로도 성립해야 한다** —
23종 게임 전부에 이미지·영상이 동시에 갖춰질 때까지 이 화면 자체를 미룰
필요는 없다(부분 콘텐츠로 시작 가능, 빈 자리는 "준비 중"으로 표기).

## ⑤ 기능(동사) — 콘텐츠 종류별

1. 게임을 **탐색한다** — 목록에서 고르면 권장사양·설명·예상 프레임(있는
   경우)·이 게임이 되는 가장 싼 견적을 **본다**.
2. 게임의 대표 이미지·추가 이미지·영상을 **본다**(콘텐츠 확보 전까지는
   텍스트만으로도 카드가 성립한다 — ④-B).
3. 용도(사무·영상편집·AI 등)를 **탐색한다** — 요즘 그 용도로 무엇을
   하는지 소개 글을 **읽는다**(콘텐츠 저작 완료 후).
4. 팝콘AI 소개 콘텐츠를 **읽는다**(이미지·영상 포함, 준비 중 표기 허용).
5. 콘텐츠를 보다가 판단이 서면 해당 조건(게임·용도·티어)을 들고 견적
   흐름(S1/mvp2)으로 **진입한다**.
6. 구매 의도 없는 단순 문의를 **등록한다**(⑨ W-3 결정 후).

**하지 않는 일**: 견적 계산 · 부품 교체 · 결제 · 재고 차감.

## ⑥ 인터랙션 — 입력 · 선택 · 이동의 흐름과 결과

| 입력·동작 | 결과 |
|---|---|
| 메인 랜딩에서 이 섹션 진입 | 허브 목록(게임·용도·소개 등 콘텐츠 종류 탐색 지점) 노출 |
| 게임 카드 선택 | 게임 상세(설명·권장사양·성립 견적) 노출. 성립 견적 0건이면 그 사실을 그대로 표시(지어내지 않는다 — `ADM-GRD-020`의 "불성립/판정 불가" 구분 관례를 고객단 언어로 옮긴다) |
| 게임 상세에서 「이 사양으로 견적 보기」 선택(가칭) | 견적 흐름(S1/mvp2)으로 조건(용도·예산 후보)을 들고 **진입**. 구체적 전달 방식(쿼리 파라미터·세션 시드 등)은 ⑨ W-4 |
| 콘텐츠 저작 전 영역(용도별 소개·팝콘AI 소개 등) | 영역 자체를 숨기거나 "준비 중" 표기 — 빈 카드 틀을 두지 않는다 |
| 문의 등록 | ⑨ W-3 결정 전까지 **비활성**(눌러도 반응 없는 버튼을 두지 않는다 — 결정 전에는 버튼 자체를 노출하지 않는다) |

## ⑦ 상태 · 예외

| 상황 | 화면 |
|---|---|
| 게임의 성립 견적 0건(매핑 스킵) | `ADM-GRD-020`과 같은 원천(`mapping_skip_reason`)을 읽어 "판정 불가" 사유를 고객 언어로 보여주거나, 최소한 "지금은 추천 구성이 없습니다"로 정직하게 표시 — 빈 카드를 채우지 않는다 |
| 이미지·영상 없는 콘텐츠 | 자리 자체를 안 그리거나 "준비 중" — `mvp2` videoDialog 관례 |
| 용도별 소개·팝콘AI 소개(저작 전) | 섹션 자체를 메뉴에서 숨긴다(만들어지지 않은 것을 고객에게 약속하지 않는다) |
| API 실패 | 콘텐츠 없음 + 콘솔 기록. 다른 콘텐츠 종류는 영향받지 않는다(한 영역의 실패가 전체를 막지 않는다 — `req-ai-workstation-shelf.md`의 "진열 실패가 격자를 막지 않는다"와 같은 원칙) |

## 비범위 — 이 섹션이 하지 않는 일

- **결제·재고 차감·회원 관리**를 하지 않는다(A-97 그대로).
- **부품 교체 대화**를 포함하지 않는다 — 콘텐츠 소비 중 필요해지면 기존
  견적 흐름으로 진입시킬 뿐, 이 섹션 안에서 견적을 만들지 않는다.
- **관리자 화면**(콘텐츠 CMS·문의 처리)은 이 정의서가 다루지 않는다 —
  W-2·W-3 결정 후 별도 정의서.
