# 요구사항 정의서 — AI 사용량 · 비용 (admin2 신규 구축)

> 이 문서는 **요구사항만** 담는다. 배치·컴포넌트·와이어프레임·색은 담지 않는다
> (`CLAUDE.md` §화면 작업의 경계, 2026-08-13 사장님 지시). UI 설계는 이 문서를
> 입력으로 사장님(또는 지정 경로)이 별도로 한다.
>
> 대상은 admin2 신규 구축이다. 기존 `mockups/admin/ai-cost.html`(옛 ID **ADM-SYS-010**)은
> 백업용 동결 — 참고만 하고 옮기지 않는다(P-09). 다만 이 화면은 admin-ia-draft(2026-08-09)
> row 50이 "**이동**(← 시스템)"으로 표기한 대상이라, **완전 신설인 나머지 4개 화면과
> 성격이 다르다** — 지어졌던 적이 있다.
>
> 작성일 2026-08-13. ④의 수치는 그 시각의 실측 스냅샷이다. 재측정은
> `SELECT count(*) FROM api_cost_logs`(및 `cost_thresholds`)를 다시 돌리면 된다.

## ① 화면 성격

**관측 창(읽기 전용 조회 화면).** 쓰기 액션이 없다 — 한도·정책을 "정하는" 것은 AI 연동
설정 소관이고, 이 화면은 그 대비 실적을 보여주기만 한다(대시보드·작업 기록과 같은 급의
순수 조회 화면).

- 열람: 로그인만 되면 등급 무관(viewer 이상).
- 쓰기: 없음.

## ③ 정의 — 이 화면이 없으면 무엇이 안 되는가

- 이 화면이 없으면(연동 이후) 프로바이더별 비용이 새고 있어도 아무도 모른다.
- **이 화면은 이미 한 번 지어졌다가 old 시스템에서 동결된 전례가 있다** —
  `mockups/admin/ai-cost.html` + `GET /api/admin/system`(`api/admin_system.py`,
  2026-07-23 전후 구축). 그 구현은 화면 정직성 규약을 정확히 지켰다 — 코드 주석 원문:
  "용도별 비중·모델별 비용은 원천(`api_cost_logs`)이 아직 없다. 지어낸 비율(72/21/7)을
  그리면 운영자는 그것을 실제 집계로 읽는다 — 자리표시자만 둔다." **이 문서는 admin2
  재구축판이 같은 원칙을 반드시 이어받아야 한다는 것을 요구사항으로 못박는다**(뒤로
  후퇴 금지 — 옛 초안(2026-07-13)의 "72%/21%/7%"·"$50" 같은 예시 수치가 admin2에서
  실측인 것처럼 되살아나면 안 된다).

## ④ 데이터

### 실측 방법

`api.db.engine`으로 `api_cost_logs`·`cost_thresholds` 직접 SELECT(읽기 전용) +
`api/admin_system.py`(옛 화면의 실제 구현) 코드 읽기. 2026-08-13 스냅샷.

### 지금 있는 것

| 원천 | 실측 내용 |
|---|---|
| `api_cost_logs` | 컬럼: `log_id`·`provider`·`model`·`tokens_in`·`tokens_out`·`cost_usd`·`created_at`. **0행**(2026-08-13). 2026-07-23 구축 당시도 0행이었다(`api/admin_system.py` 코드 주석) — **5주 가까이 변화 없음**, LLM 연동 보류가 실제로 유지되고 있다는 방증 |
| `cost_thresholds` | **0행** |
| `GET /api/admin/system`(구 시스템 소관, admin2가 재사용하지 않음 — P-09) | 반환 예: `{"ai_cost": {"empty": true, "log_rows": 0, "threshold_rows": 0, "reason": "실제 LLM 연동이 보류 상태(2026-07-21 결정)라..."}}` — **같은 SELECT 로직을 admin2 쪽에 새로 두는 것은 정본 복제가 아니다**(같은 사실을 다시 재는 것일 뿐, 라우트·화면은 새로 짓는다) |

### 연동 후에야 생기는 것

- 오늘 사용액·이번 달 누계·배치당 평균·상담 1건당 평균 — `api_cost_logs`에 행이 쌓여야
  계산 가능. 지금은 전부 계산 불가.
- 프로바이더별·모델별 분해 — `api_cost_logs.provider`/`model` 컬럼은 이미 있어 데이터만
  쌓이면 가능.
- **작업 종류별 분해는 지금 스키마로는 불가능하다** — `api_cost_logs`에 작업 종류 컬럼이
  없다(실측, `req-ai-task-settings.md`와 같은 결함). 신설 필요.
- 일 한도 대비 오늘 사용률 — `cost_thresholds` 연계, 현재 0행.

### 옛 초안 수치에 대한 경고

`docs/decisions/admin-identity.md`(2026-07-13)가 예시로 든 "일 캡 $50", "용도별 추출
72%/파싱 21%/근거 7%"는 **실측이 아니라 그 시점의 설계 구상 문구**다. 이 문서는 그 숫자를
요구사항에 반영하지 않는다 — 옛 구현조차 이미 이 수치를 화면에 쓰지 않기로 했다(위 ③
인용 참조).

## ⑤ 기능 (동사)

- 오늘/이번 달 총 비용을 본다(원천이 쌓이면).

- 작업 종류별 분해를 본다 — **단, 스키마에 작업 종류 컬럼이 추가돼야 성립**(④ 참조,
  결정 필요).
- 일 한도 대비 오늘 사용률을 본다.
- 최근 N일 추이를 본다.

## ⑥ 인터랙션

- 필터(기간·프로바이더·모델)를 바꾸면 집계가 다시 요청된다.
- 쓰기 액션 없음 — 한도 자체를 바꾸는 것은 AI 연동 설정 소관(정본 중복 방지).

## ⑦ 상태 · 예외

- **지금 이 화면을 그대로 열면 전 구간이 빈 상태다.** "0"과 "원천 없음"을 구분해
  보여준다 — 실측 그대로 `log_rows=0`·`threshold_rows=0`이며 이는 "아직 아무도 안 써서
  0"이 아니라 "쌓이는 경로 자체가 없어서 0"이다.
- 사유 문구는 "서버에 연결되면 표시됩니다"처럼 원인을 접속 문제로 돌리지 않는다 — 실제
  원인(LLM 연동 보류, 별도 승인 필요)을 그대로 말한다. 옛 구현의 주석이 이미 이 원칙을
  명시적으로 세워 두었다(③ 인용) — 이어받는다.
- 권한 없음: 401(미로그인). 이 화면은 쓰기가 없으므로 403 경로는 없다.

## 비범위 — 이 화면이 하지 않는 일

- **한도·초과 시 동작을 "정하는" 것** — AI 연동 설정 소관, 이 화면은 대비율만 보여준다.
- **개별 호출의 질문·답변 내용** — AI 응답 기록 소관.
- **웹 사양 채움(specfiller) 배치의 진행률** — ADM-AI-020 소관. 게다가 **specfiller는
  Claude Code 세션 안에서 도는 것이라 애초에 `api_cost_logs`에 잡히지 않는다**(실측:
  `api/dash.py`는 세션 전사본의 토큰 사용량을 읽어 작업 현황판에 보여줄 뿐
  `api_cost_logs`에 쓰지 않고, `tools/spec_fill_apply.py`도 `api_cost_logs`를 건드리지
  않는다) — 대상이 다른 종류의 "AI 비용"이다.

## 사장님 결정이 필요한 지점

1. **구 ID(ADM-SYS-010)를 유지할지, 새 ID(ADM-AI-050)로 갈지.**
2. **"작업 종류별" 분해를 보여주려면 `api_cost_logs`에 컬럼을 추가해야 한다** — 이
   스키마 변경을 이 축의 범위에 넣을지(AI 작업 설정과 공동 결정 필요).
3. **Claude Code 세션 비용(specfiller 등, 개발자가 Claude Code 자체에 지불하는 비용)을
   이 화면이 다뤄야 하는지, 아니면 이 화면은 "우리 서버가 프로바이더에 직접 호출하는
   비용"만 다루는지** — 지금은 후자만 가능한 구조다.
