## 기본값 (판단 기록)

- **바꾸는 범위는 완제품 PC(`PC_COMPLETE`)만.** 부품 판매가는 지금 매입가 × 마진 공식이 정한다
  (단가표 반영 · 판매가 재산정 · `tools/mall_daily_sync.py`). 쇼핑몰 값으로 덮으면 두 경로가 서로
  되돌린다. 업로드 화면의 「부품 판매가도 반영」을 켜면 같은 경로로 부품도 바꾼다(부품 개별 상품화
  작업이 그 칸을 쓰게 될 때를 위해 열어 둔다).
- **판매가가 잠긴 상품은 건너뛴다.** 직접 소싱해 덮어쓴 예외 값이다(판매가 관리 화면 규약).
- **쇼핑몰 가격 0원 · 빈 값은 쓰지 않는다**(`api/mall.py` 와 같은 규칙).
- **큰 변동(30% 이상)**: 업로드는 미리보기에 표시만 하고 사람이 보고 반영한다. 자동 갱신은 그 상품만
  보류하고 나머지는 반영한다.
- **미리보기와 반영이 다르면 거부한다.** 미리보기 뒤 우리 판매가가 바뀌면 token 이 달라져 409.
- **되돌리기는 배치 단위.** 그 뒤 다른 경로가 같은 상품을 또 바꿨으면 그 상품은 덮지 않는다.
- 마진 정책·재산정 파일(`api/admin_engine_rules.py` · `api/admin_reprice.py`)은 쓰지도 부르지도 않는다.

## 파일 형식

쇼핑몰 관리자 「상품관리 → 상품리스트 → 상품엑셀」 파일. xlsx · CSV(UTF-8/EUC-KR) · HTML 표(.xls)를
읽는다. 옛 바이너리 .xls 는 읽지 못하고 그렇게 말한다.

    상품코드  자체상품코드 > 상품번호 > pd_no > 상품코드   (쇼핑몰 pd_no = 우리 product_code)
    가격      일반회원 > 판매가 > 가격                     (일반회원 = 카탈로그 적재가 판매가로 쓰는 열)

## 1겹 ② 자동 갱신 (`api/mall_price_auto.py`)

    매일 06:00 · 13:00 KST   API 프로세스 안 스케줄러(api/mall_price_auto.start_scheduler)
                              놓친 시각은 3시간 안에 한 번 만회 · 끄기 MALL_PRICE_AUTO_SCHEDULE=off
    손으로 한 번              tools/mall_price_auto.py [--check]
    관리자 「지금 실행」       POST /api/admin/mall-price/auto/run (owner) — 같은 함수, 뒤에서 돈다
    상태                      GET  /api/admin/mall-price/auto — 마지막 실행 · 마지막 성공 · 설정 유무

어디서 읽나 — 앞의 것이 설정돼 있으면 그것만 쓴다.

| 길 | 조건 | 방식 |
|---|---|---|
| 관리자 상품엑셀 | `MALL_ADMIN_ID` · `MALL_ADMIN_PW` · `MALL_EXPORT_URL` 셋 다 있음 | 실행마다 로그인 → 파일 한 번 받기 → 업로드와 같은 해석 |
| 공개 상품 페이지 | 위가 없음(기본) | 판매중 완제품 PC 를 1.5초 간격으로 하나씩 읽기, 상한 `MALL_PRICE_MAX_READS`(3000) |

설정은 서버 `/etc/popcorn-ai.env` 에만 둔다. 화면과 API 는 «있는지»만 말하고 값은 돌려주지 않는다.
`MALL_EXPORT_DATA` 는 내려받기가 POST 일 때 보낼 폼 본문이다(필요할 때만).

실패로 끝내는 경우(판매가는 하나도 안 바꾼다): 로그인 거부 · 파일을 못 읽음 · 읽은 가격 0건 ·
공개 페이지 절반 넘게 실패 · 이미 다른 실행이 도는 중. 사유는 `mall_price_runs.fail_reason` 과 관리자
화면 「자동 갱신」에 남는다. 쿠키를 저장하지 않는 이유와
A-124 와의 관계는 decision-log **A-143**.

왜 systemd 타이머가 아닌가: 배포(`deploy/popcorn-ci deploy`)는 unit 을 설치하지 않고, 그 스크립트는 서버에
고정된 사본이라 리포를 고쳐도 사람이 다시 설치하기 전에는 바뀌지 않는다. API 는 배포마다 재시작되므로
앱 안에서 돌면 배포만으로 켜진다. 같은 DB 를 쓰는 프로세스가 여럿이어도 「그 시각 이후 auto 실행이 있나」를
DB 로 보고, 겹침은 advisory lock 이 막는다. 루프백 DB(CI · 테스트)에서는 돌지 않는다.

## 2겹 실시간 — 장바구니·결제 순간 (`api/mall_price_live.confirm`)

    자리        cart      mvp3 「견적 보관」       (api/mvp3_saved_quotes.save_quote)
                checkout  mvp3 「쇼핑몰에서 구매」 (api/mvp3_handoff.handoff_saved_quote)
    읽기        mall_price_reader.read_price — 시간 제한 3초, 익명(고객이 보는 값)
    같으면      확인 기록만 남긴다(outcome 'same') · 고객에게 아무 말 안 함
    다르면      우리 판매가를 apply_changes(moment=cart|checkout)로 고친다 → 가격 이력 · 활동 로그 · 확인 기록
                고객에게 서버 문장으로 알린다 · 보관 견적 가격도 쇼핑몰 가격으로 고친다
                인계 기록(handoff_items)에는 보던 가격과 쇼핑몰 가격을 둘 다 남긴다
    못 읽으면   막지 않는다 · 「현재 가격 확인이 안 되어 쇼핑몰에서 최종 확인됩니다」 · outcome 'failed'

- 판매가를 «안» 고치는 경우도 고객에게는 쇼핑몰 현재가를 알린다 — 고객이 실제로 결제하는 값이다.
  잠긴 판매가(`locked`) · 30% 넘는 변동(`held`, 사람 확인) · 완제품 PC 가 아닌 상품(`held`) ·
  그 사이 다른 경로가 바꿈(`stale`).
- 고객이 일으킨 반영이라 `changed_by`·활동 로그 `operator_id` 는 비어 있다. 누가 봤는지는
  확인 기록의 `quote_id`·`visitor_ref` 로 되짚는다.
- 화면(mvp3)은 서버가 «바뀌었다»고 말하고 보던 가격이 요청 가격과 같을 때만 다른 가격의 보관을
  받아들인다. 그 밖의 가격 불일치는 전처럼 거부한다(조용한 가격 교체 차단).
- 이 변경 전에는 결제 순간 확인이 부품용 `product_detail.html` 을 읽어 완제품 PC 는 늘 「확인못함」이었고
  쇼핑몰 링크도 첫 화면으로 갔다. 이제 완제품은 `system_detail.html` 을 읽고 그리로 보낸다.
- 부품을 바꾼 보관 견적(`product_snapshot.build`, `api/mvp3_build`)은 몰 상품이 «기준 PC» 하나뿐이라
  쇼핑몰 가격을 기준 PC 판매가(`build.base_price`)와 비교한다. 바뀌면 총액은 «쇼핑몰 가격 + 바꾼 부품 차액»이
  되고, 인계 기록 `note.build` 에 바꾼 부품을 남긴다.

## 남은 일

- 쇼핑몰 관리자 계정을 서버 `/etc/popcorn-ai.env` 에 넣는다(`MALL_ADMIN_ID` · `MALL_ADMIN_PW` ·
  `MALL_EXPORT_URL`). 넣기 전까지 자동 갱신은 공개 상품 페이지를 읽는다(동작은 한다, 느리다).
  넣은 뒤 `tools/mall_price_auto.py --check` 로 로그인·파일 읽기만 먼저 확인한다.
- 배포 뒤 첫 실행 결과(반영 · 보류 · 실패 건)는 관리자 「쇼핑몰 가격 반영」 화면의 자동 갱신 칸에서 본다.
