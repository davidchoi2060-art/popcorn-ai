# 관리자 처리할 일과 AI 도움 — 2026-10-01

사용자가 승인한 AI 결합 시안을 제품 작업 공간 `/admin2/pc-workspace`에 구현했다. 공통 관리자 셸을 상속하고 중앙 메뉴 정본에 진입점을 추가했다. 이 화면의 간결한 메뉴는 처리할 일/제품군/부품/사용·성능 자료/이력/전체 운영 메뉴로 구성하며 기존 화면은 유지한다. 외부 웹 검색·일괄 적용·운영 데이터 삭제·자동 검토 승인은 이번 구현에 포함하지 않는다.

## 실제 동작

- 작업 목록은 실제 DB 카탈로그에서 가격 변화/설명 부족/검토 기록 필요를 구분한다. 후보 규격 분류를 승인으로 취급하지 않는다. 제외·보관 제품은 작업 목록에서 제외한다.
- 선택 상품의 구성과 설명을 나란히 보여주고 AI 제안은 필드별 기존 값과 비교한다. 선택 적용은 브라우저 초안이며 저장 버튼으로만 기존 설명 API에 반영된다. 되돌리기는 아직 저장하지 않은 초안을 취소한다. 영구 저장 이전 버전은 기존 변경 이력에서 열람한다.
- 기존 `llm.call`의 연결 설정·업무 배정·비용 캡·폴백·사용량 기록을 재사용한다. 현재는 `task.ops_assist` 배정이다. 새로운 별도 모델 설정이나 비밀값을 만들지 않았다. 모델·키 설정 변경 시 기존 AI 설정에서 관리한다.
- 설명/검토 생성은 operator/owner만 허용한다. 자료 찾기는 제품에 등록된 부품 설명과 근거를 읽고 외부 API 호출을 하지 않는다. 검토 보조는 의견만 반환한다.
- 프롬프트는 상품 설명·현재 BOM·등록된 부품 설명·검토 항목으로 한정한다. 고객/운영자 개인정보·공급처 매입가·키를 추가하지 않는다. 제안 가능한 필드는 title/intro/benefits/scene/checks/faq뿐이며 가격·BOM·상태·승인 쓰기는 불가능하다.
- 모델 반환 JSON과 개별 변경의 Description 스키마를 검증한다. 같은 필드 중복, 임의 필드, 잘못된 값은 거절한다. 생성 전 revision과 생성 후 상품·근거 지문을 다시 확인해 중간 변경을 거절한다. 저장은 기존 revision 충돌 및 이력 로직을 그대로 사용한다.
- 설명 작성 여부와 부품 변경 후 검토 필요를 분리했다. 변경 상품도 설명이 실제로 있으면 설명 작성됨이며 검토 대기는 별도로 표시한다. 검토 승인 정책 자체는 변경하지 않았다.
