## 실제 확인

- 듀얼 SSD `AC11F5AEA43924DBA`, 일반 `N07`: 실제 AI 소개 제안 → 선택한 필드만 저장 → revision 증가·설명 이력 생성 → 검토 대기 저장. BOM·가격·facts는 유지된다. 테스트 승인 후 작업 목록에서 빠지고, 설명이 다시 바뀌면 승인 근거가 무효화되어 검토 작업으로 복귀하는 것도 확인했다.
- 제외 `P119302`: 실제 검토 보조 응답은 설명 변경 없이 소켓 불일치와 필요한 확인 자료를 제시했다. LGA1851이 등록 쿨러 지원 목록에 없는 기존 사유를 승인 메모로 우회할 수 없는 것을 확인했다. 자료 찾기는 실제 등록된 부품 근거 조회이며 외부 웹 조사 기능은 아니다.
- 위 저장·승인은 모두 DB 트랜잭션에서 전량 롤백했다. 종료 후 3제품 내용·revision·이력 건수 불변. 시험용 확인 문구를 실검수 근거로 남기지 않았다.
- 실제 LLM 제안 3회 성공(log1579/1581/1582). Gemini 혼잡·시간 초과 시 기존 Claude 폴백이 작동했다. 호출 비용 로그는 남으며 상품은 변경하지 않는다.
- 로그인한 운영 브라우저에서 듀얼 SSD 수량2·가격2,133,000원, 실제 Gemini 제안 생성·선택 적용·저장 버튼 활성화·되돌리기를 확인했다. 이 브라우저 제안은 위 3회와 별개이다.

## 운영 UI에서 발견한 오류와 수정

1. 작업 공간의 전역 click 처리기가 상세 모달의 동일 `data-tab` 버튼까지 처리하여 `openDetail`을 재귀 호출했다. 운영 콘솔 `Maximum call stack size exceeded` 확인. 클릭 처리를 `.pcw` 내부 버튼으로 한정하여 상세 모달 편집기의 이벤트를 분리했다.
2. 공통 POST 진행 배너가 AI 제안 생성도 ‘저장하는 중 → 완료’로 표시했다. 상품을 저장하지 않는 `/api/admin/pc-configurations/{id}/ai-proposals`만 전역 저장 배너에서 제외한다. 작업 공간의 인라인 진행·오류는 유지하며 실제 설명 PUT의 저장 배너는 유지한다.
3. 상세 화면의 구성 검토 플래그 문구를 ‘구성 변경 후 검토 대기’로 정정하여 설명 미작성과 혼동하지 않게 했다.
