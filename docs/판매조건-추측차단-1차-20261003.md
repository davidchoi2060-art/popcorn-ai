# 판매조건 추측 차단 1차

대표 3종 유료 재검증에서 OS·주변기기 미포함 단정과 대상 프로그램을 특정하지 않은 요구 조건 충족 주장이 재발했다. 다음 단계 요청으로 추가 유료 생성 전에 서버 검사를 연결했다.

## 현재 근거

실제 연결 DB 읽기에서 조립PC 105개 중 `sales_conditions`가 있는 구성은 0개였다. 현재 코드에도 OS·주변기기 포함 또는 완제품 보증의 확정 자료를 조회하는 경로가 없다. BOM 누락, 기존 고객 설명, 모델 notes 및 임의 facts 값은 판매조건 확정 근거로 채택하지 않는다. 따라서 AI 입력의 판매조건은 모두 `unknown`으로 명시한다. 확인된 판매조건의 등록·출처·갱신 관리 기능은 별도 후속 범위다.

## 동작

- 개별 및 일괄 생성이 공통 사용하는 AI 제안 API에서 반복 실패 문구를 검사한다. 포함·미포함·별도 구매/설치 단정, 수치 보증, 프로그램 요구 조건 충족 표현이 감지되면 해당 필드 제안 전체를 제외하고 기존 notes에 필드·확인 대상을 남긴다. 나머지 제안과 비용 기록 연결은 유지한다. 자동 재시도는 없다.
- 개별 설명 및 일괄 선택 저장은 공통 `save_copy`에서 변경 필드를 다시 검사한다. 위반은 422로 이력 INSERT·상품 UPDATE 전에 거절한다. 기존 승인 화면의 배치는 변경하지 않았다.
- 기존 저장 문구를 일괄 지우지 않으며 변경하지 않은 이전 필드는 이번 검사로 막지 않는다. 새 제안의 FAQ 질문은 단정으로 취급하지 않고 답변을 검사한다. 특장점 제목과 설명은 함께 검사한다.
- OS 포함 여부 확인, 실제 용량·부품 안내, 프로그램 요구 사양과 비교하라는 안내 및 성능을 보장하지 않는 문구는 유지한다. 출고·최종 판매가 미확정 안내를 내부 정보라는 이유로 삭제하지 않도록 프롬프트도 보완했다.

## 검사와 한계

관련 Python 회귀 69개 통과. 과거 실제 실패 문구, 확인 안내 허용, 문장 뒤 확인 요청으로 단정을 숨기는 사례, 중첩 특장점/FAQ, 생성 1회·제안 제외, 수동 저장·일괄 저장 우회 차단, 변경 없는 기존 설명 유지 등을 검사했다. 상품 DB 조회만 했으며 설명 저장·승인·스키마 변경·유료 호출은 하지 않았다.

이 검사는 관찰된 한국어 표현 중심의 1차 규칙이다. 모든 자연어 표현의 사실 여부를 증명하지 않으며 영어·우회 표현·출력 단자·FPS·실측 성능 등 전체 주장 검사는 지원하지 않는다. 프로그램 요구 조건의 출처별 대조와 확인된 판매조건을 근거로 허용하는 기능도 아직 없다. 차단 필드에 안전한 문장이 섞이면 운영자가 해당 필드를 수정해야 한다. 일괄 적용 품질을 확보했다는 의미가 아니며 실제 유료 재생성 결과는 미확인이다.
