# AI 설명 형식 오류 진단

2026-10-02. 고객 설명 유료 시험 3건 중 편집용 1건은 형식 오류로 실패했다. 당시 원본 응답과 진단 정보가 남지 않아 정확한 원인을 복원할 수 없었다. 사용자가 다음 단계의 오류 진단 보완을 승인하여 추가 유료 요청 없이 구현했다.

## 변경

- 오류를 응답 타입, 빈 응답, JSON 문법, 제안 구조, 중복 변경 항목, 개별 필드 값, 검토 모드의 변경 제안으로 구분한다.
- 화면의 기존 오류 안내 위치에 오류 종류·문제 필드 경로 또는 JSON 행/열·진단 ID·비용 기록 번호를 표시한다. 기존 문자열 detail 계약을 유지하므로 개별/일괄 생성 화면 모두 같은 방식으로 표시한다.
- 서버 로거 `api.admin_pc_workspace`에 `pc_ai_proposal_format_error` JSON 이벤트를 warning 수준으로 남긴다. 진단 ID, 제품군 ID, 리비전, 모드, 비용 기록 ID, 오류 코드, 제한된 필드 경로, 검증 규칙 이름, JSON 위치만 기록한다.
- 원본 응답, 사용자 지시, API 키, 검증 실패 값, 예외 원문·traceback을 이 진단 로그에 남기지 않는다. 외부 데이터의 알 수 없는 필드명은 `?`로 치환하며 경로·규칙은 최대 5개다.
- 비용 기록 연결을 확인할 수 없으면 명시적으로 미확인이라고 표시한다. 번호가 있으면 `api_cost_logs.log_id`와 연결해서 사용량을 조사할 수 있다.
- 자동 재시도·다른 모델 폴백·상품 저장·검토 승인을 추가하지 않는다.

## 운영 조사 방법

관리자가 오류 안내의 진단 ID를 전달하면 서버 애플리케이션 로그에서 같은 ID를 찾아 오류 코드·경로·규칙을 확인한다. 예를 들어 `field_schema`와 `too_short`이면 해당 필드의 최소 길이 또는 항목 수 계약을 확인하고, `invalid_json`이면 반환 JSON의 문법 문제가 관찰된 것이다. JSON 오류만으로 출력 토큰 소진이나 잘림을 단정하지 않는다. 전체 원문은 이 기능에서 저장하지 않으므로 문장의 전문 재현 기능은 아니다. 서버 로그 보관 정책에 따라 오래된 진단은 삭제될 수 있다.

## 검사와 한계

Python 41개 및 Node 화면 이벤트/진행 검사 2개 통과. 모의 응답으로 각 오류 분류, 민감한 값·임의 키의 비노출, 비용 기록 연결, 오류 시 LLM 호출 1회와 상품 내용 불변을 확인했다. 기존 유효 제안·저장 검증·검토 근거 변경 차단도 유지된다.

추가 유료 LLM 호출과 운영 상품 변경 없음. 과거 편집용 실패 원인을 밝혀냈다는 의미는 아니며, 다음 실패 발생 시 추적할 수 있게 만든 것이다. 수정된 설명 규칙의 실제 품질 재시험은 별도 후속 단계다.
