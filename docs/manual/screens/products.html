화면을 처음 쓰는 직원이 이 문서만 보고 바로 일을 시작할 수 있도록 썼습니다.

대상 관리자 화면(admin2)의 상품 관리를 처음 맡는 직원
화면 상품 관리 · 경로 /admin2/products · 화면 ID ADM-PRD-010 (코드 api/admin_ui_products.py 실측값입니다).
왜 이 화면인가 활동 기록 실측(2026-08-25)에서 상품 관리 처리는 전체 관리자 동작 중 2위였습니다(누적 2,941건) — 1위는 상품 사양 검수(누적 3,694건, 이 매뉴얼의 첫 캡처 판). 건수는 2위지만 화면 자체는 41개 관리자 화면 중 가장 크고 기능이 많습니다 — 목록·검색·필터·정렬·일괄 변경·신규 등록에 더해, 상품 하나를 열면 기본 정보·사양·공급처· 분류 변경 네 개 탭이 우측 서랍 안에 또 있습니다.
코드·캡처 확인 기준일 2026-08-25 — 이 문서는 그 시점의 화면 코드와, 그 코드가 실제로 그리는 화면을 로컬 서버(127.0.0.1:8000, 실서비스와 같은 DB를 보는 개발 서버)에 직접 띄워 촬영한 결과를 근거로 썼습니다.
이 화면은 실데이터를 다룹니다. 캡처 시점의 건수(전체 23,151건 등)는 매일 바뀝니다 — 정확한 지금 값은 화면 위쪽 탭에서 직접 확인하십시오.
1 눌러야 할 자리 · 봐야 할 정보(번호는 아래 목록과 1:1)
테두리 상자 = 하나로 묶어 보는 영역
화살표 = 누르면 무엇이 열리는지

1이 화면이 무엇을 하는 곳인가

카탈로그에 올라 있는 상품 하나하나를 살펴보고 고치는 화면입니다. 상품명·제조사·공급처· 판매가·매입가·재고·판매 상태부터 부품 사양, 분류까지 이 화면 하나에서 확인하고 바꿀 수 있습니다. 지금 이 상품이 손님에게 추천될 수 있는 상태인지(추천 후보에 들어가 있는지), 아니라면 무엇이 남았는지도 이 화면이 바로 알려줍니다.

2언제 여기 오는가

  • 특정 상품의 가격·재고·판매 상태를 확인하거나 바로 고치고 싶을 때
  • 상품 사양이 다 채워졌는지, 이 상품이 왜 추천 후보에 못 들어가 있는지 확인하고 싶을 때
  • 새 상품을 카탈로그에 등록해야 할 때
  • 여러 상품의 판매 상태를 한꺼번에 바꾸고 싶을 때(예: 재고 없는 상품 일괄 처리)
  • 전화 등으로 받은 매입가를 공급처별로 손으로 보정해야 할 때
  • 상품 분류가 잘못돼 있어 바로잡아야 할 때(예: 적재가 잘못 분류해 추천에서 빠진 경우)

3화면 살펴보기

가장 자주 보게 되는 기본 화면(상태 탭 「전체」 · 필터 없음)입니다. 먼저 전체 모습을 보고, 아래에서 영역별로 확대해 하나씩 설명합니다.

그림 A전체 화면

  • 1왼쪽 메뉴(LNB) — 지금 있는 화면이 진하게 표시됩니다. 「상품관리」 그룹 안에 있습니다.
  • 2경로 배지 — 이 화면의 API 경로(/admin2/products)와 필요 권한을 함께 보여줍니다. 자세한 문구는 그림 B 참고.
  • 3허브 — 새 탭에서 내부 접근 허브로 이동
  • 4권한 표시 — 로그인한 계정 이름과 등급
  • 5상태 탭 — 「전체 / 추천 가능 / 검수 대기 / 재고 없음 / 가격 검토」 다섯 갈래. 클릭하면 서버가 그 범위로 다시 조회합니다(예시로 「검수 대기」를 표시). 자세한 배치는 그림 C 참고.

  • 8제조사 필터 — 입력하면 서버가 걸러 다시 조회합니다
  • 9+ 상품 등록 — 새 상품을 만듭니다. 자세히는 그림 J 참고.
  • 10일괄 변경 바(테두리 상자) — 평소엔 안내 문구만 보이고, 행을 선택해야 실제 도구가 나타납니다(그림 E).

4무엇을 할 수 있는가

  • 상태 탭(전체/추천 가능/검수 대기/재고 없음/가격 검토)을 누르면 서버가 그 범위로 다시 조회합니다 — 탭의 숫자와 실제 표시되는 행 수가 항상 일치합니다(그림 A의 5번).
  • 상품 검색·분류 필터·제조사 필터를 조합해 좁혀 볼 수 있습니다(그림 C). 검색은 상품번호· SKU·상품명을 함께 찾습니다.
  • 표 머리글(상품명·분류·필수사양·재고·판매가·상태)을 눌러 지금 불러온 목록 안에서 정렬합니다(서버를 다시 부르지 않습니다).
  • 상품명 또는 행 오른쪽 점 3개(⋯)를 누르면 우측에 상세 패널이 열립니다(그림 F).
  • 상세 패널은 네 개 탭으로 나뉘고, 각 탭은 수정을 눌러야 그 탭만 그 자리에서 편집으로 바뀝니다 — 다른 탭은 그대로 읽기 상태입니다.
    • 기본 정보(그림 G·G-2) — 상품명·제조사·공급처(원문)·판매가· 매입가·재고·상태. 저장은 확인 창 없이 즉시 반영되고, 고친 칸마다 잠금이 걸립니다.
    • 사양(그림 H) — 그 부품 종류가 쓰는 사양 값. 저장하면 값 반영 + 해당 필드 잠금 + 그 필드의 검수 대기 해소 + (필수 사양이 다 차면) 추천 후보 자동 승격까지 한 번에 일어납니다.
    • 공급처(그림 I) — 공급처별 매입가 추가·삭제. 다른 탭과 달리 [저장] 버튼 없이 추가·삭제 각각 즉시 반영됩니다.
    • 분류 변경 — 새 분류를 고르고 미리보기를 눌러야 영향 (새로 필요한 사양 · 더는 안 쓰는 사양 · 추천 후보 진입/이탈)을 먼저 보여주고, 확정 변경을 눌러야 실제로 바뀝니다. 확정하면 분류· 분류그룹·추천 후보 여부·검수 필요 여부 네 가지가 함께 잠깁니다.
  • 게이트 체크리스트(그림 G의 42번)는 추천 후보가 되기 위한 6가지 조건(부품 분류·사양 정보· 필수 사양·판매가·판매 상태·재고)을 한 번에 보여줍니다 — 하나씩 고치고 다시 열어 볼 필요 없이 남은 것을 전부 보여줍니다.
  • 몰 관리자에서 열기(그림 G의 37번) — 새 탭에서 팝콘PC 쇼핑몰 관리자의 이 상품 수정 페이지로 이동합니다(로그인 필요, 이 화면과는 다른 시스템).
  • 검수 대기 상품은 상세 패널 하단에 검수 큐로 → 버튼이 나타나 상품 사양 검수 화면으로 이동합니다.
  • 왼쪽 체크박스로 여러 상품을 선택하면 일괄 변경 바가 나타납니다(그림 E) — 바꿀 상태를 고르고 상태 바꾸기를 누르면 확인 대화상자 후 최대 2,000건까지 한 번에 바뀝니다. 상태가 잠긴 상품은 사유와 함께 자동으로 건너뜁니다.
  • ↩ 되돌리기(그림 E) — 방금 실행한 일괄 변경만 되돌립니다 (이번 세션에서 처리한 것만 — 아래 「조심할 것」 참고).
  • + 상품 등록(그림 J)으로 새 상품을 만듭니다. 분류는 반드시 골라야 하고, 이름이 비슷한 상품이 있으면 먼저 확인을 구합니다.

5⚠ 조심할 것

로컬 화면에서 고친 값이 운영 서비스에 그대로 반영됩니다. 이 관리자 화면이 보는 DB는 개발용 별도 DB가 아니라 실제 팝콘PC 운영 DB입니다 — 저장·등록·일괄 변경 버튼을 실제로 누르면 진짜 상품 데이터가 바뀝니다.
공급처(원문) 값이 통째로 사라진 적이 있습니다. 2026-08-15에 카탈로그 일괄 적재 과정에서 이 값 4,113건이 한꺼번에 지워졌고, 자동 복구가 가능한 기간(7일)을 이미 넘겨 되살리지 못했습니다. 지금 잠금 기능이 있는 것도 이 사고 때문입니다 — [수정]으로 값을 넣고 저장하면 그 칸이 잠기고, 다음 일괄 적재가 그 값을 덮어쓰지 않습니다.
잠금이 지키는 범위가 오늘(2026-08-25) 2개에서 13개 컬럼으로 늘었습니다. 이 화면에서 실제로 잠글 수 있는 것은 [기본 정보] 저장 시 상품명·제조사·공급처(원문)·판매가·매입가(5개), [분류 변경] 확정 시 분류·분류그룹·추천 후보 여부·검수 필요 여부(4개) — 모두 9개입니다. 나머지 4개(모델명·시장가·다나와 코드·사양 원문)는 이 화면이 아니라 상품 사양 검수 화면에서 잠깁니다. 재고와 「상태」(판매중/품절 등), 데이터 출처는 잠금 아이콘이 붙어 있어도 다음 카탈로그 일괄 적재가 그대로 덮어씁니다 — 코드가 이 세 가지만은 잠금과 무관하게 무조건 새 값으로 바꾸도록 정해 놓았기 때문입니다. 재고·상태를 고쳐도 다음 적재 전까지만 유지된다고 생각하십시오.
상세 서랍에서 고친 값에는 되돌리기 버튼이 없습니다. 목록 위쪽 일괄 변경 바에만 ↩ 되돌리기가 있고, 그마저도 이번 브라우저 세션에서 처리한 것만 기억합니다(새로고침하면 사라집니다). 기본 정보·사양·분류 변경을 잘못 고쳤다면, 되돌리는 방법은 원래 값을 다시 찾아 직접 입력해 저장하는 것뿐입니다.
「상태」라는 같은 이름이 이 화면 안에서 세 가지 다른 것을 가리킵니다. ① 목록 표의 「상태」 열과 위쪽 상태 탭 — 추천 가능/검수 대기/재고 없음/가격 검토(서버가 계산한 4갈래) ② 상세 서랍 제목 옆 배지(그림 G의 38번) — 검수 대기/추천 가능/추천 제외(3갈래, 비슷하지만 다른 계산) ③ [기본 정보] 탭에서 직접 고치는 「상태」 입력칸(그림 G-2의 47번) — 판매중/품절/단종/ 삭제대기(실제로 저장되는 원래 값). ①·②는 화면이 계산해서 보여주는 것이고, ③만 실제로 바꿀 수 있는 값입니다.
조회(viewer) 권한 계정은 버튼이 흐려지지 않습니다. + 상품 등록·수정·저장· 상태 바꾸기 모두 눌러 보면 그대로 눌리고, 실제로 서버에 요청을 보낸 뒤에야 403(권한 부족)으로 거부됩니다. (상품 사양 검수 화면은 반대로 버튼 자체가 미리 흐리게 비활성됩니다 — 화면마다 표시 방식이 다릅니다.)
[+ 상품 등록]에서 [등록]·[그래도 등록]을 누르면 실제로 새 상품이 생깁니다. 이 화면 안에는 되돌리는 기능(삭제)이 없습니다 — 잘못 등록했다면 다른 화면(삭제 상품 조회 등)에서 정리해야 합니다.
분류 변경은 그 상품의 필수 사양·추천 후보 여부를 통째로 바꿉니다. 미리보기로 영향(새로 필요해지는 사양·더는 안 쓰는 사양·추천 후보 진입/이탈 여부)을 반드시 먼저 확인한 뒤 확정 변경을 누르십시오 — 되돌리기 버튼이 없다는 점(위 항목)도 함께 기억하십시오.

6자주 겪는 상황

  • 「상태를 '단종'으로 바꿨는데 목록에는 '검수 대기'라고 뜬다」 → 실제로 사양 검수가 남아서가 아닙니다. 판매중이 아닌 상품을 놓치지 않으려고 붙이는 안전망 표시입니다(단종· 삭제대기처럼 달리 분류할 자리가 없으면 「검수 대기」 쪽으로 묶입니다). 상세를 열어 게이트 체크리스트에서 진짜 이유를 확인하십시오.
  • 「게이트 6가지가 다 통과인데 상세 배지는 여전히 '추천 제외'다」 → 게이트 체크리스트와 실제 추천 후보 판정은 완전히 같은 조건이 아닙니다(예: 데모 데이터는 게이트를 다 통과해도 후보에서 빠집니다). 배지 옆 「추천 후보가 되려면…」 문구를 그대로 따르십시오.
  • 「공급처(원문)에 값을 넣고 저장했는데 다음에 보니 사라졌다」 → 저장할 때 잠금이 걸렸는지(🔒 잠김 표시)를 먼저 확인하십시오. 잠금 없이 저장된 값은 다음 카탈로그 일괄 적재가 원문 값으로 다시 덮을 수 있습니다.
  • 「사양 탭에 항목이 하나도 없다」 → 이 부품 종류에 등록된 사양 항목이 없는 것입니다 (일부 주변기기 종류는 필수 사양 자체가 없습니다). 오류가 아닙니다.
  • 「일괄 변경으로 몇 건을 바꿨는데 선택한 것보다 적게 바뀌었다고 나온다」 → 정상입니다. 이미 그 상태인 상품과 「상태」 값이 잠긴 상품은 자동으로 건너뜁니다. 결과 문구에 몇 건이 잠겨서 빠졌는지 나옵니다.
  • 「공급처 탭을 열었는데 비어 있다」 → 기본 정보 탭의 공급처(원문) 칸과는 다른 자료입니다. 이 탭은 공급처별로 등록된 구조화된 매입가 표만 보여주며, 등록된 적이 없으면 비어 있는 게 정상입니다.
  • 「새 상품을 등록하려는데 계속 '이름이 거의 같은 상품이 있다'고 뜬다」 → 실제로 이미 등록된 상품일 가능성이 큽니다. 목록에 뜬 상품을 먼저 확인하고, 정말 다른 상품이 맞을 때만 그래도 등록을 누르십시오.
