# 운영자 매뉴얼 — 매입 · 소싱

> **대상** 관리자 화면(admin2)을 처음 쓰는 직원
> **범위** 왼쪽 메뉴 「매입 · 소싱」 그룹의 화면 4개 — 공급처 · 매입 견적(용산) · 단가표 반영 · 재고 입고
> 전체 관리자 화면(41개) 매뉴얼의 시범판입니다. 이 형식이 확정되면 나머지 화면으로 넓힙니다.
> **코드 확인 기준일** 2026-08-25(이 문서는 그 시점의 화면·서버 코드를 직접 읽고 작성했습니다)

이 문서만 보고도 「매입 · 소싱」 화면 4개에서 실제로 일을 시작할 수 있도록 썼습니다. 화면을
실제로 눌러 본 것이 아니라 **화면을 그리는 코드와 서버가 하는 일을 그대로 옮긴 것**이므로,
화면의 실제 배치·색과는 다를 수 있습니다 — 그런 자리는 아래 「확인 필요」로 남겨 두었습니다.

---

## 들어가며 — 네 화면이 어떻게 이어지는가

이 네 화면은 순서가 있는 하나의 흐름입니다. 처음 보면 각각 따로 있는 화면 같지만, 실제로는
"어디서 살까"부터 "실제로 몇 개가 들어왔나"까지 한 줄로 이어집니다.

```
① 공급처            거래할 곳을 등록·관리합니다. 나머지 세 화면은 전부 여기 등록된
                    공급처만 대상으로 씁니다 — 여기가 비어 있으면 아무것도 못 합니다.
        │
        ├──▶ ② 매입 견적(용산)   상품 하나씩, 여러 공급처에 가격을 물어보고 비교해서
        │                        가장 싼 곳으로 매입가를 "확정"합니다.
        │
        ├──▶ ③ 단가표 반영       공급처가 보내오는 엑셀 파일을 통째로 올려서, 예전 가격과
        │                        비교한 뒤 사람이 고른 것만 매입가에 "반영"합니다.
        │        (②·③ 은 같은 일 — 매입가를 갱신하는 것 — 을 하는 다른 방법입니다.
        │         ②는 상품 하나씩 손으로, ③은 여러 상품을 파일로 한 번에 처리합니다.)
        │
        ▼
   ④ 재고 입고        실제로 물건이 창고에 들어온 "개수"를 기록합니다. ②·③에서 정한
                      가격과는 별개입니다 — 가격을 정했다고 재고가 느는 게 아닙니다.
```

**꼭 구분할 것 — "확정"이라는 말이 화면마다 다른 뜻입니다.**
- 매입 견적(②)의 "확정"은 **가격을 정하는 것**입니다. 재고는 늘지 않습니다.
- 재고 입고(④)의 "입고 확정"은 **수량을 원장에 기록하는 것**입니다. 가격은 바뀌지 않습니다.

같은 상품이 매입 견적에서 가격을 "확정"해도 재고 입고 목록에서 계속 보이는 것은 오류가
아니라 이 구분 때문입니다 — 뒤에서 화면마다 다시 설명합니다.

**권한 — 네 화면 공통.** 로그인한 사람은 누구나(가장 낮은 「조회」 등급 포함) 화면을 보고
목록을 조회할 수 있습니다. 등록·수정·중지·요청·회신·확정·반영·입고·보류처럼 무언가를
**바꾸는** 동작은 전부 「운영자」 등급 이상만 할 수 있습니다(「관리자」 등급까지 갈 필요는
없습니다 — 이 네 화면은 관리자 전용 기능이 없습니다).

## 1. 공급처

*(화면 ID `ADM-SRC-030` · 경로 `/admin2/suppliers` · 왼쪽 메뉴 「매입 · 소싱」 첫 항목)*

### 1) 이 화면이 무엇을 하는 곳인가

거래하는 매입처(공급처) 목록을 관리하는 화면입니다. 새 공급처를 등록하고, 정보를 고치고,
더 이상 거래하지 않는 곳은 목록에서 접어 둡니다. **이 화면에 등록돼 있어야만** 다른 세
화면(매입 견적·단가표 반영·상품 상세의 매입가 입력)에서 그 공급처를 고를 수 있습니다.

### 2) 언제 여기 오는가

- 새로운 매입처와 거래를 시작하게 됐을 때 — 등록
- 공급처의 취급 브랜드나 플랫폼(예: 다나와)이 바뀌었을 때 — 수정
- 더 이상 거래하지 않는 공급처를 정리할 때 — 중지
- 실수로 중지했거나, 예전에 거래하던 곳과 다시 거래를 트게 됐을 때 — 되살리기
- 다른 화면(매입 견적·단가표 반영)에서 원하는 공급처가 목록에 안 보일 때 — 여기서
  등록·활성 상태를 먼저 확인

> **[화면 그림]** 전체 화면 — 상단 등록줄 + 집계 줄 + 목록 표

### 3) 화면에 무엇이 있는가

**상단 등록줄** — 늘 열려 있습니다. 이름(필수) · 플랫폼(선택) · 취급 브랜드(선택)를 입력하고
[등록]을 누릅니다.

**집계 줄** — "공급처 N곳 · 활성 N · 중지 N". 서버가 실시간으로 센 값입니다.

**목록 표(8열)**

| 열 | 뜻 |
|---|---|
| 이름(+ id) | 공급처명과 내부 번호. 번호는 다른 화면·기록과 대조할 때 씁니다 |
| 플랫폼 | 예: 다나와. 비어 있을 수 있습니다 |
| 취급 브랜드 | 예: MSI, GIGABYTE. 비어 있을 수 있습니다 |
| 상태 | 활성 / 중지 |
| 연결 상품 | 이 공급처로 매입가가 걸려 있는 상품 수 |
| 단가표 파일 | 이 공급처 이름으로 업로드된 단가표 파일 수 |
| 파서 프리셋 | 있음 / 없음 — 없으면 "단가표 반영" 화면에서 이 공급처의 파일을 아예 올릴 수 없습니다 |
| 작업 | [수정] [중지] 또는 [활성으로] |

**하단** — "파서 프리셋 경고"(프리셋 없는 공급처 수) · "이 목록이 판단하지 않는 것"(연결
0건·파일 0건인 공급처가 점검용인지 실거래처인지는 화면이 판단하지 않는다는 안내).

### 4) 무엇을 할 수 있는가

- **[등록]** — 이름만 있으면 바로 만들어집니다(상태는 자동으로 "활성"). 같은 이름이 이미
  있으면 등록이 막히고, 그 공급처가 "중지" 상태라면 **"이 공급처를 활성으로 되돌리기"**
  버튼이 함께 뜹니다 — 이때는 새로 만들지 말고 이 버튼으로 되살립니다.
- **[수정]** — 이름·플랫폼·취급 브랜드를 고칩니다. 이 창에서는 상태(활성/중지)를 바꾸지
  않습니다.
- **[중지]** — 누르면 먼저 "영향"(연결된 매입가 건수 · 단가표 파일 건수 · 이 공급처가
  **유일한** 매입처인 상품 수)을 보여주고 확인을 한 번 더 받습니다.
- **[활성으로]** — 중지된 공급처를 되살립니다. 과거 매입가·단가표 이력이 그대로 이어집니다.

### 5) ⚠ 조심할 것

- **공급처는 삭제할 수 없습니다.** 화면 어디에도 삭제 버튼이 없습니다. 매입가 이력·단가표
  파일 등 여러 표가 이 공급처를 참조하고 있어서, 지우면 과거 기록이 깨지기 때문입니다.
  정리는 반드시 [중지]로 합니다.
- **점검용 공급처가 목록에 섞여 있을 수 있습니다.** 2026-08-25 기준으로 "점검-공급처-A"
  (내부 번호 95), "화면점검-공급처-임시"(내부 번호 216) 같은 항목이 실제 거래처처럼
  보이는 자리에 그대로 남아 있었습니다. 지금 정리가 진행 중인 사안이니, **이 문서를 볼
  시점에도 남아 있는지는 화면에서 직접 확인**하고 쓰십시오 — 실거래처로 착각해 매입가를
  연결하지 않도록 주의합니다.
- **공급처 이름 표기가 흔들릴 수 있습니다.** 같은 회사가 "(주)OO"와 "OO" 또는 "주식회사 OO"
  로 각각 따로 등록될 수 있습니다. 실제로 2026-08-25에 "클릭나라"와 "(주)클릭나라"가
  서로 다른 회사로 보여 각각 등록됐다가, 같은 회사로 확인되어 그날 안에 하나로 합쳐진
  일이 있었습니다(나중에 등록된 쪽을 "중지"로 접었습니다). **새 공급처를 등록하기 전에
  비슷한 이름이 이미 있는지 목록에서 검색**해 보십시오. 이름은 대소문자·앞뒤 공백을
  무시하고 중복을 막아 주지만, "(주)"가 붙고 안 붙는 차이까지는 시스템이 자동으로
  잡아 주지 않습니다.

### 6) 자주 겪는 상황

- **"등록하려는데 '이미 있는 공급처입니다'라고 뜬다"** → 예전에 등록됐다가 "중지"된
  상태일 수 있습니다. 안내창의 [이 공급처를 활성으로 되돌리기]를 누르십시오. 새로
  등록하면 매입가·거래 이력이 끊긴 별개의 공급처가 하나 더 생깁니다.
- **"공급처를 지우고 싶다"** → 지울 수 없습니다. [중지]를 쓰십시오. 과거 매입 기록은
  그대로 남고, 언제든 다시 활성으로 되돌릴 수 있습니다.
- **"이 공급처를 중지해도 되는지 모르겠다"** → [중지]를 누르면 먼저 영향을 보여줍니다.
  특히 "이 공급처가 **유일한** 매입처인 상품"이 있으면, 중지 후에는 그 상품들의 매입가를
  새로 갱신할 곳이 없어진다는 뜻이니 신중히 판단하십시오.

## 2. 매입 견적(용산)

*(화면 ID `ADM-SRC-010` · 경로 `/admin2/sourcing` · 왼쪽 메뉴 「매입 · 소싱」 두 번째 항목)*

### 1) 이 화면이 무엇을 하는 곳인가

재고가 없거나(재고 0) 안전재고보다 적게 남은 상품에 대해, 여러 공급처에 "얼마에 살 수
있는지" 물어보고 회신을 비교해서 가장 싼 곳으로 매입가를 정하는 화면입니다. 대상 상품은
직접 등록하지 않습니다 — 조건(재고 부족)에 맞는 상품이 자동으로 목록에 채워집니다.

**여기서 하는 "확정"은 가격을 정하는 것이지, 물건이 들어오는 것(입고)이 아닙니다.** 확정한
뒤에도 재고가 0이면 이 목록에 계속 남습니다 — 실제 수량을 기록하는 것은 「재고 입고」
화면의 몫입니다.

### 2) 언제 여기 오는가

- 재고가 떨어졌거나 안전재고 아래로 내려간 상품이 생겼을 때(목록에 자동으로 뜹니다)
- 공급처에 전화·메일로 "이 상품 얼마에 되나요"를 물어보고, 그 사실을 기록해 둘 때
- 공급처에서 회신(가격)을 받아서 시스템에 옮겨 적을 때
- 여러 공급처 회신을 비교해서 가장 싼 곳으로 매입을 정할 때

> **[화면 그림]** 전체 화면 — 좌측 대기 목록 + 우측 작업 패널

### 3) 화면에 무엇이 있는가

**좌측 목록(서버가 50건씩 나눠서 보여줍니다)**

| 열 | 뜻 |
|---|---|
| 상품 | 상품명 + 분류 |
| SKU | 상품 관리 번호 |
| 재고 | 지금 재고 수량(0이면 붉게 강조) |
| 안전재고 | 이 수량 밑으로 내려가면 대기 목록에 뜨는 기준값 |
| 현재 매입가 | 지금 알고 있는 매입가 |
| 대기 사유 · 진행 | "재고 0 — 자동 등록" 같은 사유와, "회신 2 · 요청 1" 같은 진행 상태 |

목록 위에는 검색창(상품명·SKU·상품코드)과 부품 종류 필터가 있고, 그 위에 "N건 대기 · 이 중
진행 중인 견적이 있는 상품은 N건" 배너가 있습니다.

**우측 작업 패널** — 좌측에서 상품을 고르면, 그 상품에 대해 지금 할 수 있는 일이 뜹니다.
아직 견적을 요청하지 않은 상품이면 "공급처 고르기 · 요청" 화면이, 회신을 받은 상품이면
"회신 비교 · 확정" 화면이 뜹니다.

> **[화면 그림]** 우측 패널 — 회신 비교 · 확정 단계(공급처별 회신가 비교 표)

### 4) 무엇을 할 수 있는가

- 상품을 고르고 공급처를 하나 이상 체크한 뒤 **[공급처 N곳에 견적 요청 기록]** — 이
  버튼은 메일이나 전화를 실제로 보내지 않습니다. "이 공급처들에 물어봤다"는 사실만
  기록에 남깁니다. 실제 연락은 전화·메일로 사람이 직접 합니다.
- 공급처에서 회신을 받으면 **[회신 입력]**으로 가격(과 메모)을 대신 입력합니다 — 이것도
  자동으로 들어오는 값이 아니라 사람이 옮겨 적는 것입니다.
- 회신이 여러 건이면 가장 싼 곳에 "최저가" 표시가 붙고, **[확정]**으로 그 가격을
  확정합니다. 확정 한 번에 다섯 가지가 함께 일어납니다 — ① 그 공급처의 매입가 저장
  ② 매입가를 그 상품에 걸린 **모든** 공급처 중 최저가로 다시 계산 ③ 판매가가 잠겨
  있지 않으면 정책대로 갱신 ④ 같은 상품의 나머지 견적 요청은 자동 취소 ⑤ 가격 이력에
  기록. 확정 결과 패널에 매입가·판매가가 "전 → 후"로 그대로 표시됩니다.

### 5) ⚠ 조심할 것

- **확정해도 목록에서 사라지지 않습니다.** 확정은 "가격 결정"일 뿐이고, 재고가 늘어나는
  것은 「재고 입고」 화면의 몫입니다. 확정한 상품도 재고가 0이면 계속 이 목록에
  남습니다 — 화면이 "확정 완료 · 입고 대기"라고 표시해 줍니다.
- **매입가에는 잠금이 없습니다.** 확정할 때마다 그 상품에 걸린 모든 공급처 중 최저가로
  **항상** 다시 계산됩니다. 특별히 협상해서 따로 정한 매입가가 있어도 다음 확정에서
  덮어써집니다(판매가는 잠글 수 있지만, 매입가는 잠글 수 없습니다 — 화면이 확정 전에
  이 사실을 경고로 먼저 보여줍니다).
- **"견적 요청 기록"은 발송이 아닙니다.** 버튼을 눌러도 공급처에 실제로 아무 연락이
  가지 않습니다. 전화나 메일은 별도로 직접 해야 합니다.
- **"오늘 확정 N건" 표시가 늘 숫자로 뜨지는 않습니다.** 이 수를 정확히 세려면 "언제
  확정했는지"를 남기는 서버 기능이 필요한데, 2026-08-25 기준으로 이 기능이 일부
  환경에는 아직 반영되지 않았을 수 있습니다. 그런 경우 화면 상단에 숫자 대신 "확정
  시각 기록이 없어 오늘 확정 건수를 셀 수 없습니다"라는 안내가 뜹니다 — 오류가
  아니라 알려진 제한입니다.
- **다른 세 화면과 달리, 이 화면은 조회 권한만 있는 사람에게도 버튼이 흐리게
  보이지 않습니다.** 요청·회신·확정 버튼이 항상 눌러지는 상태로 보이지만, 실제
  권한이 없으면 누른 뒤에 오류로 거부됩니다(확인 필요 — 정확한 오류 문구는 실제
  화면에서 확인하십시오). 자신의 권한이 "조회"뿐이면 이 화면에서 쓰기 동작을
  시도하기 전에 등급을 먼저 확인하는 편이 안전합니다.

### 6) 자주 겪는 상황

- **"확정했는데 목록에서 안 없어진다"** → 정상입니다. 확정은 가격만 정하는 것이고,
  재고가 실제로 들어와야(「재고 입고」 화면) 목록에서 빠집니다.
- **"공급처를 선택할 목록이 아예 안 보인다"** → 활성 상태인 공급처가 없는 경우입니다.
  화면이 "공급처를 먼저 등록하세요 → 공급처 관리" 안내와 바로가기를 보여줍니다 —
  「공급처」 화면에서 먼저 활성 공급처를 등록·확인하십시오.
- **"회신 가격을 잘못 입력했다"** → 이미 입력한 회신 가격을 다시 고치는 버튼이 이
  화면에는 없습니다(값이 한 번 들어오면 회신 입력 창 대신 확정 버튼만 보입니다).
  확정 전이라면 담당자·개발 담당에게 문의해 바로잡으십시오.

## 3. 단가표 반영

*(화면 ID `ADM-PRC-040` · 경로 `/admin2/price-import` · 왼쪽 메뉴 「매입 · 소싱」 세 번째 항목
— «판매가» 그룹이 아니라 이 그룹에 있는 이유는 매입가를 갱신하는 화면이기 때문입니다)*

### 1) 이 화면이 무엇을 하는 곳인가

공급처가 보내주는 엑셀 단가표(.xlsx)를 올리고, 이전 가격과 비교(어떤 상품이 얼마나
올랐는지·내렸는지)한 뒤, 사람이 직접 확인하고 고른 것만 실제 매입가에 반영하는 화면입니다.
**파일을 올리는 것과 가격에 반영되는 것은 다른 단계**입니다 — 올리기만 해서는 아무 가격도
바뀌지 않습니다. 화면 자체가 "매일 아침 3분 루틴 — 올리고 · 보고 · 골라서 반영합니다"라고
안내합니다.

### 2) 언제 여기 오는가

- 공급처로부터 새 단가표(엑셀 파일)를 받았을 때
- 매일 아침, 각 공급처의 최신 단가표가 올라왔는지 정기적으로 확인할 때
- 어제 반영한 것에 문제가 있어 되돌려야 할 때

> **[화면 그림]** 전체 화면 — 좌측 공급처별 파일 카드 + 우측 4장 요약 카드와 가격 변동 표

### 3) 화면에 무엇이 있는가

**좌측** — 공급처별 카드 목록(공급처 이름 · 최신 파일명 · 상태 배지 "대기/부분 반영/반영
완료" · 프리셋 유무). 상단에 **[파일 올리기]** 버튼이 있습니다. 프리셋 없는 공급처가
있으면 그 이름과 함께 경고 상자가 뜹니다. "이 목록이 감추는 것" 상자도 있습니다 — 공급처마다
**최신 파일 1건만** 보여줍니다(같은 이름의 파일을 다시 올리면 예전 미반영 파일이 조회에서
안 보이게 됩니다).

**우측(공급처를 고르면)**

- 파일 정보: 수신 시각 · 총 행 수 · 무변동 처리 건수
- 요약 카드 4장: **가격 변동 · 매칭됨** / **가격 변동 · 매칭 안 됨** / **발주 상태 전환** / **무변동**
- 가격 변동 표(반영 대상, 7열)

| 열 | 뜻 |
|---|---|
| 체크박스 | 반영할 행 선택. 매칭 안 된 행은 체크할 수 없습니다(비활성) |
| 단가표 모델명 | 엑셀 파일에 적힌 모델명 |
| 매칭된 상품 | 우리 시스템의 SKU. 매칭 안 되면 "미매칭" 배지 |
| 이전 매입가 | 직전 파일 기준 가격 |
| 새 매입가 | 이번 파일의 가격 |
| 변동 | 내림(초록) · 오름(빨강) · 신규(비교 대상 없음) · 상태만(가격은 그대로) |
| 매칭 · 상태 | "매칭됨"/"신규 등록 필요" + 보조 설명(예: 다른 공급처가 더 싸서 반영해도 값이 안 바뀝니다) |

- 매칭 안 된 신규 모델 목록(체크박스 없음 — "상품 사양 검수" 화면 소관)
- 발주 상태 전환 목록(품절 ↔ 가능 ↔ 문의, 정보 표시만)

**하단(우측)** — [선택 N건 반영 = 승인] 버튼, 반영 결과(시도/실제 변경/판매가 잠겨
건너뜀 세 숫자), [되돌리기], 지난 반영 이력 표(참고용).

### 4) 무엇을 할 수 있는가

- **[파일 올리기]** — .xlsx 파일을 올립니다. **파일 이름으로 공급처를 자동 인식**합니다 —
  이름이 그 공급처의 등록된 규칙(프리셋)과 안 맞으면 업로드 자체가 거부됩니다.
- 가격 변동 표에서 반영할 행을 체크하고 **[선택 N건 반영 = 승인]** — 체크하고 누르는 이
  동작이 실제 승인입니다. 결과로 "반영 시도 / 실제로 가격이 바뀜 / 판매가 잠겨 건너뜀"
  세 숫자를 보여줍니다. "반영했다"와 "실제로 바뀌었다"는 다른 말입니다 — 이미 같은
  값이거나 다른 공급처가 더 싼 행은 시도해도 실제로는 안 움직입니다.
- **[되돌리기]** — 방금 반영한 것을 취소합니다. "정말 되돌립니까?"로 한 번 더 확인을
  받습니다. 그 사이 다른 경로(예: 매입 견적 확정)로 같은 상품의 가격이 또 바뀌었으면
  되돌리기가 거부되고, **어떤 상품과 겹쳤는지 이름으로** 알려줍니다.

### 5) ⚠ 조심할 것

- **「선택 반영」 클릭이 곧 승인입니다.** 화면 맨 위에 굵게 경고가 항상 떠 있습니다 —
  파일을 올리기만 해서는 아무것도 안 바뀌지만, 체크 후 반영 버튼을 누르는 순간 실제
  매입가 · (잠겨 있지 않으면) 판매가가 바뀝니다.
- **부분 성공이 없습니다.** 체크한 행 중 하나라도 이미 반영됐거나 매칭이 안 된 행이
  섞여 있으면 **전체가 거부**됩니다. 일부만 반영되는 일은 없습니다.
- **매칭 안 된(신규) 모델은 여기서 반영할 수 없습니다.** 표에 체크박스 자체가 없습니다 —
  새로 등록해야 하는 상품이라 「상품 사양 검수」 화면의 일입니다.
- **프리셋이 없는 공급처는 파일을 올릴 수조차 없습니다.** "공급처" 화면에서 새로
  등록해도 이 화면에 바로 연결되지 않습니다 — 파일명 인식 규칙과 열 매핑(프리셋)을
  DB에 별도로 넣어야 하는데, 2026-08-25 기준으로 그것을 만드는 화면이 아직 없습니다
  (필요하면 개발 담당에게 요청해야 합니다).
- **"가격지도(단가 단속)" 시트는 적용되지 않습니다.** 화면 안내 문구 그대로, 단품
  가격을 외부에 노출하지 않기 위해 이 종류의 시트는 반영 대상에서 제외됩니다.
- **같은 파일명을 다시 올리면 예전 미반영 파일이 조용히 안 보이게 됩니다.** 삭제되는
  것은 아니지만, 공급처마다 최신 파일 1건만 보여주기 때문에 화면에서는 사라진 것처럼
  보입니다.

### 6) 자주 겪는 상황

- **"파일을 올렸는데 '공급처를 인식하지 못했습니다'라고 뜬다"** → 파일명이 그 공급처의
  등록 규칙과 다릅니다. 파일명을 확인하거나 담당자에게 문의하십시오.
- **"반영을 눌렀는데 오류가 난다"** → 체크한 행 중에 이미 반영됐거나 매칭 안 된 행이
  섞여 있을 수 있습니다. 화면을 새로고침해 최신 상태로 다시 선택하십시오.
- **"되돌리기가 안 된다"** → 반영한 뒤에 같은 상품의 가격이 다른 경로(매입 견적 확정
  등)로 또 바뀐 것입니다. 오류 메시지에 나열된 상품을 확인하십시오 — "최종 승자"
  원칙이라, 나중에 일어난 변경을 무시하고 강제로 되돌리지 않습니다.

## 4. 재고 입고

*(화면 ID `ADM-SRC-020` · 경로 `/admin2/stock-inbound` · 왼쪽 메뉴 「매입 · 소싱」 네 번째 항목)*

### 1) 이 화면이 무엇을 하는 곳인가

실제로 물건이 들어왔을 때, 그 수량을 재고 원장에 기록하는 화면입니다. 매입 견적·단가표
반영이 "얼마에 살지"를 정하는 자리라면, 이 화면은 **"몇 개가 실제로 들어왔는지"**를
기록하는 자리입니다. 여기서 입력한 수량은 재고 이동 원장에 남고, 그 상품의 재고 수량에
바로 더해집니다.

### 2) 언제 여기 오는가

- 발주한 물건이 실제로 도착해서 재고를 늘려야 할 때 — 입고
- 실사(재고 조사)를 해보니 시스템 수량과 실제가 안 맞아 바로잡을 때 — 실사 조정
- 특정 상품을 지금 당장 처리하지 않기로 했을 때 — 보류
- 예전에 잘못 입력한 입고를 취소해야 할 때 — 되돌리기
- 대기 목록에 없는 상품인데도 물건이 들어와서 수량을 기록해야 할 때 — 직접 등록

> **[화면 그림]** 전체 화면 — 좌측 대기 목록(칩 필터 포함) + 우측 게이트 판정·확정 패널

### 3) 화면에 무엇이 있는가

**좌측 목록** — 재고 0이거나 안전재고보다 적은 상품이 자동으로 뜹니다(직접 등록하지
않습니다). 검색창, 분류 선택, **[직접 등록]** 버튼이 위에 있고, 그 아래 네 개의 칩으로
좁혀 볼 수 있습니다 — **입고 대기**(기본, 보류 제외) · **재고 0** · **안전재고 미달** ·
**보류**. 각 칩 옆 숫자는 지금 조회 조건 안에서 서버가 센 건수입니다.

각 행에는 상품명, 재고/안전재고 상태 태그, 추천 후보 진입 판정, 그리고 **그 자리에서 바로**
수량 입력칸 + 사유(입고/실사 조정) + [바로 확정] 버튼(또는 보류 중이면 [보류 해제])이
있습니다.

**우측 작업 패널** — 좌측에서 상품을 고르면(또는 목록 행의 [바로 확정]을 쓰면) 여기에
표시됩니다.

| 영역 | 내용 |
|---|---|
| 추천 후보 진입 판정 | "추천 후보 포함 / 입고 확정 시 후보 진입 / 추천 후보 제외 / 입고 확정 후에도 진입 불가 / 입고 확정 후 판정" 중 하나 + 이유. 서버가 실제 추천 후보 조건을 조회해 만든 값입니다 |
| 입고 확정 | 입고 수량 입력칸 + 사유(입고/실사 조정) 버튼 + [입고 확정] |
| 확정 결과 | 서버 응답(재고 전 → 후, 품절 해제 여부, 추천 후보 진입 여부)을 그대로 표시 |
| 입고 이력 | 이 상품의 과거 입고·되돌림 기록. **되돌릴 건을 여기서 고릅니다** |

### 4) 무엇을 할 수 있는가

- 목록 행에서 바로, 또는 우측 패널에서: 수량을 입력하고 **[입고 확정]** — 재고가 그만큼
  늘어나고, 품절 상태였던 상품은 자동으로 "판매중"으로 바뀝니다. 확정 전에 "확정하면
  재고 X → Y"로 미리 보여줍니다.
- **[보류]** — 지금은 이 상품을 처리하지 않기로 하고 사유를 남깁니다(사유는 필수
  입력입니다). 보류 중인 상품은 기본 목록에서 빠지고(삭제되는 것은 아닙니다), 입고
  확정을 할 수 없게 됩니다.
- **[보류 해제]** — 보류를 풀어 다시 입고 대기 목록에 나타나게 합니다. 보류 기록 자체는
  지우지 않고 "해제 시각"만 남깁니다.
- **[되돌리기]** — 과거 입고 기록을 취소합니다. "입고 이력" 목록에서 건을 고릅니다.
- **[직접 등록]** — 재고 0·안전재고 미달이 아니어서 대기 목록에 없는 상품도, 검색으로
  찾아 수량을 기록할 수 있습니다(검색어를 넣어야 조회됩니다, 최대 50건).

### 5) ⚠ 조심할 것

- **재고 수량은 "진짜 재고 개수"가 아닌 경우가 대부분입니다.** 상품 정보를 몰(팝콘PC)에서
  받아올 때는 정확한 재고 숫자가 오지 않아서, 시스템이 "판매중이면 1, 품절이면 0"으로
  채워 넣습니다. 2026-08-25 기준 실측으로, 실제 데이터 23,122건 중 수량이 2 이상인
  것은 **1건**뿐이었습니다. 즉 이 화면에 뜨는 "재고" 대부분은 정확한 개수가 아니라
  "있음/없음" 표시에 가깝습니다 — 화면에 보이는 숫자를 그대로 정확한 재고량으로
  믿지 말고, 실제 입고 수량은 확인한 값만 입력하십시오.
- **입고를 확정해도 매입가는 이 화면에서 바뀌지 않습니다.** 재고 원장에는 단가를 남기는
  칸 자체가 없습니다. 매입가를 바꾸려면 「단가표 반영」이나 「매입 견적(용산)」 화면을
  씁니다.
- **수량 상한이 없습니다.** 잘못해서 자릿수를 하나 더 입력해도 시스템이 막아 주지
  않습니다 — 화면이 "확정하면 재고 X → Y"를 미리 보여주니, 확정 전에 반드시 되읽어
  확인하십시오.
- **입고를 확정하면 그 즉시 견적 계산에 반영됩니다.** 되돌릴 수는 있지만, 그 사이에
  이미 고객에게 나간 견적은 그 재고 상태 그대로 나간 것이라 "없던 일"이 되지는
  않습니다.
- **보류 중에는 입고 확정을 할 수 없지만, 되돌리기는 할 수 있습니다.** 보류는 "새로
  입고하지 않는다"는 뜻이지 "이미 기록된 것을 못 고친다"는 뜻이 아닙니다 — 잘못
  입력한 예전 입고를 되돌리는 데는 보류가 걸림돌이 되지 않습니다.
- **앞의 「매입 견적」 화면에서 이미 가격을 "확정"한 상품도 이 목록에 계속 뜹니다.**
  거기서 말하는 확정은 가격 결정이라 재고를 안 늘립니다 — 헷갈리면 들어가며 절의
  구분을 다시 보십시오.

### 6) 자주 겪는 상황

- **"입고 확정 버튼이 안 눌린다(비활성)"** → 그 상품이 보류 중이거나, 내 권한이
  「조회」뿐일 수 있습니다. 버튼에 마우스를 올리면 이유가 뜹니다.
- **"재고가 있는데도 왜 이 목록에 뜨나"** → 안전재고보다 적게 남았기 때문입니다(재고가
  0이 아니어도 뜰 수 있습니다). "안전재고 미달" 칩으로 따로 볼 수 있습니다.
- **"예전 입고를 되돌리려는데 안 된다"** → 그 뒤로 판매나 다른 조정이 있어서 되돌릴
  만큼 재고가 남아 있지 않은 경우입니다. 현재 재고와 필요 수량이 이력 목록에 함께
  표시됩니다.
- **"물건이 들어왔는데 목록에 그 상품이 안 보인다"** → 재고가 안전재고 이상으로 남아
  있어 대기 목록에 자동으로 뜨지 않는 상품일 수 있습니다. 위쪽 [직접 등록]으로
  상품명·SKU를 검색해 수량을 기록하십시오.
- **"이 상품이 추천 후보에 들어가는지 궁금하다"** → 목록·패널에 판정과 이유가 함께
  뜹니다. 재고 말고도 검수 통과·판매가 산정·사양 등록이 다 돼야 후보에 들어갑니다 —
  "품절" 상태인 상품은 입고 확정 전에는 판정 자체가 "입고 확정 후 판정"으로 유보됩니다
  (지어낸 판정을 보여주지 않기 위해서입니다).
