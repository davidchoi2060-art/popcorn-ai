## 주고받는 규칙

1. 모든 변경은 **PR**로 올린다. 제목 앞에 항목 번호를 붙인다. 예: `[5] 판매가 마진 계산 통일`.
2. PR 하나는 **한 항목, 대략 20개 파일 이하**. 커밋 본문에 무엇을·왜를 적는다.
3. PR 본문에 「끝까지 시나리오」 중 어느 단계가 이어졌는지(또는 아직 아닌지) 적는다. 7번 측정기가 생기면 그 결과를 붙인다.
4. 상대 담당 항목의 파일은 고치지 않는다. 필요하면 PR 댓글과 자기 구역의 「상대에게 요청」으로 요청한다.
5. 항목 상태가 바뀌면 이 파일의 자기 구역 표를 같은 PR에서 갱신한다.
6. 중헌님 결정이 필요한 항목은 결정 전까지 시작하지 않는다(표의 「결정 대기」).

> 지금은 PC 쪽이 main에 직접 push하고 있다. 3번이 승인되면 PC 쪽도 PR 흐름으로 바꾼다. 그 전까지는 클라우드 쪽 PR이 PC 쪽 커밋과 겹치지 않게 범위를 작게 유지한다.

## 대화 규칙

1. **각 작업자는 작업을 시작할 때마다 이 파일을 먼저 읽는다.**
2. 상태·결정·질문은 이 파일의 **자기 구역에만** 적는다. 상대 구역은 읽기만 한다.
3. 논의(반론·확인·세부 질문)는 이 파일이 아니라 **해당 PR의 댓글**에서 한다. 이 파일은 순서대로 갱신하는 게시판이지 대화창이 아니다.
4. 상대에게 부탁할 것은 자기 구역의 「상대에게 요청」에 한 줄로 적고, 관련 PR 댓글에도 같은 내용을 남긴다. 받은 쪽은 처리 결과를 자기 구역에 적는다.
5. 아래 「전체 항목 지도」와 「중헌님 결정 대기」는 공용이다. 담당이 바뀌거나 결정이 나면 그 사실을 받은 쪽이 고친다.
6. **화면 UI 디자인 시안은 반드시 PC 쪽(Codex)이 이미지로 만든다**(2026-10-08 중헌님 지시). 클라우드 쪽은 시안을 그리지 않고, 필요하면 PR 댓글로 PC 쪽에 요청한다.
