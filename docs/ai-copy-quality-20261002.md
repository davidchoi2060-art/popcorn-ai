## 적용할 설명 기준

1. 상품명은 고객의 사용 장면을 먼저 보여주고, 소개는 쉬운 2~3문장으로 쓴다.
2. 특장점은 실제 사양과 쓰임을 연결한다. ‘512GB에 문서·프로그램을 저장합니다’처럼 용량과 역할을 설명하고, 충분함은 작업 규모를 확인한 뒤 판단한다.
3. OS·보증·연결 단자·주변기기 포함 여부는 명시된 입력 근거가 있을 때만 단정한다. 미확인 항목을 고객 주의사항으로 확정하지 않는다.
4. 기존 상품 설명도 사실의 최종 근거로 간주하지 않는다. 부품 사양과 대조하고, 충돌은 관리자 notes에 남긴다.
5. 게임 실행 조건, 공식 권장 사양, 실제 측정 성능을 구분한다. 해상도·옵션·구성에 대응하는 측정 근거 없이 FPS를 만들지 않는다.
6. 고객에게 필요한 선택 조건과 내부 검토 요청을 분리한다.

예시 수정 방향:

- N04: ‘512GB NVMe SSD에 운영체제·프로그램·문서를 저장합니다. 영상 자료나 대용량 게임이 많다면 필요한 공간을 먼저 확인해 주세요.’ 이는 저장장치의 용도 설명이며 OS 제공 여부를 뜻하지 않는다.
- N07: OS 미포함 문장은 제안에서 제거하고, 포함 여부 확인은 관리자 notes로 이동한다.
- N07: GPU 명칭의 `RTX 5060`/`RTX 50` 혼용은 실제 등록 정보 보완 대상으로 별도 확인한다. 이번 시험에서 상품 데이터는 수정하지 않았다.

## 코드 반영과 검사 범위

`api/admin_pc_workspace.py`의 공통 프롬프트에 위 품질 기준을 추가했다. 개별 생성과 일괄 생성 화면이 같은 `ai-proposals` API를 사용하므로 두 흐름에 적용된다. benefits의 JSON 형태를 두 문자열 쌍의 배열로 명시하고, 출력 필드·항목 수를 명확히 했다.

39개 단위 검사를 통과했다. 프롬프트 전달, 제안 필드 검증, 저장 검증, 검토 근거 변경 감지 등을 확인했다. 새 프롬프트로 유료 재생성하지 않았으므로 실제 문장 품질 개선이나 편집용 실패 해결은 아직 확인하지 않았다. 프롬프트 보완은 형식 오류의 확정 원인에 대한 수정이라고 주장하지 않는다.
