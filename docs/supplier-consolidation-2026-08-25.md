## 4. (주)클릭나라 -- 별도 등록 경위와 동일 업체 가능성 메모

### 등록됨: supplier_id=495, name=(주)클릭나라, 151건

- 주요 제조사: ASRock(39), GIGABYTE(36), MSI(36), CORSAIR(9), 액슬(9)

  보류, 사장님 판단을 요청했다.

### 주의 -- 이 둘이 같은 곳일 가능성 (지우지 말 것)

- 즉 두 이름 모두 GIGABYTE를 취급한다는 공통점이 있다 -- 다만 신규 쪽은 ASRock/MSI/CORSAIR도 함께
  다루고 있어 이름(브랜드 목록)만으로는 동일 업체인지 서로 다른 업체인지 확정할 수 없다.

  Simple 시트에는 사업자번호 열이 없어 이번 작업만으로는 확인할 수 없었다.
- 만약 같은 업체로 밝혀지면: id=2를 정본으로 유지하고 id=495는 status=중지로 접은 뒤, 상품-공급처

## 7. 방법론 - 어떻게 실행했나

1. openpyxl로 엑셀을 직접 읽었다(로컬 서버 API가 아니다 -- 원본 파일이 로컬 데스크톱에 있다)
2. 정규화 스크립트로 120개를 117개 그룹으로 정리했다(병합 3, 표기정리 3)
3. 드라이런: 117개 대표 이름 전부를 실제 DB에 lower(btrim(name)) 조건으로 조회했다 -- 기존 5건과
   충돌 0건, 117개 상호간 충돌도 0건이었다
4. 1차: 되돌리는 명령을 먼저 작성한 뒤(5장) 로컬 서버(포트 8000, 사장님 서버 -- 종료하지 않았다)에
   owner로 로그인해 (주)클릭나라를 제외한 116건에 대해 POST /api/admin/suppliers를 호출했다
   (성공 116, 실패 0). (주)클릭나라는 기존 id=2와 동일 업체일 가능성이 있어 보류하고 사장님 판단을
   요청했다
5. 1차 검증: DB 재조회로 총 121행(기존 5 + 신규 116), 기존 5행 무변경, 중복 이름 0건,
   admin_operator_activity_logs에 supplier_create 116건이 기록된 것을 확인했다
6. 2차: 사장님이 (주)클릭나라를 기존 id=2와 다른 곳으로 정한 뒤, 등록 직전 유니크 인덱스 충돌을
   한 번 더 재확인하고(여전히 충돌 없음) 같은 방식으로 POST /api/admin/suppliers를 호출해
   supplier_id=495로 등록했다
7. 2차 검증: 총 122행(기존 5 + 116 + 1), id=2 스냅샷이 등록 전후 완전히 같음을 재확인했고,
   admin_operator_activity_logs에 (주)클릭나라 supplier_create 로그가 남은 것을 확인했다

API를 쓴 이유: POST /api/admin/suppliers가 이름 길이(100자), platform(50자), brands(200자) 검증과
중복 이름 차단(409), 활동 로그 기록을 이미 갖추고 있어 SQL 직접 INSERT보다 안전하다. 인증은 .env의
ADMIN_PW로 시드 owner 계정(admin@popcornpc.local)에 로그인했다 -- 두 차례 모두 막히지 않아 SQL 직접
경로는 쓰지 않았다.
