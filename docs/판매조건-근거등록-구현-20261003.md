# 판매조건 근거 등록

사용자가 판매조건 이미지 시안을 확인하고 승인한 뒤 구현했다. 기존 상품 작업공간에 판매조건 탭을 추가했고 OS·키보드·마우스·모니터 포함 여부와 보증 주체·기간을 제품별로 관리한다.

## 근거와 상태

포함 조건은 미확인/포함/미포함, 보증은 미확인/확인됨이다. 확정 상태는 확인 내용·출처 문서 또는 링크·확인일을 요구한다. 포함은 모델·조건 상세, 보증은 주체·범위·1~120개월을 추가 요구한다. 미래 확인일을 거절한다. 등록된 판매조건이 없는 기존 제품은 전부 미확인으로 표시하며 실제 조건을 임의로 채우지 않았다.

새 테이블 없이 기존 `pc_configurations.content._sales_conditions`와 `pc_configuration_history`를 사용한다. 서버가 확인자와 기록 시각을 부여한다. 설명 편집 API로 이 필드를 임의 변경할 수 없다. 저장은 기존 가져오기와 동일한 advisory lock·구성 행 잠금·개정번호·현재 검토근거 확인을 거친다. 변경 이력은 `sales_conditions`로 구분하고 이전 조건·확인자를 남긴다.

조건은 해당 구성 ID, BOM/부품 수량·저장 근거, 판매 제안과 연결한다. 조건의 대상이 바뀌거나 파생 구성으로 복제되면 미확인/재확인으로 취급하며 이전 입력은 참고로만 보여준다. 상품 설명 수정만으로 판매조건 근거가 무효화되지는 않는다. 판매조건 저장은 기존 검토 basis를 바꾸므로 이미 받은 추천 승인은 재검토 대상이다. 판매조건과 충돌하는 설명이 남으면 검토 승인도 차단한다.

## AI·설명 저장

AI 입력에는 유효한 조건 상태·상세·보증기간과 정해진 고객 안내 문장만 전달한다. 운영자 ID·확인 시각·출처 문서·입력 근거 원문은 보내지 않는다. AI는 확인된 조건의 `customer_statement`를 독립된 문장으로 사용한다. 서버는 그 문장과 정확히 일치하는 주장만 허용한다. 한 조건이 확인됐다고 다른 조건이나 보증 범위를 확대하는 문장을 허용하지 않는다. 미확인 조건은 기존 추측차단 규칙을 유지하고 단정 제안을 제외한다.

개별 및 일괄 설명 저장도 최신 확인 근거를 읽어 같은 검사를 적용한다. 이 검사는 한국어 관찰 표현 중심의 보수적 검사이며 모든 자연어/영어 표현의 사실성을 입증하지 않는다. 의미가 같은 다른 문장도 정해진 안내와 다르면 제외될 수 있다. 프로그램·게임 요구조건/성능 보장을 판매조건 등록으로 허용하지 않는다. 보증 안내는 상세 범위를 함께 확인해야 하며 보증기간만으로 모든 부품 무상 보증을 추정하지 않는다.

## 화면과 검사

승인된 좌측 조건 목록/우측 근거 입력/AI 안내 배치를 기존 작업공간 안에 구현했다. 탭·제품 변경 시 미저장 내용을 확인하고, 저장 중 제품 이동과 중복 저장을 막는다. 일부 항목만 저장해도 다른 항목의 입력 초안은 유지한다. 재마운트 시 이전 이벤트 핸들러를 해제한다. 구조·색상 변경은 판매조건 영역에 한정하며 기존 작업 목록·설명/검토/미디어 흐름을 유지했다.

관련 Python 회귀 134개와 Node 이벤트/진행 2개 통과. 실제 N07 DB 트랜잭션에서 조건저장→개정/검토근거 변경→반대 설명 차단→확정 안내 저장→조건 유효 유지→이력 2건 증가를 확인하고 전량 롤백했다. 원래 상품 내용·개정·이력 건수 복원을 확인했다. 실제 판매조건은 변경하지 않았다.

실제 템플릿·CSS·JS와 읽기 전용 DB 자료로 1440/900/600px 화면을 확인했다. 저장 동작은 로컬 전용 응답으로 검사했고 운영 DB를 변경하지 않았다. 가로 넘침/스크립트 오류 없고, 근거/보증기간 누락 차단·저장 후 재조회·탭 왕복·작은 화면 하단 버튼 접근을 확인했다. 증빙은 작업실 `outputs/sales-claim-guard-20261003/` 아래 transaction-verification.json, implemented-ui-verification.json 및 sales-implemented 이미지에 있다. 서버 반영과 실제 AI 대표 3종 검증 결과는 후속으로 추가한다.
