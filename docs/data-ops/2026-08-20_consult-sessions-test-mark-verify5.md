# 검증 세션 5건(6948~6952) data_origin='test' 표식 — 별도 적용 기록 (2026-08-20)

> 이 문서는 `2026-08-20_consult-sessions-test-mark.md`의 §「⚠ 이 목록 «뒤에» 생긴
> 검증 세션 — 미포함」이 남긴 후속 작업의 되돌림 안전판이다. **원본 문서는 건드리지
> 않았다** — 원본 서두가 "다음에 같은 종류 표식을 또 하면 새 날짜로 문서를 추가한다
> (이 문서를 고쳐 쓰지 않는다)"고 명시했고, 그 문서는 5,296건 표식의 유일한 되돌림
> 근거라 편집 실수의 대가가 이 5건보다 훨씬 크다. 그래서 별도 문서로 남긴다.

## 무엇을 했나

`consult_sessions.data_origin`을 5건에서 `'real'` → `'test'`로 바꿨다.
대상은 원본 문서 §187("이 목록 뒤에 생긴 검증 세션 — 미포함")에 이미 내역과 함께
등재돼 있던 다섯 건 그대로다.

| session_id | 담당 | 내용 |
|---|---|---|
| 6948 | 확인자 | 브라우저 고객 경로(정상 흐름 무영향 확인) |
| 6949 | 제작자 | `/api/candidates/count` 응답 확인 |
| 6950 | 제작자 | 견적 응답 확인 |
| 6951 | 제작자 | 견적 응답 확인 |
| 6952 | 제작자 | expert 빌드 확인 |

## 왜

오픈 전 점검(확인자·제작자)이 브라우저·직접 호출로 화면을 두드렸는데, 회귀 차단
게이트(`X-Popcorn-Test` 헤더, 커밋 `ead6dd3`)는 `tests/regression.py` 경로만
덮는다 — 사람이 손으로 낸 트래픽에는 헤더가 없어 `real`로 남았다. 원본 문서가
이 다섯 건을 발견 즉시 표식하지 않은 이유는 "목록의 출처가 그 문서 자신인데,
문서에 없는 것을 스크립트가 찍으면 되돌림 안전판이 실제와 어긋난다"였다 — 이번
작업은 그 다섯 건을 정식으로 문서화하고 표식하는 별도 작업이다.

## 사전 확인 (적용 전 실측)

- 대상 5건 전부 DB에 실존했다(누락 0건).
- 적용 직전 5건 전부 `data_origin='real'`이었다(이미 `test`인 것 없음 — 멱등
  조건 확인).
- **주문 영향**: `orders o JOIN consult_sessions s USING (session_id) WHERE
  s.session_id = ANY(ARRAY[6948,6949,6950,6951,6952])` → **0건**.
- 딸린 하위 원장(조인만, 쓰지 않음): `quote_snapshots` 13건 · `swap_event_logs`
  0건 · `handoffs` 0건. **이 표들에는 쓰지 않았다** — FK로 따라오는 것이지 표식
  대상이 아니다(원본 문서와 같은 원칙).
- 패턴 1~6(원본 문서의 5,296건 목록) 어디에도 이 5개 id가 없음을 grep으로
  확인했다 — 중복 표식 위험 없음.

## 적용 방법

원본 문서의 `tools/mark_test_sessions.py`를 재사용하지 않았다 — 그 스크립트는
`DOC` 경로가 원본 문서에 하드코딩돼 있어, 재사용하려면 원본 문서 본문(패턴
블록)을 편집해야 했다. 대신 같은 안전장치(트랜잭션, 기대 건수 대조, 멱등
`WHERE data_origin='real'` 조건, 적용 후 주문 영향 재확인)를 갖춘 임시 스크립트로
**직접 UPDATE**했다. 저장소에 코드를 새로 남기지 않았다(스크래치패드에서만 실행,
리포에 커밋되지 않음) — 도구 스크립트 신설·수정은 제작자 소관이라 하지 않았다.

실행 SQL(그대로):

    UPDATE consult_sessions SET data_origin = 'test'
    WHERE session_id = ANY(ARRAY[6948,6949,6950,6951,6952])
      AND data_origin = 'real';

## 되돌림

대상이 5건뿐이라 이 문서의 위 표만으로 충분하다:

    UPDATE consult_sessions SET data_origin = 'real'
    WHERE session_id = ANY(ARRAY[6948,6949,6950,6951,6952])
      AND data_origin = 'test';

영향 행 수가 5가 아니면 실행을 멈추고 조사한다(다른 경로로 값이 이미 바뀌었을
수 있다).
