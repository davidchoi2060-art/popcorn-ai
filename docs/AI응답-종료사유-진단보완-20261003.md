앱 업데이트 후 사용자 “시작하자” 요청으로 저장된 N07 JSON 오류 조사 단계부터 재개했다. 앱 26.930.31730/build12947, up_to_date 확인. 기존 구관리자 분석 채팅은 회원관리 등 독립 영역의 시안과 파일 경계 준비를 재개하도록 전달했고, 현재 작업은 llm/admin_pc_workspace 및 관련 검사·문서로 분리했다.

## 확인한 문제

N07 이전 비용기록1607은 출력2496토큰이고 요청상한2500이었다. Gemini 출력 사용량에는 thinking과 답변 토큰이 합산되므로 상한 근접 자체가 JSON 잘림을 증명하지 않는다. 당시 종료 사유나 원문은 보존되지 않았으므로 이전 오류의 원인은 확정하지 않는다.

코드는 텍스트가 있는 Gemini 응답의 finish_reason을 버리고 있었다. Gemini는 MAX_TOKENS를 요청상한 도달로 정의하며, 상한 도달 시 비어 있거나 일부만 생성된 응답에도 비용이 발생할 수 있다. 근거: [응답 종료사유](https://ai.google.dev/api/generate-content#FinishReason), [thinking과 토큰상한](https://ai.google.dev/gemini-api/docs/generate-content/thinking#token-limits-and-max_output_tokens), 2026-10-03 열람.

## 구현 범위

Gemini 어댑터는 기존 세 값 unpacking을 유지하는 ProviderResponse로 안전한 STOP/MAX_TOKENS/OTHER 상태만 전달한다. 기존 다른 어댑터의 tuple과 공개 LLMResult 생성은 호환되며 종료사유는 기본 None이다. Claude/OpenAI 종료사유 수집은 이번 범위가 아니다.

MAX_TOKENS 응답은 빈 텍스트여도 사용량·비용을 기록한 후 반환한다. provider 오류로 전환하여 재호출하지 않는다. 상품 제안 API는 JSON이 파싱 가능하더라도 MAX_TOKENS 응답을 미완성으로 거절한다. 기존 오류 표시에서 “출력 한도 도달로 응답 미완성” 및 진단 ID·비용 기록을 보여준다. 로그에는 안전한 종료상태·출력토큰·요청상한만 추가하며 원문·생성 내용·예외 입력을 저장하지 않는다. 일반 문법 오류는 기존 행/열 진단을 유지하고 토큰 수로 원인을 추측하지 않는다.

출력상한2500, 모델배정, thinking 설정, 프롬프트, 자동폴백/재시도와 저장·승인 동작은 변경하지 않았다. JSON 생성 성공률을 높였다고 검증한 변경이 아니라, 원인 구분과 불완전 응답 거절·비용 추적 보완이다. 추가 유료호출이나 운영 상품/판매조건 저장은 수행하지 않았다.
