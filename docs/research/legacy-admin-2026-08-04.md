## 2. 카테고리 진단 (사용자가 지목한 "가장 큰 문제")

### 2.1 대분류 20개가 섞고 있는 다섯 축

| 축 | 해당 대분류 |
|---|---|
| ① 실제 상품 분류 | 컴퓨터주변기기(4,235) · 모니터(622) · 기타주변기기(429) · 키보드,마우스외(321) · 음향＊방송장비(197) · 소모품(114) · 케이블/변환젠더 · 쿨링/튜닝용품 · 노트북 · 가전제품 · 화장품/미용(0) |
| ② 완제품 유형 | ai 슈퍼컴퓨터(2) · 프리미엄 피씨(231) · 가상화폐 채굴기 · 알레오코인 채굴기/부품 |
| ③ 마케팅·채널 | 베스트7주력부품 · 네이버노출 |
| ④ 내부 업무 | 내부관리용 · 고객님 개인결제 |
| ⑤ 폐기 | 삭제대기 |

**①만 카테고리다.** ②는 상품 유형, ③은 노출 규칙, ④는 업무 플래그, ⑤는 생명주기 상태다.
넷 다 카테고리가 아니라 **속성**이어야 한다.

### 2.2 진짜 부품 분류는 2단계에 묻혀 있다

`컴퓨터주변기기(4,235건 · 전체의 54%)` 아래 2단계가 실제 PC 부품 축이다:

```
프로세서(CPU) · CPU쿨러 · 메인보드(M/B) · 메모리(RAM) · 그래픽카드(VGA)
고속저장(SSD) · 저장장치(HDD) · 케이스(CASE) · 시디롬(ODD) · 파워(POWER)
+ 전체리스트 · 중고그래픽카드 · 운영체제(OS) · 제작,서비스 · 프린터
+ 컴퓨터서버 · (기타)쿨러등 · 네이워크장비/기타 · 위메이드 · 채굴기
```

즉 **대분류 1개가 전체의 절반을 담고, 나머지 19개가 절반을 나눠 갖는다.** 트리로서 기능하지 않는다.
그 안에도 `전체리스트`(카테고리가 아님) · `위메이드`(회사명) · `중고그래픽카드`(상태) · `제작,서비스`(용역)가 섞여 있다.
오타도 그대로다 — `네이워크장비`.

### 2.3 같은 것이 여러 곳에 있다

| 부품 | 중복된 위치 |
|---|---|
| **CPU** | 컴퓨터주변기기>프로세서(CPU) · **베스트7주력부품>CPU** · 내부관리용>인텔정품cpu / 인텔벌크CPU / 오픈마켓CPU |
| **쿨러** | 컴퓨터주변기기>CPU쿨러 · 컴퓨터주변기기>(기타)쿨러등 · **쿨링/튜닝용품**(대분류)>RAM/VGA/HDD/시스템 쿨러 |
| **모니터 케이블** | 모니터>모니터 케이블 · 케이블/변환젠더>모니터 케이블 |
| **노트북** | 노트북(대분류) · 기타주변기기>노트북 |
| **채굴기** | 가상화폐 채굴기(대분류) · 알레오코인 채굴기(대분류) · 컴퓨터주변기기>채굴기 |

`베스트7주력부품`은 **부품 분류 전체를 약어로 복제한 두 번째 트리**다(CPU·MBD·RAM·SSD·HDD·ODD·VGA·CAS·PWR).
같은 CPU가 어느 트리에 들어가느냐가 담당자 기분에 달려 있다는 뜻이다.

### 2.4 가장 나쁜 것 — `내부관리용`

```
상품평 0개 · 상품평 20개이하 · 상품평 21~50개 · 상품평 51개이상   ← 리뷰 수를 카테고리로 쓴다
단품비노출 · 만상장부용 · 조립관련 · MD추천상품 · 에누리 · 오픈마켓CPU  ← 업무 플래그
팝콘추천업그레이드 · 팝콘피씨 · ECS미니PC_부품 · 라이젠 3세대 · DDR3 메모리
```

**리뷰 개수가 카테고리다.** 리뷰가 21개가 되면 상품이 카테고리를 이동해야 한다 — 분류가 시간에 따라 변한다.

### 2.5 `프리미엄 피씨`도 축이 섞였다

용도(가정용/사무용 · 게임/그래픽/주식용 · 디자인/업무용 · 고성능/전문가용) +
브랜드(인텔컴퓨터 · 라이젠컴퓨터) + 폼팩터(초슬림/미니타워) + 가격대(초저가 가성비짱) +
운영상태(온라인DB완료) + 결제수단(소중한고객님※개인결제※) + 무관품목(생활가전).

**우리 S1이 묻는 "용도"가 여기 이미 있다** — 가정용/사무용 · 게임 · 디자인/업무 · 고성능/전문가.
다만 카테고리로 박혀 있어서 재사용이 안 된다.

## 3. 상품상세필드 — 우리 검수 대기와 같은 병

`상품상세필드관리`는 우리 `spec_field_defs`와 같은 물건이다. **필드별 미입력 수를 보여준다.**

| 카테고리 | 선언된 필드 수 | 실태 |
|---|---|---|
| **메인보드(M/B)** | **324** | 2,094개 상품 **전부 미입력** |
| **그래픽카드(VGA)** | **307** | — |
| 파워(POWER) | 42 | — |
| 케이스(CASE) | 38 | — |
| CPU쿨러 | 28 | — |
| 프로세서(CPU) | 22 | 아래 참조 |
| 저장장치(HDD) | 22 | — |
| 메모리(RAM) | 19 | — |
| 고속저장(SSD) | 11 | — |

**메인보드 324개 필드 안에 이런 것들이 있다:**
`헤드셋채널` · `헤드폰 단자` · `화면 크기` · `화소수` · `화질개선 칩` · `80 PLUS` · `+12V 출력` · `+3.3V 출력`

파워·모니터·헤드셋 필드가 메인보드에 쏟아졌다. **필드 정의가 카테고리별로 격리되지 않고 전역 풀에서 쏟아진 것이다.**
`화면 크기`와 `화면크기`, `화소수`와 `화소수(H/W)`처럼 띄어쓰기만 다른 중복 필드도 있다.

CPU 22개 필드 중 실제로 채워진 것은 5개뿐이다:
```
채워짐:   소켓 구분 · 설계전력 · 동작 속도 · 브랜드 분류 · 쓰레드 형태   (672개 중 18개만 미입력)
전멸:     CPU 대역폭 · GPU 코어 속도 · KC 인증 · L2 캐시 · 가상화 지원 · 등록년월 · 연산 체계  (672/672 미입력)
```

**교훈:** 이건 우리가 슬라이스에서 이미 내린 판단(`필수 사양 = 게이트가 실제로 읽는 것만`)이 옳았다는
실물 증거다. 저쪽은 324개를 선언해 두고 0개를 채웠다. **선언과 충족은 다른 일이고, 안 읽는 필드를
선언하면 상품이 근거 없이 검수 대기에 묶인다.**

## 4. 게임 설정 — 우리 미정 결정에 대한 실물 답

`완제PC > 게임설정` = **게임별 시스템레벨**. 3분류가 아니라 **숫자 척도**다(80~270).

| 레벨 | 게임 |
|---|---|
| 80 | WOW · 피파온라인4 · 리그오브레전드 |
| 160 | 디아블로2 · 배틀그라운드_최소 · 오버워치_최소 |
| 200 | GTA5 · 배틀필드4 · 배틀필드5 · 몬스터헌터_최소 · 리그오브레전드_울트라급 · 오버워치_최상급 |

| 260 | 몬스터헌터_울트라 |
| 270 | 배틀그라운드_울트라급 |

**핵심 통찰: 게임 무게는 게임당 값 하나가 아니라 `(게임 × 목표 옵션)` 쌍이다.**
리그오브레전드는 80이면 되지만 울트라로 돌리려면 200이다 — **2.5배**. 배틀그라운드는 160→220→270.
"롤 하려고요"라는 답만으로는 견적을 못 낸다. **"어느 정도로 돌리고 싶은지"를 같이 물어야 한다.**

단, 이 표에도 운영 흔적이 있다: `5555`(레벨 150 — 테스트 행) · 디아블로2 중복 2행 ·
오타 `배틀필트4/5`(배틀필드) · `리그오브래전드`(레전드).

## 5. 가격 — 우리와 공식은 같고 수수료가 다르다

카테고리관리 화면 상단 명시:

```
소비자 판매가 생성기준 = (매입가 + 기본설정된 카드수수료 (2.585%) + 실제 소비자마진)
카테고리별 설정된 마진·딜러할인율·마일리지 일괄적용 순서) 4단계 → 3단계 → 2단계 → 1단계 → 기본설정
```

| | 기존 시스템 | 팝콘PC AI 현재 |
|---|---|---|
| 공식 | 매입가 × (1 + 카드수수료 + 마진) | **같음** |
| 카드수수료 | **2.585%** | 2.2% |
| 카테고리 마진 | 있음 + **4단계 상속** | 표(`category_margin_policies`)만 있고 **행 0개·상속 로직 없음** |
| 딜러할인율 · 마일리지 | 카테고리별 | 없음 |
| 배송박스수량 | 카테고리별 + 상속 | 없음 |

**이건 세워 둔 "판매가 재산정" 작업에 직접 쓸 설계다.** 상속 규칙(하위가 이기고, 없으면 상위, 최후에 기본설정)이
이미 검증된 형태로 존재한다. 우리는 표만 만들어 두고 비워 뒀다.

수수료 2.585% vs 2.2%는 **확인이 필요하다** — 저쪽 값에 PG 외 비용이 섞였을 수 있다.

## 7. 절대 물려받으면 안 되는 것

1. **4단 고정 깊이** — 1,458건이 바닥까지 못 갔다. 깊이는 부품 종류마다 달라야 한다.
2. **카테고리에 업무 상태를 넣는 것** — `내부관리용` · `삭제대기` · `네이버노출` · `상품평 21~50개`.
3. **분류 트리를 두 벌 두는 것** — `베스트7주력부품`.
4. **전역 필드 풀** — 메인보드에 헤드폰 단자가 붙는 원인.
5. **이름에 상품명·기호를 박는 것** — `가전제품[린클음식물처리기 / 비비딕벌레퇴치기]` · `소중한고객님※개인결제※`.
6. **테스트 데이터가 운영에 남는 것** — 게임 `5555`.

## 8. 우리 설계로 옮길 제안 (확정 아님 — 사용자 판단 필요)

**축을 가른다. 카테고리는 하나만 남긴다.**

```
part_type          부품 종류 — 단일 트리, 얕게(2단 이내). 이미 우리가 가진 것.
build_type         완제품 유형(AI워크스테이션 · 게이밍 · 사무용 …) — 카테고리 아님
tag_*              마케팅 노출(베스트 · 네이버) — 이미 tag_silent/tag_white 선례 있음
lifecycle          판매중 · 단종 · 삭제대기 — 상태 컬럼
condition          신품 · 중고 — 속성(현재 `중고그래픽카드`가 카테고리인 것을 대체)
```

`spec_field_defs`는 **part_type별로 격리**하고, **게이트가 읽는 필드만** 선언한다(현행 유지·강화).

게임 무게는 **`(게임, 옵션목표) → 요구레벨`** 쌍으로 잡는다. S1이 게임을 물으면 옵션 목표도 같이 묻는다.

## 9. 사용자에게 확인이 필요한 것

1. **카드수수료 2.585% vs 우리 2.2%** — 어느 쪽이 맞나? 2.585%에 PG 외 비용이 포함돼 있나?

3. **게임 무게를 숫자 척도로 갈까**, 아니면 기존 계획대로 3분류를 유지하고 옵션 목표만 추가할까?
4. 기존 시스템의 카테고리를 **이관할 것인가, 새로 세울 것인가?**
   (이관하면 위 문제를 그대로 물려받는다. 새로 세우면 7,804건 재분류가 필요하다.)
5. **`조립` 단계**를 우리 주문 흐름에 넣나? 현재 우리 S4에는 없다.
