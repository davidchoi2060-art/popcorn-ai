## 3. 가격 — 여기가 가장 크게 다르다

한 상품에 **판매 채널(몰) 4개**가 붙어 있고, **채널마다 수수료율이 다르다**:

| 채널 | 법인 | 수수료 |
|---|---|---|
| `basic` | 주식회사 팝콘컴퓨터 | **2.585%** |
| `kjwang` | 주식회사 팝콘컴퓨터 | **7.7%** |
| `kjwang1` | 주식회사 팝콘피씨 | **4.4%** |
| `kjmart` | 주식회사 팝콘피씨 | **0%** |

**채널마다** 아래를 각각 갖는다:

- **회원 등급 6단 가격**: `시중가 · 일반회원 · 프리미엄 · VIP · VVIP · 지도가`
- `가격 · 마진 · 예정가` / `마진% · 할인% · 적립금 · 추천`
- **`카드원가`** — 카드 수수료를 반영한 원가
- **경쟁사 순위가**: `일등가 · 이등가 · 삼등가` (각각 우리 대비 차이 %)
- 배송·정책 플래그: `판/고 · 딜/노 · 기/배 · 무/배 · 착/가`
- `에누리` · `판매가로그`(가격 변경 이력)
- `견적왕 (카드 최저가 / 현금 최저가)`
- 메모 — 예: `다나와[카드몰] 적용` / `다나와[현금몰] 적용`

그리고 상품 단위로 **`지도가(카)` · `지도가(현)`** (카드가/현금가 지정가)가 따로 있다.

### 우리와의 격차

| | 저쪽(운영 중) | 우리 |
|---|---|---|
| 판매 채널 | **4개, 채널별 수수료율** | 운영 전환 스위치(전역) |
| 회원 등급 가격 | **6단** | 없음 — 단일 `sale_price` |
| 원가 | **카드원가**(수수료 반영) | `product_supplier_prices.cost_price` |
| 경쟁사 추적 | **1·2·3등가 + 격차%** | 없음 |
| 가격 이력 | 채널별 `판매가로그` | `product_price_history` ✅ |
| 마진 | 채널×등급마다 | 전역 12% + 카테고리 노드 |

## 5. 이 실사가 우리 설계에 주는 것

### 5.1 확인된 것 (기존 판단이 옳았다)

- **4단 카테고리를 서둘러 만들 이유가 없다.** 저쪽은 틀만 4단이고 실사용은 2단이며,
  강제한 결과가 미매핑 1,458건이었다.
- **카테고리에 다섯 축을 섞으면 안 된다** — 실물로 재확인.
- 사양을 **구조화한 것**(`product_specs`)은 우리가 낫다. 저쪽은 텍스트 한 덩어리라
  "스팩"이 검색 대상일 뿐이다.

### 5.2 우리에게 없어서 **새로 생각해야 하는 것**

| 축 | 왜 필요한가 |
|---|---|
| **회원 등급별 가격** | 실제로 6단을 운영 중이다. 우리 `sale_price` 단일 값으로는 이 사업을 못 옮긴다 |
| **채널별 가격·수수료** | 법인 2개 × 몰 4개가 이미 돌고 있다. A-10 운영 전환 스위치는 전역이라 이걸 표현 못 한다 |
| **경쟁사 1·2·3등가** | 가격 결정의 실제 입력값이다. 우리 `판매가 재산정`은 원가×마진만 본다 |
| **카드원가** | 카드 수수료가 원가에 들어간다. 우리 마진 계산에 그 개념이 없다 |
| **상품 단위 채널 노출 제어** | 다나와 제외·네이버 제외 같은 상품별 스위치 |
| **창고·상품위치** | 실물 재고 관리 축. 우리는 수량만 안다 |
| **담당자** | 상품마다 사람이 붙어 있다 |
| **제조사 정규화** | 2,368개가 된 모습을 봤다. 우리 620종일 때 손대는 게 싸다 |

### 5.3 아직 못 본 것

- 2·3·4단계 카테고리의 실제 내용(1단계를 골라야 채워지는 구조)
- 오픈마켓 스케줄 · 옵션 세부 규격
